# 开局设置（房主配置）

> 房主在开局前配置本局规则项；**默认值 = 当前常量**，不配置即等于现状（保证回归可复现）。
> 本文是**运行期可调数值的唯一收拢处**——各玩法文档标「设计待定」的项，最终默认值以本文为准。
> 入口：房主在大厅点「开始游戏」前弹出设置面板，确认后随开局下发全体（客户端**只读**）。

## 一、通用原则

- **房主权威**：设置由房主配置、开局时下发；客户端只读展示。
- **默认值 = 当前常量**：不配置即等于现状。
- **校验**：每项有 min / max，越界钳制。
- **每局从默认值起**：开新的一局（开房）时面板一律展示默认数值 / 开关，房主自行调整；
  **不做预设方案**（2026-10-09 删除，见 §九）。
- **面板形态（2026-10-09）**：每一节一个**带边框的盒子**（`UIKit.SectionBox`），小标题骑在上边框
  正中；**多选一**用 chip 行（说明一行 + 整行 chip），**开 / 关**用**开关组件**（`UIKit.Switch`，
  不再用「关 / 开」两枚 chip）；数字项「说明在左、输入框在右」。面板里**不写提示文案**
  （原先顶上那句「默认值 = 现状常量…」已按用户要求去掉）。
- **逐项独立**：设置项之间不互相推导，除非显式写明联动（如胜利条件的子项）。

「设计状态」列：**定稿** = 已拍板；**候选** = 方向认可、待拍板；**待定** = 尚未讨论。

### 三之一 ·「操作限时挡位」细则

> 原「操作时间倍率 ×1.0（0.5 ~ 3）」方案**作废**：改为**绝对挡位**，语义更直白
> （房主直接说「每人 30 秒」）。

- **取值**：共 5 档。
  - `现状`（默认）= 各环节沿用原常量：掷轮 **35s**、买地 / 升级决策 **25s**、
    道具阶段 **12s**、逛店 / 黑市 **20s**。
  - `15s` / `30s` / `60s` = 上述**每个环节各自**取该秒数（不是整回合共享预算）。
  - `不限时` = 不计时、**不自动兜底**；真人挂机会真的停在该回合
    （已确认接受此风险，靠现有退房 / 终止对局处理）。
  - 未知 / 非法值一律回落 `现状`。
- **生效时机**：改挡位**立即生效并重计时**——正在跑的等待按新值重新开始。
- **配置入口（两处）**：
  1. **大厅**：房主点「开始游戏」前弹极简弹窗（仅「操作限时」一排 chips + 取消 / 开始）。
  2. **对局内**：暂停 → 设置面板新增「操作限时」一行，**房主可改、客户端只读**。
  - 客户端在大厅看不到该挡位（入口仅房主可开）；开局后在对局内设置面板可见。
  - **不持久化**，每局重设。
- **表现**：决策弹窗的倒计时进度条按当前挡位重启；`不限时` 档不显示倒计时条。
  掷轮 / 逛店环节本无倒计时 UI，不新增。
- **文案**：规则说明里的「真人 35 秒不掷」「25 秒不答」按本局挡位显示（`不限时` 档显示「不限时」）。

## 九、H · 预设方案（**已删除**，2026-10-09）

**结论：不做预设方案。** 一局新游戏开始时，设置面板一律展示**默认数值 / 开关**，房主自行调整。

原表是 5 档（标准局 / 快节奏 / 大富翁 / 大乱斗 / 新手局），实现为**覆盖式** —— 只有「标准局」
是 15 项全量快照，其余四档**只改列出的那几项、剩下的沿用打开弹窗时的当前值**。于是先点
「大乱斗」再点「快节奏」，看着是切了档、实际只改了 3 个数，科技 / 畸变 / 各开关仍是「大乱斗」
那一套 —— 与「预设 = 一档配置」的预期不符，用户 2026-10-09 判为不必保留，**整段删除**
（`lobby.gd` 的 `PRESETS` 常量 / `_apply_preset()` / `_set_preset_chips` 三处全删）。

**替代它的那条口径**：`net.host_game()` 每次开房都把 `game_settings` 重置成一份新的
`GameSettings` ⇒ **开新的一局看到的就是默认值**；同一局里反复开弹窗回显的是房主刚存的那份
（方便复核），打完一局回主菜单再开房、又是默认值。理由与取舍见 `设计决策留痕.md` §二十一。

## 十、设计待定

1. 棋盘规模是否可调（大改，建议后置）。
2. 是否允许**负资产**（关闭「破产淘汰」时的结算规则）。
3. 设置面板形态：折叠分组是否够用；哪些项进「高级」、哪些常显。
4. 各「候选」项的最终默认值与范围，随「数值专场」定稿。
