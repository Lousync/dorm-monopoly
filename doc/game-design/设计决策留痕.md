## 一、顶部区域升级为「活动面板区」

> **⚠ 本节已作废（2026-10-03 · v0.5.0 批次 1）**：原拍板「小卖部 / 赌场做成桌面常驻设施、
> 全桌围观」被**反转**——两座设施撤下桌面，改为触发时独占的全屏界面。
> 反转理由：2.5D 斜视桌面下桌面的文字读不清（见 `development/plans/v0.5.0-布局2.5D.md` §三），
> 而设施正是桌面上文字最密的两块；且 Liar's Bar 式的桌游感靠"桌子本身"，不靠"设施摆桌上"。
> 本节保留只为还原当时的取舍，**不是当前事实**。

**拍板（2026-10-01）**：整条空区分两半，左小卖部、右赌场，均为常驻桌面设施。

### 目标

棋盘上方的空区升级为**桌面活动区**：进商店、开赌场时不再是全屏弹层，
而是出现在桌面的常驻设施位——全桌人都能围观，保持桌游临场感，棋盘不再被遮挡。

### 布局方案

- **整条空区分两半**：上层为数据轨（战况四家横排 + 最近战报事件流），
  下层左「小卖部」右「宿舍赌场」两座常驻设施，世界坐标随桌面旋转；
  2/3 人局没有上家座位时顶部区也会整体入画。
- **小卖部**：木柜台 + 绿白圆弧雨棚 + 招牌木牌 + 3 格货架 +
  品质图例（白绿蓝紫橙）+ 刷新按钮。
- **赌场**：绿呢牌桌 + 金色滚边 + 卡背装饰，奖池大字 + 状态行；
  开局玩法仍在屏幕弹层进行。
- **质感分层原则**：桌上的「设施」用暖色实体材质（木 / 呢 / 金），
  「数据轨 / 座位栏」保持冷色玻璃质感退居辅助层——桌游感先靠材质分层立住。

### 公共 / 私人分层（红线）

- 桌面面板只放**公共信息**：货架存货、奖池、轮到谁、牌堆余量、已公开的事件流、
  操作按钮（买 / 刷新 / 抽顶 / 抽底——所有人可见，房主只认当前行动者的点击，超时托管）。
- **私人信息永远走屏幕私弹**（沿用赌场透视的私密通道模式）：透视结果、
  以后道具系统的私人交互同理。真实桌游类比：桌面摆公共牌，手牌在各自手里。

### 镜头规则

- 活动开张 / 轮到行动时，只对**处于自己视角**的玩家平滑聚焦到活动区
  （复用掷轮对焦转盘的逻辑）；
- 身在别人视角的玩家镜头不被抢（沿用现有「自家视角」闸），想围观按空格。

> ⚠ 以上「镜头规则」随转视角一并作废（2026-10-03）：相机恒在自己座位，不存在"别人视角"。

### 未拍板

- 赌场玩法弹层迁入桌面面板的时机（桌面设施已先行常驻显示奖池 / 状态，不阻塞）。

    Hearthstone GDC 2015 UI 讲座（Derek Sakamoto）、toast / banner 规范

- **视角按钮（跟随 / 全景 / 左家 / 对家 / 右家）删除**：视角切换保留点座位卡 / Tab / 空格。
  > **⚠ 2026-10-03（v0.5.0 批次 1）反转**：转视角**整个删除**，相机固定在自己座位不再转动。

## 三、道具与系统的逐条拍板（2026-09-30）

1. 香皂融化计数 = **持有者自己的回合数**。
2. 蛋蛋节概率：使用者紫 70 / 橙 30，他人白绿蓝均分。
3. 蛋蛋节满包玩家**改发 ¥100 现金**。
4. 焦土捐款被香皂拦截时**进度不涨**。
5. 小卖部 **4 家**；**每家店独立货架**（机会卡「进入小卖部」进随机一家）。
6. **背包对所有人公开**。
7. 黑市价目：紫 1 / 橙 2 / 刷新 1 / 出口 1 块地皮；**黑市刷新不涨价**
   （递增刷新价仅小卖部）。
8. 被收地皮**回归无主、可被再次购买**。
9. 进黑市**强制且不算 debuff**。
10. **橙色在小卖部出现**，铺货 5% 概率（橙池空时并入紫）。
11. 休眠 = 保守托管、小黑屋 = 休眠（确认）。
12. 强身健体**冷却不减**。
13. 科技结果**全员公开**。

## 五、桌面实体化 + 双视角（2026-10-03 · 四条反转）

**缘起**：用户提供《骗子酒馆》《邪恶铭刻》参考截图，指出"两个游戏桌面上的东西都是实体、

`development/plans/v0.5.0-桌面实体化-设计.md`（该文件随版本删除，**本节是它的留档**）。

**参考出处**（截图在本机、带水印有版权，**不入库**）：骗子酒馆实机 = 第一人称坐席 + 三 3D 角色围圆桌 + HUD 退四角；
邪恶铭刻 3D = 第一人称俯看 + 手里实体握牌 + **桌垫是印的、牌才是实体** + 单点烛光四周近黑。
→ 两组图**都印证**了批次 1「删除转视角」的方向（都是坐在桌边看桌面，不是围观旋转）。

### 四条反转

   掷轮改为**点桌面上的转盘本体**，出牌改为**点手里的牌**，现金/体力改为**桌上的筹码堆与实体小件**。
   > **⚠ 2026-10-04 反转（批次 7）**：现金 / 体力**不再上桌** —— 筹码堆与体力件两条子系统整体退场

## 六、批次 3 落地时的取舍（2026-10-03 · 用户授权代理自行拍板）

**缘起**：批次 3 六个任务逐条过审、终审又出三条 Important 之后，用户睡前授权「剩下的任务你自己完成、设计决策你自己拍（从玩家角度）、素材走开源」。本节记的是**代理替用户拍的那些**——凡是与前面拍过的冲突或推翻，都单列。

**1. 主动丢弃道具：补回入口，不推迟到批次 5。**
座位卡上的「✕」是 `item_discard_clicked` 的唯一发射方，牌位拆除后整条链路不可达，而游戏内规则说明仍写着「可主动丢弃」。
- 关键理由：设计稿 §三 自己写着「**自己的那面立牌在 3D 视角退到画面外——第一人称看不见自己**」⇒ **批次 5 的立牌并不会自动把「✕」带回来**，推迟不等于有人做。
- 拍板：**手牌上右键 = 丢弃**，沿用原两步确认（第一次点亮待确认、第二次真丢）。右键本是本作的「次要操作」，落在牌上即丢弃；左键仍为选中。

**2. 选目标期间手牌必须对点击透明（推翻代理自己先前的一次裁定）。**
先前否决过"选目标时关闸"，怕变成「点着牌却选中了格子」。终审指出更要紧的一面：**选目标时玩家正需要点格子**，而牌底那 3~5 格会答"改选另一张牌"⇒ **指向性格子的道具打不到自家附近的格子**，是功能性漏洞。
- 拍板：**加上 `_tgt_stage == ""`**。功能漏洞比可恢复的错愕更重。

**3. 物件与 2D 相机的关系 = 语义，不是缺陷。**
轮盘**位置**来自相机（贴的是**印在桌垫上的**那个轮盘），手牌 / 立牌用**画布常量**（自由立在桌上的实物；筹码 / 体力件原也走画布常量，已在批次 7 退场，见 §七）。抽卡把 2D 取景推到 2× 时印出来的棋盘会滑动而实物不动。
- 拍板：**轮缘跟相机、实物不跟**。桌面上的实物不该因为"印出来的图案"变了而移动。已写成正式约定（`table_props.gd` 头 + `架构总览.md` §五），并出了 `freecam` 出图确认无穿帮。

**4. 丢弃待确认只在"arming 时的那个 (回合, 等待) 窗口"内有效。**
只按 `phase` 判（`playing`/`ended` 两态）在整局进行中恒假 ⇒ 跳过/超时结束道具阶段后红标整轮挂着、下一次右键一下就丢。
- 拍板：记下 arm 时刻的 `turn` 与 `await`，任一变化即解除。**不**用 `await != "item"` 一刀切——丢弃任何时候可用，一刀切会抹掉合法的一次 arm。

**5. 批次 4 的形态（本节随批次 4 计划一起定，落地后回填结果）。**
- **视角量 `view_t ∈ [0,1]`**（0 = 3D / 1 = 2D），滚轮**每格 ±0.25**，`_process` 里帧率无关地平滑逼近 ⇒ 满足"由滚轮累积量驱动、不是硬切开关"。
- **俯角与「到注视点的 3D 距离」一起插值**（50°→88°，距离 5.8/cos50° → **8.6**）。只插角度会让桌面在近俯视下超出画面（桌面竖直投影 8 格约 sin50°≈6.1 → sin88°≈8.0）。**落地回填**：计划估的是 8.2，实测中段（view_t≈0.45）会只剩 0.0~0.3 像素余量（近边贴屏），抬到 **8.6** 后同一档余量 10.9px、两端 35px 上下（`const VIEW_DIST_2D` 的注释记了完整推导）。
- **手牌随 `view_t` 淡出**（0.35→0.65 淡完），淡到 `HAND_HIT_MIN_ALPHA` 以下 `hand_hit` 直接返回 -1 ⇒ **"看不见就点不到"，于是 `game.gd` 一行都不用改**。
- **`dolly` 整个删除**，滚轮改驱动视角。
- **残余选中让牌能在 2D 端被打出（有意接受的口径）**：验收里的「出牌要回 3D」**约束的是"选中"** ——
  在 3D 端选好一张牌、再滚到 2D，牌垫上的「使用「X」」按钮**仍能把它打出去**（按钮有标签、结果也合法）。
  因为 `hand_hit` 在 2D 端给 -1 只挡住"在 2D 端**选中**"，挡不住"带着 3D 端的选中滚过去"；而
  `game._on_table_click` 判手牌只走 `hand_hit`，选中态本身不进 `view_t` 的判定。**不**为它去让 `game.gd`
  理解 `view_t`（那是批次 4 刻意避免的耦合）——按钮本身有标签、结果合法，这条口径可以接受。
- 2D 端的牌垫「使用道具」按钮**不动**（2D 下没选牌它显示「跳过」，那是合法动作；藏它要新增一处 BoardView 改动，收益不成比例）。

## 七、批次 7 反转：筹码堆 / 体力件整体退场（2026-10-04 · 用户要求「桌面减负」）

**缘起**：用户看桌面觉得挤 —— 转盘 / 两摞牌堆 / 筹码堆 / 体力件 / 手牌 / 四块立牌全摊在同一张桌垫上。
批次 7 的要求就是**给桌面减负**、把操作改到更顺手的落点（同批次的另外几项：牌垫两个阶段按钮改址 + 直出、
点牌即出牌）。

**被推翻的是批次 3 的两条**（同一次拍板的两半，理由也一样）：

1. **现金上桌**：筹码堆 —— 每 ¥5,000 一枚、封顶 8 枚，斜摞在自己面前（`TableProps.set_chips`）；
2. **体力上桌**：体力件 —— 一排方块小件，用掉的熄灭（`TableProps.set_stamina`）。

**当时的理由**：让读数"长在棋子上" —— 桌游感要求操作对象是桌子上的物件，而不是屏幕 HUD 上的数字
（与 §六 3「实物用画布常量、自由立在桌上」是同一套想法）。

**反转理由（三条）**：

- **重复**：筹码只是**身家的量级示意**（5,000 一档、封顶 8 枚），而屏幕四角的**四角身家条**
  已经写着每位玩家的身家（大字）与**精确现金**（第二行小字）。同一份读数有两个落点，
  桌上那个还是**粗档的** —— 留它等于留一个"看得见、但读不准"的数。
- **同一份数据的第二个落点（体力）**：体力件与四角身家条读的是同一个 `stamina`；
  体力最终归批次 9 的**玩家道具弹窗**（那里才是用它的地方）。
- **空间**：两件都落在近端"自己面前"那一小片桌垫上，与手牌 / 牌垫阶段按钮抢同一块地方。

**落地**：`set_chips` / `_make_chip` 与 `set_stamina` / `_make_pip` 两条子系统、`CHIP_*` / `PIP_*`
常量、静态 `chip_count()`、`Chips` / `Stamina` 两个节点池整体删除（`table_props.gd` 里只留一段说明），
`game._refresh_table_props` 里那两行调用一并删掉。**桌面剩余实物 = 转盘轮缘 / 两摞牌堆 / 手牌 / 四块立牌**。
`layout_test` 改写成**反向契约**（"接口与节点都已退场"）—— 谁把这两条加回来，那几条断言先红。

**没有反转的两条**（免得后人以为"既然实物上桌被推翻，那整套约定都翻了"）：

- `PROPS_Y`（桌上实物的高度）一字未改 —— 剩余实物仍用它；只是被删的两件曾用它。
- 「谁跟 2D 相机」的约定不变：**跟**的还是那两件（转盘轮缘 / 两摞牌堆），**不跟**的是手牌 / 立牌。

**接受的代价：不可用的牌被点 = 静默无反应（2026-10-04，本批裁定）**

## 八、批次 8 反转：抽卡演出搬到屏幕层（2026-10-04 · 用户 ①）

> **被推翻的是批次 6 Task 2/3 的「抽出起点 = 实体摞顶面 + 演出期间逐帧重推」**（§五 /
> `development/开发台账.md` §三 批次 6 两行）。本节记录这次反转的来龙去脉。

**用户反馈（①）**：抽卡时"画面聚集导致 3D 物品错位"。

房主等待仍读同一个总时长 `DeckReveal.CARD_TIME`）；新增组件 `scripts/deck_reveal.gd`

`BoardView` 里"演在桌垫画布上"的那整套（`play_deck_card` / `is_showing_deck_card` /
`_tick_deck_card` / 四段相位常量 / `_deck_*` 私有成员）与**只服务于那次推近**的
`DECK_PUSH_FACTOR` / `focus_point_zoom` **整体删除**；连带删掉 `deck_top_provider` /
