## 一、顶部区域升级为「活动面板区」

> **⚠ 本节已作废（2026-10-03 · v0.5.0 批次 1）**：原拍板「小卖部 / 赌场做成桌面常驻设施、
> 全桌围观」被**反转**——两座设施撤下桌面，改为触发时独占的全屏界面。
> 反转理由：2.5D 斜视桌面下桌面的文字读不清（见 `development/plans/v0.5.0-布局2.5D.md` §三 ——
> **该计划文件已随版本删除，本文件 §五 留有它的留档**），
> 而设施正是桌面上文字最密的两块；且 Liar's Bar 式的桌游感靠"桌子本身"，不靠"设施摆桌上"。
> 本节保留只为还原当时的取舍，**不是当前事实**。

**拍板（2026-10-01）**：整条空区分两半，左小卖部、右赌场，均为常驻桌面设施。

### 目标

棋盘上方的空区升级为**桌面活动区**：进商店、开赌场时不再是全屏弹层，
而是出现在桌面的常驻设施位——全桌人都能围观，保持桌游临场感，棋盘不再被遮挡。

### 布局方案

- **整条空区分两半**：上层为数据轨（战况四家横排 + 最近战报事件流），
  下层左「小卖部」右「宿舍赌场」两座常驻设施，世界坐标随桌面旋转；
  2/3 人局没有上家座位时顶部区也会整体入画。
- **小卖部**：木柜台 + 绿白圆弧雨棚 + 招牌木牌 + 3 格货架 +
  品质图例（白绿蓝紫橙）+ 刷新按钮。
- **赌场**：绿呢牌桌 + 金色滚边 + 卡背装饰，奖池大字 + 状态行；
  开局玩法仍在屏幕弹层进行。
- **质感分层原则**：桌上的「设施」用暖色实体材质（木 / 呢 / 金），
  「数据轨 / 座位栏」保持冷色玻璃质感退居辅助层——桌游感先靠材质分层立住。

### 公共 / 私人分层（红线）

- 桌面面板只放**公共信息**：货架存货、奖池、轮到谁、牌堆余量、已公开的事件流、
  操作按钮（买 / 刷新 / 抽顶 / 抽底——所有人可见，房主只认当前行动者的点击，超时托管）。
- **私人信息永远走屏幕私弹**（沿用赌场透视的私密通道模式）：透视结果、
  以后道具系统的私人交互同理。真实桌游类比：桌面摆公共牌，手牌在各自手里。

### 镜头规则

- 活动开张 / 轮到行动时，只对**处于自己视角**的玩家平滑聚焦到活动区
  （复用掷轮对焦转盘的逻辑）；
- 身在别人视角的玩家镜头不被抢（沿用现有「自家视角」闸），想围观按空格。

> ⚠ 以上「镜头规则」随转视角一并作废（2026-10-03）：相机恒在自己座位，不存在"别人视角"。

### 未拍板

- 赌场玩法弹层迁入桌面面板的时机（桌面设施已先行常驻显示奖池 / 状态，不阻塞）。

## 三、道具与系统的逐条拍板（2026-09-30）

2. 蛋蛋节概率：使用者紫 70 / 橙 30，他人白绿蓝均分。
3. 蛋蛋节满包玩家**改发 ¥100 现金**。

9. 进黑市**强制且不算 debuff**。

12. 强身健体**冷却不减**。

## 六、批次 3 落地时的取舍（2026-10-03 · 用户授权代理自行拍板）

**缘起**：批次 3 六个任务逐条过审、终审又出三条 Important 之后，用户睡前授权「剩下的任务你自己完成、设计决策你自己拍（从玩家角度）、素材走开源」。本节记的是**代理替用户拍的那些**——凡是与前面拍过的冲突或推翻，都单列。

**1. 主动丢弃道具：补回入口，不推迟到批次 5。**
座位卡上的「✕」是 `item_discard_clicked` 的唯一发射方，牌位拆除后整条链路不可达，而游戏内规则说明仍写着「可主动丢弃」。
- 关键理由：设计稿 §三 自己写着「**自己的那面立牌在 3D 视角退到画面外——第一人称看不见自己**」⇒ **批次 5 的立牌并不会自动把「✕」带回来**，推迟不等于有人做。
- 拍板：**手牌上右键 = 丢弃**，沿用原两步确认（第一次点亮待确认、第二次真丢）。右键本是本作的「次要操作」，落在牌上即丢弃；左键仍为选中。

**2. 选目标期间手牌必须对点击透明（推翻代理自己先前的一次裁定）。**
先前否决过"选目标时关闸"，怕变成「点着牌却选中了格子」。终审指出更要紧的一面：**选目标时玩家正需要点格子**，而牌底那 3~5 格会答"改选另一张牌"⇒ **指向性格子的道具打不到自家附近的格子**，是功能性漏洞。
- 拍板：**加上 `_tgt_stage == ""`**。功能漏洞比可恢复的错愕更重。

**3. 物件与 2D 相机的关系 = 语义，不是缺陷。**
轮盘**位置**来自相机（贴的是**印在桌垫上的**那个轮盘），手牌 / 立牌用**画布常量**（自由立在桌上的实物；筹码 / 体力件原也走画布常量，已在批次 7 退场，见 §七）。抽卡把 2D 取景推到 2× 时印出来的棋盘会滑动而实物不动。
- 拍板：**轮缘跟相机、实物不跟**。桌面上的实物不该因为"印出来的图案"变了而移动。已写成正式约定（`table_props.gd` 头 + `架构总览.md` §五），并出了 `freecam` 出图确认无穿帮。

**4. 丢弃待确认只在"arming 时的那个 (回合, 等待) 窗口"内有效。**
只按 `phase` 判（`playing`/`ended` 两态）在整局进行中恒假 ⇒ 跳过/超时结束道具阶段后红标整轮挂着、下一次右键一下就丢。
- 拍板：记下 arm 时刻的 `turn` 与 `await`，任一变化即解除。**不**用 `await != "item"` 一刀切——丢弃任何时候可用，一刀切会抹掉合法的一次 arm。

**5. 批次 4 的形态（本节随批次 4 计划一起定，落地后回填结果）。**
- **视角量 `view_t ∈ [0,1]`**（0 = 3D / 1 = 2D），滚轮**每格 ±0.25**，`_process` 里帧率无关地平滑逼近 ⇒ 满足"由滚轮累积量驱动、不是硬切开关"。

- **手牌随 `view_t` 淡出**（0.35→0.65 淡完），淡到 `HAND_HIT_MIN_ALPHA` 以下 `hand_hit` 直接返回 -1 ⇒ **"看不见就点不到"，于是 `game.gd` 一行都不用改**。
- **`dolly` 整个删除**，滚轮改驱动视角。
- **残余选中让牌能在 2D 端被打出（有意接受的口径）**：验收里的「出牌要回 3D」**约束的是"选中"** ——
  在 3D 端选好一张牌、再滚到 2D，牌垫上的「使用「X」」按钮**仍能把它打出去**（按钮有标签、结果也合法）。

- 2D 端的牌垫「使用道具」按钮**不动**（2D 下没选牌它显示「跳过」，那是合法动作；藏它要新增一处 BoardView 改动，收益不成比例）。

## 十、批次 10 定案：棋盘放大（几何优化，2026-10-04）

用户原话：`③棋盘在桌面的比例加大一点，现在不管是 2D 还是 3D 视角，都字太小了`。经确认把 ③
**拆两批**：批次 9 = (B)（已结清）、**批次 10 = (A) 只做几何优化**、批次 11 = ⑤ 小人与房子立体。

### 为什么是 A 而不是 B / C（用户选的这一档 + 它的代价）

- **A（本批）= 只做几何优化**：动桌垫留白、木纹框宽、相机远近三样。
- **B = 3D 拉近看局部**（放弃"整块棋盘同时入画"）—— 用户明确**不做**；
- **C = 改字号 / 裁棋盘 / 抬画布分辨率** —— 用户明确**不做**（抬画布分辨率已验证是**完全抵消**：
  整体等比放大画布与窗口，屏幕尺寸不变）。

**硬上限先说清（免得把"做不到的"当"没做好"）**：`棋盘的屏幕大小 = TABLE_W(8) × ①棋盘占桌垫
的比例 × ②桌垫占屏宽的比例`。**改动前** ① 是 **91%**（`MAT_MX/MT/MB` = 100/100/260）⇒ 上限
**+9.9%**（本批做到 **96.2%**，即 **+5.7%**）；**改动前** ② 是约 **94.5%** ⇒ 上限约 **+6%**；
两者相乘 ⇒ 当时估的**硬上限约 +15%**。⚠ **② 这一项（94.5% / +6%）已被实测取代**（终审 R10
点出）：它引的是"批次 5 之前"那一版的余量（`CAM_DIST` 5.8 + 8×8 方桌的"最小 10.9px / 两端约
35px"，`table_3d.gd` 的 `VIEW_DIST_2D` 段自己注明了口径），而 **T1 把桌垫裁浅（进深 6.152 →
5.626）反而松了取景余量** ⇒ T2 实际拿到 **+12.9%（2D）/ +9.0%（3D）**，**2D 端还超出了当时
那个粗糙上限** ⇒ **"≈ +15% 的合成上限"不成立**（它既把两项各自的上限相乘、② 的上限本身也估错了）。

**代价（如实留痕）**：选 A 就意味着**字只大了约 +15~19%（估算：格内文字 ~11px → 约 12.6（3D）/
13.1（2D）px，按格子屏宽等比推），仍不算大字** —— 要"明显更大"只能放弃"整块棋盘同时入画"（B），
用户已否。这是明知的取舍，不是没做到。
**实测净收益 = 两个因子相乘（都是实测、或由实测推出）**：

- **T1 缩几何 ≈ +5.7%**：棋盘占桌垫 91.0% → 96.2%（格子世界宽 = `TILE × TABLE_W /
  MAT_RECT.size_x`，桌垫 2216 → 2096）。

### 定案 1：取景判据 = 桌垫四角（顺带改准一段过期注释）

### 反转 1：棋子（小人）与装修房子——从画在桌垫上的图案，变成立在桌上的薄牌实物

  只能点开他的道具弹窗 —— 用户要的就是"瘦身"，接受。
- **文案同步**：`game._begin_peer_target` 的选目标提示、`rules_text.gd` 两处「右上角名册条」
  → 「左上角名册条里对手那一格」。**别让玩家照着找一个已经不在那儿的东西。**

### ③ 机器人进店也看得见（时序 bug）：先给 1.5 秒可见节拍

- **根因**：可见性判据本身没问题——`phase=="playing" and shop_open>=0 and shop_peer!=0`，
  **旁观者是满足的**（真人进店本来就看得见，`hud_test` 钉着）。坏在机器人：`game._run_shop` 里
  `_bot_shop` **没有 await**，于是 `_shop_buy` → `_shop_leave` → 关店广播**全在同一帧跑完**，
  任何一端的 `_process` 都来不及把 `shop_layer` 显出来 ⇒ 机器人进店对**所有人**不可见。
- **拍板**：机器人分支加一个**可见节拍**（`await` **1.5 秒**）再 `_bot_shop`，让 `shop_open>=0`
  的快照活过一帧（带 `running` / `_shop_peer` / `_shop_epoch` 三重守卫，防期间会话被换掉）。
  真人访客与「休眠自动离开」两条路径**一行不改**。
- **代价**：机器人每次进店多约 1.5 秒（`Engine.time_scale` 3× 的自动对局里 ≈0.5 秒）⇒ 四人局
  节奏略慢，换来"看得见别人买了什么"。**为什么值得**：这是"机器人进店对所有人不可见"这个
  **实机故障**的修复，不是观感微调。

### ④ 「调休」是哨兵值撞车（真 bug）

### ⑥ 钱流动的终点算早了一帧（时序 bug）：先收集差分、等身家条刷完再播

- **根因**：全项目只有一处飞钞 `game._spawn_money_fly`（所有钱变动都从广播差分进它）。它算**终点**

  只要"金额变了、名次也变了"，钞票会飞向**一格**，下一帧那格却换了人（或正要被藏起来）。
- **拍板**：`_refresh_players` 里把差分先**收集**成表，等 `_refresh_corner_bars(standing)` +
  `_refresh_corner_highlight()` 跑完再统一播。**飘字与音效锚在棋子上、与名册无关，位置不动。**
- **有意不动**：破产不出钞（`bool(p.alive)` 那道闸）、同一次广播里两笔钱并成一笔净值 ——
  两者都不是"位置错"，是既有语义；改它们属于新需求，等用户单独提。

## 十五、3D 房间一期：**推拉回归**（Ctrl + 滚轮）与「默认看屋子」（2026-10-05 · 用户提议）

### 缘起：用户的一句提问

3D 房间一期实施到 Task 3 出图时发现：**四面墙与天花板根本不在画面里**。核算相机常量
（`CAM_TILT_DEG = 50` / `CAM_DIST = 5.77` / `CAM_FOV = 39`，注视桌心）后确认这是几何必然：
画面**上缘那条视线**是 30.5° 俯角，打在地板上落在 **z ≈ −4.9**，而木桌远边在 **z ≈ −3.48**
⇒ 远边之外只剩一条窄地板带，**远墙 / 远墙上的家具全在画外**；吊灯在 `y = 10`、比相机高 5.58，
**在视轴上方 95°**，50° 俯角下**永远不可能入画**。

由此推出的设计矛盾：**「房间占上缘 32%」与「格子屏幕宽 ≥ 32px」数学上互斥** ——
要让木桌远边落到画面 32% 处，相机得退到 `D ≈ 18.7`（或把俯角压到 30° 配 `D ≈ 10.6`），
而格子会掉到 **~15px / ~26px**，双双击穿 32px 底线。

**用户当场提议**："既然现在桌面比例太大，无法看到环境，那能不能当我看不清时可以用鼠标进行画面缩放。"
—— **这一手正好把"二选一"变成由玩家现场掌控的取舍。**

### 被推翻的原决定（批次 2 → 批次 4）

- **批次 2** 拍的是「**滚轮 = 推拉相机**」（无级缩放）。
- **批次 4** 改成「**滚轮 = 3D / 2D 视角连续推移**」，**`dolly` 整个删除**。
  理由（原文）："参考（邪恶铭刻）就是这么切视角的，且 2D/3D 两档比无级推拉更贴合
  『看全局 vs 操作』的分工。"
- 该决定此后被写进 `架构总览.md` §五（"滚轮 = 3D / 2D 视角连续推移…**推拉已取消**"）
  与 `开发台账.md` §一（"**推拉已取消**"）。

### 新决定（用户 2026-10-05 拍板）

| 项 | 定案 |
|---|---|
| **手势** | **按住 `Ctrl` + 滚轮 = 推拉相机**（只改"相机到桌心的距离"这一维） |
| **默认取景** | **偏屋子那一档**（用户选「默认看屋子」）：木桌四角入画 + 上缘留一条带子给房间 |
| **2D 端** | **一字不改**（推拉只在 3D 端生效，`view_t = 1` 时归零） |
| **格子下限** | **默认档仍是 32px**（硬底线）；**拉远端不设下限**；**推近端不得低于默认档** |

### 为什么是 Ctrl + 滚轮，而不是抢滚轮

**滚轮是切 3D/2D 的唯一入口**（`table_3d.gd:787`，没有按钮替代），抢走它就没有 3D/2D 了。
⇒ 推拉**另给手势**。选 `Ctrl` + 滚轮的理由：**零冲突风险、零屏幕占用**，且"Ctrl + 滚轮 = 缩放"
是桌面软件的通行习惯。
**这不是替掉原决定**：批次 4 那句"两档比无级推拉更贴合分工"**仍然成立** ——
推拉是**在档内补一个自由度**，不是回到无级缩放。
（**备选**（留档）：右键拖拽 —— 手感更连贯，但要先查拾取链路有没有占用右键；
右下角 ±／滑杆控件 —— 最容易发现、不抢手势，但占屏幕角落、操作不连贯。）

### 代价（承认）

1. **`layout_test` 的契约要改写成两条**：21 档余量扫描**只在默认档的推拉值下成立**；
   另加"推拉三端各自的下限/上限"断言（默认档 ≥ 32px、推近端 ≥ 默认档、`view_t = 1` 逐字节不变、
   拉远端必须把远墙拉进画）。
2. **拉远会摊薄阴影贴图密度** —— `留痕` §十三 已记过"射程一大、阴影贴图密度稀 ~2.4×"，
   推拉再放开一档会加剧。**要实测确认能不能接受**（性能探针 + 出图）。
3. **默认档的"屋子感"弱于预期**（几何必然）：默认档只把木桌四角拉进画，**家具与远墙要再拉远才进画**。
   ⇒ 别把"默认档没家具"当缺陷查；实测数字由 Task 7 报出。

### 备选（若将来判定推拉不可用）

- **只抬环境光 + 维持现状**：房间只有地板可见（Task 3 出图已是这样），最省，但"屋子"读不出来。
- **把俯角压低到 ~30° + 房间收浅**：能在**同距离**下把远墙拉进画（上缘落到 `z ≈ −10.6`），
  但桌面被压成一条，格子近大远小、可读性更差。

### 追加拍板：**地板落到真实桌高 + 桌子加底座**（同日，用户选 A）

**怎么发现的**：控制者在派 Task 5（四把椅子）前核查椅子的落点，发现**计划把地板放在 `y = 0`**
—— 也就是**桌面那一层**（Task 3 把它改成 −0.02，只是为了不被木纹外框盖住）。后果是
**桌子读作"平铺在地板上的一块板"，而椅子/家具没法"站对"**：椅子按人体比例（`FURNITURE_SCALE = 5`）
站着时椅面在桌面上方 2.25 单位；要"站对"就得让椅面低于桌面，即椅子沉到地板以下 ——
**而地板就在桌面那一层，装不下任何东西**。

**中途先做的实证（避免误导用户）**：控制者临时把地板降到 −3.7、墙跟着加高，出图对比 ——
**远墙确实进画了，但只占顶上约 6% 一条暗带，与不降的画面上几乎看不出差别**。
⇒ 先把"降地板能大幅改善可见性"这个猜测**证伪**，再向用户提问，而不是拿算术当结论。

**定案（用户选 A）**：**地板落到 `FLOOR_Y := -3.70`，桌子补一块底座（裙板）。**
`3.70 / 5 = 0.74 m` 正是真实桌高。**整间屋子的比例一次全对上**：

| 件 | 数值 | 是否合理 |
|---|---|---|
| 椅子（5×） | 椅面 `-1.45`（低于桌面）、椅背顶 `+0.8`（高过桌面） | ✓ 正是 §六 要的"椅背挂名牌" |
| 书桌（5×） | 高 `3.75`，顶面 `+0.05`（与桌面齐平） | ✓ |
| 吊灯（`y = 10`） | 离地 `13.7 / 5 = 2.74 m` | ✓ 正常的吊灯 |
| 房间 `22×18×19.7` | `4.4 × 3.6 × 3.94 m` | ✓ 正常的宿舍（**2026-10-06 改正**：定案时 `ROOM_CEIL_Y = 13` ⇒ 16.7 / 3.34 m；一期 Task 7 抬到 **16.0** ⇒ 19.7 / 3.94 m，见 §十六）|

**代价**：① 桌子多一块底座（新几何，约 10 行）；② 3D 端会开始看得见桌子**前方的立面**
（此前桌子悬在纯黑里）；③ 四面墙高度从 13 变成 **19.7**（定案落地时 16.7；一期 Task 7 抬 `ROOM_CEIL_Y`
13 → 16 ⇒ 19.7，见上表那行）。

**备选（留档）**：**B 维持地板在桌面高度** —— 家具一律缩到约 ×2 当"小摆件"，最省、零新几何，
但"屋子"退化成"地板上的沙盘"，与《骗子酒馆》的坐定感差得远。
**C 只降地板、桌子不加底座** —— 桌子看起来悬空，未采用。

## 十六、3D 房间一期：**实施里的取舍与实测值**（2026-10-06 · Task 1~9 收官）

> 对照 §十三 ⑨「删掉桌面旁的 3D 物件」。**本节只记实施里拍过板 / 量过数的地方**，
> 设计契约本身见 `doc/development/3D房间-一期设计.md`（那份的 §四 已按本节回填）。

### ① 为什么"删掉的房间"又回来了 —— 这次是**另一套几何**，不是把旧剪影捡回来

§十三 ⑨ 删的是批次 6 那层**剪影**（三面墙 + 书架 + 床架，`BoxMesh` + 共用近黑材质，只为"别让桌子
悬在纯黑里"）。一期换的是**程序化房间**（`scripts/room.gd`）：有地板高度、有家具的**真实比例**、
有椅子（含二期放人的锚点）、有地毯、有光照收口 —— 目标是"像一间宿舍"，不是"加点背景"。
**保留的约束一条没丢**：房间物件一律不投影、光一个都不加（房间那盏补光不投影，见 ⑤）。

### ② 取景：**只动一个数**，「32% 上缘」与「格宽 ≥32px」的互斥由用户拍板

**定案**：`CAM_DIST 5.77 → 8.90`；`CAM_FOV 39` / `CAM_TILT_DEG 50` / `VIEW_DIST_2D 9.20`
**一字未动**（动 `CAM_FOV` 会把 2D 端余量打红：33 ⇒ −12.1px）⇒ **2D 端逐字节不变**。
**实测格子屏幕宽**：默认档 **32.3px** / `Ctrl` 推近端 **44.5px** / `Ctrl` 拉远端 **23.7px** / 2D 端 **53.2px**。
**"屋子看不见"（Ruling N）被推翻**：房间带 **10.5% → 22.9%（默认）/ 30.0%（拉远）**。
**32% 没有落成断言**：两者数学上互斥，实施时没有为凑 32% 去动相机（那会把格宽推到 32px 之下）。
**代价（承认）**：默认档格内字约 6px ⇒ **默认档不再是"读棋盘"的档**，读棋盘靠 `Ctrl` 推近（44.5px）
或 2D 端（53.2px）—— 与本作"3D = 临场 / 2D = 看全局"的分工一致。

### ③ `Ctrl` + 滚轮请回 `dolly`（§十五 的实施落地）

落成 `dolly ∈ [1.00, 1.40]`，**权重 `(1 − view_t)`**（乘在 3D 端那一段距离上再与 `VIEW_DIST_2D`
插值）⇒ 2D 端**逐字节不变**（有断言钉着）。**推拉不改俯角** ⇒ "抬头看吊灯"仍然做不到。
**被迫连带改的两个房间常量**（实测理由）：默认机位 `z = 8.90` 正好**贴在近墙上**，
`dolly > 1.01` 一拉就**穿墙到屋外 ⇒ 整屏全黑，而所有推拉断言照绿**（断言抓不到的那类错）⇒
**`ROOM_NEAR_EXTRA := 5.0`**（只把近半侧加长，给相机让站位；远半侧一个数不动、那一段永不入画）
+ **`ROOM_CEIL_Y := 16.0`**（拉远端把相机顶高到 14.85，天花板还在 13 就会窜到屋顶上方）。
**对称放大 `ROOM_D` 试过、更糟**：远墙带从 18% 掉到 5%（默认档的远墙几乎贴到视口顶端）。

### ④ `FURNITURE_SCALE` 5 → 10：锚点是 §六 那张比例表，Task 4 的尺寸是**错测量**

Kenney 这批 `.glb` 是**半比例**的（书桌 `0.384` 高按米读只有 0.38 m、椅子约 0.47）。
Task 4 报的"椅子宽 0.479"**漏量了嵌套子节点的位移**，真值 `0.335 × 0.608 × 0.314`。
× 5 的后果：**椅背顶落在桌面之下 0.66** ⇒ §六 要的"椅背挂名牌"根本摆不出来。
⇒ 定档 **10.0**（实测合并 AABB ×10：椅子 `2.0 × 4.7 × 2.0`、书桌 `3.84` 高 ⇒ 顶面 `+0.14`
与桌面齐平；书桌 / 书架 / 收纳箱三件重取摆位，仍由 `ROOM_W`/`ROOM_D` 推导）。
**变红验证**：临时改回 5.0 ⇒ 只有"书桌顶面齐平 / 椅背顶高过桌面"两条红。

### ⑤ 材质与光照收口：**"屋子像样"卡的是材质，不是取景**

Task 7 判图时家具 / 椅子**全是同一块奶白纯平色**（Kenney 零贴图）、比被照亮的桌面还抢眼 ⇒
换成**暗木调** `0.34/0.27/0.21`（同族 `wood_floor.jpg`、roughness 0.88）；**墙**从 `0.30/0.285/0.27`
**再改成 `0.30/0.22/0.15`**（Task 9，见 ⑦）；桌下加一块**地毯**（模型自带色 ×0.45 —— 原色是 Kenney 展示用的
饱和砖红）；补光用 **`OmniLight3D`**（照度代理式只认 omni）放近侧偏右、`y = 0.5` ⇒
**桌面 N·L≈0、墙 N·L≈1**，实测**桌面贡献 0.0494 ≤ 0.08**（批次 13 ⑧ 用户签过字的"桌面均匀"没被动）。
**没加小摆件**：出图判过"像样"即止，加件只会再占一组几何断言。

### ⑥ 吊灯可见几何**整任务砍掉**（Ruling U，本期最省的一笔）

`task-6` 整任务跳过：那段几何**从取景轨道上的任何位置都看不见**（相机整幅画面都在地平线以下，
而吊灯的光在 `y = 10`；实测偏轴 104°/101°，半视角只有 19.5°；推拉只改距离、不改俯角）。
⇒ **光的位置与三个 `LAMP_*` 常量照旧不动，只是不建可见几何**。**代价（承认）**：房间里**没有可见灯具**，
光的来源在画面里没有交代 —— 这恰好回到批次 13 ⑨ 已拍板的状态（"台灯只留光"）。
**天花板仍保留**（房间的边界，静态网格很便宜；且 50° 俯角下从不入画）。

### ⑦ 验收（Task 9）：观感收口三条 —— **定位都是量出来的**

1. **左右两道游离的亮线** = **侧向那两把椅子的椅背名牌被侧视**（牌面法线朝屋外）。
   真窗口渲染逐像素扫：左缘 `x 28–59 / y 287–356` 有 **94** 个亮度 >0.45 的像素（最亮 **0.67**）、
   右缘 `x 1220–1251` 同样 94 个（0.55）；**把 `Seat1` / `Seat3` 的名牌各藏一次，两道线各自消失**
   ⇒ 就是这两块牌。**做法 = 把牌从"挂在椅背外侧"改成"嵌在椅背外表面上"（往里 0.06）**：
   椅子自己的背板把牌从**背面**挡住，实测同一区最亮值 **0.67 → 0.16**（= 椅背本身）；
   **朝向屋外那一面照旧露在最外**（标签比牌本身还外 0.01）⇒ 二期"人坐上椅子"仍读得到。
   **没选压暗**（试过 ×0.45）：那只是把亮线换成暗线（同一区最亮仍有 0.44），且要动"牌色 = 棋子色"
   那条语义（两个套件都钉着它）。
2. **左上那块偏亮的灰白斑块** = **墙**（不是家具）。逐节点隐藏 + 逐像素采样定死的：
   `(50,100)` 只在**藏西墙**时变黑、`(150,80)` 只在**藏远墙**时变黑；亮是**吊灯**打的
   （关吊灯 ⇒ `#584a3a` 掉到 `#1b1919`）。**要害不是亮、是"灰"**：那块 `R/B = 1.5`，
   而屋里的木色是地板 `4.3` / 书桌 `3.2`（亮度只比地板高 1.4 倍）⇒ **只动绿蓝两维**：
   `0.30/0.285/0.27` → `0.30/0.22/0.15`，实测那块 `#584a3a` → `#583920`（**R/B 3.1**）。
3. **断言消息的空插值**：`实得「」` 是因为那个变量**只在"抓到非 omni"时才有值** ⇒
   改成报**每盏非吊灯的类名**（通过时印 `OmniLight3D`、不通过时印 `DirectionalLight3D（非 omni）`）。
   **变红验证**：临时塞一盏平行光 ⇒ 该条 FAIL，且消息里点名了它，其余不受影响。

### ⑧ 性能与导入（一期收尾）

- **帧率**：p50 ≈ **2.0~3.0 ms**、p95 ≈ **12.0~12.4 ms**（`--fps=12`，空盘与 `--fps-houses=1`
  满盘两档都在噪声内）—— **与批次 11 基线一致**，房间 + 三个家具 + 四把椅子 + 地毯几乎不花钱。
  采样里那条 ≈0.5 s 的周期长帧是**早已登记的环境 / 驱动现象**（§开发台账 §三 批次 6 条）。
- **导入一致性**：`.import` **不破例**（Task 1 裁决：默认设置 + `.gitignore` 不动，证据是空项目
  导入同一 `desk.glb` 的 `[params]` 段逐字节一致）。新克隆 `--import` 一次即可重建，见 Task 9 报告。

## 十七、3D 房间二期改版：**人物完全静止 + 头顶名牌 + 四件配色拉开**（2026-10-06 · 用户判图 2 条）

**用户原话（判图后，两条一起给）**：

> ①玩家人物不要乱动，然后加个标识，不然我不知道他是谁
> ②地板、椅子、墙面、家具颜色太接近了，缺少真实感

**⇒ 这一节推翻了二期 spec §5.7 的旧定案**（「不改名牌，靠角色本身认人」）。
推翻的是**结论**，不是当时的推理 —— 当时那三条理由（名字该由 HUD 名册条承担 / 角色本身比一块牌
更清楚 / 承认侧向看不见是已接受的取舍）都还在，是**实测出来的新事实**把它们推翻了：
**"角色本身比一块牌更清楚"这件事，在这个照度下不成立**（见下"为什么读不出来"）。

### ① 人物完全静止（不再播 `idle`）

**拍板前的问法**：把"不要乱动"拆成四个选项（完全静止 / 压到几乎看不出 / 只去掉行动者提速 /
先当 bug 查）—— **用户选「完全静止」**。⇒ 不是"幅度收小"，是**一帧动画都不播**。

- `idle` 待机整段退场（`IDLE_ANIM` / `_loop_idle()` / `_place()` 里那句 `play()` 全删）。
- **连带退场**：`ACTOR_SPEED 1.4` / `IDLE_SPEED 1.0` / `char_speed()` —— 那条"当前行动者 =
  同一条 `idle` 提速"的表达失去了载体（没有动画就没有速度可调）。
- **保留的**：四个玩法事件反应（出牌 / 付钱 / 被抢地 / 破产）**一个不删**。
  理由：它们**是一次性的、由事件触发的**，不是用户说的那种"常驻乱动"；
  而且它们是这四个玩法在 3D 房间里**唯一的可见反馈**（二期 Task 4 刚做完）。
  判据没变：`speed_scale` 一律留在 1.0（不许"顺手放大一点看得清"）。
- **随取景淡出保留**（读棋盘那几档不画人 + 不画牌）：那条是**性能契约**，与静止无关。

**顺带查出来的一个真缺陷（本改版最有价值的一条）**：
把 `_react_finished` 从 `play(idle)` 改成 `stop()` 之后，`chars_test` 当场红了 ——
**`AnimationPlayer.stop()` 不会把姿态复位**：实测 `stop()` 之后分件仍停在**末帧**
（slot1 的世界 AABB 深 **6.89**，而同一模型在静止姿上是 **4.5**；播放器报"在播 否"却是伸手姿态）。
**旧版之所以看不出来**：`play(idle)` 会**逐帧重写**躯干 / 双臂 / 头，把残留姿态盖掉 ——

`chars_test` 的 (e) 条钉住"打完一次牌，分件相对静止姿位移 = 0.000000"。

### ② 头顶名牌（`Chars/Tags/Tag{i}`）

**拍板前的问法**：标识做成哪一种（头顶浮动名牌 / 头顶只有棋子色小牌 / 把椅背名牌转过来 /

- **结构**：`Tag{i}` → `Plate`（棋子色 `QuadMesh` + 一点自发光）/ `Label`（昵称，`Label3D`）/
  `Border`（金边，只有当前行动者露出来）。牌与字各自 `billboard` 朝向镜头。
- **位置**：立**在头顶之上**，位置按模型**世界 AABB 顶**（`_tag_top()`）实测算 +
  `TAG_GAP 0.28`，**不写死"头顶在第几米"** —— `SEATS_ROOT_Y` / `CHARS_SCALE` / `HEAD_SHRINK`
  哪一个改了，牌子都跟着走。
- **牌子为什么挂在 `Chars/Tags` 下（兄弟节点）而不是 `Char{i}` 里**：`chars_test` 有一整批断言

  几条判据会**悄悄换了对象**。挂成兄弟则各量各的。代价：显隐 / 透明度由 `_apply_fade` 显式带着做。
- **当前行动者 = 牌上一圈金边**（静止的，不闪）。这是一条**改进**而不只是替代：原先那套
  "谁动得快"**要求玩家盯着看**，而金边是一眼可见的静态事实。
- **椅背名牌整段删除**（用户追加的一条：「去掉椅子上的铭牌」）：
  `NAMEPLATE_SIZE` / `NAMEPLATE_FONT_PS` / `NAMEPLATE_SINK` / `NAMEPLATE_ANCHORS` /
  `_make_nameplate()` / `_refresh_nameplates()` 全删。它的职责整体搬到头顶名牌；
  而它**本来就看不见**（挂在椅背朝外那一面）—— "认不出谁是谁"有一半原因就在这儿。

**"靠角色本身认人"为什么读不出来（可量化的原因）**：`CHAR_TINT` 为了守住
「角色不许是画面里最亮的东西」把整张贴图压到 `0.29/0.25/0.21`，加上屋里只有一盏吊灯
⇒ 蓝 / 红 / 绿三个人在**背对镜头**的那两把椅子上都是一团暗褐色，只能靠正面那张脸认 ——

**③ 牌堆：4x MSAA + 程序化牌背**

## 十九、五条选项决策拍板（2026-10-06 · 用户逐条拍板）

> 背景：清账轮把「不需要拍板」的项做完后，剩余项里有一类是**选项二选一**——
> 逐条向用户解释利害后拍板如下。**当前事实与落地口径见 `development/未完成项-交接.md`**
> （⑪⑭⑮ 与新增 ㉑），本节只记拍板与被否的备选。

### ① 人物动画偏快：慢放 0.6×（否掉换素材）

* **拍板**：方案 (a) **慢放**，倍率 **0.6×**——`chars.gd` 新增 `REACT_SPEED_SCALE := 0.6`，
  `REACT_ANIMS` 四条反应（出牌 / 付钱 / 被抢地 / 破产）全走它；`chars_test` 那条
  「反应速度恒 1.0」的断言改为钉这个常量（该断言当初立的是"不许**顺手加速**"，
  改为"不许**随手乱调**"——拍板过的倍率本身不受它管）。
* **理由**：动画没有被加速（`speed_scale` 恒 1.0），是**素材本身短**（付钱
  `holding-left` 0.1667 s，普查自注「一闪」），而人物其余时间完全静止 ⇒ 画面里唯一的动静
  对比之下更显快。慢放零新增素材、只动一处常量。
* **被否的备选**：换更长素材——普查 §5.4 全查过：包里比 `holding-left` 长的只有
  `pick-up`（0.3333 s）一条，且**不闭合**（结束在弯腰姿态）要手摆回位；出牌那边
  `interact-right` 0.6667 s 已是包里最长的互动动作。换素材这条路没货。
* **预期读数**：出牌 / 被抢 0.67 → **1.11 s**、付钱 0.17 → **0.28 s**、破产 0.33 → 0.56 s。

### ② 选目标提示条与战报气泡撞带：动态让位（否掉固定下移 / 搬名册条）

* **拍板**：提示条显示期间**贴着当前气泡栈正下方**（栈有几条它就多低，留 8~12 px 间距）；
  气泡增减与提示条进出选目标态时各重算一次落点。
* **理由**：固定下移（y≈200）改动最小，但没气泡时提示条凭空偏下；搬去左上角名册条下方
  要重做「取消」按钮布局、还要与名册条自身逻辑协调（交接里早注过"这条候选要重新想"）。
  动态让位观感最顺，代价只是多一处落点重算。
* **被否的备选**：固定下移（嫌"空带"）；挂名册条下方（布局重做量大）。

### ③ 道具试验场用例保存 / 回放：做，存 user://（否掉进仓库 / 不做）

* **拍板**：做。存 **`user://lab_cases/`**（不进仓库）；顶栏「存用例 / 读用例」+
  `--lab-case=名字` 启动参数直达回放。
* **理由**：试验场是个人验证沙盒，用例多数是"我自己下次要复现"的配方——`user://`
  无 CI 负担、仓库干净；真有需要分享的用例，导出文件给出去就是了。
* **被否的备选**：存 `tests/cases/`（可分享可接 CI，但多一类文件要维护，当前没有这个需求）；
  不做（复制状态 JSON 已能手工复现，但每次都要重摆一遍，痛点还在）。

### ④ M4 客户端掷轮测试：继续挂账（否掉扩回归 / 双端夹具）

* **拍板**：继续挂账。**重启条件**：哪天真要动 RPC 掷轮链路（改 `c_roll` 签名 / 掷轮流程），
  届时优先「扩联机回归——client 轮到时真发一次 `c_roll`」，**不搭双端单测夹具**。
* **理由**：查证过联机回归里的 client 是被动的（只收快照、从不发 `c_roll`，回合由房主托管
  代打）⇒ 这条路确实没覆盖；但它防的是"接错线"这类低频回归，为它先搭双端夹具不划算。

### ⑤ 2D 视角看不全对面两家：保持现状（否掉拉远 / 临时拉远）

* **拍板**：**保持现状**，并给定调——**2D = 读盘**（`VIEW_DIST_2D` 9.20、格宽 53.2 px
  的契约与 spec §九 硬底线一字不动）；**看全场 = 3D 端 Ctrl+滚轮拉远**（已有）。
* **理由**：2D 下**信息并不缺**——对面玩家的棋子 / 房子都画在棋盘上、照常可见，
  看不到的只是对面椅子上坐着的角色模型（纯装饰）。
* **被否的备选**：拉远到 16.5 看全三家（格宽掉到 ≈29.7 px，翻「≥32 px」硬底线，一批
  布局断言重验收）；2D 端加临时拉远（对称 3D dolly，底线不破但多立一条交互契约）——
  **日后实机确需 2D 看人时，从这条重启**。

## 二十一、开局设置：**预设方案整段删除**（2026-10-09 · 用户拍板）

> 背景：用户在大厅「游戏设置」弹窗上问「几个不同类型的局（标准局 / 大乱斗…）有什么区别」。
> 核代码（`lobby.gd._apply_preset`）后确认：**只有「标准局」是 15 项全量快照**，其余四档
> （快节奏 / 大富翁 / 大乱斗 / 新手局）**只改列出的那几项**，剩下的**沿用打开弹窗时的当前值**。
> 另有第二处缺陷：**预设 chip 点了不高亮** —— `_sync_panel()` 给别的每一行 chip 都刷了高亮，
> 唯独漏了 `_set_preset_chips`，所以点完没有任何"我选了哪档"的反馈。
> **当前事实见 `game-design/开局设置.md` §九**，本节记拍板理由与被否的备选。

* **病灶**：预设是「叠加式」的 —— 先点「大乱斗」（科技开 / 畸变高 / 四开关全开）再点
  「快节奏」，看着是切了档、实际只改了 补贴 / 限时 / 回合上限 三个数，科技与畸变仍是
  「大乱斗」那一套。**这与「预设 = 一档配置」的预期直接冲突**，也是"看不出区别"的根因。
* **用户拍板：不做预设方案，整段删除。** 替代口径 = **开新的一局一律从默认值起**，

## 二十四、音量控件：**「音效音量」改名「音量」+ 去掉「静音」开关 + 0 = 真静音 + 落盘**（2026-10-09）

> 由来：用户问「设置里把『音效音量』调成 0 和打开静音效果一样吗」。查下来答案是
> **听感上几乎一样、但不是一回事**，由此带出四件改动。

* **原来的两条路**（`_apply_audio()`）：
  * 静音开关 → `AudioServer.set_bus_mute(0, true)`：硬性置零，输出数字静音。
  * 音量 0 → `set_bus_volume_db(0, linear_to_db(maxf(v, 0.0001)))` = **−80 dB**：
    振幅乘 1/10000，**不是零**。本作音效是程序化满幅 PCM，理论上大音量下还听得见极轻的声音。
  * 两者**互不同步**（拖到 0 时开关仍显示「关」），但都叠在**总线 0 = Master** 上
    —— 全项目只有 `fx.gd` 那一池音效挂 Master（无自定义总线布局、无 BGM）。
* **拍板**（用户：既然 0 能静音，就一个控件够了）：
  * 「音效音量」→「**音量**」（原来那个名字名不副实，它调的是总音量，将来加 BGM 也会被压）。
  * **去掉「静音」开关**（字段 `audio_mute` 与 cfg 的 `[audio] mute` 键一并删）。
  * **0 档做成真静音**：`set_bus_mute(0, audio_volume <= 0.0)`。这一步是**前置**而非可选 ——
    只要还留着 −80 dB 那档，删掉开关就等于项目里再没有「绝对无声」这一档了。
* **被否的备选**：
  * **保留「静音」开关**（两个控件各管一段，功能上更全）：用户明确要简化为一个。
  * **0 档维持 −80 dB、只把开关删掉**：省一行代码，但把「绝对无声」弄丢了，否掉。
  * **滑块改成分贝刻度**（那样中段才有可用分辨率）：超出这次要求，且会改动存储值语义，否掉。
    当前是线性振幅：0 档 −80 dB / 1 档 ≈ −40 dB / 50 档 ≈ −6 dB / 100 档 = 0 dB，
    「想小声点」时主要靠前 20% 的行程。
* **顺带修掉的既有缺陷**：`user://settings.cfg` 的 `[audio]` 段**只有读、没有任何地方写**
  （`game.gd` 读它；`main_menu._save_cfg()` 只管 `[player]`/`[net]`；`dev_tools.toggle()` 只管 `[dev]`）
  ⇒ 音量改了每局都回到 100。现在**松开滑块**（`drag_ended`）与**离开面板**（「返回」）各写一次；
  **不在 `value_changed` 里写** —— 那是拖动时每个像素一次写盘。写法照 `dev_tools.toggle()`
  **先 load 再 save**，否则会把别的段整个抹掉（`main_menu._save_cfg()` 顶部那条注释记的就是这个坑）。
  `settings_test._test_audio_persist()` 钉住「落盘」与「不抹别的段」两条。

## 二十八、道具唯一性重审：**按效果判、不按品质档**（2026-10-10 · 用户授权代理定案）

> 本节只记**讨论过程、拍板理由与备选**；**当前事实**见 `game-design/道具系统.md` §五、
> `game-design/术语表.md`「唯一性」与 `game-design/道具图鉴.md` 逐件条目。

- **缘起（用户两问）**：先提「道具金卡可以重复出现（不是唯一道具）」，再追问「其他品质也有唯一的卡牌，
  **这个唯一是你设计的吗、需不需要去掉**」，最后授权：「**不用我圈，按你推荐的来**」。
- **核实（不是本次重构设计的）**：改前（`3bbf321`）21 件 unique，改后同一批也是 21 件 ——
  **`unique` 一列一件没动**，道具重构只做了「按新档位重新分档」。分布：**白 10 / 蓝 3 / 紫 3 / 金 5**，
  其中 17 件是被动。
- **它带来的真问题**：「全局仅一件」× **68 件小池** × **4 人** ⇒ 中后期可获取池明显收窄；
  **金档 5 件全唯一**更让它**整个空掉**，而**黑市的候选池是「紫 + 金」** ⇒ 黑市退化成「只出紫」。
- **判据（定案）**：唯一性**只留给「多件会破坏某件事」的件**——**不按品质档，按效果**。保留 4 件：
  `招财猫` / `保安巡逻`（**倍率型**租金增益 ⇒ 多件加速雪球）· `空想者的香皂`（**全局**负面免疫 ⇒
  多件稀释整套 debuff 体系）· `园中叶`（地皮护罩 ⇒ 多件让**抄家 / 强拆 / 征收整套攻击玩法失效**）。
  **金档不再一律唯一**。
- **两条既有先例**（证明这不是新发明）：租金类**常驻**增益全仓只有 `招财猫` / `保安巡逻` 两件，
  两件本来就都是唯一；防御类里 `护腕`（蓝·一次性·抵消后损坏）**本来就不是唯一** ⇒
  「**一次性防御不唯一**」已有先例。
- **被否的备选**（都试过判据，逐条否掉）：
  - **按品质一刀切**（「金货一律唯一」）—— 改前就是这个口径的一半，正是金池空掉的根因；
  - **被动一律唯一** —— 会把 `砍价高手` / `信托基金` 这些**定额型**收益也算进去，它们多件并不破坏任何机制；
  - **全仓放开（0 件唯一）** —— 会让 `招财猫` 叠 4 件、`园中叶` 叠 4 件，直接废掉租金曲线与整套攻击玩法。
