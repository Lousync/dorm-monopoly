# 设计决策留痕

> 讨论过程、拍板理由、当时的备选方案与日期都记在这里；**当前事实**（机制与数值现在长什么样）
> 以 `game-design/*` 为准。写代码时以玩法文档为准，本文件只用来还原当时的取舍。
> 未排期的待办与返工项见 `development/开发台账.md` §三。
> 更新：2026-10-03。
>
> 贯穿下面所有想法的核心是**桌游感**——把操作对象从「屏幕上的 UI」变成「桌子上的物件」：
> 想法一是**物件上桌**（商店 / 赌场成为桌面设施，纯 2D 即可做），
> 想法二是**桌面变真**（2.5D 材质感：立体棋子、投影、俯角）。两步互相加分、互不冲突。

## 一、顶部区域升级为「活动面板区」

**拍板（2026-10-01）**：整条空区分两半，左小卖部、右赌场，均为常驻桌面设施。

### 目标

棋盘上方的空区升级为**桌面活动区**：进商店、开赌场时不再是全屏弹层，
而是出现在桌面的常驻设施位——全桌人都能围观，保持桌游临场感，棋盘不再被遮挡。

### 布局方案

- **整条空区分两半**：上层为数据轨（战况四家横排 + 最近战报事件流），
  下层左「小卖部」右「宿舍赌场」两座常驻设施，世界坐标随桌面旋转；
  2/3 人局没有上家座位时顶部区也会整体入画。
- **小卖部**：木柜台 + 绿白圆弧雨棚 + 招牌木牌 + 3 格货架 +
  品质图例（白绿蓝紫橙）+ 刷新按钮。
- **赌场**：绿呢牌桌 + 金色滚边 + 卡背装饰，奖池大字 + 状态行；
  开局玩法仍在屏幕弹层进行。
- **质感分层原则**：桌上的「设施」用暖色实体材质（木 / 呢 / 金），
  「数据轨 / 座位栏」保持冷色玻璃质感退居辅助层——桌游感先靠材质分层立住，
  立体感（俯角 / 投影 / 厚度）留给想法二的 2.5D 路线。

### 公共 / 私人分层（红线）

- 桌面面板只放**公共信息**：货架存货、奖池、轮到谁、牌堆余量、已公开的事件流、
  操作按钮（买 / 刷新 / 抽顶 / 抽底——所有人可见，房主只认当前行动者的点击，超时托管）。
- **私人信息永远走屏幕私弹**（沿用赌场透视的私密通道模式）：透视结果、
  以后道具系统的私人交互同理。真实桌游类比：桌面摆公共牌，手牌在各自手里。

### 镜头规则

- 活动开张 / 轮到行动时，只对**处于自己视角**的玩家平滑聚焦到活动区
  （复用掷轮对焦转盘的逻辑）；
- 身在别人视角的玩家镜头不被抢（沿用现有「自家视角」闸），想围观按空格。

### 未拍板

- 赌场玩法弹层迁入桌面面板的时机（桌面设施已先行常驻显示奖池 / 状态，不阻塞）。

## 二、3D 视角（俯视 2D → 可倾斜的 2.5D / 完整 3D）

**状态**：想法讨论完毕，挂起——等美术第一批「模型」素材定格式（2D 立绘 vs 3D 模型）后拍板路线。

### 现状

整个对局画面是纯 2D（自研 2D 相机：注视点 / 缩放 / 旋转），镜头恒为俯视，所以观感是 2D。

### 三条路线

1. **假 2.5D（斜切变形）**：Godot 2D 只有仿射变换，做不出真透视，文字跟着变形，
   可读性受损。**不推荐**。
2. **SubViewport 2.5D（推荐的中间路线）**：现有 2D 棋盘整体渲染进 SubViewport，
   作为贴图铺在 3D 场景的斜置桌面上，Camera3D 透视观看；俯角成为表现参数
   （90° = 现在的俯视，45~60° = 3D 感，可做动画）。
   - **核心好处：玩法代码零改动**——2D 相机、座位旋转、世界面板全部原样活在
     SubViewport 内部；
   - 输入：3D 射线打桌面 → UV → 2D 坐标映射回现有命中逻辑；
   - 屏幕层 HUD（行动条 / 顶栏 / 私弹）照常叠加；
   - GL Compatibility 渲染器支持该管线；
   - 成本：相机层 + 输入映射重做，一次性中大型改造。
3. **完整 3D**：格子 / 棋子 / 模型全 3D 资产 + Camera3D。效果上限最高，
   但渲染层推倒重来，现阶段不建议。

### 决策依赖

- 美术素材格式：2D 立绘 → 保持纯 2D 即可；3D 模型（glTF）→ 走路线 2。
- 路线 2 下，现有「点座位转视角」可升级为 Camera3D 环绕桌面（后续增强项）。

### 关联

- 格子已放大到 112×112 世界像素，为模型预留版面（见 `棋盘与地产.md`）。

## 三、玩家牌位垫 + 选项菜单

**原交互原型**：`布局原型-玩家区与选项菜单.html`。

遗留项：使用道具阶段的真实逻辑随道具系统解冻；事件反馈 B 横幅 / C 角标
留作查寝 / 破产等大事件的备选；牌垫右侧装饰位**留空**（之后有东西要放）。

### 拍板记录

- 顶区数据轨（战况 / 最近战报）删除，小卖部 / 赌场两座设施长高铺满顶区。
- **战况下沉到各家座位卡**（方案 A）：排名徽章（按身家 1~4）+「地产 ×n · 身家」行。
- 最近战报 → **屏幕悬浮框**（右上角、可折叠，头部带「第 N/30 轮」；
  修订拍板：不放桌垫上）。
- 座位卡左侧空白**先留白**；左下「操作提示」见下「左下角规则说明」。
- **屏幕清理**：顶部横幅拆除（轮次进战报框头部、行动提示留在行动条、退出进菜单）。
- **事件围绕玩家桌垫**（设计原则）：个人事件反馈在牌垫上呈现。按真实游戏调研做了
  **三种候选样式**，原型控制条「反馈」可切换对比（2026-10-01 待挑选）：
  - **A 飞钞**：账单从桌面飞进（出）金额栏 + 金额浮动 ±字 + 金额栏闪色
    （Monopoly GO 的收支反馈模式——动效代替弹窗）；
  - **B 横幅**：大字横幅从牌垫上扫过、即进即出（Hearthstone 回合横幅模式——
    靠运动宣告，不占驻留 UI）；
  - **C 角标**：牌垫装饰区堆叠小 toast，上限 3 条自动消退（通用 toast 规范——
    不盖关键 HUD、角落锚定、可堆叠）。
  - 参考：Monopoly GO 设计深度解析 thewhyofplay.com/2024/08/23/monopoly-go-a-design-deep-dive、
    Hearthstone GDC 2015 UI 讲座（Derek Sakamoto）、toast / banner 规范
    （LogRocket、NN/g indicators-vs-notifications）。
- **牌垫 = 座位卡（下沉身家 / 徽章）+ 小装饰物**（骰子 / 筹码 / 奶茶杯等宿舍风小件，
  纯装饰、程序绘制）。
- **回合两阶段**（2026-10-01 拍板）：① 转轮盘 → ② 使用道具。牌垫第二行为阶段条
  （当前阶段点亮，进入②时道具牌位点亮提示可操作）；**转动转盘大按钮做在牌垫上**，
  道具阶段变灰为「等待使用道具」。实现注意：回合状态机要给 use_item 阶段留位，
  道具阶段细节随道具系统解冻细化。
- **视角按钮（跟随 / 全景 / 左家 / 对家 / 右家）删除**：视角切换保留点座位卡 / Tab / 空格。

### 左上角「暂停」按钮 + 暂停菜单

> 2026-10-02（v0.1.0）：入口按钮文案由「☰ 选项」改为「⏸ 暂停」（点它就是暂停，名字直说功能）。
> **操作说明已做**，但没放进菜单，而是独立成左下角的「📖 规则说明」面板（见下一节）。

- 菜单：继续 / 设置 / 退出游戏。
- 设置页做**可扩展框架**：首批「音效音量 + 静音」，后续会加更多设置项。
- **退出游戏二次确认**：房主退出 = 对局结束；非房主退出 = 机器人接管。
- **暂停语义**：房主打开菜单即全场暂停（回合状态机、转盘、赌场倒计时、
  35 秒代掷计时全停），其他人见「房主已暂停」遮罩；非房主打开菜单仅本地，
  显示「对局进行中 · 仅房主可暂停」；单机即房主。

### 左下角「规则说明」面板（2026-10-02，v0.1.0）

- 原「操作提示」只有一小块常驻文本，容量不够；改为**收起态一个「📖 规则说明」按钮，
  点开原位向上展开**分页面板，五页：基础操作 / 回合与行动 / 棋盘与地产 / 经济与胜负 /
  道具与事件。
- 文案独立成一份文案表：**数值一律引用代码常量**（起始资金、工资、上限轮数、
  地价 / 租金表、品质售价、赌场注码…），表格区间与格型数量从数据算——
  写死的话改数值就会忘了改说明。
- 展开时占据左下角，**格详情卡让位**（两者锚在同一块地方）；格详情卡本身改为
  默认隐藏、点格子才弹。
- 待办：内容目前是摘要版，是否扩成完整规则书 / 加插图待定。

## 四、道具与系统的逐条拍板（2026-09-30）

1. 香皂融化计数 = **持有者自己的回合数**。
2. 蛋蛋节概率：使用者紫 70 / 橙 30，他人白绿蓝均分。
3. 蛋蛋节满包玩家**改发 ¥100 现金**。
4. 焦土捐款被香皂拦截时**进度不涨**。
5. 小卖部 **4 家**；**每家店独立货架**（机会卡「进入小卖部」进随机一家）。
6. **背包对所有人公开**。
7. 黑市价目：紫 1 / 橙 2 / 刷新 1 / 出口 1 块地皮；**黑市刷新不涨价**
   （递增刷新价仅小卖部）。
8. 被收地皮**回归无主、可被再次购买**。
9. 进黑市**强制且不算 debuff**。
10. **橙色在小卖部出现**，铺货 5% 概率（橙池空时并入紫）。
11. 休眠 = 保守托管、小黑屋 = 休眠（确认）。
12. 强身健体**冷却不减**。
13. 科技结果**全员公开**。

**补记**

14. **换座位的落点结算 = 方案 A**（纯位移、不结算落点、不付租）——2026-10-02 拍板。

当时留下的「待讨论」项已分流到各玩法文档末尾的「设计待定」节：
数值专场（焦土捐款比例、刷新价曲线、品质权重份额）、
开局设置专场（胜利条件、起始资金、各开关细节、畸变触发节奏）、
预告待落定（被动道具可否不进店、道具 / 科技改品质刷新概率、园中叶效果）。

## 五、操作倒计时的呈现位置

**拍板（2026-10-02）**：倒计时**嵌在当前行动者的座位卡里**（左列「体力」行下方，
环节名 + 进度条 + 剩余秒数，随座位朝向旋转），不做屏幕层悬浮条。

### 备选与取舍

先用可交互原型（`倒计时位置-原型.html`，桌垫 1:1 复刻 + 真实走秒）对比了五个位置：
悬浮在底栏上方（第一版实现，被否）、桌垫阶段条右端 / 紧跟状态文字 / 正中央 / 最左端、
嵌座位卡。最终选座位卡——倒计时跟着「谁在操作」走，在桌上而非屏幕层，
与「物件上桌」的桌游感一致（见本文件开头的设计主轴）；窗口换人时倒计时自然跟到下一位的卡上。
