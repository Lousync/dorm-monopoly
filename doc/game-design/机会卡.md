# 机会卡（三类事件卡：机会 / 道具 / 畸变）

> 三类卡统称**事件卡**（术语表的口径）。落在机会格 → **先掷类别、再按类别取值**。
> 畸变的全场机制见 `畸变.md`（其中 §二「例外通道」是机会格这条支路）；
> 效果标签体系见 `道具系统.md` 的「效果标签」。

## 一、抽卡

- 棋盘 **4 个 `event` 格**一律叫「**机会**」（2026-10-09 起命运格并入，格型仍是 `event`、
  图标统一 `luck`）。
- **先掷类别，再按类别取值**（概率精确，不靠牌堆配比拼出来的近似值）：

| 类别 | 概率 | 结算 |
|---|---|---|
| **机会卡** | 85% | 从**统一的机会牌堆**抽一张（预生成洗牌、抽完再补洗，见 `_draw_chance_card` / `_new_event_deck`） |
| **道具卡** | 10% | 按品质权重随机得一件（权重表 `ItemData.CHANCE_ITEM_WEIGHTS`）；唯一池过滤 / 缺货向下降档 / 满包作废，口径与失物招领一致 |
| **畸变卡** | 5% | 从现有畸变的**随机池**抽一条，**全场立即生效**（例外通道见 `畸变.md` §二） |

概率写死为 `GameData.CHANCE_P` / `CHANCE_ITEM_P` / `CHANCE_AB_P`，**不进开局设置**。

### 边界规则（四条）

1. **畸变总开关 =「关」**（`开局设置.md` 的触发频率「关」）→ 第三档作废、那 5% **并入机会卡**
   （实际分布 **90 / 10 / 0**）。理由：畸变被房主关掉，机会格不该绕过设置把它塞回来；
   道具卡那 10% 不动。
2. **畸变卡池**只取 `implemented == true` **且** `trigger == "随机"` **且**已过 `min_round`
   的条目（`_ab_random_pool`）——**条件型不进池**：它们靠条件检测触发、`cond` 要求有触发主体，
   硬抽会很怪。
3. **持续型撞车走「新盖旧」**：抽到持续型、而场上已有持续型生效中时，先把旧的那条提前结束，
   保住「全场同时最多 1 条持续型」这条不变量。
4. **绕过两道闸门**：玩家中途抽卡**不属「回合开始的畸变窗口」**，因此不受闸门一（每回合最多
   1 条）与闸门二（同时最多 1 条持续型）约束 —— 闸门二由上面第 3 条用「新盖旧」兜住。

### 卡池过滤（按开局开关）

- 黑市未开 → 不发 `enter_blackshop` 卡；小卖部关 → 不发 `enter_shop` 卡；**滤空则回退全池**。
- 「小抄」偷看的是**机会牌堆的顶张**（`_peek_event`）。牌堆只装机会卡 ⇒ 它**看不到**
  「这一次会不会抽中道具卡 / 畸变卡」（相对改造前是一次轻微削弱，见 `道具图鉴.md`）。

### 与科技的交界

- **「厄运保单」只认 `money` 负数、「喜报频传」只认 `money` 正数** ⇒ §二 那 15 个新增字段
  **都不触发**这两个科技（避免语义漂移）。改造前它俩是「未来承诺」，字段真实存在后这就是
  「现状」——按现状写死，别顺手把新字段也接进去。

## 二、卡字段（数据契约）

一张卡 = 一个**字段字典**，`_apply_card` 按固定顺序分派（不引入 effect 对象 —— 图鉴生成器
复用同一份 `GameData.card_kind()`，改成对象就会多出第二来源）。

### 现有字段

| 字段 | 含义 |
|---|---|
| `t` | 卡面文本 |
| `money` | 收支（正数入账；负数扣钱，**可被香皂免疫**） |
| `from_each` | 每位**其他存活**玩家给你该金额（受害者逐人独立免疫） |
| `to_each` | 你给每位其他存活玩家该金额（你持皂则整条免疫） |
| `move_steps` | 前进 / 后退若干格（负数倒退；途中踏过起点照常领工资；**移动后照常结算落点**；后退可被香皂免疫） |
| `go_jail` | 直接送宿委会（可被香皂免疫） |
| `enter_shop` | 进入一家随机小卖部。**字段保留；当前 50 张卡里没有使用它的卡**（小卖部靠踩格进入，见 `小卖部.md`）—— 不是漏了一张 |
| `gain_item` | 获得指定 id 道具（背包满作废） |
| `gain_item_quality` | 随机获得一件指定品质道具（唯一池过滤；缺货 / 满包作废提示） |
| `enter_blackshop` | 进入黑市（见 `黑市.md`） |

> `only` 字段随「命运」一起退场：机会格只剩一种，已没有可筛的格型。

### 新增字段（15 个，**全部已实装 2026-10-09**）

| 类 | 字段 | 含义 |
|---|---|---|
| 指定目标 ✅ | `steal_from: int` | 从选定目标夺取现金（不足则取其所有；只归零，不会把人打成破产） |
| | `charge_to: int` | 向选定目标收取现金（文案区分于夺取） |
| | `jail_to: true` | 送选定目标去宿委会（他跳过下一回合） |
| | `each_from_target: int` | 选定目标给每位其他存活玩家该金额（**收钱方含抽卡者本人** —— 卡面「让他请全宿舍」即此意；逐个收，目标见底时排在后面的只拿得到剩下的） |
| | `steal_item_from: true` | 从选定目标随机夺一件道具（**自己背包满则整条作废**，目标空背包则提示没得抢） |
| 地皮与位置 ✅ | `seize_tile: "take"\|"swap"` | `take` 夺目标一块投入最少的地（含装修等级）；`swap` 与目标各随机一块互换（无地则作废） |
| | `force_buy_tile: int` | 以该百分比原价强买目标一块地（投入最少的一块；现金不足作废；**含装修等级** —— 过户恒保留 `level`，所以 33% 原价买到的是**带装修的那块**，与「夺地」同口径） |
| | `swap_pos: true` | 与目标交换棋子位置（**不结算落点、不领工资**） |
| | `pull_target: true` | 把目标拉到你当前格（他**照常结算落点**） |
| | `push_back: int` | 目标后退 N 格（照常结算落点） |
| | `shuffle_pos: true` | 全场玩家位置**随机重排**（无目标） |
| 抉择与情报 ✅ | `choices: Array` | 二选一（最多 3 项），每项 `{t: 选项文案, …效果字段}` |
| | `peek_deck: int` | 私密偷看机会牌堆顶 N 张（`N` 夹在 `[0, 牌堆大小]`；看到的那几张记在 `_peeked`，仅供测试 / 摆拍读） |
| | `shuffle_deck: true` | 重洗机会牌堆（作废所有人的预知：`_peeked` 一并发清） |
| | `bury_deck: true` | 把机会牌堆顶一张塞到底部（跳过一张；只有一张时等于原样） |

- **情报类**（`peek_deck` / `shuffle_deck` / `bury_deck`）：三张都**只动牌堆**，不碰任何对局状态。
  本作的身家 / 现金 / 背包 / 地皮本来就全是公开信息，**唯一真正隐藏的是牌序** —— 所以「窥探现金 /
  公开身家」那类卡是废卡，不在字段表里。三条都先保证牌堆非空（抽空则现补洗一手，同 `_draw_chance_card`
  的口径）。

- **选目标**：复用现有「选目标」那套（**桌面立牌**点亮）。合法目标按字段过滤：
  `seize_tile` / `force_buy_tile` 只列**名下有地**的玩家（口径同「强拆令」）；其余列所有其他存活玩家。
- **抉择**：卡面演出给 1~3 个按钮（**只有抽卡者那一端出**：旁人看到同一张卡，但整排按钮不出镜），
  客户端提交所选项、房主结算。**两级组合**（两个分支都要选目标）先选分支、再选目标，共两次交互。
  这排按钮**就是**这张卡的「确定」—— 卡停住后整排出镜、选完即收卡，不再另点一次确定。
  bot / 休眠托管 / 超时 / 没作答 ⇒ 房主取第一项；选项 ≤ 1 时直接按第 0 项结算、不进交互。

## 三、结算顺序

依次处理：`money → from_each → to_each → go_jail → move_steps → gain_item / gain_item_quality
→ enter_shop → enter_blackshop`。

- 上面那 15 个新字段里，**目标类 / 地皮与位置类 / 情报类**都插在 `go_jail` 之后、`move_steps` 之前
  （先定点打击、再位移），即 `… → go_jail → [目标类 → 地皮类 → 情报类] → move_steps → …`
  （**15 个新字段已全部实装 2026-10-09**）；
  **抉择卡 `choices` 单独排在整张卡的最后**（`enter_blackshop` 之后、`_check_end` 之前）——
  分支自带的效果字段要**递进走同一套顺序**（见 `_apply_card` 的抉择分支），效果最后落地：
  - 目标类内部顺序：`steal_from → charge_to → each_from_target → steal_item_from → jail_to`
    （逐条独立结算：一条作废 —— 无人可选 / 目标持皂 —— 不影响下一条）。
  - 位移与落点：`swap_pos` / `shuffle_pos` **不结算落点**（纯换位）；`pull_target` / `push_back`
    **照常结算落点**（与 `move_steps` 同口径，可能连环触发）。
- `move_steps` 走完后**照常结算落点**——所以「前进 X 格」可能又触发一张机会卡或买地，属设计内。
- 卡型配色按效果分 good / bad / move / jail / info 五类（`GameData.card_kind()`；抽卡演出与
  图鉴页读同一份，不另抄）。其中 `seize_tile:"take"`（夺地，对抽卡者有利）归 **good**、
  `seize_tile:"swap"`（互换，中性）**与它分开判**、归 **move** —— 两者**不同色**，
  别把互换也涂成收益色（玩家可见的错话）。

## 四、免疫点

「空想者的香皂」按**效果标签**判定（标签体系见 `道具系统.md`）。

| 效果 | 标签 | 香皂 |
|---|---|---|
| `money` 负数、`to_each`、`go_jail`、`move_steps < 0` | debuff | 抽卡者持皂**免疫** |
| `from_each` 扣受害者 | debuff | **逐受害者**独立免疫 |
| `money` 正数、`gain_item*` | 中性 | 不受影响 |
| `steal_from`、`charge_to`、`jail_to`、`each_from_target`、`steal_item_from`、`seize_tile:"take"`、`force_buy_tile`、`pull_target`、`push_back`（**已实装**） | debuff | **目标**持皂则整条免疫 |
| `push_back`（**另加**） | 后退类 | 目标持**雨伞**也免疫（图标口径同 `move_steps < 0`）；`pull_target` 是**拉**不是**推**，雨伞不管它 |
| `seize_tile:"swap"`、`swap_pos`、`shuffle_pos`、`peek_deck`、`shuffle_deck`、`bury_deck`（**已实装 2026-10-09**） | 中性 | 无效 |
| `choices`（**已实装 2026-10-09**） | 按所选分支**逐项**判定 | 同各项 |
