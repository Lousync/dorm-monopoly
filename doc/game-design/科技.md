## 一、机制

- **发车前**，每名玩家**独立发现三张科技、选一张**；三张必属**同一等级**。
- **等级随机定档**（2026-10-04 拍板；2026-10-09 去掉骰子）：每局在**三档里等概率抽一档**
  （各 **1/3**）；全场同一等级，结果全员可见（战报公告 + 屏幕层演出）。
  - 原口径是「掷 1~6 点 → 1~2 白银 / 3~4 黄金 / 5~6 钻石」——均匀 6 面映射到 3 档，
    概率**本来就是各 1/3**，所以 2026-10-09 用户判「不需要掷骰子动画」时直接改成随机选一档，
    **分布不变、平衡不动**（`TechData.random_tier()`）。骰面绘制、快滚时长与 RPC 的 `pips`
    参数随之删除。
  - ~~黄金/钻石池定稿前暂不掷骰~~ **已恢复（2026-10-07）**：三档池子定稿补齐，定档接线。
- **等级可由房主指定**（2026-10-07）：大厅「游戏设置」的「科技等级」——**随机（默认）**
  / 白银 / 黄金 / 钻石；指定档不随机、本局固定该档；**整个等级选择只在科技开关打开时显示**。
  随机与指定走**同一种定档演出**（2026-10-09 起无骰面）。见 `开局设置.md` §八。
- **允许重复**（2026-10-04 拍板）：多名玩家可选同一条科技，各自独立生效。
- **结果公告全员**（等级 + 各家所选项，公开，定稿）。
- 科技池按等级分池，数据表可扩展。
- **科技效果一律无 buff/debuff 标签**——香皂对科技无效。

## 二、等级

| 等级 | 骰子 | 定位 | 强度曲线 |
|---|---|---|---|
| **白银** | 1~2 | 基础强化，人人能用的稳收益 | 温和，无代价或微小代价 |
| **黄金** | 3~4 | 明显强化，开始改变打法 | 中，可带轻代价 |
| **钻石** | 5~6 | 局面级强化，重塑经济 / 节奏 | 强；科技**不做成后期海克斯的超模**（发育型为主，不一步登天） |

## 五、对局中获得（口子已开、抽卡未做）

**2026-10-10**：数据形状已经按「**科技可以有多条**」设计 —— `p.techs` 是列表
（`doc/development/联机协议.md` 的快照字段 `players[].techs`），发放统一走 `game._grant_tech(p, name)`。
**但抽卡本身没有做**：当前唯一的发放路径仍是发车前那次三选一，恰好发 1 条 ⇒ 多条共存
在结构上可能、在对局上不可达。将来加「科技卡」时只需调 `_grant_tech`，**不必再动一次地基**。

### 已在代码里定下的四条口径

1. **重复获得 = 幂等**：`_grant_tech` 遇到已持有直接返回 `false`、**不做任何数值补偿**。
   理由：科技里有一批计数器型（`厄运保单` 4 次 / `天命在握` 4 次 / `任意门` 2 次 / `悔棋` 1 次 /
   `东山再起` 1 次 / `接收大员` 1 次），允许叠加就得**逐条**定义「可不可叠」——在没有科技卡的今天
   那是凭空发明规则。
   *（备选：重复时按档折现 `TECH_DUP_CASH := {白银 1000, 黄金 3000, 钻石 8000}`。比叠加安全、可测，
   不需要逐条定标。**未实现**。）*
2. **`implemented` 闸在 `_grant_tech` 里** —— `TechData.pool()` 那道闸只在**按档抽卡**时生效，
   按名发放会绕过它。
3. **定档保留（按档发）**：中局发的科技也取自**本局那一档**（`pool(_tech_tier, …)`）——
   「本局科技等级」仍是全场共识，UI 不用新增档位选择，稀有度仍有档位锚。与既有的
   「畸变总开关为关时畸变卡那一档作废、5% 并入机会卡」是同一条思路：**没定档（`tech_on = false`）
   时不生成科技卡**。
   *（备选「按条发 / 卡面自带档位」：更像道具卡、惊喜感更强，但会**打散「全员同档」**这条已定稿机制，

### 同档内的覆盖 / 叠加规则

方案 B 之后「多条共存」在结构上可能，但**在对局上仍不可达**（唯一发放路径 = 开局三选一，恰好 1 条）。
下表**只约束将来**，代码不动。**因为定档是「全场同档」，跨档组合天然不可能**（如 `富二代` 钻石 +
`助学金` 白银），同档组合很少：

| 档 | 组合 | 规则 |
|---|---|---|
| 钻石 | `富二代`（起始资金 ×2） + `预支未来`（+¥30000） | **顺序待定**：建议「先 ×2、再 +30000」（乘算在前、加算在后，与道具侧 `招财猫 → 保安巡逻` 的「先加后乘」口径**相反**，须显式写明） |
| 钻石 | `双开`（每回合 2 件） + `熟能生巧`（不冷却） | **独立叠加**（一个管件数、一个管冷却） |
| 黄金 | `灵活就业`（首件 −1⚡） + `手速惊人`（冷却 −1） | **独立叠加** |
| 黄金 | `地产眼光`（前 2 块半价） + `批发拿地`（−25%） | **已有定稿**（乘算叠加） |
| 跨档（备选「按条发」时才可能） | `摸鱼时刻`（转 0 +¥500） ↔ `闲不住`（转 0 改为前进 2 格，「不再算掷出 0」） | **覆盖**：`闲不住` 生效时 `摸鱼时刻` 不触发 |
| 跨档 | `熟能生巧`（钻石） ↔ `手速惊人`（黄金） | **覆盖**：不冷却压倒「冷却 −1」 |
| 跨档 | `预支未来`（不再领工资） ↔ `工资上调` / `金饭碗` / `校园卡`（道具） | **覆盖**：工资类加成**一并作废**（`预支未来` 的 desc 只说「经过起点不再领工资」，**没说是否连加成一并作废** —— 这是本批新暴露的口径空洞，**按「一并作废」定**） |

> 「设置联动」那几个已知项（`金字招牌` / `大器晚成` / `预支未来`）见 §四 的同名小节。
