# 赌场

> 地图格型 `casino`（2 格）。逻辑与表现在 `scripts/casino.gd`（game 的子节点，自带全屏演出层），纯规则在数据/工具层。
> **原「炸弹猫」玩法已移除**（见 §五）。当前游戏为「投骰子」。
> 更新：2026-10-03 · v0.5.0 批次 1。

---

## 一、触发与注码

- **落到「宿舍赌场」格** → **全员下注**（`GameData.CASINO_STAKE`，按各自现金封顶）→ **奖池 = 所付之和**（赢家通吃）。
- 存活 **< 2 人**时不开局，直接离开。
- 每人下注额 = `CASINO_STAKE`（当前 800，数值待专场）。

## 二、演出（全屏场景）

进入赌场是一段**演出**，分三步：

1. **整屏切进**：触发时拉起赌场自带的**全屏演出层**（`casino._ui_layer`，照暂停菜单那套
   「全屏压暗底 + 居中面板」），独占整屏、压住底栏与两侧栏；**不再推近棋盘相机**。
2. **桌面相机不动**：整段演出期间对局相机保持原状（视角恒在自己座位，不抢镜头）。
3. **抽游戏** + **场景布置**（见 §三）。

## 三、流程

```
落到赌场格 → 全员下注 → 整屏切进赌场场景 → 抽取本局游戏（CSGO 开箱式卷轴）
           → 面板变为该游戏布景 → 玩完 → 赢家通吃/平分 → 结算 → 关闭全屏、回桌
```

### 抽游戏

- 赌场中央一条**横向卷轴**滚动（先快后慢、轻微回弹），中线标记命中本局游戏（CSGO 开箱手感）。
- 命中后卷轴淡出，面板**切换为该游戏的布景**。
- **当前抽奖池只有「投骰子」是真实游戏，其余为占位**（因此**固定抽到「投骰子」**）；以后抽奖池扩充（见 §六）。

### 游戏：投骰子

- **每名存活玩家同时掷一颗 6 面骰**（掷骰动画后一并定格）。
- **点数最大者通吃奖池**。
- **平局**：点数并列最大者**平分**奖池（`奖池 / 并列人数` 向下取整，余数按行动顺序逐人 +1）。

## 四、表现

- **触发式全屏界面**：赌场自带一整屏演出层（`casino._ui_layer`），触发时独占、结束即收场；
  原先画在桌面上的常驻赌场设施（奖池 / 状态行）已随 v0.5.0 批次 1 撤下。
- **场景内渲染**：抽游戏卷轴 / 骰子在该全屏层的面板里渲染（面板即"赌场场景"）。
- **屏幕层**：仅状态提示；私人信息无（本游戏无透视）。

## 五、已移除：炸弹猫

- 原「炸弹猫」（12 张牌堆：炸弹×3 / 拆除×2 / 小鱼×7，轮抽、拆除化解、小鱼比多）**整块删除**：含纯规则 `scripts/bombcat.gd`、赌桌 UI 与 `tests/casino_test.gd` 中的对应规则测试。
- 删除原因：功能有问题，且改用更简单直观的「投骰子」。

## 六、同步（联机）

全程 **host 权威**：下注、掷骰、判定在房主侧；客户端只渲染。

| RPC | 方向 | 载荷 | 用途 |
|---|---|---|---|
| `s_casino_start` | 房主→全员 | 游戏名、注码、奖池、参与顺序 | 触发**全屏切进 + 抽游戏**演出 |
| `s_casino_roll` | 房主→全员 | 各 peer 点数 | 骰子定格 |
| `s_casino_end` | 房主→全员 | 赢家数组、奖池 | 结算、关闭全屏回桌 |

> 本表原有一行 `s_casino_draw`（"卷轴定格、切换场景"），**从未实装**——抽游戏的定格与切换
> 已并进 `s_casino_start`。`scripts/casino.gd` 实际只有 start / roll / end 三个 `@rpc`。
