## 1. 点名（重做）

### 现状
- 品质：蓝；类型：`active`（主动）；`target: "player"`（需选一名其他玩家）。
- 能量 **⚡3** / 冷却 **3**。
- 效果：指定一名其他玩家，其**下一次转盘点数 +3**。
- `icon`：`item_rollcall`（图已有，不用换）。
- 代码：`scripts/item_data.gd` 的 `ITEMS["点名"]`；效果在 `scripts/game.gd` `_use_item` 的
  `match id: "点名"` 分支（写目标玩家的 `roll_bonus += 3`）。

### 改为
- 能量 **⚡4** / 冷却 **6**。
- 效果：使用时先**指定一名其他玩家**，再**由使用者选定该玩家下一次转轮盘的点数**（0~12 任选）。
  - 目标的这一次转盘**按所选点数走**，不再随机。
  - 名字 / 品质 / 类型 / `target` / `icon` 不变。

### 落点与施工要点
1. **数据**：`scripts/item_data.gd` → `点名` 的 `"cost"` 3→**4**、`"cooldown"` 3→**6**，
   `"desc"` 改成「指定一名玩家，由你决定他下一次转盘的点数。」（卡面用玩家视角一句话）。
2. **交互（两步）**：现状 `点名` 走 `_on_use_pressed` 的 `_begin_peer_target(slot)`（只选玩家）。
   重做后需要「先选玩家 → 再选点数」：
   - 复用**作弊器的 0~12 点数选择器**：`_open_cheat_picker(slot)` / `cheat_picker` / `cheat_slot`
     （见 `scripts/game.gd` `_on_use_pressed` 里 `if iid == "作弊器"` 与 `_open_cheat_picker`）。
     可让「选完玩家」后转去开这个选择器。
   - 选择器回调最终应发 `_send_use_item(slot, 目标peer, 点数)`（`arg`=目标 peer，`arg2`=点数）。
3. **效果**：`_use_item` 的 `"点名"` 分支改为把**目标的强制点数**记到一个状态字段并等其回合取用。
   现成可复用的机制：`cheat_roll`（作弊器用的「本回合强制点数」）。即
   `t.cheat_roll = clampi(arg2, 0, 12)`（而不是给 `t.roll_bonus`）。
   - 若沿用 `cheat_roll`，注意**目标**的这次转盘定在该点数后要清零。
4. **⚠ 顺带确认的缺陷（与本次落点同处）**：转盘覆盖逻辑 `scripts/game.gd` **约 1468–1484 行**，
   `cheat_roll`（作弊器）与 `tianming_roll`（天命在握）的处理目前**被嵌在
   `if int(p.get("roll_bonus", 0)) != 0:` 分支内**（第 1477 行缩进为 3 tab）——
   即**只有同回合也被「点名」加过点数的玩家，作弊器 / 天命在握才会生效**。
   疑似缺陷。重做点名会动到这段，**请一并理清各「强制/加成点数」的优先级与顺序**（建议：
   先取基础随机 → 应用 roll_bonus → 若存在强制点数（cheat_roll / 点名 / 天命）则覆盖）。
5. **状态同步**：`cheat_roll` 目前**不在** `s_state` 的玩家字段里（`联机协议.md` §三：
   `{peer,name,color,bot,money,pos,alive,skip,sleep,stamina,items,item_used}`）。房主权威计算、
   转盘结果走 `s_roll`，客户端不需要它也能正确显示；若想给目标玩家/旁观者一个「被点名了」的预览，
   再把对应字段加进快照。
6. **文档**：回填 `doc/game-design/道具图鉴.md` 的「点名」逐件条目；`CHANGELOG.md` 记一条。

### 待确认（施工前问一下作者）
- 点数范围就取 **0~12**（与转盘一致）。
- 目标**已休眠 / 已出局**时：不允许选（沿用 `_begin_peer_target` 的存活过滤）还是要特殊处理？
- 目标本来就有其它强制点数（作弊器 / 天命在握）时的**优先级**如何（见第 4 点）。
- 是否允许对**自己**用（现状 `点名` 只能选其他玩家，保持不变即可）。

### 验证
- `tests/item_test.gd`：加断言 —— 用后 `⚡4`、冷却 `6`、目标进入强制点数状态；
  转盘时目标该回合点数 == 所选值。
- `tests/regression_test.gd`：视需要补一条（如强制点数不被 `roll_bonus` 分支吞掉）。
- 手动：道具试验场 `--lab` 或联机跑一局，目标转盘确实落在所选点数。

## 2. 紫档「去一次性」（批量）

### 动机
紫档（史诗）现在 17 件里 **14 件是 `type: "consumable"`（用后焚毁、整局只出一次）**，
复用价值极低、手感偏弱。改成：**只保留少数「不可逆 / 剥夺 / 全局重置」类为一次性，
其余改 `active`（可反复用），用较大的冷却来限速。**

机制说明：本作里 `type` 二选一——
`"consumable"` = 用后**焚毁、回池后整局不再出**（`game.gd` 约 5071 行 `once = d.type=="consumable"`
→ 记入 `items_consumed`）；`"active"` = **留在背包/道具池**、靠 `cooldown` 限制。
卡面右上角：consumable 显「一次性」，active 且 `cooldown>0` 显「⏳预览」（§八 `ItemData.shop_state`）。

### 保留「一次性」（4 件，不改）
| 道具 | 理由 |
|---|---|
| 平均主义 | 全局现金重置，复用会反复洗牌 |
| 强拆令 | 地皮变无主，永久毁地、不可逆 |
| 拆解钳 | 摧毁对方随机道具（剥夺） |
| 没收 | 夺对方随机道具（剥夺） |

> `强拆令` 现状 `type=consumable` 却写着 `cooldown: 4` —— 一次性下冷却无意义，
> 可保留可清掉，不强制。

### 改为「主动」并设冷却（11 件）
| 道具 | 现在 | 改为 |
|---|---|---|
| 抄家队 | consumable | active · **cd 6** |
| 快递直达 | consumable | active · **cd 4** |
| 时间暂停 | consumable | active · **cd 7** |
| 包场 | consumable | active · **cd 8** |
| 代课 | consumable | active · **cd 4** |
| 顶楼加盖 | consumable | active · **cd 5** |
| 转专业 | consumable | active · **cd 8** |
| 宿舍改造 | consumable | active · **cd 6** |
| 打印店 | consumable | active · **cd 6** |
| 老虎机 | consumable | active · **cd 3** |
| 出老千 | consumable | active · **cd 4** |

> `保安巡逻` / `重修卡` 本就是 `passive`，不动。

### 落点与施工要点
1. **数据**：`scripts/item_data.gd` —— 上表 11 件的 `"type"` 由 `"consumable"` 改 `"active"`，
   并补上对应 `"cooldown"` 数值。效果代码**不用改**（复用/焚毁逻辑按 `type` 自动分流）。
2. **自动生效处**（无需改，供核对）：
   - 用后是否回池：`game.gd` 约 5071 行 `once = String(d.type)=="consumable"`。
   - 卡面右上徽章：`item_card.gd` 约 158 行 `is_once = type=="consumable"`；`shop_state`（§八）。
   - 冷却/唯一性：`_item_pool`（`game.gd` 约 4821）—— active 不再因使用而移出。
3. **文档**：逐件回填 `doc/game-design/道具图鉴.md`（类型 + 冷却列）；若 `道具系统.md`
   的徽章/示例表提到这些件，一并更新；`CHANGELOG.md` 记一条。
4. **测试**：`tests/item_test.gd` 加断言 —— 上述件用后**仍在背包**、且 `cd` 等于设定值；
   保留的四件用后**离开背包且不再回池**。

### 待确认
- 冷却数值是否合适（尤其 `包场 cd8` / `转专业 cd8` / `时间暂停 cd7` 这类干扰他人的，可否再高）。
- 改 active 后是否要顺带调**品质权重/售价**（本次不动，仅类型与冷却）。
- `出老千` / `老虎机` 复用会多次开盘，确认赌场流程能反复进入。

### 验证
- 道具试验场 `--lab`：用一次后仍能再用（冷却走完），右上角显 ⏳ 而非「一次性」。
- 联机一局：上述件确实按冷却而非焚毁。
