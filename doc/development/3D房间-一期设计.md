## 一、背景与目标

对局画面现在是「**一张桌子 + 四周纯黑**」——这是 `design/设计决策留痕.md` §十三 ⑨ 的结果：
批次 13 曾把 `table_3d._build_room`（三面墙）/ `_build_bookshelf`（书架）/ `_build_bedframe`（床架）
连同 `ROOM_*` 常量**整段删除**，理由是"给桌面减负、去氛围"。

用户现在的目标是**反过来**：要一间**看得见的屋子**，参照《骗子酒馆》那种"**我在一间屋子里跟人打牌**"的临场感。
用户已明确两点：**要有坐着的人物**、**要对手势 / 反应**（这两条属于二期）。

**本期的目标**：把屋子立起来，并把**取景与光照契约**改到位，使二期"往椅子上放人"时不需要再动契约。

---

## 二、范围

### 做

天花板 / 地板 / 四面墙 + 家具（书桌 / 书架 / 收纳箱 / 椅子 ×4）+ 椅背名牌 + 吊灯的可见几何
+ 取景契约改动 + 光照契约改动 + 验收断言。

### 明确不做（防止范围蔓延）

- **人物模型 / 骨骼 / 动画**（二期）
- **转视角**（相机仍固定在自己座位、全程不旋转 —— 批次 1 删掉的，本期不恢复）
- **房间里的可交互物件**（点家具没有反应）
- **门窗开合 / 动态光照**（灯不闪不摇）
- 与玩法事件的任何挂钩（二期）

## 三、题材与房间内容（已拍板）

**学生宿舍，不是棋牌室。**

理由：本作 56 个格子本身就是校园地名（一/二/三食堂、小卖部、宿委会、公共澡堂、快递驿站、
失物招领、教学楼 A/B、体育馆…）。参照作品用酒馆是因为它的题材是酒馆；本作的题材是宿舍，
照抄酒馆的砖墙与酒瓶架反而丢掉身份。

### 吊灯：不是"书桌台灯"

`table_3d.gd` 里那盏 `OmniLight3D` 的**世界位置**是：

```
LAMP_LIGHT_POS := Vector3(-4.126823, 10.0, 0.0)      # 桌心为原点；桌面在 y = 0
```

**y = 10** —— 这在桌面上方 10 个单位，**不可能是台灯**。而且这个 10 是**批次 13 ⑦⑧ 为"桌面均匀"
人为抬上去的**（原文：只有 y 变了，`2.728671 → 10.0`），它**并不对应任何一个真实存在过的物件**
（灯的可见几何批次 12 A1 就已删净）。

⇒ **配的可见物件是「吊在桌上方的灯」**（一根线从天花板垂下来的灯泡 / 吸顶灯），y = 10 正是这个高度。
**好处：光的位置一个数都不用动**，`LAMP_ENERGY` / `LAMP_RANGE` / `LAMP_ATTEN` 与批次 13 ⑦⑧ 调好的
桌面照度**全部保留**。变的只是我们给它配什么形状。

> ⚠ **更正（2026-10-06，裁决 Ruling U）：这盏"看得见的吊灯"本期不做 —— 它从取景轨道上的
> 任何位置都看不见。** 相机**整个画面都在地平线以下**（3D 端上缘那条视线是 30.5° 俯角、
> 2D 端接近正俯视）⇒ **任何高于相机的东西恒不可见**；而相机在 `y ≈ 4.42`（3D 端）/
> `y ≈ 9.20`（2D 端），吊灯的光却在 `y = 10` —— 实测偏轴 **104° / 101°**，而半视角只有 19.5°。
> **推拉也救不了**（推拉只改距离、不改俯角：要退到 `D ≈ 30` 才把吊灯塞进画面，那时格子约 9px）。
> 要把吊灯画出来**只有"能把视角抬起来"这一条路**（第三条轴）—— 那是新的设计决定，不在本期。
> ⇒ **光的位置与三个 `LAMP_*` 常量照旧不动；只是不建它的可见几何**，
> 即回到批次 13 ⑨ 已拍板的状态（"删掉房间剪影、**台灯只留光**"）。
> **代价**：房间没有可见灯具、光的来源在画面里没有交代。**天花板仍保留**（房间的边界）。

**副作用（要在设计里承认）**：吊灯得从天花板吊下来 ⇒ **本期必须做天花板**。

### 一条硬约束：吊灯必然偏左

光在 `x = -4.126823`（**负的**，桌子 8 宽、x ∈ [−4, +4]，所以它在**桌子左缘之外**）。
⇒ 画面上那盏看得见的吊灯**必然偏左**，不可能在正中。三个构图方案都不例外。

## 四、取景契约（**本期最重要的改动**）

### 现状（**动工之前**的读数 —— 现值见本节末「实施后回填」）

```
CAM_FOV       = 39.0°      # 从默认 75° 收窄来的
CAM_DIST      = 5.77       俯角 CAM_TILT_DEG = 50.0°     # ⚠ 实施后 = 8.90
VIEW_DIST_2D  = 9.20       2D 端俯角 CAM_TILT_2D_DEG = 88.0°   # 本期一字未动
```

`layout_test` 现有契约：**整条视角轨道 21 档上，桌垫（`TABLE_SIZE`）四角都必须入画、余量 > 5px**；
最紧 **81.6px**（@ wt=0.00，**这一档的读数随相机一起作废**，见下）；
外圈木纹是"桌子本身"、**可以出画**。

### 改成（用户选 B 档：房间占上缘 32%）

> ⚠ **实施后更正（2026-10-06，Task 7）："收紧回木桌四角"没有采用，32% 也降级成"要报出的目标值"。**
> 落到代码里的是：**判据仍是「桌垫四角」**（木纹可以出画那条不变），**硬门是格宽 ≥ 32px**，
> "上缘 32%" 只作为**报出值**。理由见本节末的「实施后回填」—— 两者在数学上互斥的结论
> （Ruling N）在实施中以真实取景复核过一遍，用户当时选的也是"默认看屋子 + 格宽底线 32px"。

| 端 | 契约 |
|---|---|
| **2D 端（`view_t = 1`）** | **一字不改** —— 沿用「桌垫四角入画」。俯角 88° 接近正俯视，房间的墙本就在画面外，只看得见地板 ⇒ 天然满足"2D 要看清棋盘" |
| **3D 端（`view_t = 0`）** | 判据从「桌垫四角」**收紧回「木桌四角」**，**并新增**「木桌上缘 ≤ 屏幕高度 32%」<br>**⚠ 实施时没有采用这一条**：判据仍是桌垫四角、32% 改成报出值（见上框 / 实施后回填） |
| 中间档（`0 < view_t < 1`） | 逐档插值：要求的入画范围从 `view_t=1` 的**桌垫四角**连续过渡到 `view_t=0` 的**木桌四角**。21 档的余量表必须**单调**，不允许中间某档突然变紧 |

> 注意方向：**木桌比桌垫大** ⇒「木桌四角入画」比「桌垫四角入画」**更严**。
> 所以这条改动是**在 3D 端收紧、在 2D 端维持**，不是"两端都放宽"。

### 为什么 3D 端这条是「历史回滚」

批次 10 **之前**，取景判据本来就是**木桌四角**（±5.2 / ±4.28，最紧 93.4px）；批次 10 为了把棋盘
放大，才**松成**"只认桌垫四角、木纹可以出画"（理由与代价见 `设计决策留痕.md` §十）。

现在要让房间在上缘出现，**木桌的远边必须进画** ⇒ 把这条**收回去**。这是**动批次 10 已拍板的
东西**，用户已在设计评审中明确点头。

### ⚠ 追加（2026-10-05 用户当场拍板）：**Ctrl + 滚轮 = 推拉**（第二条轴）

**缘起**：用户提出"桌面比例太大、看不见环境，能不能用鼠标缩放"。查证后确认这**正好解开**了上面
"32% 与格子下限互斥"的死结 —— 把二选一变成**由玩家现场掌控的取舍**。

**手势为什么不能是滚轮**：滚轮已经被「3D / 2D 视角连续推移」占满（`table_3d.gd:787`，
每格 `VIEW_STEP`），**而且那是切 3D/2D 的唯一入口**（没有按钮）⇒ 推拉必须另给手势。
**定案：按住 `Ctrl` + 滚轮 = 推拉相机**（只改"相机到桌心的距离"这一维）。

**这一手是把批次 4 删掉的 `dolly` 请回来**（`设计决策留痕.md` §四：批次 2 拍「滚轮 = 推拉」
→ 批次 4 改成视角推移、**`dolly` 整个删除**；`架构总览.md` §五 记着"推拉已取消"）。
**不是替掉滚轮，而是加成第二条轴** —— 原决定"两档比无级推拉更贴合『看全局 vs 操作』的分工"
仍然成立，推拉是**在档内补一个自由度**。

**默认取景 = 偏屋子那一档**（用户 2026-10-05 选「默认看屋子」）：

| 档 | 取景 | 格子屏幕宽 |
|---|---|---|
| **默认**（`view_t = 0`，推拉在默认档） | 按上表回滚后的取景：**木桌四角入画** + 上缘那条带子留给房间 | **硬底线 32px**（§九） |
| **Ctrl 滚轮拉远**（推拉最远端） | 房间进一步进画 —— **远墙 / 家具 / 吊灯在这一端才全见** | **不设下限** |
| **Ctrl 滚轮推近**（推拉最近端） | 格子最大、房间退场 —— **这一端才是"读棋盘"的档** | 不得低于默认档 |
| **2D 端**（`view_t = 1`） | **一字不改** | 53.2px（现状） |

**推拉只作用在 3D 端**：`view_t` 越大权重越小，`view_t = 1` 时**归零**
⇒ 2D 端那条"桌垫四角入画"的契约**完全不受影响**（这是本期唯一不允许被碰的契约）。

**⚠ 要说清的一件事（几何上确定的，别当缺陷查）**：默认档只把**木桌四角**拉进画，
上缘留出的地板带**很窄**。实测当前机位：上缘那条视线落在地板 **z ≈ −4.9**，而木桌远边在
**z ≈ −3.48**，可见地板带只有约 1.4 个单位深。⇒ **默认档看得见的是「桌子 + 一圈地板 +
上缘一条带子」；家具与远墙要再拉远一些才进画。**
Task 7 负责把**默认档 / 拉远端 / 推近端三处的实测数字**报出来，不许静默取值。

### 随之要重取的常量

`CAM_FOV` / `CAM_DIST` / 俯角 / `VIEW_DIST_2D` —— **按批次 10 的老办法沿 21 档重扫一遍余量表**，
不能只调一个（批次 10 的教训：四个常量是一起取的）。

**已知副作用**：格子屏幕宽会缩。**动工前**实测 **47.3px**（3D 端）/ **53.2px**（2D 端）。
设计上的估算是"约 35px" —— **实施后实测：默认档 32.3px（设计估算的 35px 是接近的）、
推近端 44.5px、拉远端 23.7px、2D 端 53.2px（一字未动）**，见下。

---

### ⚠ 实施后回填（2026-10-06 · 一期 Task 7/8/9 实测；**以本节为准**）

**相机只动了一个数**：`CAM_DIST` 5.77 → **8.90**。`CAM_FOV 39` / `CAM_TILT_DEG 50` /
`VIEW_DIST_2D 9.20` **一字未动** —— 动 `CAM_FOV` 会把 2D 端的余量打红（33 ⇒ −12.1px），
所以保 2D 端**逐字节不变**（那是本期唯一不许碰的契约）。

| 档 | 格子屏幕宽 | 说明 |
|---|---|---|
| **默认**（`dolly 1.00`） | **32.3px** | spec §九 的硬底线（32）；格内字约 6px ⇒ **默认档不再是"读棋盘"的档** |
| **`Ctrl` 推近端**（`DOLLY_MIN`） | **44.5px** | **"读棋盘"靠这一档**（以及 2D 端） |
| **`Ctrl` 拉远端**（`DOLLY_MAX` = 1.40） | **23.7px** | 看屋子那一端，**不设下限** |
| **2D 端**（`view_t = 1`） | **53.2px** | 本期一字未动 |

**"屋子看不见"那条老结论（Ruling N）被这一批推翻**：房间带 **10.5% → 默认档 22.9% /
拉远端 30.0%**，**远墙真的进画了**（`layout_test` 有断言钉住墙脚三点入画、且拉远端比默认档
多看一截屋子）。默认档仍是"桌子 + 一圈地板 + 上缘一条带子"，**但那条带子已经是有内容的
屋子**（地板 / 墙脚 / 站在地板上的家具）。

**随之改掉的房间常量**（Task 7，理由：默认机位 `z = 8.90` 正好**贴在近墙上** ⇒ `dolly > 1.01`
一拉就穿墙、整屏全黑，而所有推拉断言都照绿 —— 断言抓不到的那类错）：

- **`ROOM_NEAR_EXTRA := 5.0`**（新）—— 只把**近半侧**加长（`z ∈ [+9, +14]`），给拉远时的相机
  让出站位；**远半侧一个数都不动**（远墙 / 家具 / 椅子 / 默认档取景全部不变），
  而那一段**永远不在画面里** ⇒ 视觉上零代价。**不是"把房间偷偷放大"**：可见的屋子仍是 `22 × 18`。
  （对称放大 `ROOM_D` 实测更糟：远墙带从 18% 掉到 5%。）
- **`ROOM_CEIL_Y := 16.0`**（原 13.0）—— 同一件事的另一半：拉远端把相机顶高到 `y = 14.85`，
  天花板还留在 13 就会窜到屋顶上方，而天花板是双面的 ⇒ 又一张全黑摆拍。四面墙是纯色平面、
  天花板从不入画 ⇒ 这一项也是零视觉代价。
- **`FLOOR_Y := -3.70`** 与 **`FURNITURE_SCALE := 10.0`** —— 见 §六「地板高度与桌子底座」与
  `设计决策留痕.md` §十六（`FURNITURE_SCALE` 从计划里的 5.0 改档到 10.0，锚点是 spec §六 那张比例表）。

**"32% 上缘"这条**：没有落成断言。实测下界（硬线）是"格宽 ≥ 32px"，32% 只是报出值 ——
两者在数学上互斥（Ruling N），实施时复核过：默认档房间带 **22.9%**、拉远端 **30.0%**，
**没有为了凑 32% 去动相机**（那会把格宽推到底线之下）。取舍与逐档读数见
`设计决策留痕.md` §十六。

## 五、光照契约（用户选 B 档）

### 现状

**全场只有一盏 `Light3D`**（那盏吊灯），`layout_test` 有一条断言钉着"全场只有一处 `Light3D`"；
`WorldEnvironment` 背景近黑；桌面亮度**刻意均匀**（批次 13 ⑦⑧：左右落差 5.1:1 → 1.27:1）。

### 改成

**环境光（抬高）+ 一盏不投影的弱补光** —— 补光只影响房间，不参与阴影管线。

| 断言 | 改动 |
|---|---|
| 「全场只有一处 `Light3D`」 | 改成「**全场只有一处投影源**」 |
| — | **新增**：「房间物件一律不投影」 |
| 「桌面照度均匀」 | **保留**（补光主要落在桌外） |
| — | **新增**：「补光对桌面的照度贡献 ≤ 阈值」—— 防止以后调补光时悄悄改掉桌面 |

### 为什么不选另外两档（留档）

- **只抬环境光**：断言不用改、最省，但房间会发平（没有明暗、没有方向），像"被均匀打亮的布景"。
- **让吊灯兼照房间**：最像参照图，但**会直接反转批次 13 ⑧「桌面亮度均匀」**——那是用户签过字的
  （当时把左右落差从 5.1:1 压到 1.27:1），且会让桌面外缘变暗、格子远排/近排的字更难读，
  还要放大留痕里那条「射程一大、阴影贴图密度稀 ~2.4×」的代价。

### 尺子只能用一把

批次 13 ⑦⑧ 吃过一次教训：**两把尺子打架、旧记录作废**（"照度代理式"可从代码重算；
"屏幕取像素"随相机 / 几何世代变）。⇒ 本期的照度验收**沿用 `layout_test` 里那把照度代理式**，
**不要再引"屏幕取像素"**。

## 六、构图（用户选 B 档）

上缘那 32% 的带子（正对相机的墙 + 两侧）放：

- **远墙偏左**：**书桌 + 书架 + 收纳箱** —— **偏左不是随便摆的**：吊灯的光在 `x ≈ −4.13`（§三），
  只有把书桌放在**左半侧**，它才落在光域里、被"舔"出桌面与书架的边缘。摆在远墙正中反而会落在光域之外，
  变成一块暗的剪影（那就退化成了批次 13 ⑨ 删掉的那种剪影的效果）。
- 选它的理由：水平线条多、体量矮，**与"桌子"是同族木质家具**，画面最干净
- **代价（承认）**：宿舍辨识度不如"双层铁架床 + 蚊帐"那一档（更像自习室 / 书房）

### 三档共同（不随选项变）

- **天花板 / 地板 / 四面墙**（吊灯要有地方吊、房间要有边界）
- **四把椅子围桌**，椅背挂名牌，**名牌用各家的棋子色**（与 `GameData.PLAYER_COLORS` 同源）
- **吊灯**：~~一根线从天花板垂到 y = 10 的灯泡，位置固定在 `x ≈ −4.13`~~

### 地板高度与桌子底座（2026-10-05 用户拍板 · 追加）

**问题**：计划把地板放在 `y = 0`，也就是**桌面那一层**（Task 3 改成 −0.02 只是为了不被木纹外框盖住）。
于是桌子读作"**平铺在地板上的一块板**"，而**椅子 / 家具没法"站对"**：椅子按人体比例
（`FURNITURE_SCALE = 5`）站着时，椅面在桌面上方 2.25 单位；要"站对"就得让椅面低于桌面，
也就是椅子沉到地板以下 —— 而地板就在桌面那一层，**装不下任何东西**。

**定案**：**地板落到真实桌高 `FLOOR_Y := -3.70`，桌子补一块底座（裙板）。**
`3.70 / 5 = 0.74 m` —— 正是真实桌高。于是整间屋子的比例**一次全对上**：

- **椅子**（5×）：椅面 `-3.70 + 2.25 = -1.45`（**低于桌面** ✓）、椅背顶 `-3.70 + 4.5 = +0.8`
  （**高过桌面 0.8** ✓ —— 正是 §六 要的"椅背挂名牌"）
- **书桌**（5×）：`3.75` 高，顶面落在 `+0.05`（与桌面齐平 ✓）
- **吊灯**（`y = 10`）：离地 `13.7 / 5 = 2.74 m` ✓ 一盏正常的吊灯
- **房间**：`22 × 18 × 19.7` ⇒ **`4.4 × 3.6 × 3.94 m`** ✓ 一间正常的宿舍
  （**2026-10-06 改正**：原写 `16.7` ⇒ `3.34 m` —— 那是 `ROOM_CEIL_Y = 13` 时的数；一期 Task 7 把它抬到
  **16.0**（§四 那节，本 spec 此前**自相矛盾**：§四 写 16.0、这里写 16.7）⇒ 层高 `16.0 − (−3.70) = 19.7`。
  这一项**不影响**下面"1 世界单位 = 0.2 m"的推导（那条靠 8 宽桌 / 3.70 桌高就够）。）

> ⚠ **实施后更正（2026-10-06，Ruling T）：上面括号里写的是 5×，落地的是 `FURNITURE_SCALE = 10`。**
> 这张表的**关系**（椅背高过桌面、书桌顶面与桌面齐平）一条不变，**数值随缩放翻倍**（实测合并
> AABB × 10）：**椅子**（`chair.glb` `2.0 × 4.7 × 2.0`）⇒ 椅背顶 `FLOOR_Y + 4.70 = **+1.00**`
>（spec 写的是 +0.8，**同一档**）；**书桌**（`desk.glb` `3.84` 高）⇒ 顶面 `FLOOR_Y + 3.84 = **+0.14**`
>（与桌面齐平 ✓）。吊灯离地 `13.7 / 5 = 2.74 m` 与房间 `22 × 18` ⇒ `4.4 × 3.6 m` **两条与缩放无关**，
> 原样成立。**为什么不是 5**：Kenney 这批 `.glb` 是**半比例**的（书桌 "0.384" 高按米读只有
> 0.38 m）—— Task 4 报的"椅子宽 0.479"是**漏量嵌套子节点位移**的假值，真值 `0.335 × 0.608 × 0.314`；
> × 5 会让**椅背顶落在桌面之下 0.66**、§六 那条"椅背挂名牌"根本摆不出来。推导见
> `scripts/room.gd` 的 `FURNITURE_SCALE` 注释与 `设计决策留痕.md` §十六。

**顺带收益（实测，别夸大）**：地板降下去后上缘视线能打到 `z ≈ −12`，**远墙进画** ——
但只占顶上约 **6%** 一条带子（地板带扩到约 10%），**又细又淡，不足以替代 Ctrl+滚轮推拉**
（那一轴仍是"看屋子"的主力）。⇒ 降地板的主要理由是**桌椅能不能站对**，不是"看得见屋子"。

**代价（承认）**：① 桌子多一块底座（新几何，约 10 行）；② 3D 端会开始看得见桌子**前方的立面**
（此前桌子是悬在纯黑里的）；③ 四面墙高度从 13 变成 **19.7**（本决策落地时是 16.7；一期 Task 7 又把
`ROOM_CEIL_Y` 从 13 抬到 16.0 ⇒ 19.7，见上）。

**备选（留档）**：不降地板、家具一律缩到约 ×2 当"小摆件" —— 最省、零新几何，
但"屋子"退化成"地板上的沙盘"，与《骗子酒馆》的坐定感差得远。

### ⚠ 本项目的第一次：`.import` 破例

`.gitignore` 的现有约定（原文）：

> 本项目全部资产都用默认导入设置（已核对 25 个 `.import` 的键完全一致）… 故不入库。
> **一旦有人改过某个资产的导入设置，该设置就只存在于本机，不会随仓库共享 —— 那时应把 `*.import` 改回入库。**

**Kenney 的 3D 模型很可能需要非默认导入设置**（网格压缩、材质 / 贴图处理）。
若确实需要 ⇒ **把这一批模型的 `.import` 入库**（**只这一批**，其余仍按原约定忽略），
并在 `.gitignore` 里补一行说明为什么破例。

**验证方式**：新克隆一次仓库，确认模型与原样一致。

### 性能

**先给个好数**：批次 11 实测 —— 满盘 **56 个房子节点**与空盘的帧时间**在噪声内相同**
（avg 2.40 vs 2.23ms）。⇒ **静态网格在本项目里很便宜**，房间网格数**不是**风险。

真正的风险在两处：

1. **阴影** —— 吊灯是唯一投影源。**房间物件一律不投影**（沿用旧房间剪影那条"不投影"约定）
   ⇒ 阴影预算不变。这条写进断言（§五）。
2. **第二盏灯** —— 本节选的 B 档是**一盏不投影的弱补光**，不进阴影管线 ⇒ 代价可控。

**验收用现成的探针**：`--fps=秒数`（**必须 `--` 分隔符、必须不带 `--headless`**，这两条都踩过坑），
跑**空盘 + 满盘**两组，与批次 11 基线（avg ≈ 2.2~2.4ms）对比。
