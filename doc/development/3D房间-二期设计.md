> **状态**：**草案（2026-10-06 控制者起草，等用户过目）** —— 下面的设计**大部分是提案**，

## 一、背景与目标

一期把屋子立了起来（`ROOM_ENABLED` 总开关、地板/墙/天花板、家具、四把椅子、名牌、
吊灯的可见几何、`Ctrl` + 滚轮推拉）。**但椅子上没有人。**

用户从一开始就明确两件事：**要有坐着的人物**、**要对手势 / 反应**。这两条都是一期明确不做的
（一期 §二"明确不做"：人物模型 / 骨骼 / 动画），留给二期。

**二期的目标**：让四把椅子坐上报社里那四个人，并且**对玩法事件有反应** ——
出牌、付钱、被抢地、破产各自动一下。参照《骗子酒馆》的临场感：对手不是数字，是坐在对面的人。

---

## 二、范围

### 做

- 人物模型（Quaternius 动画人形）**坐在椅子上**（复用一期的 `GameRoom.seat_anchor(slot)`）
- **骨骼动画**：待机 + 四个玩法事件反应
- 随取景淡出（沿用"看不见就不显示"的既有约定）
- 性能实测与验收

### 明确不做（防止范围蔓延）

- **面部表情 / 口型同步 / IK**（成本极高、收益极低）
- **碰撞 / 物理**（人物是纯表现）
- **自定义建模**（一期 §七 已定：`D:\blender` 留给"必要时"；二期的默认路线是**用现成带动画的模型**）
- **与玩法数值 / 状态机 / `@rpc` 的任何耦合**（沿用一期同一条纪律）
- **一期已经做完的东西**（房间 / 家具 / 椅子 / 名牌 / 取景 / 光照）—— 二期只往里加人

可以据此改登记为 CC0 —— 那是**放松**，安全方向。

### ⚠⚠ 真正的硬风险：**格式**

**Quaternius 的包只有 FBX / OBJ / Blend，没有 glTF/GLB。** 而：

- **Godot 4 不能原生导入 FBX**（这是 Godot 4 就砍掉的能力）。
- `.blend` 可以走 Godot 的 Blender 集成，但**本项目从未配过**：
  实测 `project.godot` **没有 `[filesystem]` / `blender_path`**，而 `D:\blender` 是 **Blender 5.2**
  —— Godot 4.6 的 Blender 导入器**有它支持的版本区间**，5.2 是否在区间内**未验证**。
- OBJ **不带骨骼、不带动画**（只有网格）⇒ 对二期没用。

⇒ **可走的三条路**（Task 0 逐条试、按顺序取第一条走通的）：

1. **配 `blender_path` 直读 `.blend`** —— 最省（一步导入，Godot 自动转换）。
   风险：Blender 5.2 的兼容性。
2. **FBX → Blender → 导出 glTF/GLB → Godot** —— 多一步，但 glTF 是 Godot 的亲儿子，
   且**批量转换可以写成 Blender 脚本**（`D:\blender\blender.exe --background --python conv.py`）。
   风险：Blender 5.x 的 FBX 导入器行为、骨骼/动画导出是否完整。
3. **换素材** —— 找**带 glTF/GLB 的**动画人形（例如 Kenney 系的「Blocky Characters」系列，
   格式为 GLB）。**代价**：Kenney 的方块人风格与一期家具同源（一致性反而更好），
   但**动画数量少、动作幅度小**，且要重新核许可（Kenney 系是 CC0，无争议）。

**这一条必须在 Task 0 里定死**，因为**它决定后面所有任务**：能走 1/2 ⇒ 用 Quaternius；
只能走 3 ⇒ 换素材、`LICENSE` 登记跟着换、且"4 个不同的人"可能要改成"1 个模型换 4 种颜色"。

### 还有一个**必须先看动画清单**的问题

包页只说「many animations」，**没列清单**。而这些包常见的是**站立/行走/奔跑**一类，
**未必有"坐着"这一档**。⇒ 若没有坐姿动画，只有两条路：

- **手动摆姿势**：在 Godot 里把 `Skeleton3D` 的髋/膝/脊柱骨骼转到坐姿（一次性、可代码固化），
  再叠待机摆动。**成本可控，但是"摆姿势"不是"播动画"**（需要 Task 0 确认骨骼命名）。
- **接受站着** —— **不可接受**（四个人围着桌子站着，比没有还糟）。

⇒ **Task 0 必须把动画清单逐条列出来**（名字 + 时长 + 是否循环），并判断坐姿从哪来。

## 五、设计提案

### 5.1 谁出场：**slot 0 不出人**（**待点头**）

一期的 `GameRoom.seat_anchor(slot)` 里 **slot 0 = 近侧 = "我"**，而**相机就在"我"这个位置**。
⇒ **"我"不渲染人物**（第一人称），只保留一期的椅背 + 名牌。
理由：① 相机在"我"头上，渲染出来要么挡视线要么穿模；② 一期 §六 已经定了"我这一侧只有椅背"。

⇒ 实际渲染 **3 个人**（slot 1/2/3）。**待点头**：也可以给"我"渲染一双搭在桌上的手
（成本另算，且会挤占桌面）。

### 5.2 坐在哪：复用 `seat_anchor(slot)`（**已定**，一期留的接口）

一期 §十 写死了这个接口的用途：「**二期把人放上去只改这一处**」。
⇒ 二期**只读** `seat_anchor(slot)` 拿 `Transform3D`，把角色放在椅面上、朝向对齐椅子。
**不许**在二期里另算一套座位坐标 —— 那正是"人坐错位"最难查的那类错。

### 5.3 随取景淡出（**待点头**）

一期的取景结论：**默认档看得见桌子与一圈地板，椅子大多在画外**；推拉拉远才看得见屋子。
⇒ 人若永远渲染，**"读棋盘"那一档就是在白算 3 个骨骼动画**。

**提案**：沿用项目既有的「看不见就淡出」约定（手牌随 `view_t` 淡出就是这一条），
**按"角色是否落在视口内 + 当前推拉档"淡入淡出**。
- **推近端 / 2D 端**（读棋盘）⇒ 淡出（且**停掉动画**，省算力）
- **拉远端**（看屋子）⇒ 淡入

⇒ 好处：**二期不会把一期的"读棋盘"档拖慢**。**待点头**：也可以在 2D 端让角色的**头**
露出来（俯视看得到头顶），看你要不要那点"四个人在"的感觉。

### 5.4 动画集合（**待点头**，且**部分依赖 Task 0 的清单**）

| 动画 | 触发 | 备注 |
|---|---|---|
| **待机** | 常驻 | 呼吸 / 小幅摇摆，**必须循环且幅度小**（大了像晕船） |
| **当前行动者** | 回合切换 | 提案：行动者用**另一个待机**（略前倾 / 幅度大一点）当"轮到我了"的暗示 —— 比发光圈更"人" |
| **出牌** | 出道具 / 掷轮 | 抬手 / 向前 |
| **付钱** | 资金减少 | 略低头 / 手向下（与既有**飞钞**演出同拍） |
| **被抢地** | 名下地产易主 | 后仰 / 拍桌 |
| **破产** | 出局 | 最大的一个动作（趴下 / 抱头）—— **一期 §二 说好要"各自动一下"，这个是重头** |

**⚠ 上表的"动作"全是意图，不是动画名** —— **具体用包里哪一条动画，由 Task 0 的清单决定**。
**这一条不能瞎填**（写了不存在的动画名，计划本身就废了）。

**待点头**：① 幅度（"动一下"到什么程度）；② 是否四家一起动（比如有人付钱、全场都看一眼）；
③ 破产的人是否**留在座位上趴着**（而不是消失）。

### 5.5 事件从哪来：**只读表现层，不碰玩法**（**已定**，一期同一条纪律）

一期 §二 / `AGENTS.md` §四：**玩法逻辑只在房主算，客户端只渲染**。
⇒ 二期**绝不**新增 `@rpc`、**绝不**改状态机。

**提案**：从**已有的表现层事件**挂钩 —— 项目里已经有这些可读的信号 / 状态：
- **资金变动**：`_money_flies`（批次 13 ⑥ 的飞钞队列，正是"钱变了"的那一帧）
- **地产易主**：房子等级表 `_cache_house_levels()` / `_refresh_houses()` 那一套
- **出牌**：手牌实体（`table_props` 的 `set_hand_selected` / 出牌那条路）
- **破产**：`s_state` 里的出局标记（**读**，不写）
- **轮到谁**：`st.turn_i` / 行动者光环（`set_ring`）

⇒ **若某个事件在表现层读不到**：**加一个只读信号**（`signal char_event(kind: String, peer: int)`），
**发信号的地方仍是表现层**。**绝不去改玩法**。

### 5.7 名牌朝向 —— 一期终审带出的观察（**已定案：不改名牌，靠角色本身认人**）

**观察（一期终审发现，留档在此）**：一期的四块名牌**都挂在椅背朝外那一面**
（一期 §六 的原话："读它的人站在椅子背后"）⇒ **从相机看过去，只有 slot 0（近侧＝"我"）那块的字
是正面朝向观众的**；slot 2 看到的是牌背，slot 1/3 是侧视 —— 而侧视正是**一期 Task 9 ①
修掉的那两道"游离亮线"**（当时把牌**嵌进椅背** `NAMEPLATE_SINK 0.06`、压暗，代价就是侧向那块更看不见了）。
**⇒ 今天"哪把椅子是谁"是靠棋子色读的，不是靠名字。**

**定案（控制者 2026-10-06，玩家体验角度）：不改名牌。** 理由：
1. **名字本来就不该由名牌承担** —— HUD 的**名册条**已经写着每个人的名次 + 棋子色 + 昵称；
   名牌在画面里的职责是**氛围**（"这椅子有人"），不是信息。
2. **二期放上角色之后，"谁坐哪"由角色本身回答** —— 四家各有模型 / 配色 / 动作，
   比一块更清楚。⇒ **二期不做"把名牌转过来"这种事**（转过来就等于把牌子对着坐的人、而不是对着观众，
   反而丢了"椅子属于谁"的读法）。
3. **代价（承认）**：在二期落地之前，侧向那两把椅子的所属**只能靠棋子色**读。
   这是**已接受的取舍**（换掉了两道游离亮线）。
**⇒ 二期开工时不需要动名牌**，只需保证 `NAMEPLATE_ANCHORS` 仍被 `seat_anchor(slot)` 一致地暴露
（一期 §十 的接口）。

`CHARS_ENABLED := false` ⇒ 一个角色都不建，画面**逐字节回到一期的样子**。
与 `ROOM_ENABLED` 同一条纪律：**二期不许把游戏搞坏**。

## 六、性能

一期实测过：**静态网格在本项目里很便宜**（满盘 56 个房子节点与空盘帧时间在噪声内）。
**但骨骼蒙皮 + 逐帧动画是另一回事** —— 本项目**从未测过**。

⇒ 验收必须用现成探针 `--fps=秒数`（**必须 `--` 分隔符、必须不带 `--headless`**），
与一期基线对比，并且**分别测"拉远端（角色在播）+ 推近端（角色已淡出/停播）"两组**。

**已经设计好的省法**（§5.3）：读棋盘那一档角色淡出 + **停掉动画** ⇒ **二期不拖慢主玩法档**。

## 七、验收判据

- **`CHARS_ENABLED = false`** ⇒ 画面与一期**逐字节一致**（回退开关真的能回退）
- **人坐在椅子上、不穿模**：每个角色的世界 AABB 落在**该椅子的座面上方**，
  且**不与桌子/椅子/彼此相交**（一期 Task 4/5 已有同型的"不相交 + 落在房间里"断言，照抄形状）
- **"我"不渲染人物**（slot 0 无角色节点）—— 断言在
- **动画真的在动**：抽样两帧，骨骼姿态**不相同**（否则"播了但没动"看不出来）
- **角色 ↔ peer 对得上**：复用一期 Task 5 那条"座位顺序 == `game._seat_peers()`"的断言
  （**二期最怕的还是"人坐错位"**）
- **淡出真的停了动画**：推近端 `AnimationPlayer.is_playing() == false`
- **性能**：两组 `--fps=` 与一期基线对比

| 3 | **2D 端角色淡出（不露头顶）** | 2D 端是**"读棋盘"那一档**（53.2px 格子）。三个头顶在画面角落晃动是**纯噪声**，且会让人误以为那是可点目标。⇒ 淡出，把这一档留给棋盘 |
| 4 | **破产的人趴着留在座位上，不消失** | 桌游的体感是"**人还在桌上**"。消失等于"这家没了"（像被踢出局），趴着则是**"他输光了、趴在桌上"** —— 更有人味，也给了破产那一刻一个可见的落点。**且与"不许中途加入/观战"的规则不冲突**（纯表现） |
| 5 | **动作幅度：含蓄**（专业牌友，不是合家欢） | 本作的视觉调性一直是**克制的**（暗色底 + 金色点缀、动画全是一次性过渡、桌面反复"减负"）。**夸张动作会与整体调性打架**，也会在**四家同时动**时把棋盘变成马戏团。⇒ 幅度小、频率低、只有破产那一下放大 |
