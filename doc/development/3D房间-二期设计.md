## 一、背景与目标

一期把屋子立了起来（`ROOM_ENABLED` 总开关、地板/墙/天花板、家具、四把椅子、椅背名牌
吊灯的可见几何、`Ctrl` + 滚轮推拉）。**但椅子上没有人。**

用户从一开始就明确两件事：**要有坐着的人物**、**要对手势 / 反应**。这两条都是一期明确不做的
（一期 §二"明确不做"：人物模型 / 骨骼 / 动画），留给二期。

**二期的目标**：让四把椅子坐上报社里那四个人，并且**对玩法事件有反应** ——
出牌、付钱、被抢地、破产各自动一下。参照《骗子酒馆》的临场感：对手不是数字，是坐在对面的人。

## 四、素材定案：Kenney「Blocky Characters 2.0」（GLB / CC0）

> Godot 4.6 **原生导入、零 ERROR/WARNING**，`project.godot` 不必动。
> ⇒ 三选一的导入通路**问题不存在**；原推演里那句"换 Kenney 的代价 = 只有 1 个模型换 4 色"
> **也是错的 —— 包里有 18 个模型**。**以下是最终采用的素材。**

**素材 = Kenney「Blocky Characters 2.0」（CC0，包内自带 GLB）**，落在 `assets/models/chars/`：

- **18 个模型**里挑 **4 个**（按玩家棋子色索引、确定性选取，见 §5.2）；**27 条动画**逐条量过
  名字 / 时长 / 轨道数 / 首尾闭合（普查 §五），**`loop_mode` 导入后全是 `LOOP_NONE`**（要循环得自己设）

- 材质是 `KHR_materials_unlit` ⇒ 导入即 `SHADING_MODE_UNSHADED`、**不响应一期光照**（见 §5.2 末）

⇒ 逐条实测见 `doc/development/chars-导入与动画普查.md`；素材登记见根 `LICENSE`

## 五、设计提案

### 5.1 谁出场：**slot 0 不出人**（**已定**）

一期的 `GameRoom.seat_anchor(slot)` 里 **slot 0 = 近侧 = "我"**，而**相机就在"我"这个位置**。
⇒ **"我"不渲染人物**（第一人称），只保留一期的椅背。
（v0.8.0 改版：椅背名牌已删、认人改走头顶名牌，见 §5.7 —— 「我」这一侧**没有头顶名牌**，
因为相机就在那儿。）
理由：① 相机在"我"头上，渲染出来要么挡视线要么穿模；② 一期 §六 已经定了"我这一侧只有椅背"。

⇒ 实际渲染 **3 个人**（slot 1/2/3）。**已定：不给"我"渲染搭在桌上的手** —— 手要占桌面，
而那正是玩家读棋盘的地方（§九 ②）；`tests/chars_test.gd` 有一条"slot 0 无角色"钉着它。

### 5.2 坐在哪：复用 `seat_anchor(slot)`（**已定**，一期留的接口）

一期 §十 写死了这个接口的用途：「**二期把人放上去只改这一处**」。
⇒ 二期**只读** `seat_anchor(slot)` 拿 `Transform3D`，把角色放在椅面上、朝向对齐椅子。
**不许**在二期里另算一套座位坐标 —— 那正是"人坐错位"最难查的那类错。
`tests/hud_test.gd` 钉着"角色顺序 == `game._seat_peers()`"（二期最怕的还是坐错位）。

**落地值（`scripts/chars.gd`，全部是实测反推、不是拍的）**：
- **`CHARS_SCALE := 2.8125`**（= 座面 2.25 ÷ 髋枢轴 0.800）—— **不是 `FURNITURE_SCALE` 的 10.0**：
  这个包与一期家具**不是同一个比例族**，×10 的人有 5.4 m 高（比整间屋子还高）。
- **坐姿是手摆的，不是播包里的 `sit`**：`sit` 把腿**平举**（腿是一整块刚体、没有膝关节），
  按一期椅子比例会**捅进桌子 1.66 世界**。改手摆 = `SEAT_ROOT_Y := -0.2`（整体下移）
  + `LEG_SQUASH`（`leg-*.scale.y` 压短）⇒ 实测脚底与 `FLOOR_Y` 差 **0.0000**、髋枢轴与座面差 **0.0000**。
- **那条下移必须挂在角色之上的"外套节点"上**，不能挂在 GLB 的 `root` 上 —— `idle` 带一条
  `root` 的常值轨道，**一播就把 `position.y` 写回 0**、坐姿被顶掉（普查 §5.3 实测）。
- **逐座位选模型**：按该玩家的**棋子色**索引确定性选取（4 色 → 4 个模型，18 个里挑 4 个）——
  同一 peer 两次进来必须是同一张脸（`hud_test` + "同 peer 同脸"两条钉着）。
  **4 色映射到 4 个模型，不共用**：两个对手共用一张脸会破坏「四家各有模型」这条。
  （v0.8.0 改版后认人靠头顶名牌，但**这条仍然保留** —— 模型是角色自己的脸，两家撞脸
  与「牌上写着不同的名字、脸上却是同一个人」自相矛盾。）
- **色调**：`CHAR_TINT := Color(0.29, 0.25, 0.21)` 乘在模型自己的 `albedo_color` 上
  （Godot 里 `albedo_color` 乘 `albedo_texture` ⇒ **贴图没动**、只压暗压灰）。定标在**最亮的那个座位**：
  吊灯在 `x = -4.13`、左座照度是右座的 **1.385 倍**，规则要在最不利处成立。
  **判据 = 角色不许是画面里最亮的东西**（不许比木框 / 桌面亮）。
- **材质**：包内是 `KHR_materials_unlit` ⇒ 导入即 `SHADING_MODE_UNSHADED`、不响应一期光照；
  而**不能照抄 `room.gd` 的材质覆盖**（那会**抹掉角色的贴图**）⇒ 二期另写了一个
  **只调光照参数、不碰贴图**的辅助函数，并有断言钉住"角色材质不是 `UNSHADED`"。

### 5.3 取景与人物可见性 —— **淡出已整段取消**（v0.8.0 第三次改版，2026-10-06）

> ⚠ **本节原定的"随取景淡出并停播"整段删除**。用户 2026-10-06 第三条原话：
> **「2D 视角下人物不要消失」**。下面第一段留档（说明当初为什么这么定），第二段是现在的事实。

**当初的定案与理由（已推翻，留档）**：沿用项目既有的「看不见就淡出」约定（手牌随 `view_t`
淡出就是这一条），按"当前推拉档 / `view_t`"淡入淡出并**停播** —— 因为"读棋盘那一档"是**主玩法档**，
二期不许把它拖慢（§六）。淡出契约曾是：
`t = max(view_t, (1 − dolly)/(1 − FADE_NEAR_DOLLY))`，`t ≥ 0.75` ⇒ 全隐 + `is_playing() == false`。
定案里还有一条明确判断：**"2D 端也淡出，不露头顶"**（§九 ③）—— 当时的理由是"三个头顶在画面角落
晃动是纯噪声，且会让人误以为那是可点目标"。

**现在的事实（v0.8.0）**：

1. **淡出整段取消**：`set_fade` / `FADE_SOLID_T` / `FADE_GONE_T` / `FADE_NEAR_DOLLY` /
   `_apply_fade` / `_framing_t` / `_framing_host` / `_process` **全删**。四档取景
   （默认档 / 拉远端 / 推近端 / 2D 端）下人物**恒可见**。
2. **为什么连 3D 端那两档一起取消**（不只是 2D）：淡出是**为性能付的账**，而这笔账已经不用付了
   —— v0.8.0 第二次改版把待机动画整段退场（人物完全静止），二期实测 `CHARS_ENABLED` 开/关
   在同一会话里 p50 只差 **0.02 ms** ⇒ 只剩三个静止角色的**绘制调用**，省不出东西。
   留一条"推近就消失"只会让人以为出 bug。
3. **原定案里"不露头顶是噪声"那条判断也被推翻了**：头顶名牌在第二次改版里已经**删掉**
   （认人改走桌面立牌，见 ①），所以"头顶在角落晃"这个前提不存在了；
   而"让人误以为可点目标"也不成立 —— 人物现在就是可点目标的邻居（桌面立牌才是）。

**⚠ 遗留（如实记，待控制者裁决）**：取消淡出**不等于自动看得见**。2D 端相机本来就贴着棋盘
（`VIEW_DIST_2D 9.20`、格宽 53.2px），而座位在桌子之外 ⇒ 实测 2D 端只能看到**左右两家的一小截**
（画面边缘的竖条），**对面那家仍在画框之外**。要三家都进画，`VIEW_DIST_2D` 得退到 ≈16.5，
格宽会从 53.2px 掉到 ≈29.7px —— 那会翻掉一期定的"**2D 端那条契约是本项目唯一不许碰的**"。
⇒ 两条路摆在控制者面前：**接受现状**（不再强制隐藏，看得见多少算多少）或**重取 2D 端相机契约**。

### 5.4 动画集合（**已实装**；**动画名全部是普查实测存在的**，不是意图）

| 动画 | 用什么 | 触发（从**已同步的状态**读边沿） |
|---|---|---|
| **待机** | ~~`idle`~~ | **v0.8.0 改版已退场**：一帧动画都不播（用户：「玩家人物不要乱动」）。模型停在自己导入时的静止姿 + 手摆坐姿 |
| **当前行动者** | **头顶名牌上一圈金边** | `st.turn` 换人。v0.8.0 改版起（原先的 `idle` 提速已退场）—— 静止的金边比「谁动得快」一眼可见 |
| **出牌** | `interact-right` | `st.players[i].item_used` 假→真（**不用"手牌少一张"**：多数道具用完不进背包，那样会漏掉绝大多数出牌、还把丢弃算进去） |
| **付钱** | `holding-left` | 钱循环里的 `diff < 0`（**与既有飞钞同一拍**） |
| **被抢地** | `emote-no` | `st.tiles[i].owner` 由**还活着的**上一手主人变成别人 |
| **破产** | `die` + **手摆座位收势** | `alive` 真→假。**见下** |

**幅度 = 含蓄**（§九 ⑤，用户定的调性）：**不放大 `speed_scale`**、不加额外演出；只有破产那一下
是重头。**四家不连动**（谁付钱谁动）。

**⚠ 破产那一条推翻了早期设计里的一句依据（Task 4 实测更正）**：原先写的是"`die` 的末帧
正是躺下 / 趴着，**恰好对上**『破产的人留在座位上趴着』"—— **对坐着的人不成立**：
`die` 的末帧是把整个人**绕脚底转 −90°**，坐着的人会**落到地板以下 0.42**、
**躯干躺到 `z ∈ [−12.5, −5.2]`（远墙在 −9）** ⇒ 出图就是"**人不见了**"，
正是 §九 ④ 明确否掉的那种"消失"。
⇒ **处置**：**摘掉那一条轨**（同 `_loop_idle` 的手法），**保留 `die` 自己其余内容**（举双手），
**再手摆座位收势**（前折 5° + 侧倒 45° + 低头 12°，顶在"不与桌子实体体积相交"的几何上限）。
**结果：人留在自己那把座位上、歪倒在椅子上、举着双手、头看得见** —— 与"椅子空了"对比强烈。
**⚠ 措辞更正**：早期写的"**趴在**座位上"是**在知道几何之前**的措辞，那条决定的**本意是
"留在座位上、而不是消失"**（§九 ④），本意已满足，**但姿势是"歪倒"不是"趴"**；
桌面是从地板到桌面的一整块实体体积，"趴上去"会把人埋进去、从相机看又是"不见了" ⇒ 几何上做不到。
**破产被记住**（`_dead_peers`）：不记住的话**一次重建**就把他**复活**了（`_apply_poses` 按它刷姿态）。
另：`play()` 之后直接 `pause()` 停在的是第 0 帧，**必须先 `seek(时长)`** 才停得住末帧。

### 5.5 事件从哪来：**只读表现层，不碰玩法**（**已定**，一期同一条纪律）

一期 §二 / `AGENTS.md` §四：**玩法逻辑只在房主算，客户端只渲染**。
⇒ 二期**绝不**新增 `@rpc`、**绝不**改状态机。

**落地（Task 4）**：四个事件**全部从已同步的 `st` 读**（房主侧 `game.gd` 的
`_react_chars()` / 钱循环里的差分）⇒ **没有加只读信号** —— 能从已同步的状态读出来，
直接调用就比走信号少一层。`game.gd` 的三处接线（`set_chars` / `set_actor` / `react`）
**全部是只读表现层调用**：**状态机 / 结算 / `s_state` / 每一个 `@rpc` 都没碰**。
**端到端实测**（10 轮真对局，临时探针已删）：`pay` 44 次、`play` 6 次横跨三家机器人；
**`rob` / `die` 在自动对局里不自然出现** ⇒ 只有单测覆盖（如实记档）。

### 5.7 名牌 —— **v0.8.0 判图后改版：椅背名牌删除，改挂头顶名牌；人物完全静止**

> ⚠ **本节原定的「不改名牌、靠角色本身认人」已被推翻**（用户 2026-10-06 判图后拍板）。
> 下面第一段是**当时的推理**（留档，说明为什么曾经这么定），第二段是**现在的事实与理由**。
> 改版的完整记录见 `game-design/设计决策留痕.md` §十五。

**当时的观察与定案（已被推翻，留档）**：一期的四块名牌都挂在椅背**朝外**那一面 ⇒ 从相机看过去
只有 slot 0（近侧＝「我」）那块是正面朝向观众，slot 2 看到牌背、slot 1/3 是侧视。
当时的结论是「名字不该由名牌承担（HUD 名册条已经写着），二期放上角色之后谁坐哪由角色本身回答」。

**现在的事实（v0.8.0，2026-10-06）**：用户判图时两句原话 ——
**①「玩家人物不要乱动，然后加个标识，不然我不知道他是谁」**、
**②「地板、椅子、墙面、家具颜色太接近了，缺少真实感」**。⇒ 三条定案：

1. **完全静止**：`idle` 待机整段退场，**一帧动画都不播**；连带「当前行动者 = 同一条 `idle`
   提速 1.4×」一起退场。**四个玩法事件反应保留**（一次性、由事件触发，不是「乱动」）。
2. **头顶名牌**（`Chars/Tags/Tag{i}`）：**棋子色牌 + 昵称**、整块 `billboard` 朝向镜头、
   立在**头顶之上**（位置按模型**世界 AABB 顶**实测算，不写死高度）。
   **当前行动者 = 牌上一圈金边**（静止的，不闪）—— 替掉原来的提速线索。
3. **椅背名牌整段删除**（`NAMEPLATE_SIZE` / `NAMEPLATE_FONT_PS` / `NAMEPLATE_SINK` /
   `NAMEPLATE_ANCHORS` / `_make_nameplate()` / `_refresh_nameplates()` 全删）。
   **为什么删得掉**：它的职责整体搬到了头顶名牌，两块牌子同时存在只会互相干扰；
   而它**本来就看不见**（挂在椅背朝外那一面）——「认不出谁是谁」有一半原因就在这儿。

**「靠角色本身认人」为什么读不出来（可量化的原因）**：`CHAR_TINT` 为了「角色不许是画面里最亮的
东西」把整张贴图压到 `0.29/0.25/0.21`（见 §5 那张表），加上屋里只有一盏吊灯 ⇒ 蓝 / 红 / 绿三个人
在**背对镜头**的那两把椅子上都是一团暗褐色，只能靠正面那张脸认 —— 而正面只有对面那一家露得出来。
⇒ 四个模型互不撞车这件事仍然成立（`CHAR_MODELS_BY_COLOR` 一字未改），但「看得见」是另一回事。

**顺带查出来的一个真缺陷（`stop()` 不复位姿态）**：改版把 `_react_finished` 从 `play(idle)` 改成
`stop()` 之后，`chars_test` 当场红了 —— 实测 `AnimationPlayer.stop()` **不会把姿态复位**，
分件停在**末帧**（slot1 的世界 AABB 深 6.89，而同一模型在静止姿上是 4.5）。
旧版之所以看不出来，是因为 `play(idle)` 会**逐帧重写**躯干 / 双臂 / 头，把残留姿态盖掉。
⇒ 现在由 `_rest_xf`（`_place()` 里记的**静止姿快照**）+ `_rest_pose()` **显式还原**。

**第四次复核（v0.8.0，同日）**：**头顶名牌整段删除**（用户：「人物顶部铭牌去掉」）——
它守的那件事（认人）整体落到**桌面立牌**上（见 §5.9）。角色层因此**不再有"行动者"这个概念**
（`set_actor` / `_apply_actor` 一并删除），行动者改由立牌上那圈金边表达（判据仍是 `_op_owner`）。

### 5.9 桌面立牌（**名册条的替身**）—— 第四次复核新增

**屏幕左上角的名册条整体删除**，四个人（除我）的信息改成**桌面上每名对手一块立牌**。
它承载的东西与旧名册格**逐项一致**：名次徽章 + 棋子色小片 + 昵称 + 行动者倒计时；
交互也一致：点它 = `game._on_corner_bar_clicked`（选目标态 ⇒ 选人，否则 ⇒ 开道具弹窗）、
选目标时描金边、行动者挂倒计时。

**做法（**v0.8.0 第五次复核已改**：牌面是**原生 3D 画的**，不烘贴图）**：
一度走过"把名册格那一块 Control 烘成贴图"的路（`make_chip` + 离屏 `SubViewport`），
用户 2026-10-06 否掉了它：「不要这个贴图，一是尺寸不对，二是文字模糊」——
那条路**两条病都躲不掉**（位图分辨率固定、缩了就糊；宽高比被 Control 的内容宽度绑死、
与牌面尺寸对不上）。⇒ 现在牌面由 `table_props._make_placard` 用**真 3D 元素**画：
薄盒牌身 + 棋子色小片 + **`Label3D` 写的名次与昵称**（矢量渲染，缩到多小都清楚）+ 贴底细倒计时。
`game` 只推数据（`set_placards` / `set_placard_hot` / `set_placard_timer`），
判据仍是唯一那份 `_hl_peers` / `_op_owner`。

**朝向**：整块**正对相机**（`root.basis = camera.basis`）。不用 `look_at`：2D 端近正俯视时
"看向哪"与"上在哪"几乎共线，`look_at` 会退化、牌面绕视线轴的旋转不可预期。
**2D 端因此自动平躺**（正俯视下"正对相机"与"平贴桌面"是同一件事），不必另写插值。

**尺寸是几何硬约束**：木纹带只有 `WOOD_FRAME(0.85) + 0.066 ≈ 0.92` 宽（用户要求"木桌尺寸不变"
⇒ 这个上限不许动）⇒ 牌面宽取 **0.80**、高 **0.30**（2.67:1），世界字高：昵称 0.135 / 名次 0.105。

**已知代价（如实记）**：默认档取景下对面那把椅子（slot 2）的头本来就顶到画面上沿
（台账 §三 那条未修项），头顶再挂一块牌会被**部分裁掉 / 压在顶部 HUD 上**。
拉远端（「看屋子 / 看人」那一档）三块牌都完整。⇒ 仍按老口径：**认人用拉远端**。

`CHARS_ENABLED := false` ⇒ 一个角色都不建，**回退开关真的能回退**。
与 `ROOM_ENABLED` 同一条纪律：**二期不许把游戏搞坏**。
**口径（Task 1 实测更正）**：说"逐字节回到一期"**不准确** —— 实测**这个摆拍本身就不是
逐字节确定性的**（同配置重跑也差 9.4k 像素）。**正确的判据 = 角色带（x ≥ 1000）的像素差**：
关角色时该带 **0 像素差**、开时 **114k 像素差**。

## 六、性能

一期实测过：**静态网格在本项目里很便宜**（满盘 56 个房子节点与空盘帧时间在噪声内）。
**二期要问的是逐帧动画** —— 本项目此前**从未测过**。
（**⚠ 担心的那个成本不存在**：这个包**没有蒙皮**，是 6 块刚体网格 + 每条 8 轨道、
最多 39 帧的**节点变换**动画。）

**实测（v0.8.0 二期 Task 5，本机 MX550 / `gl_compatibility`）** —— 同一支探针 `--fps=12`
（**必须 `--` 分隔符、必须不带 `--headless`**），**口径 = 加 `--disable-vsync`**
（一期记过：加不加 `--disable-vsync` 的读数**不可直接比**；本机开 vsync 会被 165 Hz 屏锁死），
分别测两端（**拉远端 = 角色在播 / 推近端 = 角色已淡出且停播**），并**另做一组
`CHARS_ENABLED = false` 的对照**（同一次会话、同一口径）：

| 组 | p50 | p95 | 平均帧 |
|---|---|---|---|
| 拉远端·**角色在播** | 2.259 ms | 4.346 ms | 4.005 ms |
| 推近端·**角色停播** | 2.274 ms | 4.102 ms | 4.405 ms |

> ⚠ **上表是 v0.8.0 第二次改版之前的读数**（当时人物还在播待机、那一档还淡出停播）。
> **第三次改版起淡出取消**（§5.3），人物在四档恒可见且一帧动画都不播 ⇒ 上表里
> "推近端·角色停播"那一行的意义随之作废；`CHARS_ENABLED` 开/关同会话 p50 只差 0.02 ms。
| 对照：`CHARS_ENABLED = false` 拉远端 | 2.291 ms | 4.493 ms | 4.833 ms |
| 对照：`CHARS_ENABLED = false` 推近端 | 2.288 ms | 4.327 ms | 4.512 ms |

⇒ **两端 p50 相同（2.259 vs 2.274，Δ 0.7%），"读棋盘"那一档没有变慢**；
更有力的证据是**对照组**：开 / 关角色在**同一端**上 p50 也只差 0.01~0.03 ms（**开角色反而略低**）
⇒ **3 个角色的待机动画在本项目里测不出成本**。
（表里的"平均帧"差是**已登记的环境周期性长帧**（每 ≈0.5 s 一次、每次 ≈0.5 s，
见 `开发台账.md` §三 批次 6/10/11 条）：四次跑到的长帧数是 9 / 11 / 12 / 11，
平均帧的差全由它解释，**不是角色的开销**。）
与已登记基线的对比：批次 11（同口径 `--disable-vsync`）**p50 1.87~1.99 ms**、
一期（另一口径）**p50 2.06~2.98 / 满盘 2.17 ms** —— 本次两端均 ≈2.26 ms，
**略高于批次 11、与一期同档**；但**这个偏移在"关角色"的对照里一样存在**（2.288），
⇒ 归属**测量环境 / 口径差异**，**不是二期引入的**。

**已经设计好的省法**（§5.3）：读棋盘那一档角色淡出 + **停掉动画** ⇒ 二期不拖慢主玩法档 ——
上面两组数**证明它成立**。

## 七、验收判据

全部实装并有断言（`tests/chars_test.gd` **57 条** + `tests/hud_test.gd` 的座位序一条）：

- **`CHARS_ENABLED = false` ⇒ 能真的回退**：判据是**角色带（x ≥ 1000）的像素差为 0**
  （不是"逐字节" —— 见 §5.7 末的口径更正）
- **人坐在椅子上、不穿模**：判据 ③ 的措辞已重述为「**每个分件的真实世界 AABB 不得与桌子的
  实体体积相交**」（= `TableBase` 盒 ∪ 从底座顶到桌面的那一层）—— **取代**旧的"合并 AABB
  与底座比 x 间隙"（那个 5 mm 来自**浮在桌面上方**的头、**不代表会不会穿模**）。
  实测 **0 件相交、最近的头部留 45.5 mm**。**脚底 / 髋枢轴两条落位断言**：
  与 `FLOOR_Y`、与座面各差 **0.0000**
- **腿穿椅面不是缺陷**（实测后判定）：椅子座面顶在 `y = -1.300`、腿分件顶（即髋）在 `-1.450`
  ⇒ 腿终止在座面顶之下 3 cm 且在座面足迹之内，重叠被椅子自己包住
- **"我"不渲染人物**（slot 0 无角色节点）
- **动画真的在动**：**两个动画相位的世界位置必须不同**（"只拍一帧既证明不了它在动、
  也证明不了它没在动"）；`loop_mode` 必须是自己设的 `LOOP_LINEAR`
- **角色 ↔ peer 对得上**：`hud_test` 那条"座位顺序 == `game._seat_peers()`"
  （**二期最怕的还是"人坐错位"**）
- **淡出真的停了动画**：推近端 / 2D 端 `AnimationPlayer.is_playing() == false`，
  且**淡出可逆**（推回默认档角色又回来、又在播）；两条端点断言 + **两帧像素比对**
  （在播的档角色带差 25.8% / 6.6%、推近端与 2D 端**整帧 0.00**）
- **色调**：角色不许是画面里最亮的东西（有效 albedo × 照度 ≤ 桌面那一笔，
  在最不利座位实测 0.910）+ 材质不是 `UNSHADED`
- **性能**：见 §六（两端 + 开 / 关角色的对照）
