## 一、背景与目标

一期把屋子立了起来（`ROOM_ENABLED` 总开关、地板/墙/天花板、家具、四把椅子、名牌、
吊灯的可见几何、`Ctrl` + 滚轮推拉）。**但椅子上没有人。**

用户从一开始就明确两件事：**要有坐着的人物**、**要对手势 / 反应**。这两条都是一期明确不做的
（一期 §二"明确不做"：人物模型 / 骨骼 / 动画），留给二期。

**二期的目标**：让四把椅子坐上报社里那四个人，并且**对玩法事件有反应** ——
出牌、付钱、被抢地、破产各自动一下。参照《骗子酒馆》的临场感：对手不是数字，是坐在对面的人。

## 五、设计提案

### 5.1 谁出场：**slot 0 不出人**（**已定**）

一期的 `GameRoom.seat_anchor(slot)` 里 **slot 0 = 近侧 = "我"**，而**相机就在"我"这个位置**。
⇒ **"我"不渲染人物**（第一人称），只保留一期的椅背 + 名牌。
理由：① 相机在"我"头上，渲染出来要么挡视线要么穿模；② 一期 §六 已经定了"我这一侧只有椅背"。

⇒ 实际渲染 **3 个人**（slot 1/2/3）。**已定：不给"我"渲染搭在桌上的手** —— 手要占桌面，
而那正是玩家读棋盘的地方（§九 ②）；`tests/chars_test.gd` 有一条"slot 0 无角色"钉着它。

### 5.2 坐在哪：复用 `seat_anchor(slot)`（**已定**，一期留的接口）

一期 §十 写死了这个接口的用途：「**二期把人放上去只改这一处**」。
⇒ 二期**只读** `seat_anchor(slot)` 拿 `Transform3D`，把角色放在椅面上、朝向对齐椅子。
**不许**在二期里另算一套座位坐标 —— 那正是"人坐错位"最难查的那类错。
`tests/hud_test.gd` 钉着"角色顺序 == `game._seat_peers()`"（二期最怕的还是坐错位）。

**落地值（`scripts/chars.gd`，全部是实测反推、不是拍的）**：
- **`CHARS_SCALE := 2.8125`**（= 座面 2.25 ÷ 髋枢轴 0.800）—— **不是 `FURNITURE_SCALE` 的 10.0**：
  这个包与一期家具**不是同一个比例族**，×10 的人有 5.4 m 高（比整间屋子还高）。
- **坐姿是手摆的，不是播包里的 `sit`**：`sit` 把腿**平举**（腿是一整块刚体、没有膝关节），
  按一期椅子比例会**捅进桌子 1.66 世界**。改手摆 = `SEAT_ROOT_Y := -0.2`（整体下移）
  + `LEG_SQUASH`（`leg-*.scale.y` 压短）⇒ 实测脚底与 `FLOOR_Y` 差 **0.0000**、髋枢轴与座面差 **0.0000**。
- **那条下移必须挂在角色之上的"外套节点"上**，不能挂在 GLB 的 `root` 上 —— `idle` 带一条
  `root` 的常值轨道，**一播就把 `position.y` 写回 0**、坐姿被顶掉（普查 §5.3 实测）。
- **逐座位选模型**：按该玩家的**棋子色**索引确定性选取（4 色 → 4 个模型，18 个里挑 4 个）——
  同一 peer 两次进来必须是同一张脸（`hud_test` + "同 peer 同脸"两条钉着）。
  **4 色映射到 4 个模型，不共用**：两个对手共用一张脸会破坏 §5.7 定的"靠角色本身认人"。
- **色调**：`CHAR_TINT := Color(0.29, 0.25, 0.21)` 乘在模型自己的 `albedo_color` 上
  （Godot 里 `albedo_color` 乘 `albedo_texture` ⇒ **贴图没动**、只压暗压灰）。定标在**最亮的那个座位**：
  吊灯在 `x = -4.13`、左座照度是右座的 **1.385 倍**，规则要在最不利处成立。
  **判据 = 角色不许是画面里最亮的东西**（不许比木框 / 桌面亮）。
- **材质**：包内是 `KHR_materials_unlit` ⇒ 导入即 `SHADING_MODE_UNSHADED`、不响应一期光照；
  而**不能照抄 `room.gd` 的材质覆盖**（那会**抹掉角色的贴图**）⇒ 二期另写了一个
  **只调光照参数、不碰贴图**的辅助函数，并有断言钉住"角色材质不是 `UNSHADED`"。

### 5.3 随取景淡出（**已定案**，且前提被实测更正过一次）

一期的取景结论：**默认档看得见桌子与一圈地板，椅子大多在画外**；推拉拉远才看得见屋子。
⇒ 人若永远渲染，**"读棋盘"那一档就是在白算 3 个动画**。

**⚠ 前提更正（2026-10-06，Task 1 出图实测）**：原先写的是"默认档看不见人 ⇒ 所以淡出"，
**实测反了** —— **默认档下角色是画面上最大、最抢眼的东西之一**（占右侧约 21% 宽、约 64% 高，
被右缘切掉）。⇒ **淡出不能建立在"默认档看不见"上**。**正确的判据是"是不是读棋盘的那几档"**：
- **推近端 / 2D 端**（读棋盘）⇒ 淡出（且**停掉动画**，省算力）
- **默认档与拉远端**（看屋子 / 临场）⇒ 在

**定案**：沿用项目既有的「看不见就淡出」约定（手牌随 `view_t` 淡出就是这一条），
**按"当前推拉档 / `view_t`"淡入淡出并停播**。**不按"是否落在视口内"**——
角色在 3D 端恒在画内（哪怕被切一半），按视口判会一直为真、等于没判。

**淡出契约（`chars.gd.set_fade(t)`，已实装并断言）** —— `t` = 「读棋盘程度」：

| `t` | 状态 |
|---|---|
| `t ≤ FADE_SOLID_T = 0.25` | **全亮**（`transparency == 0`）+ `idle` **在播**（3D 默认档 / 拉远端） |
| `0.25 < t < 0.75` | 线性淡 |
| `t ≥ FADE_GONE_T = 0.75` | **全隐**（外套节点 `visible = false`）+ **`is_playing() == false`** |

`t = max(view_t, (1 − dolly) / (1 − FADE_NEAR_DOLLY))`，`FADE_NEAR_DOLLY := 0.7`（= 一期
`table_3d.DOLLY_MIN`，有一条跨文件断言钉住两者相等 —— "哪天一期那个档位改了、这里没跟，
就是『该淡的那一档不淡』"）⇒ **推近端 `dolly = 0.7` ⇒ `t = 1.0`（全隐停播）**；
**默认档 `dolly = 1.0` 与拉远端 `1.4` ⇒ `t = 0.0`（全亮在播）**。
**停播只在"已经看不见"之后发生**（提前停会让"半透明但看得见"的那几帧僵住）。
两个端点都可逆（推回默认档角色又回来、又在播），并有断言。

**已定：2D 端也淡出，不露头顶**（§九 ③）—— 2D 端是"读棋盘"那一档，三个头顶在角落晃
是纯噪声、还会被误读成可点目标。

### 5.4 动画集合（**已实装**；**动画名全部是普查实测存在的**，不是意图）

| 动画 | 用什么 | 触发（从**已同步的状态**读边沿） |
|---|---|---|
| **待机** | `idle` | 常驻。**循环模式必须自己设**（`loop_mode = LOOP_LINEAR`）—— 导入器给的全是 `LOOP_NONE` |
| **当前行动者** | **同一条 `idle` 提速**（`ACTOR_SPEED 1.4` vs `IDLE_SPEED 1.0`） | `st.turn` 换人。**包里没有第二条持续型动画**（`walk` / `sprint` 是位移动作，坐着的人播它不合适） |
| **出牌** | `interact-right` | `st.players[i].item_used` 假→真（**不用"手牌少一张"**：多数道具用完不进背包，那样会漏掉绝大多数出牌、还把丢弃算进去） |
| **付钱** | `holding-left` | 钱循环里的 `diff < 0`（**与既有飞钞同一拍**） |
| **被抢地** | `emote-no` | `st.tiles[i].owner` 由**还活着的**上一手主人变成别人 |
| **破产** | `die` + **手摆座位收势** | `alive` 真→假。**见下** |

**幅度 = 含蓄**（§九 ⑤，用户定的调性）：**不放大 `speed_scale`**、不加额外演出；只有破产那一下
是重头。**四家不连动**（谁付钱谁动）。

**⚠ 破产那一条推翻了早期设计里的一句依据（Task 4 实测更正）**：原先写的是"`die` 的末帧
正是躺下 / 趴着，**恰好对上**『破产的人留在座位上趴着』"—— **对坐着的人不成立**：
`die` 的末帧是把整个人**绕脚底转 −90°**，坐着的人会**落到地板以下 0.42**、
**躯干躺到 `z ∈ [−12.5, −5.2]`（远墙在 −9）** ⇒ 出图就是"**人不见了**"，
正是 §九 ④ 明确否掉的那种"消失"。
⇒ **处置**：**摘掉那一条轨**（同 `_loop_idle` 的手法），**保留 `die` 自己其余内容**（举双手），
**再手摆座位收势**（前折 5° + 侧倒 45° + 低头 12°，顶在"不与桌子实体体积相交"的几何上限）。
**结果：人留在自己那把座位上、歪倒在椅子上、举着双手、头看得见** —— 与"椅子空了"对比强烈。
**⚠ 措辞更正**：早期写的"**趴在**座位上"是**在知道几何之前**的措辞，那条决定的**本意是
"留在座位上、而不是消失"**（§九 ④），本意已满足，**但姿势是"歪倒"不是"趴"**；
桌面是从地板到桌面的一整块实体体积，"趴上去"会把人埋进去、从相机看又是"不见了" ⇒ 几何上做不到。
**破产被记住**（`_dead_peers`）：不记住的话一次淡出往返 / 一次重建就把他**复活**了。
另：`play()` 之后直接 `pause()` 停在的是第 0 帧，**必须先 `seek(时长)`** 才停得住末帧。

### 5.5 事件从哪来：**只读表现层，不碰玩法**（**已定**，一期同一条纪律）

一期 §二 / `AGENTS.md` §四：**玩法逻辑只在房主算，客户端只渲染**。
⇒ 二期**绝不**新增 `@rpc`、**绝不**改状态机。

**落地（Task 4）**：四个事件**全部从已同步的 `st` 读**（房主侧 `game.gd` 的
`_react_chars()` / 钱循环里的差分）⇒ **没有加只读信号** —— 能从已同步的状态读出来，
直接调用就比走信号少一层。`game.gd` 的三处接线（`set_chars` / `set_actor` / `react`）
**全部是只读表现层调用**：**状态机 / 结算 / `s_state` / 每一个 `@rpc` 都没碰**。
**端到端实测**（10 轮真对局，临时探针已删）：`pay` 44 次、`play` 6 次横跨三家机器人；
**`rob` / `die` 在自动对局里不自然出现** ⇒ 只有单测覆盖（如实记档）。

### 5.7 名牌朝向 —— 一期终审带出的观察（**已定案：不改名牌，靠角色本身认人**）

**观察（一期终审发现，留档在此）**：一期的四块名牌**都挂在椅背朝外那一面**
（一期 §六 的原话："读它的人站在椅子背后"）⇒ **从相机看过去，只有 slot 0（近侧＝"我"）那块的字
是正面朝向观众的**；slot 2 看到的是牌背，slot 1/3 是侧视 —— 而侧视正是**一期 Task 9 ①
修掉的那两道"游离亮线"**（当时把牌**嵌进椅背** `NAMEPLATE_SINK 0.06`、压暗，代价就是侧向那块更看不见了）。
**⇒ 今天"哪把椅子是谁"是靠棋子色读的，不是靠名字。**

**定案（控制者 2026-10-06，玩家体验角度）：不改名牌。** 理由：
1. **名字本来就不该由名牌承担** —— HUD 的**名册条**已经写着每个人的名次 + 棋子色 + 昵称；
   名牌在画面里的职责是**氛围**（"这椅子有人"），不是信息。
2. **二期放上角色之后，"谁坐哪"由角色本身回答** —— 四家各有模型 / 配色 / 动作，
   比一块更清楚。⇒ **二期不做"把名牌转过来"这种事**（转过来就等于把牌子对着坐的人、而不是对着观众，
   反而丢了"椅子属于谁"的读法）。
3. **代价（承认）**：在二期落地之前，侧向那两把椅子的所属**只能靠棋子色**读。
   这是**已接受的取舍**（换掉了两道游离亮线）。
**⇒ 二期开工时不需要动名牌**，只需保证 `NAMEPLATE_ANCHORS` 仍被 `seat_anchor(slot)` 一致地暴露
（一期 §十 的接口）。

`CHARS_ENABLED := false` ⇒ 一个角色都不建，**回退开关真的能回退**。
与 `ROOM_ENABLED` 同一条纪律：**二期不许把游戏搞坏**。
**口径（Task 1 实测更正）**：说"逐字节回到一期"**不准确** —— 实测**这个摆拍本身就不是
逐字节确定性的**（同配置重跑也差 9.4k 像素）。**正确的判据 = 角色带（x ≥ 1000）的像素差**：
关角色时该带 **0 像素差**、开时 **114k 像素差**。

## 六、性能

一期实测过：**静态网格在本项目里很便宜**（满盘 56 个房子节点与空盘帧时间在噪声内）。
**二期要问的是逐帧动画** —— 本项目此前**从未测过**。
（**⚠ 担心的那个成本不存在**：这个包**没有蒙皮**，是 6 块刚体网格 + 每条 8 轨道、
最多 39 帧的**节点变换**动画。）

**实测（v0.8.0 二期 Task 5，本机 MX550 / `gl_compatibility`）** —— 同一支探针 `--fps=12`
（**必须 `--` 分隔符、必须不带 `--headless`**），**口径 = 加 `--disable-vsync`**
（一期记过：加不加 `--disable-vsync` 的读数**不可直接比**；本机开 vsync 会被 165 Hz 屏锁死），
分别测两端（**拉远端 = 角色在播 / 推近端 = 角色已淡出且停播**），并**另做一组
`CHARS_ENABLED = false` 的对照**（同一次会话、同一口径）：

| 组 | p50 | p95 | 平均帧 |
|---|---|---|---|
| 拉远端·**角色在播** | 2.259 ms | 4.346 ms | 4.005 ms |
| 推近端·**角色停播** | 2.274 ms | 4.102 ms | 4.405 ms |
| 对照：`CHARS_ENABLED = false` 拉远端 | 2.291 ms | 4.493 ms | 4.833 ms |
| 对照：`CHARS_ENABLED = false` 推近端 | 2.288 ms | 4.327 ms | 4.512 ms |

⇒ **两端 p50 相同（2.259 vs 2.274，Δ 0.7%），"读棋盘"那一档没有变慢**；
更有力的证据是**对照组**：开 / 关角色在**同一端**上 p50 也只差 0.01~0.03 ms（**开角色反而略低**）
⇒ **3 个角色的待机动画在本项目里测不出成本**。
（表里的"平均帧"差是**已登记的环境周期性长帧**（每 ≈0.5 s 一次、每次 ≈0.5 s，
见 `开发台账.md` §三 批次 6/10/11 条）：四次跑到的长帧数是 9 / 11 / 12 / 11，
平均帧的差全由它解释，**不是角色的开销**。）
与已登记基线的对比：批次 11（同口径 `--disable-vsync`）**p50 1.87~1.99 ms**、
一期（另一口径）**p50 2.06~2.98 / 满盘 2.17 ms** —— 本次两端均 ≈2.26 ms，
**略高于批次 11、与一期同档**；但**这个偏移在"关角色"的对照里一样存在**（2.288），
⇒ 归属**测量环境 / 口径差异**，**不是二期引入的**。

**已经设计好的省法**（§5.3）：读棋盘那一档角色淡出 + **停掉动画** ⇒ 二期不拖慢主玩法档 ——
上面两组数**证明它成立**。

## 七、验收判据

全部实装并有断言（`tests/chars_test.gd` **57 条** + `tests/hud_test.gd` 的座位序一条）：

- **`CHARS_ENABLED = false` ⇒ 能真的回退**：判据是**角色带（x ≥ 1000）的像素差为 0**
  （不是"逐字节" —— 见 §5.7 末的口径更正）
- **人坐在椅子上、不穿模**：判据 ③ 的措辞已重述为「**每个分件的真实世界 AABB 不得与桌子的
  实体体积相交**」（= `TableBase` 盒 ∪ 从底座顶到桌面的那一层）—— **取代**旧的"合并 AABB
  与底座比 x 间隙"（那个 5 mm 来自**浮在桌面上方**的头、**不代表会不会穿模**）。
  实测 **0 件相交、最近的头部留 45.5 mm**。**脚底 / 髋枢轴两条落位断言**：
  与 `FLOOR_Y`、与座面各差 **0.0000**
- **腿穿椅面不是缺陷**（实测后判定）：椅子座面顶在 `y = -1.300`、腿分件顶（即髋）在 `-1.450`
  ⇒ 腿终止在座面顶之下 3 cm 且在座面足迹之内，重叠被椅子自己包住
- **"我"不渲染人物**（slot 0 无角色节点）
- **动画真的在动**：**两个动画相位的世界位置必须不同**（"只拍一帧既证明不了它在动、
  也证明不了它没在动"）；`loop_mode` 必须是自己设的 `LOOP_LINEAR`
- **角色 ↔ peer 对得上**：`hud_test` 那条"座位顺序 == `game._seat_peers()`"
  （**二期最怕的还是"人坐错位"**）
- **淡出真的停了动画**：推近端 / 2D 端 `AnimationPlayer.is_playing() == false`，
  且**淡出可逆**（推回默认档角色又回来、又在播）；两条端点断言 + **两帧像素比对**
  （在播的档角色带差 25.8% / 6.6%、推近端与 2D 端**整帧 0.00**）
- **色调**：角色不许是画面里最亮的东西（有效 albedo × 照度 ≤ 桌面那一笔，
  在最不利座位实测 0.910）+ 材质不是 `UNSHADED`
- **性能**：见 §六（两端 + 开 / 关角色的对照）
