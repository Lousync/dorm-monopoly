# 实施计划：把 doc/game-design/ 改写为游戏设计文档

> 目标版本：0.2.0（文档专场）。本计划在版本合并进 `main` 后连同文件一起删除。
> 口径：2026-10-02 与用户逐条敲定 ——
> 1. `game-design/README.md` 的**索引**并入 `AGENTS.md`，**术语表**单独成篇留在 `game-design/`；
> 2. 开发进度痕迹（批次 / 已落地 / 补丁 / 实现进度）全部归拢进 `doc/development/开发台账.md`；
> 3. 代码引用只留「数据表指针」（如「数值表在 `scripts/item_data.gd`」），
>    函数名 / 常量名 / 测试文件名 / 启动参数清除；
> 4. 通稿重写：现在时陈述、统一骨架、去掉「本对话」「待用户确认」这类协作痕迹，
>    「待数值专场」改写为「设计待定」。

## 一、目标骨架

每篇按需取用下面五节（**顺序固定，不适用的节直接省略**），开头一句定位、结尾一节待定：

```
# <系统名>
> 一句话定位（不写状态 / 进度 / 日期）

## 规则        玩家能做什么、系统怎么运作
## 数值        表 / 公式 / 范围；缺口标「设计待定」
## 表现        界面 / 动效 / 文案（玩家看到什么）
## 边界与例外  特殊冲突怎么处理、已知取舍
## 设计待定    本节集中列出尚未拍板的设计问题
```

`术语表.md` 例外，只有一张表。

## 三、进度与待办的去向

写进 `doc/development/开发台账.md`：

- §一 系统状态表 —— 保留现状（✅ / 📐 / ⛔ 这套标记只在这里用）。
- §二 道具批次进度 —— 吸收 `道具系统.md` §十四的批次一~五与补丁记录（浓缩为一行一批）。
- §三 跨文档待办 —— 吸收各设计文档原「待办」节里**可施工**的条目（数值专场回填、面板实现、贴图等）。
  与设计文档的「设计待定」分工：**「设计待定」= 还没定的设计问题**（放 doc），
  **台账 §三 = 已定但还没做的开发任务**（放 development），台账条目可指回文档对应小节。
- 补丁记录（小卖部购买修复等）—— 归 `CHANGELOG.md`，台账不重复。

## 四、验收

1. `git grep -nE "_(item|grant|immune|resolve|use)_[a-z_]+|SOIL_DONATE|item_data\.gd|tests/|--card-gallery|--lab" -- doc/game-design/`
   —— 期望只剩允许的「数据表指针」。
2. 全篇搜 `已落地|已实现|待实现|批次|实现进度|补丁|状态：` 在 `doc/game-design/` 下清零。
3. 每篇的「设计待定」与台账 §三 对得上（同一件事不该两边各写一份）。
4. 逐篇比对改写前后：**规则与数值不得在搬运中丢失或改动**（数值改口径要单独说明）。
5. 文档改动不触碰代码，跑 `tests/load_all.gd` 确认无意外，`git grep docs/` 仍为零。
