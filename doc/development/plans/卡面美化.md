## 一、卡面现状（改之前先看清）

### 1.1 结构（自上而下）

`DeckReveal`（`scripts/deck_reveal.gd`）是一层挂在 hud 里的**屏幕层** `Control`（`FULL_RECT`、
`z_index = 40`，压在棋盘与四角身家条之上、**所有模态面板之下**）。它不动相机 —— 这是它的立身之本。

- `_card`：一张 **320×480**（2:3）的**翻面容器**，一个普通 `Control`；`scale / rotation / modulate`
  全由 `tick()` 的相位驱动。里面两张面：
  - `_back` = `_card_face_back(deck, accent)`：外框 `UIKit.card_stylebox(固定深金褐, 圆角 16, accent 3px
    描边, 投影 12, accent 光晕 0.12)`，再铺满一张 **Atlas 牌背 SVG**（`_make_card_art`，压成低透明度线纹）。
  - `_front`：
    - 道具卡面（`item_id` 非空）→ `ItemCard.make(item_id, CARD_SIZE)`（**另一套版式**：圆徽章 / 图区 /
      名称条 / 描述 / 品质条，见 `doc/game-design/道具系统.md` §九）。
    - 否则 → `_card_face_front(deck, text, style)`：外框 `card_stylebox(style[1], 16, style[0], 2, 12)`
      + 同一张 Atlas 线纹 + 中央一块 `plate`（内缩 34 ⇒ 有效 252×412，底色 `0.045/0.05/0.078 @0.88`，
      圆角 12，`accent@0.5` 的 1px 边框）+ 一个 `VBox`（`separation 8`，整块 `ALIGNMENT_CENTER`）：
      标题 `UIKit.label(deck, 30, accent)` → 1px `ColorRect` 分隔线（`accent@0.35`）→ 正文
      `UIKit.label(text, 18, TEXT)`。
- 卡下方：「确定」按钮（`UIKit.button(…, "primary")`，150×46）**或**抉择卡那一排分支按钮（`CHOICE_BTN` 168×42）。
- 另有一块**独立**的 `_bury_box`（小抄置底询问）——它没有卡面，与抽卡演出各自独立，本次不碰。

四相位（`tick()`）：**抽出 `OUT` 0.34** → **翻面 `FLIP` 0.30**（压到最扁那一瞬换面 + 提亮反光）→
**停留 `HOLD` 1.50**（上下浮动 + 呼吸微光）→ 停在「等确定」（姿态与 HOLD 一字不差）；
`request_close()` 之后才走 **`BACK` 0.28** 收尾。`CARD_TIME = OUT+FLIP+HOLD`，被 `hud_test` 钉住。

### 1.2 三类卡现在分不分得开 —— **实测（2026-10-10 摆拍）**

**（1）代码层面的事实**（先列出来，好跟下面的实拍对照）

1. **卡背图案只有两张**：`_deck_back_tex` 用 `deck == "机会"` 这个**标题字符串比较**当配色键 ⇒
   机会用绿底纹 SVG，**道具卡、畸变卡、失物招领一律用蓝底纹 SVG**。
2. **背面还把家族与卡型混在一起**：`_card_face_back` 的描边色吃的是 `card_palette(kind)[0]`
   （**卡型**色）⇒ 同是机会卡，`good` 卡背面是绿边、`bad` 卡背面是红边。于是"背面是什么颜色"
   既不纯粹表示家族、也不纯粹表示卡型 —— **谁都不是**。
3. **文字卡（机会 / 畸变）版式完全一样**：同一个 `_card_face_front`，只差 `accent` 色、标题文字、
   与 `_make_card_art` 里第二个三元给出的底纹色调。
4. **道具卡族是另一种"卡类"**（它是 `ItemCard`）。

**（2）实拍结论 —— 把 §1.2 原先那句"基本分不开"改掉**

基准图（本次实拍，命令见 §4.5）：`shots/kp_chance_card.png`（机会 good）、
`shots/kp_itemreveal_card.png`（道具卡面）、`shots/kp_abstyle_plain.png`（畸变）。

| 实拍 | 卡框 / 标题 / 分隔线（= `card_palette(kind)[0]`，**卡型**色） | 卡面底纹（= `_make_card_art` 那个三元，**家族**色） | 卡面主体 |
|---|---|---|---|
| 机会（good） | 绿 `#74cf87` | **橄榄绿 + 暗红**格纹（`green_darkred` × 金 tint） | 深蓝黑 `plate` + 标题 / 正文 |
| 道具卡面 | 无（`ItemCard` 走**品质**色：白档 ⇒ 灰） | **无格纹** | 中灰平底 + 图区 / 名称条 / 描述 / 品质条 |
| 畸变（aberr） | 紫 `#c9a6ff` | **薰衣草紫 + 棕褐**格纹（`blue_brown` × 蓝 tint） | 与机会同一套结构 |

⇒ **修正**：三张实拍在**整体色调**上确实分得开（绿 / 灰 / 紫）——
但**分得开靠的是"卡型色恰好不同"（good 绿、aberr 紫、白档灰），不是"家族有系统标识"**。
图上坐实的是下面三个真问题：

1. **卡框色表达的是卡型，不是家族**。机会 `good` 卡绿框、`jail` 卡紫框、`info` 卡金框 —— 而畸变卡**也是紫框**。
   **最易混的一对：机会的 `jail` 型卡（紫框 + 绿/暗红格纹）↔ 畸变卡（紫框 + 紫/棕格纹）**
   （`#a885f2` 与 `#c9a6ff` 是两个几乎一样的紫，见 §4.3 逐色表），只能靠格纹底色去分。
   ⇒ 方案 A 的"**家族认框、卡型认章**"（= 正面外框也归家族）正是冲这一条来的。
2. **家族色只活在"卡面底纹"这一层，而且很弱**：底纹是低透明度的线纹，被卡框的卡型色压住。
   实拍里 `good` 机会卡的底纹是绿格、`aberr` 畸变卡是紫格 —— 但那是因为两者的 `kind` 不同；
   换成 **`bad` 型机会卡就是"红框 + 绿格"**，家族色被红框吃掉。
3. **道具卡面与另两族分属两种"卡类"**：道具卡面是**平底 + 图区 + 名称条 + 品质条**（无格纹、无深色 `plate`），
   文字卡是**深色 `plate` + 格纹外框**。⇒ 三类卡之间只有"圆角矩形 + 2~3px 描边"这一层共用。

**（3）另外几处一眼可见、此前没写进稿子的东西**

- **卡背与卡面几乎不像同一张牌**：`_card_face_back` **没有那块深色 `plate`** —— 卡背是**整张满铺格纹**
  （`_make_card_art`）+ 描边 + 光晕。实拍见 `shots/kp_deckout_card_outa.png`。
- **卡背的曝光只有 `OUT` 那 0.34 秒，而且是"小卡 + 倾斜 + 半透明"**：实拍里卡背出现在
  `scale ≈ 0.6`、`rotation ≈ -0.03`、`alpha` 刚爬起来的时候。⇒ **家族身份不能只靠卡背**，
  必须落到停住的正面（这一条直接改了方向 A 的第 1 条，见 §二）。
- **卡面主体是一大片空**：文字块（标题 + 分隔线 + 正文）只占卡面中间约 **1/3**，上下各留 ~230 / ~290 px 的深色 `plate`。
  「大卡面 + 小内容」是当前最扎眼的一处 ⇒ 这正是本稿把**标题改顶部对齐**（方向 B 那两处微调）的理由。
- **`ItemCard` 的圆徽章在 320×480 这档是 72px**（`bs = size.y * 0.15`），落点 `(-bs*0.42, -bs*0.42)`
  ⇒ 约六成在卡内、四成骑在卡外（正是 §九 说的"半出卡外"，**不是 bug**）。
  但方案 A 给**文字卡**做两枚同类徽章时**不能照抄这个尺寸** —— 建议 `bs ≈ 36`（见 §二 方向 A）。
- 顺带一条现状：`ItemCard` 的**描述框留白偏大**（「招财猫」那条描述只用了两行，框里还空着一半），
  这是 `ItemCard` 自己的事，**不在本稿范围**，记一笔备查。

### 1.3 哪些是程序化画的（先例：转盘 / 房子等级纹理 / 卡背图案）

全部关键图形都是运行时画的，本次美化可完全沿用这套家底：

- **九宫格渐变纹理**：`UIKit._rounded_tex` 逐像素 SDF 生成「圆角 + 纵向渐变 + 描边 + 顶部高光 +
  光晕 / 投影」，按钮、卡片、面板、胶囊全走它；`card_stylebox` 把光晕与投影**画到控件矩形之外**
  （`expand_margin`）—— 这一条对本次很关键（见 §四 4.6 第 4 条）。
- **徽章 / 胶囊**：`ItemCard._badge` / `ItemCard._pill`（圆 / 胶囊 + 描边 + 投影），**已经骑在卡边外**。
- **渐变块**：`UIKit.grad_rect`（线性 / 径向渐变 `TextureRect`，背景、光斑、暗角都用它）。
- **文字符号**：`UIKit` 全程用 emoji 当图标（⏸ / ⚡ / ⏳ / 🌀 / 💰 都在用），**不落 png**。
- 唯一的真"素材"是两张 CC0 的 Atlas 牌背 SVG（`assets/cards/atlas_back_green_darkred.svg`、
  `atlas_back_blue_brown.svg`，授权见根 `LICENSE`）与道具图标 Twemoji PNG。
  **本次美化沿用这两张 SVG，不新增任何素材**（关于"要不要第三张牌背"见 §四 4.6 第 2 条）。

## 二、三个美化方向（推荐 **A**）

### 方向 A（**推荐**）：家族化卡背 + 卡型徽章

**改什么**

1. **家族色 = 卡背 + 正面外框 + 标题 + 光晕 + 左上家族徽章**；**卡型色退出"外框"，只留在右上卡型徽章**。
   原则：**家族认框、卡型认章**（家族色表见下）。
   这一条是**看图后改的**（原稿只说了"卡背按家族"）：
   - 实拍显示 `card_palette("jail")` `#a885f2` 与 `card_palette("aberr")` `#c9a6ff` 是**两个几乎一样的紫**
     ⇒ 只要"正面外框"还按卡型上色，**机会 `jail` 卡与畸变卡就永远撞色**，光改卡背救不回来。
   - 而且**卡背的曝光只有 0.34 秒**（`OUT` 段）：`deckout` 实拍里卡背是**小卡 + 倾斜 + 半透明**，
     玩家真正盯着看的是**停住的正面**。⇒ 家族身份**必须落在正面上**，不能只躺在卡背。
   - 卡型改用**徽章**承担（卡型色 + 图标 + 中文）：五色退到一小块面积上，但**有文字托底**，比纯色更准；
     `jail` / `aberr` 那种"两个紫"也就不再靠颜色去猜。
   - **道具卡面是例外**：它的外框 = 品质色（`ItemCard` 既有语言，**别动**），家族身份改由
     **卡背 + 一圈家族色外发光**承担 —— 它的版式本身就是最强的家族信号，不必再加徽章（见 §3.2）。
2. **卡面加两枚骑在卡边外的圆徽章**（与 `ItemCard` 同一套语言，把 `ItemCard._badge` / `_pill` 提炼成
   `UIKit.badge` / `UIKit.pill`）：**左上 = 家族徽章**（家族色），**右上 = 卡型徽章**（卡型色 + 图标 + 中文）。
   **尺寸别照抄 `ItemCard`**：它那个 `bs = size.y * 0.15` 在这档是 **72px**（实拍里已相当抢眼），
   文字卡只有一枚文字标题、放两枚 72px 徽章会盖掉版面 ⇒ 建议 **`bs ≈ 36`**（约 `size.y * 0.075`）。
3. **版式微调**：标题改**粗体**（`UIKit.bold_label`）并从"整块居中"改成"**顶部对齐 + 上留白**"；
   分隔线改成**两端渐隐**的 2px 横线（`grad_rect` 横向渐变，不落素材）；外框加一层**家族色光晕**；
   圆角 16 → 18。**理由有实拍支撑**：现状文字块只占卡面中间约 1/3，上下各空 ~230 / ~290 px，
   标题改顶部对齐能立刻把"大卡面、小内容"的观感收掉（见 §1.2（3））。
4. **动效点缀**（见下"从 C 借"）：翻面光扫 + 抽出 / 收起的家族地面光。
3. **版式微调**：标题改**粗体**（`UIKit.bold_label`）并从"整块居中"改成"**顶部对齐 + 上留白**"；
   分隔线改成**两端渐隐**的 2px 横线（`grad_rect` 横向渐变，不落素材）；外框加一层**家族色光晕**；
   圆角 16 → 18。
4. **动效点缀**（见下"从 C 借"）：翻面光扫 + 抽出 / 收起的家族地面光。

**怎么程序化实现**：全部用现成件 —— `card_stylebox`（已有 `glow` 形参）、`stylebox`、`grad_rect`、
`bold_label`、`label`；徽章用 `ItemCard._badge` 那一套圆 + 描边 + 投影，图标用文字符号。**零素材新增**。

**代价**：小。改 2 个脚本（`deck_reveal.gd` + 一处色表）；**零 RPC 改动**、零调用点改动（见 §四 4.1）。

**风险**：低。唯一"玩家看得到的行为"变化是**道具卡 / 失物招领的卡背 绿→蓝**（这是有意的，见 §五）。

### 方向 B：版式重做（分区骨架）

**改什么**：把 `_card_face_front` 的"单个居中 VBox"拆成**三段固定分区**：顶区（家族带，高 34）/
中区（正文区，独立底板 + 内缩，标题贴顶、正文垂直居中）/ 底区（页脚 = 家族色细线 + 家族名小字）。
用 `set_anchors_preset` + `offset_*` 定位而不是 VBox 居中 ⇒ 标题永远落在同一个 y。

**代价**：中（要重排整个函数体）。
**风险**：中 —— 畸变标题（「🌀 畸变 · 枪打出头鸟」）比「机会」长得多，锁宽换行后可能吃掉正文高度；
长短文案的适配得逐张看摆拍图。**B 的收益（标题落点稳定、分区清楚）A 已经拿到七成**，
B 额外拿到的主要是"页脚"这类装饰性分区。

### 方向 C：质感与动效

**改什么**：
- **翻面光扫**：`FLIP` 第二半让一道斜向高光扫过卡面（`grad_rect` 线性渐变）。
- **家族地面光**：卡背后一层径向渐变（家族色 `@0.22`），随 `OUT` 升起、随 `BACK` 收回。
- **呼吸偏家族色**：把现在纯白的 `modulate` 呼吸，轻微偏向家族色（幅度 0.03 不变）。

**代价**：小（都在 `tick()` 的相位分支里加几行）。
**风险**：低 —— 但**单靠动效解决不了"静态帧分不开"**：截图、静止画面里三类卡仍是一个样。
⇒ C 只能当点缀，**不能单独立项**。

### 推荐：**A 为主**，从 C 借两项，从 B 借两处微调

| 采纳 | 来自 | 理由 |
|---|---|---|
| 家族三色卡背 + 两枚外挂圆徽章 | A | 一次同时解决"家族身份没有系统标识"与"卡型只能靠颜色猜"两个真问题 |
| 标题粗体 + 顶部对齐 + 分隔线渐隐 | B（只借这两处） | 收益大、代价小、不重排整段；实拍里"大卡面、小内容"最扎眼 |
| 翻面光扫 + 家族地面光 | C | 便宜、好看、**不碰相位时长** |
| ~~整段分区重做 / 页脚~~ | B（不采纳） | 边际收益递减，长短文案适配风险最高 |

**理由（看图后更硬）**：实拍证明三类卡**不是"分不开"、而是"分得开得靠运气"** ——
整体色调的差异全部来自**卡型色**（`good` 绿 / `aberr` 紫 / 白档灰），家族本身只剩一层很弱的底纹色调；
于是**机会 `jail` 卡 与 畸变卡 撞成两个几乎一样的紫框**（§1.2、§4.3）。
A 用最小改动把"家族"这一维从卡型色里**拆出来**；B 的整段重做收益边际递减且长短文案适配风险最高；
C 单独做解决不了识别问题。

## 三、与「道具卡 / 畸变卡」的统一语言

三类卡**共用同一段演出**（同一个 `DeckReveal`），所以统一与分化必须说清：

### 3.1 统一在哪

- **同一段演出**：四相位、同一张 320×480 卡、同一个「确定」按钮、同一套圆角 / 描边 / 投影 / 光晕参数。
- **「家族 = 外框 / 光晕 / 卡背」对三类卡一致**：机会绿 / 道具蓝 / 畸变紫 —— 停住的正面与翻面前的卡背都认得出。
- **徽章语言一致**：**骑在卡边外的圆徽章**。这条正是 `道具系统.md` §九 已定的
  道具卡语言（"两枚徽章骑在卡边（半出卡外）"）⇒ 文字卡**借用同一套语言**，只是内容不同（见 3.2）。
- **文字卡骨架一致**：标题（粗体、顶部）→ 渐隐分隔线 → 正文（居中）。

### 3.2 分化在哪

| | 机会卡（文字卡） | 畸变卡（文字卡） | 道具卡面 |
|---|---|---|---|
| 卡背 | 绿家族 | **紫家族** | 蓝家族 |
| 外框 / 标题 / 分隔线 | **绿家族**（不是卡型色） | **紫家族** | 品质色（`ItemCard` 既有语言，**不动**）；**外面套一圈家族色外发光** |
| 左上 / 右上徽章 | 🎲 家族 / 💰💸🚶🚨ℹ️ **卡型** | 🌀 家族 / 🚨 卡型 | ⚡ 消耗·被动标 / 一次性·⏳冷却·计数位（**全保持不动**；**不叠家族徽章**） |
| 卡面主体 | 标题 + 正文 | 标题「🌀 畸变 · 名」+ 正文 | `ItemCard` 的图区 / 名称条 / 描述 / 品质条（**保持不动**） |

> 一句话：**家族认框、卡型认章**；道具卡族不套文字卡骨架 —— 背面与外发光走家族语言，
> **正面仍是那张 `ItemCard`**（品质色 + 徽章 + 图区），它自己的层次照旧。
> 卡型徽章与家族徽章**都只出现在文字卡上**（`ItemCard` 上不叠，否则它同时有品质 / 卡型 / 家族三套徽章、必然打架）。
> 道具族的家族信号本来就最强 —— **"它长着 `ItemCard` 的版式"这件事本身就是"道具族"的标志**，
> 不需要再加徽章；再加一圈家族色外发光就够把三族的"光晕"连成一套。
>
> **⚠ 道具族的家族痕记必须加在 `DeckReveal` 这一层，不许加进 `ItemCard`**：
> `ItemCard` 是**共用件** —— 小卖部货架 / 手牌 / 发现三选一 / 黑市 / 弹窗都在用它。
> 往它身上加"家族"概念，会让**货架上一件商品也长出"机会格抽卡家族"的痕记**。
> ⇒ 那一圈家族色外发光由 `DeckReveal` 作为 `ItemCard` 的**外层 / 兄弟节点**加上去（见 §4.6 第 5 条）。

## 四、实现方案与风险

### 4.1 那条「`"机会"` 既是配色键又是卡类名」的纠缠 —— 怎么解（核心）

**现状**：`_deck_back_tex(deck)` / `_make_card_art(deck)` 用 `deck == "机会"` 这个**标题字符串比较**
当配色键；而同一次调用里 `deck` 又被当成标题（`_card_face_front` 里的 `UIKit.label(deck, 30, …)`）。
一个值担了两种角色。

**做法：把"家族键"从标题里拆出来，用一份显式派生，且不新增参数、不改签名。**

```gdscript
# scripts/deck_reveal.gd — show_card() 内部（伪码，三行）
var family := "chance"
if item_id != "":          # 道具卡面（道具卡 / 失物招领）—— item_face 本来就是"这是道具卡面"
    family = "item"
elif kind == "aberr":      # 畸变公告（s_card 那一路 kind 恒为 "aberr"）
    family = "aberr"
```

**依据（今天完整且无歧义）**：所有 `deck != ""` 的调用点恰好落进这三档 ——
文字卡只有「机会」与「🌀 畸变 · 名」两种，道具卡面一律带 `item_id`。所以：

- `deck` 参数**只剩"标题 / 演出标题"一个角色**，`family` 承接配色键 ⇒ **两个角色分开了**，
  代码里再也**没有"拿标题当键"的比较**。
- 以后新增一类文字卡时，只需在派生处加一行（并在 §4.6 第 3 条的断言上放行）。

**备选（不推荐）**：

1. **给 `s_card` / `show_card` 加显式 `family` 形参**，由调用点传 —— 更面向未来，但
   `show_card(deck, kind, text, item_id)` 的签名被 `hud_test` / `chance_test` 用 4 参调用钉着，
   加参要改约 9 处测试 + 5 处调用点 + `联机协议.md` 的 `s_card` 行，**收益只是"将来少写一行派生"**。
2. **按 `deck.begins_with("🌀")` 判畸变** —— **不要**。那是另一种"拿标题当键"，标题一改配色就跟着坏。

### 4.2 要动哪些文件 / 哪些函数

| 文件 | 函数 / 常量 | 动什么 |

### 4.3 三处配色表怎么收（单一来源）

现状三处：`GameData.card_kind()`（**判定**）、`tools/gen_gallery.gd` 的 `KIND_*`（图鉴页）、
`UIKit.card_palette()`（演出）。**判定与展示必须分开** —— `card_kind()` 的判定顺序是契约
（`jail_to` 先于 `go_jail`、`seize_tile` 的 take/swap 分开判），**一行不动**；要收的是后两处**展示**映射。

> **顺带发现一处已经烂掉的不一致**（这正是"三处共享但没人对账"的后果）。
> **逐色对照表 —— 两边的当前实际值**（合并时照这张表改）：

| 卡型 | 演出 `card_palette(kind)[0]` | 它的 `Color.to_html()` | 图鉴 `KIND_COLOR` | 判定 |
|---|---|---|---|---|
| `good` 收益 | `GOOD` = `Color(0.455, 0.812, 0.529)` | `#74cf87` | `#7ddc9b` | 不等（页面偏亮偏青） |
| `bad` 损失 | `Color(0.94, 0.45, 0.42)` | `#f0736b` | `#f08b7a` | 不等（页面偏粉） |
| `move` 移动 | `Color(0.42, 0.70, 0.95)` | `#6bb3f2` | `#7cc4f0` | 不等（页面偏亮） |
| `jail` 查寝 | `Color(0.66, 0.52, 0.95)` | `#a885f2`（**紫**） | `#f0c064`（**琥珀**） | **完全不同色** |
| `info` 其他 | **无独立键** ⇒ 落进 `_` 默认 `ACCENT` = `Color(0.961, 0.702, 0.259)` | `#f5b342`（**金**） | `#9fb3c0`（**灰蓝**） | **完全不同色** |

- **五路全不等**：`jail` 与 `info` 更是**两个完全不同的颜色** —— 同一张「突击查寝」在页面上是琥珀、
  在卡面上是紫；同一张「翘课去兼职」（`info`）在页面上是灰蓝、在卡面上是金。
- `card_palette` 还多两个键：`bust` = `Color(0.95, 0.35, 0.35)` → `#f25959`、
  `aberr` = `Color(0.79, 0.65, 1.0)` → `#c9a6ff`。图鉴页没有对应项（它只列 `card_kind()` 的五类）。
- **`card_palette("jail")` 的 `#a885f2` 与 `card_palette("aberr")` 的 `#c9a6ff` 是两个几乎一样的紫** ——
  这正是 §1.2 实拍里"机会 `jail` 卡 ↔ 畸变卡 最易混"的根因。
- ⇒ 合并时**以演出（玩家真看到的）为准**，图鉴页那几处 hex 改由 `Color.to_html(false)` 现算、不再手写；
  且**必须给 `info` 补一个显式键**（现在它靠兜底撞上 `ACCENT`，是"没写"而不是"写了金"）。

**放哪里**：推荐放进 **`GameData`**（它已经是 `card_kind()` 的家，且 `LEVEL_COLORS` 已有
"展示色住在数据类"的先例）。关键理由：**`ui_kit.gd` 里有 `Fx.play` 这类 autoload 引用，
`--script` 模式（生成器）不能 import 它** —— `game_data.gd` 里 `CASINO_STAKE` 那段注释讲的正是这个坑。

> 备选：新建 `scripts/card_style.gd`（`class_name CardStyle`）—— 分工更干净，但**新增 `class_name`
> 要先跑一次 `--import`** 才能被 `--script` 认到（本仓已踩过），且要确认 CI 的生成器步骤拿得到它。
> 若团队更看重"数据类不掺展示"，选这条，代价是那一步 `--import`。

### 4.4 会不会牵动 `hud_test` 里钉抽卡演出的那几段

**不会** —— 前提是**签名与相位常量都不动**，本稿的派生化正好满足：

| `hud_test` 钉住的东西 | 本稿是否触碰 |
|---|---|
| 用 4 参调 `show_card("机会", …)` / `show_card("失物招领", …, "招财猫")` | **不碰**（派生化不新增参数） |
| `CARD_TIME == OUT + FLIP + HOLD` | **不碰**（四常量不动） |
| `is_awaiting_confirm()` / `is_confirm_visible()` / 收尾后 `_card == null` | **不碰**（只改画法，不改显隐逻辑） |
| `z_index < menu_layer / pause_mask / shop_layer` | **不碰** |
| "卡面就是那张 `ItemCard`"（`find_children` 按脚本类型数节点，断言 **恰好 1 张**） | **不碰** —— 道具卡面前面那张卡仍是 `ItemCard`，**别把它换成自定义卡面**；家族外发光 / 家族徽记要挂在它**外面**（兄弟节点），**别让它多出第二张 `ItemCard`** |

（它钉着卡型判定与逐字卡面文案 —— 本稿不改文案，实现时跑一遍确认）。
⇒ 改完先跑 `load_all`，再跑 `hud_test` + `chance_test` + `tools/gen_gallery.gd`。

### 4.5 摆拍验证方案

三条硬规矩（`AGENTS.md` §三）：**不加 `--headless`**（空帧）；**`--` 分隔符不能漏**；
**文件名决定摆拍内容**。出图门是 `not path.contains("plain") or path.contains("card")`
⇒ 想拍到卡，文件名**要么不含 `plain`、要么含 `card`**。三帧连拍落在 **0.6 / 1.2 / 1.8 s**。

**（0）改前基准 —— 已实拍（2026-10-10）**

下面三条命令**已于 2026-10-10 实跑并留档在 `shots/`**，就是 §1.2 那三张图的来源。
它们将来用于**逐项对比**：**同一文件名、同一参数**在改后重拍一遍，即可逐张比对。

```powershell

# ② 道具卡面（ItemCard 正面；卡背的家族色见下面（3））
```

- 每张图会连出 `x.png` / `x_1.png` / `x_2.png` 三帧；**挑第 2 或第 3 帧看**（第 1 帧可能还在 `OUT` 相位）。

把 ①②③ 并排看**卡背 / 卡框 / 底纹**：改后应当读成 **绿 / 蓝 / 紫**三族（改前：机会绿、道具与畸变都靠卡型色撞运气，见 §1.2）。

⇒ **三帧全是正面**。唯一能拍到卡背的是 `deckout` 分支：它按 **0.06 s / 0.16 s** 各补一张

（`_make_card_art`）+ 描边 + 光晕。改前的预期是：**机会 与 道具 都是绿背**
（`item_face` 那段硬借"机会"），畸变是蓝背（`deck != "机会"`）—— 这正是方案 A 要改掉的那一条。
**顺带**：`deckout` **不转轮、相机不动**，背景就是全景 ⇒ 可与 `kp_chance_card.png` 逐格比对
"桌面没被放大 / 滑动"，也能顺带看到（4）的家族地面光。

**（4）抽出瞬间的家族地面光**

同 `kp_deckout_card_outa.png` / `_outb.png`：卡背后有没有一层家族色的地面光。

**（5）改前改后对比**

用**同一文件名、同一参数**重拍一遍，逐张比对；`shots/` 已 gitignore ⇒ 基准图不进仓，仅供人工比对。

### 4.6 风险清单（按大小排）

1. **图鉴页配色被统一**（`jail` 由琥珀改紫，其余四色微调）—— 这是顺手修正一处**已烂的不一致**，
   但会让 `图鉴.html` 的 chip 颜色变。必须重跑生成器并提交，且**在设计侧确认新色是对的**。
2. **道具卡 / 失物招领的卡背 绿→蓝**（玩家可见）。理由充分（家族化），但要明确这是**有意**的。
   —— 不新增第三张牌背 SVG：那属"引入素材"，与 `AGENTS.md` §四 相悖；畸变的紫靠**底色 + 描边 +
   光晕 + 底纹色调**做出来（三色里只有机会、道具各有一张现成 SVG，畸变复用蓝的那张）。
3. **派生依赖"今天恰好只有三档"**：将来冒出第四种 `deck != ""` 的文字卡，会**静默落进 `chance`**。
   ⇒ 在派生处加一条断言 / 注释，并把这条口径写进 `联机协议.md` 的 `s_card` 行。
4. **光扫必须 clip，但别 clip `_card`**：`_card` 直接 `clip_contents = true` 会把卡外侧的投影 /
   光晕一起切掉（那是 `card_stylebox` 的 `expand_margin` 画出来的）⇒ 光扫要放进**独立的
   `clip_contents = true` 的容器**里，且**两枚徽章不能放进那个容器**（它们本就骑在卡外）。
5. **别把家族痕记加进 `ItemCard`**（最容易顺手做错的一条）：`ItemCard` 是**共用件**
   （货架 / 手牌 / 发现三选一 / 黑市 / 弹窗都用它）。那一圈家族色外发光**只能由 `DeckReveal`
   在 `ItemCard` 外面加**（兄弟节点 / 外层容器），`ItemCard` 本身**一行不改**。
   同理，若要把 `ItemCard._badge` / `_pill` 提炼进 `UIKit` 给文字卡复用，那必须是**纯搬移**（外观零变化）。
6. **畸变长标题**：标题顶部对齐后，正文可用高度变小；「🌀 畸变 · 枪打出头鸟」换行后要逐张看
   摆拍图。这正是**不采纳 B 的整段分区重做**的原因。
7. **视觉没有自动化**：`hud_test` 只能钉结构与显隐，钉不了"好不好看"。⇒ 靠 §4.5 那几张基准图
   人工比对。建议实现时把基准图留档（`shots/` 已 gitignore，不进仓）。
8. **正面外框改家族色会丢掉"红框 = 损失"的既有直觉**（实拍里的 `bad` 卡现在是红框）。
   兜底：`bad` 的卡型徽章仍用红（`#f0736b`）+ 文案「💸 损失」，**颜色 + 文字双通道**，
   比只靠一个红框更准。若实机觉得丢了直觉，备选是"外框家族色 + 内侧再加一圈 2px 卡型色细线"。

## 五、与现状的差异清单

### 5.1 纯视觉（零行为变化）

- 卡背**家族三色**（绿 / 蓝 / 紫）+ 家族色的描边 / 光晕 / 底纹色调。
- **文字卡的正面外框 / 标题 / 分隔线由「卡型色」改成「家族色」**（`good` 卡不再是红绿随卡型跳，
  而是恒为家族色）；**卡型色只留在右上徽章上**。这是本稿"看图后"改动最大的一条（见 §二 方向 A 第 1 条）。
- 卡面两枚**外挂圆徽章**（左上家族、右上卡型），尺寸 **`bs ≈ 36`**（不是 `ItemCard` 的 72）。
- 卡型**图标 + 中文 + 色**上卡面（文字卡）。
- 标题**粗体 + 顶部对齐**；分隔线**两端渐隐**；圆角 16 → 18。
- **翻面光扫** / **家族地面光** / 呼吸**偏家族色**。
- **道具卡（含失物招领）卡背 绿 → 蓝** + 一圈家族色外发光（其品质色外框与自身徽章**全不动**）。
- 图鉴页五个卡型 chip 的颜色改为与卡面同源（`jail` 由琥珀 → 紫、`info` 由灰蓝 → 金）。

### 5.2 动了结构（但**不动玩法**）

- 拆开 `"机会"` 兼作配色键与卡类名的纠缠：`_deck_back_tex` / `_make_card_art` / `_card_face_back`
  的形参由"标题"改成"家族"，并新增家族派生（§4.1）。
- 新增**家族表**与**卡型表**，把 `card_palette` 与图鉴的 `KIND_*` 并到**单一来源**（§4.3）。
- `gen_gallery.gd` 的 `KIND_*` 改读同一来源 ⇒ **重跑生成器、提交 `图鉴.html`**。
- `ItemCard._badge` / `_pill` 提炼进 `UIKit`（`ItemCard` 版式与行为不变）。
- `dev_tools.take_shot` 加 `ckind` 摆拍分支（纯开发工具）。

### 5.3 明确**不动**

- `GameData.card_kind()` 的**判定顺序**（契约：`jail_to` 先于 `go_jail`、`seize_tile` take/swap 分开判）。
- `DeckReveal` 的四个相位常量（`OUT` / `FLIP` / `HOLD` / `BACK`）与 `tick()` 的相位判据。
- `s_card` / `show_card` 的**签名**（RPC 表不动；`deck` 仍 = 标题）。
- `ItemCard` 的版式与既有品质语言。
- **相机**：演出全程不动 —— 这是屏幕层演出的立身之本，任何"推近镜头"的方案都不予考虑。
