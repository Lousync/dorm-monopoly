# v0.5.0 批次 10 实施计划：棋盘放大（几何优化）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让棋盘在桌垫/木桌上占比更大、两端格内文字大约 **+12~15%** —— 桌垫留白收窄、木纹框变薄、相机拉近。

**Architecture:** 纯**常量重定标 + 对着既有断言夹值**。改 `MAT_MX/MT/MB`（桌垫留白）→ `MAT_RECT` 变 →
**必须同步重算** `TEX_WINDOW_PX`（同比例同中心）→ `TABLE_D` 派生变（桌面变浅）；`WOOD_FRAME` 变薄 →
**`LAMP_BASE` 必须跟着内移**；`fit_zoom` 变 → **`HAND_BASE_PX`（画布常量）必须重取**；最后收
`CAM_DIST` / `VIEW_DIST_2D`（**一起收**）到取景余量逼近下限。

**Tech Stack:** Godot 4.6.2 / GDScript / `gl_compatibility`。

**Spec:** `doc/development/plans/v0.5.0-批次10-设计.md`（本计划实现的就是它）。

## Task 1: 桌垫留白 + 木纹框 + 贴图窗口 + 两处锚点重取（相机**不动**）

**Interfaces:**

- Produces（Task 2 依赖）：重定标后的 `MAT_*` / `WOOD_FRAME` / `TEX_WINDOW_PX` / `HAND_BASE_PX` / `LAMP_BASE`。
- **过渡态（知悉）**：本任务不动相机 ⇒ 棋盘会**先变得比之前略大一点（约 +6%）**，但相机推近要到 Task 2
  ⇒ **本批不得只发布 Task 1**（"字更大"要到 T2 才成立）。

- [ ] **Step 1: 改桌垫留白 + 木纹框 + 重算贴图窗口**

`scripts/board_view.gd`：`MAT_MX := 40.0`、`MAT_MT := 40.0`、`MAT_MB := 90.0`（**三个一起缩**）。
`scripts/table_3d.gd`：`WOOD_FRAME := 0.7`。

然后**按新 `MAT_RECT` 重算** `TEX_WINDOW_PX`（别抄旧值）：

```
MAT_RECT.size = (2016 + 2*MAT_MX, 1344 + MAT_MT + MAT_MB) = (2096.0, 1474.0)
ratio   = 1474.0 / 2096.0 = 0.703244…
size.y  = MAT_WINDOW_W * ratio = 2020.0 * 0.703244 = 1420.55
position= ((2048 - 2020)/2, (2048 - 1420.55)/2) = (14.0, 313.72…)
⇒ TEX_WINDOW_PX := Rect2(14.0, 313.72, 2020.0, 1420.55)
```
**写进代码时要带算式注释**（照该常量原有的注释风格），并注明"与 `BoardView.MAT_RECT` 同比例同中心、
改一边必须改另一边（`layout_test` 有断言）"。

- [ ] **Step 2: 重取 `HAND_BASE_PX`（画布常量，桌垫一缩就漂）**

起手值 `Vector2(1009.0, ~1800.0)`。**判据是 `layout_test` 手中牌那一族的 5 条**（整排落在**木纹留白**上、
在木桌内、不陷桌、连命中盒也没被画布边缘裁掉、比棋盘更靠自己）。
夹法：整排的**屏幕包围盒**要落在"桌垫下沿之外、木桌之内"那条带里且上下都留余量。
- 提示：新桌垫下沿（画布 px）= `1024 + 1420.55/2 = 1734.3`；木桌下沿 ≈ 1734.3 + 0.7×(2020/8) = **1911.0**
  （0.7 世界单位 = 176.75 画布 px）。整排牌心别贴着这两条线。
- **同时更新那段注释里的实测数字**（它写着旧口径下"上沿离桌垫下沿 47.0 画布像素"之类的数）。

## Task 2: 相机夹值 + "字更大"的可执行断言 + 出图

**Files:** `scripts/table_3d.gd`、`tests/layout_test.gd`

- [ ] **Step 1: 先加断言（在相机还没动时量基线）**

在 `tests/layout_test.gd` 的取景段（21 档余量 / 面积比那一段之后）加：

```gdscript
	# 批次 10：本批的目标是"字更大"，而"看着像"拦不住回退 —— 钉一条**格子的屏幕宽度下限**。
	# 取**最不利**的一格（远端中间那格：50° 俯角下它被透视压得最扁），量它四角投影的包围盒宽。
	# 基线（批次 9 的取景）：约 63px；批次 10 收完相机后应 ≥ 70px。
	t3.snap_view(0.0)
	var probe_idx: int = t3.board.grid_to_index(GameData.BOARD_COLS / 2, 0)   # 远端中间
	var tp: Vector2 = t3.board.tile_pos(probe_idx)
	var tmn := Vector2(INF, INF)
	var tmx := Vector2(-INF, -INF)
	for sx in [0.0, 1.0]:
		for sy in [0.0, 1.0]:
			var wp: Vector3 = t3.canvas_px_to_world(tp + Vector2(sx, sy) * t3.board.TILE)
			var sp: Vector2 = t3.camera.unproject_position(wp)
			tmn = tmn.min(sp)
			tmx = tmx.max(sp)
	var tile_w: float = (tmx - tmn).x
	_check(tile_w >= 70.0,
		"格子的屏幕宽度 ≥ 70px（实得 %.1f；批次 9 基线约 63px —— 这是本批'字更大'的判据）" % tile_w)
	t3.snap_view(1.0)
	# 2D 端同样量一次（两个端都要更大，用户就是这么说的）
	var tmn2 := Vector2(INF, INF)
	var tmx2 := Vector2(-INF, -INF)
	for sx in [0.0, 1.0]:
		for sy in [0.0, 1.0]:
			var wp: Vector3 = t3.canvas_px_to_world(tp + Vector2(sx, sy) * t3.board.TILE)
			var sp: Vector2 = t3.camera.unproject_position(wp)
			tmn2 = tmn2.min(sp)
			tmx2 = tmx2.max(sp)
	var tile_w2: float = (tmx2 - tmn2).x
	_check(tile_w2 >= 70.0, "2D 端格子屏幕宽度也 ≥ 70px（实得 %.1f）" % tile_w2)
	t3.snap_view(0.0)
```

**先跑一次**（相机未动）：它会**红**（基线约 63px）—— 那就是本任务要抬上去的量。
**把两个基线数（3D 端 / 2D 端）记进报告与常量注释**。

> **70 这个下限是"许愿值"，按基线修正**：量出基线 `b` 之后，**下限先按 `ceil(b × 1.10)` 定**
> （本批目标是 +12~15%，取 10% 作为"确实变大了"的保守门槛）。若收完相机后能到的最大值
> `m ≥ ceil(b×1.10)`，就把下限钉在 `ceil(b×1.10)`；若 `m` 到不了（几何上限），**把下限钉在
> `m × 0.98`（略低于实测，只拦回退）并在报告里如实写明"只到 Xpx"**。别为了过断言去动
> `MAT_*` 的布边底线或裁棋盘。
