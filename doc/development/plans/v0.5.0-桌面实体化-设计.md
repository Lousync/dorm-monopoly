  另有一张 2D 视角：牌摆在深色木桌上、略俯视，卡是**有厚度和投影的实体**。

**两条被这两组图纠正的认知**：
1. 两个参考**都不是"转视角围观"**，而是**坐在桌边第一人称看桌面**——印证了批次 1「删除转视角」的方向。
2. **邪恶铭刻的桌垫是印的（平的），牌和道具才是实体**——这正是本设计要走的「路线 B」。

**从参考里提炼的三条观感要素**（也是本方向的目标）：
- **物理感**：牌/物件有厚度、有投影、会微微抬起；
- **自己的手/牌**是锚定"我坐在这儿"的最强线索（两个游戏都有）；
- **单点暖光 + 四周近黑**：观感主要来自光，而不是几何。

## 二、目标与非目标

**目标**：把对局界面从"一张斜放的印刷桌垫 + 屏幕 HUD"变成**一张铺着桌垫的实体书桌**——
桌上有实体物件、手里握着牌、身后是几乎全黑只有台灯亮着的宿舍。

**非目标**（本方向不做）：
- 不做完整 3D 化（路线 C：格子/棋子/转盘的渲染层推倒重来）——**保留批次 2 的贴图当桌垫**。
- 不动玩法逻辑与数值；不动 `联机协议.md`（视角与手牌都是**本地表现**，不进 `s_state`）。
- 不做真实宿舍房间建模（只做**剪影 + 单光源**）。

## 三、第 1 节：交互重排（手中牌 + 桌上实体）

**拆掉**
- **底部操作坞整条**（自己的头像/现金/体力槽 + 5 个道具牌位 + 「转动转盘」「使用道具」两个按钮）。
- **座位卡上的道具牌位那一排**（四家都拆）。

**新增（桌面上的实体，3D 视角可见）**

| 原件 | 新形态 |
|---|---|
| 自己的 5 个道具 | **手中牌**：有厚度的实体卡，近端、朝自己倾斜。点一张选中 → 再点目标（沿用现有两段式选目标逻辑） |
| 自己的现金 | **桌上筹码堆**：按金额分档（如每 ¥5,000 一枚） |
| 自己的体力 | **面前一排 5 个小件**（用掉的熄灭） |
| 转盘 | 桌面中央**可点实体** = 掷轮入口 |
| 机会/命运牌堆 | 两摞**有厚度的实体**（抽卡四段动画沿用） |

**座位卡 → 桌上立牌（第 5 批次）**：改造为**有厚度、带投影的 3D 立牌**；
**名字 / 身家 / 操作倒计时 / 点选目标 / 公开背包 全部原样保留**，只去掉道具牌位那一排。
（自己的那面立牌在 3D 视角退到画面外——第一人称看不见自己；2D 视角下仍可见。）

**屏幕层**：保留「暂停 / 战报 / 规则说明」三个角按钮、事件气泡、格详情卡；
新增**四角身家条**（名次 + 名字 + 身家，四家都挂，像骗子酒馆的头像角标）。

## 四、第 2 节：双视角 + 滚轮

**相机沿一条平滑轨道连续推移**（由滚轮累积量驱动，**不是硬切开关**）：
- **3D 端**：第一人称俯看桌面（约 50°），手里有牌；
- **2D 端**：接近正俯视（85~90°），只看桌上地图，手牌移出视野；
- 滚轮**向前** → 推向 2D；**向后** → 拉回 3D。

**各视角能干什么**
- **2D**：点桌上转盘**可掷轮**；手牌不显示（**出牌要回 3D**）。
- **3D**：点手牌出牌；点转盘掷轮。

**取消**：相机推拉（批次 2 的滚轮功能）被视角推移取代。
**视角是纯本地的**：各客户端各自切，不进协议、不同步，玩法逻辑一行不动。

## 五、第 3 节：3D 物件与房间

**路线 B**：批次 2 那张贴图**降级为"印在桌上的桌垫"**（邪恶铭刻的做法），其上叠**真 3D 物件**（有厚度、能投影、能遮挡）。

**物件**：手牌 / 两摞牌堆 / 转盘（可点）/ 筹码堆 / 体力件 / 对手立牌×3。

**房间**：近黑 + 剪影（书架、床架）+ **一盏台灯**当唯一暖光源。
→ 连带：批次 2 因"当时无投影物"**关掉了阴影**，本批要**重开**，并让台灯有衰减、四周落到近黑。
> **补记（2026-10-04 终审修复波 D）**：「剪影可辨」**不能只靠这盏灯** —— 台灯够得到近处的书架
> （离灯 ~6.1，出图 19/255），够不到远处的床架（~11.0，出图 **1/255**，比它身后的近黑背景
> 4~6/255 还暗）。剪影靠材质的**极弱自发光底光**（`table_3d.ROOM_EMISSION`）抬到背景之上
> （实测床架 18/255），"台灯是唯一主光源"这条不变（底光只有背景量级）。

**素材**：优先开源——**Kenney** 的 3D 家具/道具包、**ambientCG** 的贴图（均 CC0、可商用）；
筹码/立牌/体力件这类**程序化生成**（BoxMesh/CylinderMesh + 自绘贴图）。
按规矩登记进 `assets/CREDITS` 与根目录 `LICENSE` 的「第三方素材」一节。

## 八、风险与待定

**风险**
1. **性能**：3D 物件 + 重开阴影 + 2048² SubViewport 每帧重绘，叠加在一台 MX550 上；批次 6 要实测帧率。
2. **对齐**：3D 物件必须与"桌垫贴图"的 UV 坐标系严格对齐（批次 2 的 `TableGeometry` 已提供换算），否则物件会漂。
3. **手牌可读性**：手牌是斜的，卡面文字会比屏幕层难读——这正是第 4 条放宽原则的代价，需对着图调角度与字号。
4. **素材授权**：Kenney/ambientCG 是 CC0 可商用，但仍须登记；**参考截图有版权，不入库**。

**待定（做到那步再定）**
1. 体力件具体是什么小件（对着图定）。
2. 筹码堆的分档与上限（对着图定）。
3. 手牌的排布（扇形/并排）、选中与出牌的具体手感。
4. 2D 端的确切俯角（85° 还是 90°）。
5. 台灯的位置与照射范围。

## 九、批次 4 开工前补记（2026-10-04 · 代理自行拍板，用户睡前授权）

**1. 本机拿不到外部素材 —— 批次 6 改走"程序化 + 现有本地素材"。**
实测：WebSearch 返回空、WebFetch 对外域一律被拦（`Unable to verify if domain … is safe to fetch`）。仓库现有可用素材只有
`assets/textures/wood_floor.jpg`（ambientCG WoodFloor064，CC0）、`assets/icons/`（99 个 twemoji）、
`assets/pieces/`（4 个 Kenney 棋子贴图）、`assets/cards/`（2 个 CC0 牌背），**没有任何 3D 模型**。
⇒ 批次 6 的"Kenney 3D 家具包 / ambientCG 贴图"改为：**网格全程序化**（`BoxMesh`/`CylinderMesh`/`TorusMesh` 拼剪影），
贴图只用**仓库里已有的那份木纹**。原设计稿 §五 的"程序化生成"那条从备选升级为唯一路径。**授权登记不变**（新增素材为零）。

**2. 批次 2 推迟的"棋盘铺满桌面"比例目标，被批次 5 的立牌解锁。**
批次 2 的 T4c 裁定"纹理窗口必须覆盖整张画布"（否则四条座位栏既看不见也点不到），把比例目标推迟到"座位栏换成桌上立牌"之时 ——**那正是批次 5**。
⇒ 批次 5 应一并做：座位栏离开 2D 画布后，**把 `TEX_WINDOW_PX` 收到棋盘区域**、**放大桌面平面**并给外圈加木纹边框
（桌垫 = 印在木桌上的一块布），这才是参考里那个观感的最后一块。**批次 5 的 dispatch 必须点名这条**，否则它会随批次 2 的注释一起被忘掉。

**3. 立牌必须"向后倾"。** 2D 端接近正俯视，直立薄板从上方看只剩一条线；立牌向后倾（像桌上的菜单牌）才能让
3D 端看到正面、2D 端也仍看得到一块被压扁的面。倾角对着图定。
