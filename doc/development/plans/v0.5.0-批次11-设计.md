# v0.5.0 批次 11 设计：小人与房子立体化 + 悬停信息条上屏幕层

> 状态：**设计（待评审）** ｜ 立项 2026-10-04 ｜ 范围：**⑤**（本版本最后一批）
> 上级：用户需求五条。③ 已拆为批次 9（B）/ 批次 10（A）并完成；**本文 = ⑤**。
> 用户原话：`⑤ 3D视角下，鼠标悬停到棋盘上的玩家小人上时，显示的玩家信息弹窗的角度不对
>（角度变成面向我）；3D视角下，小人和房子也要立体（角度变成面向我）`。

## 1. 目标

棋盘上那两样**画在桌垫上的平面图案**（玩家棋子「小人」、装修「房子」）做成**立在桌上的 3D 薄牌**，
并把"悬停小人时浮出的信息条"从**画布**（随桌面倾斜、所以在 3D 下是歪的）搬到**屏幕层**（天然面向镜头）。

## 2. 为什么必须动、以及为什么这么动

- 桌垫是一张**印在桌上的贴图**（`TableProps` 与 `board_view` 的分工见架构总览 §五）：
  **图案随桌垫一起倾斜**，所以 3D 下"小人"和"房子"看着就是**贴纸**，悬停提示条也是**歪的**。
- 批次 6/9/10 已经确立的做法：**有厚度、能投影、能互相遮挡的实物一律搬进 `TableProps`**
  （转盘轮缘 / 两摞牌堆 / 手牌 / 已退场的立牌）。本批把最后两样图案按同一条规则搬过去。
- 薄牌（不是真 3D 建模）：与用户选的"立起来的 3D 薄牌"一致（真建模工作量大、且这游戏的美术是
  程序化 + 现有素材）。**后倾 ≈25°**（与已退场的立牌同款做法）—— 那样 2D 端（近正俯视）与
  3D 端（50°）**都能看见一块面**，直立薄板在 2D 端会只剩一条线。

## 3. 与其它部分的边界

- **不动**玩法逻辑 / `@rpc` / `s_state` 字段 / 取景常量（批次 10 刚重定标完）。
- **不动**桌垫上印着的东西：格子底板、格名/价格、归属色带、格详情卡的锚点（`tile_screen_pos`）。
- **不动**四角身家条 / 道具弹窗 / 抽卡演出（批次 8~9 的成果）。
- 悬停**信息条的内容**（昵称 / 身家 / 名次）与判据**不变**，只换载体与朝向。

## 4. 两条**控制器先定**的设计细节（可推翻，但要说理由）

### 4.1 动画保真度：**保留四样，全部在 3D 里重写**

现有 2D 棋子有四样动作（`board_view.play_move` / `_teleport_anim` / `_make_token` 的弹入 / `_set_ring`）：

| 动作 | 本批做法 |
|---|---|
| **逐格走子** | position 补间（世界坐标）+ **竖直小跳**（抬 y 一个弧）+ 落地**挤压**（scale y 压 / x 张，回弹）—— 音效 `Fx.play("tick")` 保留 |
| **传送**（`传送` 类道具） | 材质 alpha 淡出 → 瞬移 → 淡入 + 回弹（`TRANS_BACK`）—— 需要把薄牌的材质切成 ALPHA 混合（**淡完切回不透明**，照手牌那套既有做法） |
| **弹入**（新棋子出现） | scale 从 0 弹到 1（`TRANS_BACK`） |
| **当前行动者光环** | 一条**3D 光环**（薄圆环 / 扁圆柱，贴桌垫、随行动者移动）—— 不再用 2D Panel |

**不做**：更花的表现（拖尾、粒子、影子单独动画）。**理由**：这四样是"看得懂发生了什么"的下限，
其余是装饰；本批的风险已经够高（棋子动画从 2D 搬 3D 是这条链上最重的一步）。

### 4.2 房子贴图：**烘焙 4 张等级纹理**（复用现有画法，不新建素材）

房子图案现在是 `board_view.HouseIcon`（一个 `Control._draw`：墙 + 屋顶三角 + 门，颜色取 `GameData.level_color`）。
薄牌需要一张**纹理**。做法：**建一个 `SubViewport`（约 64×48，透明底）**，在里面跑一次现有 `HouseIcon`
的绘制，`get_texture()` 拿到纹理 —— **4 个等级各烘一张、建的时候烘一次**（不是每帧）。
- 好处：**画法只有一份**（`HouseIcon` 不复制），且与桌垫上原来的配色/形状逐像素一致。
- 代价：多一个 `SubViewport`（一次性的，烘完可以留着复用）。**若实测更省的做法存在（例如直接
  画进 `Image`），实现者可以换 —— 但必须在报告里说明为什么**。

## 5. 设计

### 5.1 棋子（小人）搬进 `TableProps`

- 每张薄牌 = `BoxMesh`（宽 × 高 × 厚，尺寸写死**世界单位**，与"手牌/立牌不跟 2D 相机"同一条约定），
  正面贴 **Kenney 棋子贴图**（`UIKit.piece_tex(slot)`，素材缺失时退回纯色块 —— 与现状一致）。
- 位置 = `canvas_px_to_world(tile_pos(idx) + TILE/2 + slot_offset)`（**与印刷图案同一套链**；
  `TILE` / `slot_offset` 从 `board_view` 沿用，不另立一份）。
- **后倾 ≈25°**（绕 X 负角：顶边往远端倒 ⇒ 面朝近端镜头）。
- 节点池：每 peer 一块，**只建一次**；刷新只改 transform / 可见性 / 贴图（照手牌的幂等约定）。
- **鼠标透明**：棋子不吃点击（点它下面那格仍是"点格子"）—— 与现状一致（棋子 `MOUSE_FILTER_IGNORE`）。
- **悬停命中**：`TableProps.token_hit(canvas_px) -> int`（`-1` = 没命中）：把薄牌的八个角经
  `unproject_position` → `screen_to_viewport` 折成画布像素取包围盒（**与 `hand_rect` / 已退场的
  `_standee_rect` 同一条链**），重叠时取**离相机最近**的那块。**不缓存**（相机一变就得重算）。

### 5.2 光环（当前行动者）

- 一条**贴在桌垫上的环**（`TorusMesh` 压扁 / 或一个扁圆柱的环），套在当前行动者的棋子上；
  跟着棋子走（每帧重贴它的世界位置）。
- 尺寸**跟印刷图案**（`board_view` 报一个画布像素半径 ⇒ 3D 侧量真变换换算成世界单位）——
  与转盘轮缘同一条口径（它也是"压在印刷图案上"的），这样滚轮推近时环不会与格子脱开。

### 5.3 房子搬进 `TableProps`

- 每格一块薄牌，位置 = 格内那条带（现在 `HouseIcon` 在格子右下 y84-106 那条带）⇒ **沿用同一个
  格内相对位置**（画布像素），**位置与尺寸都跟印刷图案**（同转盘轮缘/牌堆的口径：它们压在格子上，
  取景一缩放就得跟着）。
- 正面贴 §4.2 烘出来的等级纹理；`level == 0` ⇒ 整块隐藏。
- 节点池：每格一块（56 格 × 1 块），只建一次。

### 5.4 悬停信息条上屏幕层

- 从 `board_view._token_tip`（画布 Control）搬到**屏幕层**：由 `TableHud.build_play_ui` 建一个
  `g.token_tip`（屏幕层 Control，`z_index` 取**屏幕 HUD 带内**的值 —— **写之前先核对目标层现有 z**，
  照批次 8/9 的规矩；它不该盖住四角身家条与动作按钮的交互，也不该被它们盖住）。
- **内容与判据不变**（昵称 / 身家 / 名次 / 已出局），数据来源不变（`board._peers_info` 那份 ⇒
  由 `game` 在广播时喂给屏幕层，或屏幕层直接读 `st` —— **单一来源仍是 `_refresh_players` 那份**）。
- **朝向**：屏幕层 Control 天然面向镜头 ⇒ 这就是用户要的"角度面向我"。
- **位置**：`game` 每帧把棋子的**屏幕坐标**（`TableProps` 给世界点 → `camera.unproject_position`
  → 屏幕）喂给它，摆在棋子正上方；出屏时按既有逻辑夹在屏幕内。
- **悬停判定**：`TableView3D._unhandled_input` 的 `InputEventMouseMotion` 分支里，现在把屏幕点映射
  成画布像素后**没有**转给实体层 —— 本批让它在 `_unhandled_input` 里**先问实体层**
  （新增 `on_table_hover: Callable`，签名 `func(canvas_px: Vector2) -> int`，返回 peer 或 NO_PEER），
  拿到谁就交给 `game` 去显隐信息条。**默认无效（Callable()）= 不悬停任何人**（同 `on_table_click` 的注入方式）。

## 7. 验收

1. 全量套件 + 联机回归全绿、`SCRIPT ERROR` 0。
2. **出图**（真实窗口）：3D 端一张**近景**（`freecam` + 焦点落在有棋子的格）—— 小人立着、
   房子立着、**悬停信息条正着读**；2D 端一张确认两端都看得见。
3. **可执行断言**：棋子薄牌的 `BoxMesh.size.y > 0.1`（有高度、不是平面）、法线不朝上
   （后倾 ⇒ 2D 端也看得见一块面）、**`token_hit` 在棋子画布落点上命中、在空白格上不命中**、
   **信息条挂在屏幕层**（`get_parent()` 是屏幕层、且它的 `size`/位置随相机变化被重摆）。
4. **动画的可观察量**（走子/传送不能"看不见"）：`play_move` 期间棋子的世界 y 有抬升（弧），
   传送期间材质 alpha 下过 0（用 `token_alpha()` 之类的只读查询钉住）。
5. 单人试玩：走子看得出逐格跳动、传送看得出淡出淡入、悬停小人弹出正着的信息条、
   房子在小人旁边立着。

## 8. 不变量与风险

- **不变量**：玩法 / `@rpc` / `s_state` / 取景常量 / 新增素材（`LICENSE`）一律不动；
  **棋子与房子在桌面上的"格内相对位置"不变**（玩家看到的位置不该变，只是从贴纸变实物）。
- 风险一：**棋子动画是最重的一块**。2D 的 `Tween` 直接改 `position`/`scale`/`modulate`；
  3D 要改 `global_position`（含 y 抬升）、`scale`（绕自身轴）、`材质 albedo.a`。
  **淡入淡出必须把材质在不透明 ↔ ALPHA 之间切**（手牌那套先例），否则在 3D 端会脱出深度写入。
- 风险二：**光环/房子"跟印刷图案"**（位置 + 尺寸都跟 `board._zoom`）—— 抽卡推近虽然已取消
  （批次 8），但取景/人数变化仍会改 `_zoom` ⇒ 与轮缘/牌堆同一条规则，**每帧或每次广播重推**。
- 风险三：悬停从"画布内命中"改成"3D 命中 + 屏幕层显示"，**中间那一步（相机不可用/命中落空）要有降级**
  （照 `standee_screen_center` 那条先例：拿不到就返回 null / 不收条）。
- 风险四：56 格 × 1 房子薄牌 + 4 块棋子 + 1 光环 —— **节点数与绘制数上升**，必须**实测帧率**
  （`--fps=N`）并与批次 10 的数字对比；薄牌都用**同一份 mesh/材质**（按等级分 4 份材质），别一格格新建。
