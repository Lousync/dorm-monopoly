# v0.5.0 批次 9 设计：立牌退场 + 四角身家条开道具弹窗 + 选目标换落点

> 状态：**设计（待评审）** ｜ 立项 2026-10-04 ｜ 范围：**③ 的后半（B）**
> 上级设计：本次会话用户需求五条。整体走**方案 A**；③ 经用户确认**拆两批**：
> **批次 9 = (B)（本文）**、批次 10 = (A) 棋盘放大、批次 11 = ⑤ 小人与房子立体。
> 先做 (B) 的理由：(A) 必须重取 `STANDEE_BASE_PX`（立牌桌位），而 (B) 正好把它删掉。

## 1. 目标（批次 9）

把"桌上那块显示玩家信息的 3D 立牌"整条退场，玩家信息与"选目标"都搬到**屏幕层的四角身家条**上：

1. **立牌退场**：删掉 `TableProps` 的 standees 子层（约 500 行）与 `game._refresh_standees`。
2. **四角身家条可点**：点某一条 → 打开该玩家的**道具弹窗**（卡牌 / 能量 + 身家现金）。
3. **选目标改点身家条**：指向性道具（强拆令 / 交换生 / 包场 等）的"点玩家"从"点桌上立牌"改成
   "点屏幕上的身家条"；"可选中"的高亮反馈也随之从立牌搬到身家条。

用户原话：`③…玩家的卡片（桌面上显示信息的）去掉，点击屏幕上的玩家弹窗弹出他的道具弹窗，显示他拥有的卡牌、能量等`。

## 2. 为什么可以安全地删立牌（先证明没丢东西）

立牌上原本有四样信息，逐条核对它们的去处：

| 立牌上的东西 | 退场后去哪 | 依据 |
|---|---|---|
| 名字 / 身家 | 四角条**本来就有**（大字身家 + 小字现金） | `game._refresh_corner_bars` |
| 公开背包（品质色小卡 + 件数） | **道具弹窗**（本批新增，且比"品质色小卡"信息更全） | `st.players[].items` |
| 操作倒计时 | 四角条**本来就有**一条独立的倒计时行 | `game._refresh_corner_timer`（批次 5 修复波 A 就是为"自己的回合在 3D 端看不到秒数"加的，正好是立牌退场后唯一的落点） |
| "可被选中"高亮 | 四角条的高亮样式（本批新增） | `game._push_peer_highlight` |

⇒ **删立牌不丢任何一条信息或反馈**。四角条在 3D / 2D 两端都常驻（比立牌更稳）。

## 3. 与后续批次的边界（本批次**不做**）

- **不做** 棋盘放大（批次 10）：`MAT_*` 留白、`WOOD_FRAME`、`CAM_DIST` / `VIEW_DIST_2D`、`TEX_WINDOW_PX`、
  `HAND_BASE_PX` **一律不动**。本批只删立牌、不动任何取景常量。
- **不做** 小人与房子立体、悬停信息条上屏幕层（批次 11）：`board_view` 的棋子与本批无关。
- **不动** 玩法逻辑 / `@rpc` / `s_state` 字段 / `s_card` 签名。

### 4.2 四角身家条可点（`table_hud.gd` + `game.gd`）

- `_make_corner_bar` 的 `root.mouse_filter`：`IGNORE` → **`STOP`**（它现在要吃点击），
  并 `root.gui_input.connect(...)` → 回调宿主 `game._on_corner_bar_clicked(peer)`。
  **条内的子控件保持 `IGNORE`**（否则点到名字那块就不冒泡到条根）；`root` 的 `STOP` 会接管。
- `game._on_corner_bar_clicked(peer: int) -> void`（唯一后果函数）：
  - **在选目标态**（`_tgt_stage == "peer"`）→ 走**既有的** `_on_seat_clicked(peer)`（它自己会判
    "是不是可选目标"，非目标静默 no-op）。**不开弹窗**（选目标途中弹模态会互相打架）。
  - 否则 → 打开该玩家的道具弹窗（4.3）。
- **"可选中"高亮搬到四角条**：`game._push_peer_highlight(peers)` 现在把 `peers` 推给
  `_refresh_corner_bars` 之外的新入口 `_refresh_corner_highlight(peers)`：命中的那几条描**金边 + 提亮**，
  其余回到常态。**注意 `_refresh_corner_bars` 有签名缓存（状态没变就早退）** ⇒ 高亮**不能**塞进那段，
  要单独贴一次（与 `standee` 时代"广播后重放高亮"同款：`_refresh_corner_bars` 跑完后再调一次
  `_refresh_corner_highlight`，或把它计入签名）。

### 4.3 玩家道具弹窗（新文件 `scripts/player_popup.gd`，`class_name PlayerPopup extends Control`）

屏幕层模态（挂在 `game` 的 `hud` 层里，与四角条同层）：

- **形态**：全屏压暗底（`MOUSE_FILTER_STOP`，点它 = 关闭）+ 居中面板。
- **`z_index = 45`**：高于棋盘 / 四角条 / 动作按钮 / 抽卡大字卡（40）；低于**整个模态带** ——
  结算 50 / 弹问 60 / 小卖部 70 / 暂停菜单 80。
  **写这一档时必须核对目标层全部现存 z**（批次 8 的 `menu_layer` 没设 z 是一次教训；
  本批 Task 2 的审查又抓到**第二次**：初稿写 65，漏算了 **结算 50 与弹问 60** ⇒ 会盖住**弹问面板**。
  可达路径：在掷轮窗口里开着弹窗 → 超时被系统代掷 → 落在可买格弹出购买询问（460 宽 / z 60）
  → 被弹窗的压暗底（STOP）压住、点不到 ⇒ **静默超时放弃**）。
- **内容**（数据全取**已同步**的 `st.players[peer]`，客户端也准）：
  - 标题行：玩家名（自己标「我」）+ 名次徽章（复用 `UIKit.rank_badge`）+ 棋子色小片；
  - 一行大字：**身家**（`_state_worth` 同款口径）+ 小字**现金**；
  - **能量（体力）**：`current / cap` 数字 + 一排点亮/熄灭的小格（形态对齐原来的体力件，但只是 2D 读数）；
  - **卡牌列表**：一件一行或一格 —— 图标（`ItemData.def(id).icon` → `res://assets/icons/<icon>.png`）+
    品质色边框（`ItemData.QUALITY_COLORS`）+ 名称 + **冷却**（`cd > 0` 时显示"冷却 n"）+
    **被动**标记（`type == "passive"`）；`implemented == false` 的照常列出但标"未实装"；
  - 空背包显示"背包是空的"；
  - 破产（`alive == false`）显示"已出局"，其余读数照旧。
- **接口**：`open(peer: int, data: Dictionary) -> void`（`data` = 名字/身家/现金/体力/上限/卡牌/破产，
  由 `game` 组装，**单一来源仍是 `game` 的 `_state_*`**）、`close() -> void`、`is_open() -> bool`。
- **关闭**：✕ / 点压暗底 / `Esc`（接进 `game._unhandled_input` 的 Esc 链）。
- **数据刷新**：打开期间来状态广播 → 重填（保持打开），玩家离场/对局结束 → 关闭。
- `DeckReveal` 的教训：**卡片/文字/图标这些子控件的 `mouse_filter` 一律显式 `IGNORE`**，只有压暗底吃点击。

### 4.4 飞钞终点改四角条

`_spawn_money_fly(peer, diff)` 现在把终点设在 `table_props.standee_screen_center(peer)`
（立牌牌心）。改成**该玩家四角条的屏幕中心**：`game` 侧新增
`_corner_bar_screen_center(peer) -> Variant`（查 `corner_bars` 里 `peer` 对上且 `root.visible` 的那条，
返回 `root.get_global_rect().get_center()`；查不到或不可见返回 `null`）。调用方保持"拿不到就退回棋子"
的既有降级（`card_at = token_at`）。

## 6. 验收

1. `load_all` + 全量套件全绿、`SCRIPT ERROR` 0。
2. **hud_test 新断言**：
   - 四角条 `root.mouse_filter == STOP` 且点它**真的**开了弹窗（弹窗 `is_open()` 且内容含该玩家的
     卡牌数 / 体力值）—— 用**真点击链路**（`root.gui_input` 发一个按下事件或调
     `_on_corner_bar_clicked`，两者都要有一条）；
   - 弹窗里**卡牌数与 `st` 一致**、**体力值一致**、被动件有被动标记；
   - 选目标态下 `_push_peer_highlight([...])` 后**那几条身家条描金边**（读材质/样式盒，不读内部标志），
     其余没亮；点亮的条被点 → 走 `_on_seat_clicked`（选目标链通）；
   - **反向契约**：`table_props` 上不再有 `set_standees` / `standee_hit` / `set_standee_timer` /
     `set_standee_highlight` / `standee_screen_center`；`game` 上不再有 `_refresh_standees`。
3. **联机回归同一条命令跑完**（改动了选目标链路与飞钞落点）。
4. **出图**：一张"点开某玩家道具弹窗"的图（弹窗里卡牌/能量读得出）+ 一张"选目标态下四角条亮着"的图
   （`--shot=xx_target_plain.png` 那条分支改到四角条高亮）。
5. 单人试玩：点四角条 → 弹窗开/关（✕ / 点外部 / Esc）；用一张指向性道具 → 四角条亮 → 点亮的条能选目标。

## 7. 不变量与风险

- **不变量**：玩法逻辑 / 数值 / `@rpc` / `s_state` 字段 / 哨兵 / 新增素材（`LICENSE`）一律不动；
  **本批不动任何取景常量**（`MAT_*` / `WOOD_FRAME` / `CAM_DIST` / `VIEW_DIST_2D` / `TEX_WINDOW_PX` /
  `HAND_BASE_PX`）。
- 风险一：四角条改成 `STOP` 后**会吃掉它那一小块屏幕上的点击** —— 那块原先落在 3D 桌面上（点格子/点棋子）。
  四条都在屏幕角、与棋盘主体不重叠（批次 5 就有"角标不遮挡立牌与三个角按钮"的断言），所以影响面小；
  但要出图核对一次。
- 风险二：`_refresh_corner_bars` 的签名缓存会把"只变高亮"的广播早退掉 ⇒ 高亮必须**独立贴一次**（4.2 已写明）。
- 风险三：弹窗的 z 档必须**核对目标层现有 z**（批次 8 的 `menu_layer` 教训）；且要有一条断言钉住
  "弹窗 < 暂停菜单"。
- 风险四：立牌退场后，`layout_test` 里"四块立牌在整条视角轨道上都看得见""立牌贴在桌沿"等一整类断言
  随之作废（它们守的是"指向性道具点得到人"，这条现在由"四角条可点"承担）—— 换成新断言，别只删。
