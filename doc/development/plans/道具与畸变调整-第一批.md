## 五、顶楼加盖「拖动无法使用」（已定位并修复）

- **用户复现（2026-10-07）**：房主侧；选好地皮、有弹窗显示选中地皮编号，但**道具没被用掉**
  （没丢弃、没扣能量、效果没生效）。
- **真因**：`game._apply_item_effect` 开头的目标校验把 `arg` **一律当 peer**：
  `var need_target := target != ""; if need_target and _player_by_peer(arg).is_empty(): return false`。
  而 `target == "tile"/"own_tile"`（快递直达 / 顶楼加盖）的 `arg` 是**格号** ⇒ 格号不等于某个存活
  玩家 peer 时校验直接判否、效果返回 false、`_use_item` 退还体力/冷却 —— 表现正是「选完地用不出」。
  既有回归之所以没抓到：`_prop_idx(0)` 恰好等于 peer 1。
- **修复**：校验只在 `target == "player"` 时生效（`need_player`）；`tile/own_tile` 交给各效果分支自查
  （快递直达查格号范围、顶楼加盖查归属）。
- **顺带**：无自有地时 `_on_use_pressed` 显式提示「你没有可加盖的地皮」（原先 `_begin_tile_target`
  对空表静默返回，玩家只见"点了没反应"）。
- **已实施（2026-10-07）**：`game.gd` 两处；`regression_test` 改用**格号 ≥10（≠ peer）**的地产钉住，
  `item_test` 加「走完整 `_use_item` 链路」的用例。

## 十三、缩差畸变（中期防贫富悬殊）

> 背景（用户 2026-10-07）：轮数上升后贫富差距显著增大 ⇒ 要一批**中期**（≈第 30 回合起）
> 随机出现的「缩差」畸变。可用素材：身家 `_net_worth`（现金 + Σ 地价 + 等级×升级费）、
> 排名（`_standing_by_peer` / `_rank_of`）、地皮累计投入 `price + level × upgrade_cost`。

### 机制：轮次门槛（拍板 2026-10-07）
- `aberration_data.gd` 加可选字段 **`min_round`**；`game._ab_candidates` 收集**随机池**时
  `if round_no < min_round: skip` ⇒ **第 30 回合起才可能随机触发**（走既有随机池 + `FREQ_P` 频率），
  **不是必触发**。

### 斗地主（拍板 2026-10-07）
- **效果**：**房产等级最高的玩家**把**自己一块「累计投入最少」的地皮**过户给**身家排名最后的玩家**。
- **口径**：「房产等级最高」= Σ(名下地皮 level) 最大（并列按行动序）；「累计投入最少」=
  `price + level × upgrade_cost` 最小那块；目标 = `_net_worth` 最小的存活玩家。
- **拍板**：过户**保留房产等级**；「地主」若本身就是末位 / 无地皮 ⇒ **空过（无事发生）**。
- **tag**：**中性**（对地主 debuff、对末位 buff 相抵，不吃香皂）。

### 改革开放（提案 · 随本轮实装）
- **效果**：**身家排名最后的玩家随机获得一件紫色道具**（`_grant_item_of_quality(p, "紫", "改革开放")`）。
- **边界**：背包满 / 紫池空 ⇒ 落空（记日志）。**tag**：`buff`。

- **已实施（2026-10-07）**：`aberration_data.gd` 新增两条（`min_round=30`）；`game._ab_candidates`
  抽 `_ab_random_pool()` 统一过轮次门槛；`game._ab_apply_instant` 加「斗地主 / 改革开放」两个分支；
  `畸变.md` / CHANGELOG 已补；`aberration_test` 加用例（门槛 / 斗地主保留等级与空过 / 改革开放发紫货）。

## 十六、道具卡面显示「被改动的能量 / 冷却」（炉石式红绿）

- **现状**：手牌左上角能量 = **基础值**（`ItemData.def(id).cost`）；右上角冷却徽章 = 实例**剩余** `it.cd`。
  被科技 / 道具 / 畸变改动后**看不出来**。
- **改动来源（现状）**：
  - **能量** `_item_cost(p, it)` = 基础 cost −（本回合首件：错峰用电 / 灵活就业 各 −1）+ `cost_pen`
    （二两寒暑 / 喇叭）+ 实例 `cost_delta`（二手群接龙），下限 0。
  - **冷却** `_use_item`：`cd = 基础 cooldown`，熟能生巧 →0、手速惊人 −1（下限 1）；保安队长对**目标** +2。
- **提案**：新增 `game._hand_card_state(p, it)` 算「生效值 / 基础值」，交 `ItemCard`：
  - 能量显示**生效值**：> 基础 → **红**、< 基础 → **绿**、相等 → 常规色。
  - 冷却显示**生效冷却**：同样红/绿。
- **拍板（2026-10-07）**：
  1. 冷却：道具**未被使用** → 显示**基础冷却**；**冷却中（已被使用）** → 显示**当前剩余**。
  2. 能量：**首件折扣按「首件价」显示**（即本回合首件生效时的价）。
  3. 配色：**红 = 变高、绿 = 变低**（对齐炉石）。**确认**。

  `player_popup` 组装处传；小卖部卡面（第八项）同口径可复用。

## 十七、二青会酒寒暑 · 增强（授予的组队学习：1⚡ / 无冷却 / 独立次数）

- **授予的「组队学习」实例**：**能量 1**（基础 2 → 1）、**无冷却**（cd 0）、且**与普通道具使用次数分开结算**
  —— 即「**每回合保底能用一次**」，不占普通道具的每回合上限。
- **技术点**：
  - 实例覆盖：`cost_override: 1` + `cd_override: 0`（`_item_cost` / `_use_item` 读它们）。
  - **独立次数**：`_use_item` / `_item_limit` 对这类「奖励件」走**独立计数**（如 `p.bonus_used`，
    `_item_turn_start` 重置）；它**不写** `item_used_n`、也不被普通上限挡住。
  - 或用**特殊 id**（`组队学习·寒暑`）走独立数据行 + 标记，避免污染普通「组队学习」。
- **拍板（2026-10-07）**：① 独立次数——与普通道具**分开结算**（本回合已用过普通道具仍可用）；
  ② **完全独立**：**不占**「双开 / 重修卡」那套次数上限，也**不与其联动**。
- **已实施（2026-10-07）**：玩家字段 `bonus_used`（回合开始清零）+ `_item_usable_now` 统一口径
  （`_has_usable` / `_item_phase` / `_bot_use_one` / `_hand_unusable_slots` 共用），授予件走
  `hidden` + `bonus` 数据行，`_item_pool` 排除 hidden；`item_test` 钉住「额度用满仍可用 / 每回合 1 次」。
