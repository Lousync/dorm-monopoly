## 一、拼车（蓝·主动）冷却 3 → 5

- **现状**：`item_data.gd:122` `{"quality":"蓝","cost":3,"type":"active","unique":false,"cooldown":3}`；
  效果 `game.gd:5172`（传送到指定玩家格并立刻结算）。图鉴 `道具图鉴.md:314` 写「冷却3」。
- **改动**：`cooldown` 3 → **5**；图鉴标题「冷却3」→「冷却5」；CHANGELOG。
- 能量 / 效果 / 目标 / 唯一性**不动**。`tests/*` 无拼车断言，不触发既有断言。

## 二、刮刮乐（紫·一次性）**降品质**

- **现状**：`item_data.gd:174` `{"quality":"紫","cost":2,"type":"consumable","unique":false,"cooldown":0}`，
  `desc`「获得 ¥100~¥1000」；效果 `game.gd:5256`（`randi_range(1,10)*100`，期望 ~¥550）。
  **代码与图鉴一致 ⇒ 不是写错**，是**品质配错**：一个史诗道具收益还不如白档「兼职中介」（2⚡ → ¥800）。
- **方案**：**紫 → 白**（推荐：收益量级本就与白档同档，且当前白档偏少）。备选：只降一档 → 蓝。
- **改动**：`item_data.gd` quality；图鉴标题「紫·史诗」→「白·普通」；CHANGELOG。
- **待确认**：落 **白** 还是 **蓝**。

## 三、枪打出头鸟（条件型畸变）改 **B 方案**（轮次门槛）

- **冲突**：钻石科技「预支未来」开局 +¥30000（起始 20000 ⇒ **50000**）⇒ 第一回合就成「出头鸟」，
  被抽 **20%×50000 = ¥10000**，这项钻石科技被自己的畸变吃掉一大截。
- **方案 B**：**加轮次门槛** —— 前 N 轮不触发（N 取 3~5，推荐 **3**）。
- **改动**：`aberration_data.gd` 给「枪打出头鸟」`cond` 加 `min_round`（或 `game.gd:_ab_cond_met`
  里判 `round_no >= N`）；`畸变.md` 补口径；CHANGELOG。
- **待确认**：N = 3 还是 5。

## 五、顶楼加盖「拖动无法使用」（探查结果）

  `drag_active=true` / `tgt_tiles=[该格]` → 拖到该格松手 → `item_action={"action":"used"}`。
  **拖动路径与效果都通**，headless **未能复现**「拖动无法使用」。
- **待补复现信息**：你是**房主**还是**客户端**？卡面是否**置灰**（体力 < 3 / 本回合已用 / 被禁）？

  ② 真机取景 / 屏幕→画布命中偏差。

## 六、玩家面板显示「已选科技」

- **现状**：点对手立牌打开的**玩家面板**（`scripts/player_popup.gd`；数据由 `game._open_player_popup`
  一处组装，`game.gd:6171`）展示：名字 / 名次徽章 / 身家 / 现金 / 能量 / 背包逐件 —— **没有科技**。
- **数据已就绪**：`st.players[].tech` 随快照下发（`_broadcast_state` 的 `"tech"` 字段，客户端也准）；
  科技名 + 描述在 `TechData.def(name)`（`desc`）。
- **方案**：
  1. `game._open_player_popup` 的 data 字典加 `"tech": String(p.get("tech", ""))`。
  2. `player_popup._fill` 在**能量行之后**加一行「科技：<名>」+ 其下小字 `desc`（`UIKit.TEXT_DIM`）；
     空串（未开科技 / 未选 / 已出局）则**整行不显示**。
  3. 出局者：建议**不显示**（科技已无意义）。
- **验收**：`hud_test`（或新用例）钉住「面板里有 tech 行、文案 = `TechData.def(tech).desc`」。
- **注意**：这是**界面**改动、不是平衡 —— 与 `balance/items` 的定位不符，建议**另开分支**
  （如 `feature/player-panel-tech`）；至少也应**单独一条提交**，别混进平衡提交。
