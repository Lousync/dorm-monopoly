# v0.5.0 批次 7 设计：桌面减负与操作改址

> 状态：**设计（待评审）** ｜ 立项 2026-10-04 ｜ 范围：**仅批次 7**（② + ④）
> 上级设计：本次会话的用户需求五条（①抽卡不推近 / ②按钮改址+直接出牌 / ③棋盘放大+玩家信息上屏幕 /
> ④删筹码体力件 / ⑤小人与房子立体）。整体走**方案 A：分 4 批推进**，逐批验收。
> 本文只覆盖批次 7；其余三条的边界见 §2「与后续批次的边界」。

## 1. 目标（批次 7）

把近端桌面上那两摊"屏幕派到桌上来的东西"收掉，并把回合操作从桌垫挪回屏幕层：

1. **④ 删除桌上的筹码堆与体力件**（`TableProps.set_chips` / `set_stamina` 两条子系统整体退场）。
2. **② 牌垫阶段按钮退场**：删掉桌垫下缘那两枚「转转盘 / 使用道具」。
3. **② 新增屏幕右下角动作按钮**：轮到我掷轮时是「转动转盘」，掷完之后是「结束回合」。
4. **② 卡牌改为点击直出**（杀戮尖塔式）：点手中一张牌 = 直接使用；右键丢弃的两步确认不变。

一条玩法逻辑都不改：`st` 字段、所有 `@rpc`、`s_state` 结构、房主权威模型全部不动。

## 2. 与后续批次的边界（本批次**不做**）

## 3. ④ 删除筹码堆与体力件

### 3.1 现状

- `table_props.gd` 里两条并列子系统：`set_chips()`（每 ¥5,000 一枚、封顶 8 枚、斜摞在自己面前）
  与 `set_stamina()`（一排方块小件，用掉的熄灭）。二者各自有节点池、共用 mesh、材质。
- 它们是**近端桌面的实物读数**：身家的量级（筹码）与体力（小件）。
- 由 `game._refresh_table_props()` 每次状态广播调用。

### 3.2 决定与理由

**整体删除。** 理由（用户要求 + 与批次 9 的协同）：

- 身家读数已在**四角身家条**（大字身家 + 小字现金），筹码只是"量级示意"，重复。
- 体力将由**批次 9 的玩家道具弹窗**承担（弹窗里含"能量"= 体力），桌上的小件是同一份数据的第二落点。
- 桌面越干净，批次 9 放大棋盘的空间越大（近端留白与相机取景都会被重定标）。

### 3.3 具体删除清单（`scripts/table_props.gd`）

- 常量：`CHIP_PER` / `CHIP_MAX` / `CHIP_R` / `CHIP_H` / `CHIP_STEP` / `CHIP_LEAN_PX` /
  `CHIP_BASE_PX` / `CHIP_COLOR` / `PIP_SIZE` / `PIP_STEP_PX` / `PIP_BASE_PX` / `PIP_LIT` / `PIP_SPENT`。
- 函数：静态 `chip_count()`、`set_chips()`、`_make_chip()`、`set_stamina()`、`_make_pip()`。
- 成员：`_chips_root` / `_chips` / `_chip_mesh` / `_pips_root` / `_pips` / `_pip_mats` / `_pip_mesh`。
- 注释：文件头「摆放约定」里"筹码 / 体力件 / 手牌 / 立牌…"那句、`PROPS_Y` 段里提到筹码的地方、
  「自己的现金（筹码堆）与体力（小件排）」整节 —— 改成一句"已退场，读数见四角身家条 /
  批次 9 的道具弹窗"，并注明**删除原因**（别只留一个空洞）。

### 3.4 调用点

- `game.gd: _refresh_table_props()`：删掉 `set_chips(...)` / `set_stamina(...)` 两行与它们的注释段。
- `game.gd: _refresh_board_followers()` 的注释里"筹码 / 体力件不跟相机"那句一并改准（它们不存在了）。

### 3.5 不变量

- `PROPS_Y` **保留**（转盘轮缘 / 两摞牌堆 / 立牌 / 手牌仍用它）。
- 桌面剩余实物：转盘轮缘、两摞牌堆、手牌、四块立牌。

## 4. ② 牌垫阶段按钮退场

### 4.1 现状

`board_view.gd` 里一组「牌垫阶段按钮」：`_phase_layer` / `_phase_box` / `_phase_spin` / `_phase_use`、
`_build_phase_buttons()`、`_place_phase_buttons()`、`set_phase_buttons()`，以及信号
`phase_spin_clicked` / `phase_use_clicked`。文案与三态由 `game._refresh_item_buttons()` 每次广播推来。

### 4.2 决定

- **整体删除**（层、两枚按钮、三个函数、两个信号）。
- `_ready` 里的 `_build_phase_buttons()` 调用、`_apply_cam` 里的 `_place_phase_buttons()` 调用一并删。
- `game.gd` 里 `board.phase_spin_clicked.connect(_on_roll_pressed)` 与
  `board.phase_use_clicked.connect(_on_use_pressed)` 两条连接删除。
- `game._refresh_item_buttons()` **整体删除**，`_refresh_actions()` 改调新的 `_refresh_action_button()`。
- `board_view.mat_rect_px()` **保留**（它是"桌垫在画布上的矩形"的公开查询，测试与批次 9 的取景都要用；
  它不是按钮的一部分，只是按钮曾用它摆位）。
- `_on_roll_pressed` / `_on_skip_pressed` / `_on_use_pressed` / `_on_item_slot_clicked` **保留**
  —— 它们仍是玩法入口，只是改由新的按钮与手牌点击驱动。

### 4.3 保留的入口（改址后依旧可达）

- **掷轮**：桌面上的**转盘实体**继续可点（`table_props.wheel_hit` → `_on_roll_pressed`，`_on_table_click` 第 2) 段）
  —— 它是看得见的实物，保留；右下角按钮是**第二条**入口。
- **出牌**：见 §6。

## 5. ② 屏幕右下角动作按钮

### 5.1 形态

屏幕层一枚按钮（`TableHud.build_play_ui` 里建，暂名 `g.action_btn`），贴在**屏幕右下角、四角身家条之上**
（右下角那条是"上家"的身家条，`CORNER_SLOTS[3]`：`mx=12 / my=56`，尺寸 195×104 ⇒ 占屏幕右下角
`x∈[-207,-12] / y∈[-160,-56]`）。按钮放在它**上方**：右边距约 20、底边约 -172，尺寸约 200×56。

> **落位出图定案**：本批次结束前用 `--shot` 出一张"轮到我"的图核对它不与身家条 / 战报浮层 / 立牌打架；
> 若挤，优先把按钮往屏幕中心挪（保持右下象限），不动身家条的位置。

### 5.2 状态机（唯一来源是 `st`）

`_refresh_action_button()` 每次状态广播（`_refresh_actions`）里推一遍：

| 条件 | 文案 | 配色 | 可见 | 点击后果 |
|---|---|---|---|---|
| `phase=="playing"` 且 `await=="roll"` 且 `turn==my_peer` | **转动转盘** | primary（黄，点亮） | 是 | `_on_roll_pressed()` |
| `phase=="playing"` 且 `await=="item"` 且 `await_peer==my_peer` | **结束回合** | normal（或独立的"收尾"色） | 是 | `_on_skip_pressed()` |
| 其余（不是我的窗口 / 我在移动与落地结算中 / 弹窗等待 / 已结束） | — | — | **隐藏** | — |

- 「其余」含 `await==""`（我掷完、正在移动与结算那一段）。**故意不显示禁用态的「转动转盘」**
  —— 那会让玩家以为还能再掷；这一段本来就没有可做的操作。
- 掷完之后如果**没有可用道具**，房主侧根本不进道具阶段（`_item_phase` 有 `_has_usable` 早退）
  ⇒ 「结束回合」不出现、回合自动推进。这是既有行为，本批次**不改**（不为"每回合都弹一次结束回合"
  强开一个空窗口）。**注意**：这一点会在出图/试玩里表现为"掷完直接跳下家"，是设计而非 bug。
- 重开道具窗口（重修卡允许用两次）时，按钮重新出现为「结束回合」。

### 5.3 新增玩法入口

```gdscript
## 右下角动作按钮的唯一后果函数（文案与状态由 _refresh_action_button 决定）
func _on_action_pressed() -> void:
    if String(st.get("await", "")) != "" and int(st.get("await_peer", -1)) != my_peer \
            and int(st.get("turn", -1)) != my_peer:
        return
    match String(st.get("await", "")):
        "roll":
            _on_roll_pressed()
        "item":
            _on_skip_pressed()
```

（上面的守卫按实现时的实际字段收紧到"轮到我 + 窗口是我的"，spec 只钉语义：**只有表 5.2 那两行
对应的点击才做事**，其余一律空转。）

## 6. ② 卡牌点击直出（杀戮尖塔式）

### 6.1 现状

点手中一张牌 → `_on_hand_clicked` → `_on_item_slot_clicked`（记 `selected_slot` + 桌上那张牌抬起 + 提亮）；
**再点牌垫上的「使用道具」** → `_on_use_pressed` 才真正出牌（按 `target` 分派：作弊器弹点数框 /
选玩家 / 选地块 / 直接发）。两次点击、两处落点。

### 6.2 决定

**一次点击出牌**。`_on_hand_clicked` 改成"选中并立刻使用"：

```gdscript
func _on_hand_clicked(hi: int) -> void:
    # 直出：点一张牌 = 选中并立刻用它（杀戮尖塔式）。需要选目标的进选目标态，
    # 作弊器弹点数框，其余直接发。
    _on_item_slot_clicked(my_peer, hi)   # 玩法侧唯一入口：记 selected_slot + 桌上那张牌抬起
    _on_use_pressed()                    # 既有的出牌分发，一行没改
```

- **"再点同一张 = 取消" 这条退役**：现在点任何一张 = 出它。取消只在**选目标态**里（Esc / 右键）。
- 右键丢弃的两步确认（`_on_discard_clicked`）**一字不动**。
- `_hand_clickable` 那道闸（轮到我 + 道具阶段 + 没在选目标 + 已实装）**不动**：非道具阶段点牌仍然空转。
- `_on_use_pressed` 里 `if selected_slot < 0: _on_skip_pressed()` 那一支变成**不可达**（它现在只在
  选中之后被调）——按实现时清理成守卫，语义不变。
- `selected_slot` **保留**（它仍是"选目标态里那张牌是哪个槽"的载体，`_target_item_id` / dev_tools
  的 `target` 摆拍分支都在读它）；只是它的生命期变短：进选目标态时被 `_on_use_pressed` 立刻清掉，
  不会常驻。

### 6.3 文案同步

- `rules_text.gd` 基础操作页那句"点一张选中 → 点桌垫「使用道具」确认" 改成
  "点一张牌 = 直接使用（需要选目标的再点目标）；**右键**点牌 = 丢弃（再点一次确认）"。
- `README.md` 里同一处描述一并改。
- `rules_panel_test.gd` 里对那句话的断言跟着改。

## 9. 不变量与风险

- **不变量**：房主权威、`st` 字段、`@rpc` 表、`s_state` 结构、`GameData.NO_OWNER` 哨兵 —— 一律不动。
- 风险点一：删 `_refresh_item_buttons` 后，客户端的"跳过道具阶段"入口只剩新按钮 —— 必须确认
  客户端（非房主）点「结束回合」走 `c_item_skip.rpc()`（`_on_skip_pressed` 里已有这条分支）。
- 风险点二：`hud_test` 里那条"屏幕底部不能有提前 return 打死小卖部/黑市"的守卫断言 —— 删按钮时
  别顺手把 `_process` 里那段结构改坏。
- 风险点三：`_refresh_action_button` 必须在**每次**状态广播里跑（含客户端），否则客户端的按钮状态会停在旧值。
