# 卡牌统一元数据模型 · P1 实施计划

> 分支：`feature/0.16.0`｜状态：进行中｜2026-10-10
> 关联：`doc/development/架构总览.md`、`doc/development/未完成项-交接.md`
> 说明：本仓约定实施计划随版本开发，合并进 `main` 后连同文件一起删除（历史见 `git log`）。

## 一、背景

四类卡（事件 / 道具 / 科技 / 畸变）的元数据分散在四张**异构**数据表里：
`GameData.EVENTS`（数组、字段驱动）、`ItemData.ITEMS`、`TechData.TECHS`、
`AberrationData.ABERRATIONS`（各自字典 + `def()`）。字段命名与分级概念各自为政
（道具 `quality` / 科技 `tier` / 畸变 `tag`；描述有 `t` 也有 `desc`），
缺少一个统一的「卡牌」视图。后续要做工具（卡牌编辑器、统一图鉴、一致性校验）时
必须逐个适配。

## 二、目标（P1）

建立一个**统一只读的卡牌元数据注册表** `CardDB`，把**道具 / 科技 / 畸变**三族的元数据
归一成统一的 `CardMeta` 形状，提供跨族查询与一致性自检。**事件族本批不纳入。**

## 三、拍板（2026-10-10，用户）

1. **事件卡先不管**：P1 模型里预留 `event` 族占位；待模型统一后，**删除现有事件卡设计、
   用新模型重设计**（已登记 `未完成项-交接.md`）。
2. **保留 `raw`**：统一视图原样带出各系统特有字段（不深拷，靠 const 表只读）。
3. **渐进迁移**：`CardDB` 只做加法，**不动**原四张表与各自的 `def()`，旧消费方照旧。

## 四、设计

### 归一化字段 `CardMeta`

| 字段 | 类型 | 说明 | 道具 | 科技 | 畸变 |
|---|---|---|---|---|---|
| `id` | String | 全局唯一键（各族原键） | 键 | 键 | 键 |
| `family` | String | 所属卡族 | `item` | `tech` | `aberration` |
| `title` | String | 显示名（各族均 = id） | id | id | id |
| `desc` | String | 描述 / 卡面文本 | `desc` | `desc` | `desc` |
| `category` | String | 族内分级 | `quality` | `tier` | `tag` |
| `icon` | String | 图标键（可能为空） | `icon` | 空 | `CARD_FAMILIES.aberr.glyph` |
| `tags` | Array | 检索标签 | `unique`/`hidden`/`bonus`/`target:*` | 空 | `type`/`trigger` |
| `implemented` | bool | 是否已实装 | 同 | 同 | 同 |
| `raw` | Dictionary | 原表条目（系统特有字段） | 引用 | 引用 | 引用 |

### 接口（`scripts/card_db.gd`）

- `families() -> Array` — 已接入的族（顺序即展示序）
- `ids(family) -> Array` / `has(family, id) -> bool`
- `def(family, id) -> Dictionary` — 归一化元数据；未命中返回 `{}`
- `all(family) -> Array` — 该族全部归一化元数据
- `find(id) -> Dictionary` — 跨族定位，返回 `{"family":..., "meta":...}`；未命中 `{}`
- `validate() -> Array` — 一致性自检（返回问题描述列表，空 = 通过）

### 归一化规则

- `title = id`（四族现有显示名都就是键本身）。
- `category` 直接取各族分级字段，不做跨族统一——事件族根本没有稀有度，只有卡型，
  强行统一会失真；因此保留「族内分级」语义。
- `tags` 由布尔标记与枚举字段拼出，稳定序、去重。
- `raw` 取原表条目引用。const 字典在 Godot 4 中只读，天然满足"只读约定"。
