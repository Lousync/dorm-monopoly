## 一、① 规则说明面板搬到右上、与「战报」互斥

**现状**：按钮在右上（`rules_panel.gd:_build_button`，`-250..-118` / y12..46），面板却在**左下角**
（`_build_panel`，`BOTTOM_LEFT`，384×422）——点按钮、面板从屏幕另一侧冒出来，观感是"没对上"。

**改**：面板锚点改 `TOP_RIGHT`，**右边缘 −12**（与展开的「战报」栏同一条线）、顶边 52
（在「规则说明 / 战报」两枚按钮下沿之下）。展开动画支点从"左下角"改成"右上角"。

**互斥**（用户明写）：`_toggle_log()` 展开战报前先 `_set_rules_open(false)`；
`_set_rules_open(true)` 先收起战报栏。理由：两者都落在右上同一块地方，同时开会叠。

**保留**：`_set_rules_open(true)` 仍隐藏 `info_panel`（格详情卡悬浮在被点格子上方，仍可能与
右上角重叠）。`_dock_band()` 里那条"为左下角规则面板让位"的夹位**删除**——面板搬走后它恒为
no-op（`offset_right` 变成负数），留着会误导后来人。

## 二、② 名册条搬到左上角「暂停」旁并瘦身；「我」那条对齐右下角按钮

**现状**：他人的信息在**右上角「战报」下方**的名册条（`ROSTER_ROW_SIZE` 高 78，一行 = 徽记 +
名字 + 身家 + 一条倒计时行）；「我」那条在左下角、离底 56。

**改**：
- 名册条锚点 `TOP_RIGHT` → `TOP_LEFT`，落在暂停按钮右侧（x≈104，y≈10）。
- 一行内容 = **名次徽章 + 棋子色小片 + 昵称 + 一条很细的倒计时条**（用户选"每行仍带细倒计时"）。
  去掉**身家**与现金行。名册行从此**要建 `badge_slot`**（"徽章只有我这条有"的时代结束）。
- 行序仍取 `standing`（身家倒序 = 名次），**本来就是实时排序**，一行不动。
- `MY_BAR_SLOT.my` 56 → **20**：底边与右下角「转动转盘」按钮（`offset_bottom = -20`）平齐。
- 文案同步：`game._begin_peer_target` 的选目标提示、`rules_text.gd` 两处「右上角名册条」
  → 「左上角名册条」。**别让玩家照着找一个已经不在那儿的东西**。

**代价（如实留痕）**：左上名册条与顶部居中的**畸变横幅**（y6..48）可能抢同一条 y 带 ⇒
新增一条 hud_test 重叠断言钉住，并在实现里给名册条右边缘设一个"到畸变横幅左缘为止"的软上限。

## 三、③ 机器人进店也看得见（时序 bug）

**根因**：可见性判据本身没问题——`phase=="playing" and shop_open>=0 and shop_peer!=0`，
**旁观者是满足的**（真人进店你本来就看得见，`hud_test:2075` 钉着）。坏在机器人：
`game._run_shop` 里 `_bot_shop` **没有 await**，于是 `_shop_buy` → `_shop_leave` → 关店广播
**全在同一帧跑完**，任何一端的 `_process` 都来不及把 `shop_layer` 显出来 ⇒ 机器人进店对
**所有人**不可见。

**改**：机器人分支加一个**可见节拍**（`await 1.5s`）再 `_bot_shop`，让 `shop_open>=0` 的快照
活过一帧。真人访客路径**一行不改**。

**代价**：机器人每次进店多约 1.5 秒（`Engine.time_scale` 3× 的自动对局里 ≈0.5 秒）⇒ 四人局
节奏略慢，换来"看得见别人买了什么"。

## 四、④ 「调休」是哨兵值撞车（真 bug）

**根因**：`game.gd:131` 的 `_ab_extra_peer := -1` 与**第一个机器人的 peer id（−1）**撞车
（`net.gd` 里机器人从 −1 起编号）。`_aberration_window`（`game.gd:694`）无条件比对
`_ab_extra_peer == p.peer` ⇒ 那台机器人**每回合**白拿一次双掷，且**与畸变开关无关**、
不扣 `_ab_no_roll` ⇒ 纯加成，正是用户说的"一进游戏就有个调休 buff"。

**判据**：日志里会出现 `【调休】补班时间…` 却**没有**对应的 `【畸变】调休 —— …`；合法调休两条都有。

**改**：哨兵改用 `GameData.NO_PEER`。**`AGENTS.md` §四早就写了「哨兵别用 −1（机器人 peer 从
−1 起编号）」**，这是漏网的最后一处（同类先例：`_set_ring(-1)`、`_shop_peer != 0`）。

## 五、⑤ 玩家详情弹窗放大 + 按上限画槽位

**字看不清的根因**：`ItemCard` 描述字号 = `size.y × 0.042`，弹窗现在给 120×168 ⇒ **7px**。

**改**：卡面改 `ItemCard.SIZE_LARGE`（220×300 ⇒ 描述 12px / 名称 21px）；`PANEL_W` 460 → ~520。

**槽位**（用户选"画 cap 个槽位、空槽留占位框"）：背包区按 `_bag_cap(p)`（基础 **5**、
带「置物架」**7**——`game-design/道具系统.md` §六「每人 5 格」是规则上限）画**固定槽位数**：
已拥有的格子放整张卡、空的放**虚线占位框**，一眼看出"还能装几张"。

## 六、⑥ 钱流动的终点算早了一帧（时序 bug）

**现状**：全项目只有一处飞钞 `game._spawn_money_fly`（所有钱变动都从广播差分进它）。

**根因**：它算**终点**（那条身家条 / 名册行的中心，`_corner_bar_screen_center`）发生在
`_refresh_corner_bars(standing)` **之前**——而后者才是真正写 `bar.peer` / `root.visible` /
重排行序的地方。名册按身家排序 ⇒ 只要「金额变了、名次也变了」，钞票会飞向**一行**，
下一帧那行却换了人（或正要被藏起来）。

**改**：`_refresh_players` 里把差分先**收集**成表，等 `_refresh_corner_bars(standing)` +
`_refresh_corner_highlight()` 跑完再统一播。**飘字与音效锚在棋子上、与名册无关，位置不动。**

**有意不动**：破产不出钞（`bool(p.alive)` 那道闸）、同一次广播里两笔钱并成一笔净值——
两者都不是"位置错"，是既有语义；改它们属于新需求，等用户单独提。

## 七、⑦⑧ 桌面亮度均匀 + 各排房子同色（同一根因）

**根因**：全场唯一光源在桌子**左侧、z=0**。薄牌**后仰 25°**（`HOUSE_LEAN_DEG`）⇒ 最底那两排
（世界 z≈1.7~2.2）的牌面**背对灯**，只剩环境光（0.20）＋**白色**自发光 ⇒ 冲成近灰
——就是用户⑦说的"立牌没有颜色"。同一盏灯的**4.4:1** 左右落差就是用户⑧要取消的"渐变"。

**改**（用户选"桌面完全均匀 + 保留屏幕暗角"）：
- **光照去落差**：主光源只抬 y（平面落点不变 ⇒ 保住 `layout_test` 那条「光源不在桌垫窗口内」），
  衰减 0.72 → ≈0、范围与能量重取、环境光抬到"四角与中心基本一致"。
- **房子牌面不吃直射光**（自发光档）⇒ 各排同色，与灯的位置无关。
- 屏幕四周暗角（`build_vignette`）**保留**——用户点名要留。

**这是一次有意的设计反转**：批次 6/10 特意调出"近黑房间 + 一盏台灯 + 中心亮四周暗"，
`layout_test` 用四条断言把它钉住了（`i_far >= 1.1`、衰减 ≤ 1.0 等）。本批把那块**改写成
"均匀"断言**（四角/中心亮度比 ≤ 阈值），并在 `设计决策留痕` §十三 留痕。

## 八、⑨ 删掉桌面旁的 3D 物件

**只剩房间剪影**要删：`table_3d._build_room`（三面墙）＋ `_build_bookshelf`（书架）＋
`_build_bedframe`（床架），连同 `ROOM_*` 常量与 `room / room_mat` 成员。
**灯的可见几何批次 12 A1 已删，只留光**——它是唯一光源 + 唯一投影源，**删了屋子全黑、影子全丢**，
`layout_test` 有一条"全场只有一盏灯"钉着。`WorldEnvironment` 背景保留。
