## 〇、这次改什么（一页速览）

| 项 | 现状 | 重构后 |
|---|---|---|
| 内部品质键 | 白 / 绿 / 蓝 / 紫 / 橙（**5 档**） | **白 / 蓝 / 紫 / 金（4 档）**；`绿`、`橙` 两个键消失 |
| 显示名 | 普通 / 稀有 / 超稀有 / 史诗 / 传说 | **普通 / 稀有 / 史诗 / 传说** |
| 件数分布 | 白13 / 绿17 / 蓝13 / 紫18 / 橙7 | **白 27 / 蓝 20 / 紫 16 / 金 5**（合计 68，严格递减） |
| 抽品质 | 三张人为权重表 + 黑市自带一张 | **全池等概率**（黑市例外：只从 紫/金 两档抽，池内等概率） |
| 稀有度门闸 | 权重 + 档价 | **只剩档价**（`QUALITY_PRICES` 重定）+ 刷新价 + 黑市地皮价 |
| 逐件平衡 | 数值多为占位 | **68 件逐件过一遍**（见 §三） |
| 图标 | 10 个文件缺、4 个冗余 | 3 个冗余改名顶上 + 7 个新烘焙；1 个删除（见 §七） |
| 已知 bug | bot 按档定价，读不到单件 `price` | 修（见 §八） |

**数量分布就是稀有度曲线**：全池等概率 ⇒ 每档的**件数占比**就是它在货架上的**出现概率**：

| 档 | 件数 | 占 68 | 货架单栏出现率 | 定位 |
|---|---|---|---|---|
| 白·普通 | **27** | 39.7% | ~40% | 常见小件，抽到不亏 |
| 蓝·稀有 | **20** | 29.4% | ~29% | 对现有规则的稳定调用 |
| 紫·史诗 | **16** | 23.5% | ~24% | 一次性的强干预 |
| 金·传说 | **5** | 7.4% | ~7% | 改写规则的招牌件，全局唯一 |

> 两条必须看清楚的推论：
> ① `紫` 从旧权重的 5% 涨到 **~24%**（因为池里有 16 件紫）。**「史诗」会比过去常见 5 倍**，
>    拦住它的只剩 **价格**（紫 ¥3200 = 开局现金的 16%）与刷新价。这是本次改动**观感上最大的一处变化**，
>    见 §九「实现风险」第 1 条。
> ② `蓝` 从旧权重的 50%（蓝20+绿30）掉到 ~29%；`金` 从 5% 涨到 7.4%。整条曲线被「摊平」。

## 一、四档的质量纲领（归位的判据）

先立判据，再逐件归位——否则 68 件的挪动会变成拍脑袋。

| 档 | 纲领 | 判据（任一条不满足就往下挪） |
|---|---|---|
| **白·普通** | 常见小件 | ① 收益量级 ≤ ±¥1000；② 不改变任何博弈结构；③ **用错也不致命**（最多亏一次使用机会） |
| **蓝·稀有** | 规则的稳定调用 | 位移 / 交换 / 干扰 / 能力型被动；**需要选时机或选目标**，但结果可预期 |
| **紫·史诗** | 一次性的强干预 | 夺（没收/拆解）、拆（强拆令/抄家队）、改归属（转专业/交换课表/宿舍改造）、改节奏（时间暂停/包场/代课）；**用一张就改写局面**，所以是 `consumable` 为主，抽到要"下决心用" |
| **金·传说** | 改写规则 / 牵出子系统 | 全局唯一；每张都带一个自己的机制（计费器 / 标签免疫 / 礼物分发 / 焦土 / 地产护罩） |

**与「显示名对齐」旧口径的关系**：旧拍板说「旧绿(稀有)→蓝、旧蓝(超稀有) 逐件上并紫或下并蓝」。
那条方向**在本稿里被数量约束推翻**——旧蓝 13 件若整档留在蓝，蓝 ≥ 30 件，`白>蓝>紫>金` 直接不成立。
所以本稿采用**「先钉件数、再逐件按纲领归位」**：旧蓝里有 4 件（护身符 / 体测 / 换课 / 点名）
比旧绿里的多数件更弱，就该下到白；旧绿里有 7 件（置物架 / 充电宝 / 夜跑 / 护腕 / 组队学习 /
组队学习·寒暑 / 二手群接龙）比旧蓝里的多数件更强，就该上到蓝。**新旧档位不是「整档平移」，
是「逐件重排」。**

## 三、与现状的差异清单

按「改动的性质」分三类。**逐条对应到测试与代码**，实现时照着勾。

### 3.1 纯标签变化（51 件）——只动数据表的 `quality` 键

这些件的效果、数值、体力、冷却、唯一性**全不动**，只是换了品质键（有的同时换了显示名）。
实现上是纯数据改动，风险最低：

## 四、品质常量 / 定价 / 刷新曲线的具体改法

### 4.1 `ItemData` 的四个品质常量

```gdscript
const QUALITIES := ["白", "蓝", "紫", "金"]          # 同时是降档排序键（低 → 高）
const QUALITY_NAMES := {"白": "普通", "蓝": "稀有", "紫": "史诗", "金": "传说"}
const QUALITY_COLORS := {
	"白": Color(0.93, 0.93, 0.93),   # 原样
	"蓝": Color(0.36, 0.6, 0.92),    # 原样
	"紫": Color(0.66, 0.47, 0.92),   # 原样
	"金": Color(0.96, 0.62, 0.25),   # ← 沿用原「橙」的琥珀值：保住「顶档 = 琥珀」这套口径
}
```

**颜色口径**：三档的色值原样搬、顶档沿用原琥珀值——即 `QUALITY_COLORS` 的**取值集合不变**，
只是键从 `橙` 改名成 `金`。这样 `deck_reveal` 的卡背金、`item_card` 的卡框、
`table_props` 的牌身色、`gen_gallery` 的 chip 色**都不需要调色**，只跟着键名走。

> 提醒：`GameData.LEVEL_NAMES` 里也有一个「绿」（装修等级 未装修/绿/蓝/紫/金）。它与道具品质**无关**，
> 但重构后「道具没有绿、装修有绿」容易让人误读——建议在 `术语表.md` 里点一句澄清（**不建议**为此改装修等级名，那是另一套系统的既成口径）。

### 4.2 定价（唯一的稀有度门闸）

```gdscript
const QUALITY_PRICES := {"白": 600, "蓝": 1600, "紫": 3200, "金": 8000}  # 待数值专场 → 本稿定稿
```

| 档 | 旧价 | 新价 | 倍数 | 理由 |
|---|---|---|---|---|
| 白 | 600 | **600** | ×1 | 不动。它是 40% 的常见件，价格要与「一顿 ¥300~800 的即时收益」同量级 |
| 蓝 | 1800（旧蓝） | **1600** | ×0.89 | 略降：蓝档现在装着「组队学习 / 护腕」这类工具件，不全是超稀有件 |
| 紫 | 3000 | **3200** | ×1.07 | 略升。**这是拦住「24% 出现率」的主要门闸**——¥3200 ≈ 开局现金的 16% |
| 金 | 4500（旧橙） | **8000** | ×1.78 | **买得起要下决心**：¥8000 = 开局 ¥20000 的 4 成。一次买金 = 清掉近半开局资本 |

`REFRESH_BASE` / `REFRESH_STEP`（刷新曲线）：

```gdscript
const REFRESH_BASE := 800   # 500 → 800
const REFRESH_STEP := 400   # 300 → 400
```

理由：全池等概率后，**刷新 = 再赌一次有没有金档**（单栏 7.4%、三栏 ~20%）。刷新价若还停在
500 起，玩家会养成「刷到出金为止」的习惯，等于把稀有度门闸从价格挪回概率。起点抬到 800
（> 白档价 600）、步进抬到 400，让「刷金」有实打实的成本。

黑市地皮价（`BLACK_COST`）：

```gdscript
const BLACK_COST := {"紫": 1, "金": 3}   # 旧 {"紫": 1, "橙": 2}：键重命名 + 金 2 → 3
```

理由：黑市**只从 紫/金 两档抽**（控制侧定的定位，保留），池内等概率 ⇒ 金单栏出现率
5/(16+5) ≈ **24%**，三栏约 56%。也就是说**黑市是金档的主要来源**，远高于小卖部的 7%。
把金的地皮价抬到 3 块，是用**价格**（而不是回退到概率）把这道口子收住——与控制侧
「定价是唯一的稀有度门闸」同一条口径。**备选：保持 `{"紫":1,"金":2}`**（若实机发现 3 块太劝退）。

`BLACK_REFRESH_COST`（1 块，不涨价）与 `BLACK_EXIT_COST`（1 块）**不动**。

> 刷新价与黑市地皮价都是「数值专场」的遗留占位（`道具系统.md` §十一），本稿一并定稿。

## 七、顺手修的 bug（bot 定价读不到单件覆盖）

**事实**（已核实）：小卖部购买链路与 UI 走的是 `ItemData.item_price(id)`——它会先看单件
`price` 覆盖、再回落到档价；但 bot 的两处策略走的是 `ItemData.price(quality)`——**只看档价**：

| 位置（按函数名找） | 现状 | 后果 |
|---|---|---|
| `_discover_bot_pick` | `ItemData.price(品质)` | bot 在失物招领三选一里按**档价**排序 |
| `_bot_shop` | `ItemData.price(品质)` | bot 在小卖部里挑「档价最贵」的一件 |

**后果实例**：`二青会酒寒暑`（单件 ¥8000）在 bot 眼里只值 **橙档 ¥4500**。
而 `tests/item_test.gd` 恰好钉着「二青会单件售价 = ¥8000」这条契约——**实现违反了自己被测试钉住的契约**。

**改法**：这两处改用 `ItemData.item_price(id)`（与 UI / 购买链路同源）。
**顺带**：黑市 bot 比价走 `QUALITY_PRICES` 值排序——黑市计价是**地皮数**（`BLACK_COST` 按档），
那里按档排序**是对的，不要跟着改**。改完补一条回归断言：bot 在货架上会优先拿 `二青会酒寒暑`
（或至少：`item_price` 与 `price(quality)` 不一致的件，bot 的排序跟 `item_price` 走）。

> 本稿把 `二青会酒寒暑` 的单件覆盖改成 ¥2600（§二），这条 bug 修完后的观感变化会小很多 ——
> **但 bug 仍要修**：契约是「单件覆盖优先」，任何 `price` 覆盖都该被 bot 看见。

## 八、实现风险（牵动哪些既有系统，各要动什么）

按「动了会不会漏」排序，**前 3 条是本稿的重点**。

### 1. 观感风险（最大）：紫 / 金 会明显比过去常见

全池等概率 ⇒ 出现率 = 件数占比。`紫` 由过去的权重 **5%** 涨到 **~24%**，`金` 由 **5%** 涨到 **7.4%**。
**小卖部平均每 1.3 架就出一件紫**。拦它的只剩价格（紫 ¥3200）与刷新价（800 起）。
- 这是「稀有度靠数量扛」的**必然结果**，不是 bug。但必须让设计者知情：**「史诗」这个显示名会名不副实**。
- 处置建议：**先按本稿价格上，实机跑几局再调价**，不要因为「紫太多」就回退到加权（那会推翻控制侧的 ②）。
- 备选（若调价不够）：把紫档再压缩到 12 件、白/蓝相应加厚（`白 30 / 蓝 21 / 紫 12 / 金 5`），
  紫降到 ~18%。代价是紫档要再挪 4 件——本稿的 27/20/16/5 是控制侧给的初值，可微调。

### 2. 白档膨胀 + 唯一性池收窄：货架 / 发现可能频繁缺货

白档 27 件里有 **10 件 `unique: true`**（招财猫 / 砍价高手 / 幸运数7 / 校园卡 / 校历 / 公交卡 /
信托基金 / 雨伞 / 应急基金 / 护身符）。唯一件被持有 / 在售后就从可获取池**整个消失**。
四人局后期，白档可抽的件会明显变少，而小卖部现在**全池抽**——池子窄了，会更多地抽到蓝紫。
- **处置**：实机重点看「后期货架是不是只剩中高档」。若明显，可（a）把部分白档被动的 `unique`
