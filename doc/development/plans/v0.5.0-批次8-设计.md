# v0.5.0 批次 8 设计：抽卡演出搬到屏幕层（大字演出）

> 状态：**设计（待评审）** ｜ 立项 2026-10-04 ｜ 范围：**仅 ①**
> 上级设计：本次会话用户需求五条。整体走**方案 A：分 4 批推进**（批次 7 已完成，见
> `v0.5.0-批次7-*`）。批次 9 / 10 见 `v0.5.0-批次7-设计.md` §2。

## 1. 目标（批次 8）

把「机会 / 命运」抽卡演出从**桌垫画布**（`BoardView._world`，随 3D 相机倾斜、被透视缩小、
靠推近镜头才读得出字）搬到**屏幕层**：一张固定大尺寸（约 320×480）、屏幕居中的卡，
四段节奏不变。**相机全程不动** —— 这就是用户 ① 要的"画面不要聚集"。

用户原话：`①「机会」「命运」抽卡动画时画面不要聚集，会导致桌面 3D 物品错位`。

## 2. 为什么"错位"、以及本批怎么治

- 现在 `play_deck_card` 会 `focus_point_zoom(..., DECK_PUSH_FACTOR=2.0)` 把 **2D 相机**拉近 2 倍：
  桌垫上印着的图案（棋盘 / 两摞卡背 / 转盘图案）**整体放大并滑动**。
- 跟图案走的实物只有**转盘轮缘与两摞牌堆**（批次 6 起逐帧重推）；**手牌 / 立牌**是"不跟 2D 相机"的
  实物（见 `table_props.gd` 文件头的摆放约定）—— 于是推近的那一刻，**手牌与立牌相对棋盘明显错位**。
- 本批**取消这次推近**（不再动 2D 相机）⇒ 图案不动、实物不动、错位从根上消失。
- 代价：卡面字不再靠"拉近"保证可读 ⇒ 卡改在**屏幕层以固定大字**演（不依赖相机与桌面比例）。

## 3. 与后续批次的边界（本批次**不做**）

| 留给 | 内容 |
|---|---|
| 批次 9 | ③ 棋盘放大、立牌退场、四角身家条开道具弹窗、选目标改点身家条 |

## 4. 设计

### 4.1 新组件 `scripts/deck_reveal.gd`（`class_name DeckReveal extends Control`）

屏幕层的一个 `Control`，挂在 `game` 的 `hud` 层里（与四角身家条 / 右下角动作按钮同层），
`z_index = 65`（压在棋盘与身家条之上、小卖部 70 与暂停菜单之下），`mouse_filter = IGNORE`（绝不吃点击）。

**接口**（三个，全部幂等）：

```gdscript
const CARD_SIZE := Vector2(320.0, 480.0)      # 屏幕像素，2:3 —— 与旧 CARD_SIZE(260×390) 同比例
const OUT := 0.34                              # 四段相位时长，与旧板一字不差（房主等待靠它同步）
const FLIP := 0.30
const HOLD := 1.50
const BACK := 0.28
const CARD_TIME := OUT + FLIP + HOLD + BACK    # = 2.42s，与旧 BoardView.DECK_CARD_TIME 相等

func show_card(deck: String, kind: String, text: String) -> void   # 开演（重复调用先收掉上一张）
func tick(delta: float) -> void                                   # 相位推进（由 _process 调；测试可直接快进）
func is_showing() -> bool
```

- **相位与节奏与旧版一字不差**：抽出（`_ease_out_back` 回弹 + 微倾 + 淡入）→ 翻面（绕竖轴压扁到 0 换面
  + 换面点提亮）→ 停留（上下浮动 + 呼吸微光）→ 收回（缩回 0.58 + 淡出）。
- **唯一的语义变化：整段演在屏幕正中，不移动相机**。旧的"起点 = 实体牌堆顶面 / 收回回牌堆"取消
  ⇒ **本组件不依赖 `board` / `table3d`**（不注入 provider、不查画布坐标）。
  - 取舍：失去"从桌上那摞抽起"的实体感（用户选的正是"卡搬到屏幕层做大字演出"，已接受）。
- 卡面/卡背的构建从 `board_view.gd` **搬过来**（`_deck_back_tex` / `_make_card_art` /
  `_card_face_front` / `_card_face_back` / `_show_deck_face` / `_ease_out_back`），逻辑不变。
- 字与板按新尺寸等比放大：标题 24→30、正文 15→18，正文锁宽按新尺寸重算（内宽 − 4）。

### 4.2 相机不动之后要一并撤掉的东西

| 撤掉 | 位置 | 理由 |
|---|---|---|
| `focus_point_zoom(..., DECK_PUSH_FACTOR)` 那一笔 | `board_view.play_deck_card` | 正是"画面聚集"本身 |
| `DECK_PUSH_FACTOR` 常量 | `board_view` | 无引用 |
| `_deck_prev_zoom` 与收尾的"还原缩放" | `board_view` | 没推近就没得还原 |
| `deck_top_provider` / `_refresh_deck_from` / `_deck_from` / `_deck_shown` / `_deck_kind` / `_deck_restore` | `board_view` | 起点不再来自实体牌堆 |
| `BoardView.DECK_CARD_TIME` | `board_view` → 迁到 `DeckReveal.CARD_TIME` | 房主等待仍读它（`game.gd:606` 改引用） |
| `_process` 里"抽卡期间逐帧重推轮缘/牌堆"那条 | `game.gd:3551` | 相机不动 ⇒ 图案不动 ⇒ 无需逐帧重推 |
| `_refresh_actions` 里 `not board.is_showing_deck_card()` 那个条件 | `game.gd:1616` | 演出不再动相机，"避让"无意义（其余两个条件保留） |
| `board_view` 的 `_deck_card`/`_deck_back`/`_deck_front`/`_deck_t`/`_tick_deck_card`/`is_showing_deck_card`/`play_deck_card` 与四段相位常量 | `board_view` | 全搬到新组件 |

**保留**：`_deck_pos` / `_build_deck` / `deck_center` / `deck_screen_pos` / `deck_screen_size`。

### 4.3 接线

- `TableHud.build_play_ui`：建 `g.deck_reveal = DeckReveal.new()`，挂进 `hud`。
- `game.s_card`：`board.play_deck_card(...)` → `deck_reveal.show_card(deck, kind, text)`；
  `game.gd:606` 的等待 `BoardView.DECK_CARD_TIME` → `DeckReveal.CARD_TIME`。
- `dev_tools.take_shot`：`while g.board.is_showing_deck_card()` → `while g.deck_reveal.is_showing()`；
  `deckout` 分支的 `g.board.play_deck_card(...)` → `g.deck_reveal.show_card(...)`，并**删掉**那段
  "先把注视点就位 / 必须带 freecam"的注释与 `focus_point`（相机不再参与）。
- `hud_test`：把「抽卡推近」段改成「演出在屏幕层、相机不动」段（见 §6）。

## 6. 验收

1. `load_all` + 全量套件全绿、`SCRIPT ERROR` 0。
2. **hud_test 新断言**（取代旧的 `DECK_PUSH_FACTOR` 链）：
   - `deck_reveal.show_card(...)` 后 `is_showing()` 为真；
   - **相机不动**：`board._zoom` / `board._center` 在演出前后**完全相同**（这正是本批的判据）；
   - `deck_reveal.tick(CARD_TIME + 0.1)` 后 `is_showing()` 为假、节点已回收。
   - 反向契约：`board` 上**不再有** `play_deck_card` / `is_showing_deck_card` / `DECK_PUSH_FACTOR`。
3. **联机回归同一条命令跑完**（改动了 `s_card` 的落点与房主等待常量）。
4. **出图**（真实窗口）：一张"卡正在屏幕上大字演出"的图（`--shot=xx_deckout_card.png` 走 `deckout` 分支）
   —— 确认卡在**屏幕正中**、字读得出、**背后的桌面没有放大/滑动**。可与批次 7 的桌面图对比。
5. 单人试玩：走到机会/命运格 → 卡在屏幕中央大字演出 → 桌面纹丝不动。

## 7. 不变量与风险

- **不变量**：玩法逻辑、`@rpc`、`s_state` 字段、`GameData` 哨兵一律不动；新增素材为零（`LICENSE` 不动）。
- 风险一：`DeckReveal` 自己的 `_process` 每帧推进 —— 但它**只在 `is_showing()` 时做事**（其余帧直接
  `return`），不做成常态每帧开销。
- 风险二：`z_index = 65` 是否盖得住该盖的、又不盖住暂停菜单 —— 出图核对。
- 风险三：卡面字在 320 宽的板上是否读得出 —— 出图核对；不够就加字号（板尺寸已是屏幕层，随便调）。
- 风险四（计划纪律，来自批次 7 的教训）：测试文件以 `_test.gd` 结尾；联机回归 `sleep` 用 3s。
