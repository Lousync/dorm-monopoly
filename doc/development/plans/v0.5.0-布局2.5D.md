## 一、目标与非目标

**目标**：把对局画面从"俯视的 2D 棋盘 + 屏幕 HUD"变成**一张斜看的实体桌面**——
像几个人围着桌子玩（参考 **Liar's Bar**），桌面本身有透视、有光影。

**三条具体要求**（用户 2026-10-03 提出）：

1. **撤掉桌面上的小卖部 / 宿舍赌场常驻设施**，改为**触发时切到独立全屏界面**。
2. **棋盘做成桌面**——56 格环形棋盘铺满桌面，外围露出一圈木桌边，人在桌对面/两侧。
3. **2.5D 透视**，观感对标《邪恶铭刻》/《Liar's Bar》。

**非目标**（本版不做）：

- 不做真实 3D 物件（格子/牌没有厚度）——那是路线 B，留待以后评估。
- 不做玩法改动；不动 `联机协议.md`（协议无变化，`s_state` 字段不变）。
- 不重建 3D 房间环境（先用暗背景 + 暗角 + 一盏顶灯）。

## 二、总体方案：路线 A（SubViewport 2.5D）

现有 2D 世界（棋盘 / 棋子 / 转盘 / 牌堆）**整体搬进一个 `SubViewport`**，把该 SubViewport
当**贴图**铺在 3D 场景里一张**水平桌面**上，用 `Camera3D` 以约 50° 俯角观看。

**三层结构**（从下到上）：

```
① 3D 场景
   WorldEnvironment(暗背景) + 顶灯 OmniLight3D(暖光，带阴影)
   ├─ 桌面板 MeshInstance3D(水平 PlaneMesh) —— 材质贴 SubViewport 的画面
   ├─ 对手立牌 ×(1~3)  Sprite3D + Label3D
   └─ Camera3D（固定在自己座位，俯视 ~50°，滚轮 = 沿视线推拉）
② SubViewport —— 现有 2D 世界原样装进来
   board_view 的 2D 相机保留（仍可"推近转盘/牌堆"演出），但不再受"转视角"驱动
③ 屏幕层 HUD（最上层 Control）——底栏、右栏名册、战报、暂停、规则说明、
   格详情卡、事件卡，以及小卖部 / 赌场的全屏界面
```

**选它的理由**：② 是"原样搬家"——`board_view` 的世界层本来就是独立子树，
2316 行里绝大部分不用改；而"玩法代码零改动"正是这条路的全部价值。

## 三、构图与视角

- **相机固定在自己座位**，不跟人、不旋转。**转视角功能整个删除**（见 §八）。
- **俯角 ~50°**（Liar's Bar 偏平、邪恶铭刻偏陡，50° 是能看清格子又有纵深的中间值）。
- **滚轮 = 推拉 3D 相机**（沿视线前后），**拖拽平移删除**（第一人称没有"平移桌子"这回事）。
- **桌子水平放着，歪的是相机**。只有水平桌面才有自然的阴影与光照；把桌面本身斜过来贴图会变形。
- **棋盘铺满桌面**：不是"棋盘摆在桌上"，而是棋盘即桌面，外围露出一圈木桌边。
- **桌面占比**：目标让桌面成为画面主体（下方留出信息带）。探针实测相机需比当前近得多、FOV 要收紧（见 §七）。
- **环境**：暗色背景 + 四周暗角（屏幕层 ColorRect + shader）+ 顶端一盏暖色顶灯。

**屏幕分工（本方案的命门）**：

```
╔════════════════════════════════════════╗
║ ⏸暂停                         📜战报 ║
║      ┌──────────────────────┐          ║
║      │   [对手A]  [对手B]   │ ← 立牌   ║
║      │ ┌──────────────────┐ │          ║
║      │ │ 棋盘 = 桌面       │ │          ║
║      │ │ ◉转盘    ▣牌堆    │ │          ║
║      │ └──────────────────┘ │          ║
║      └──────────────────────┘          ║
║  ▓自己的牌位 ▓道具×5 ▓体力 ▓¥ [转动转盘]║ ← 屏幕层，不斜
║ 📖规则说明            轮到你转盘了      ║
╚════════════════════════════════════════╝
```

**「可读信息上屏幕层」是硬原则**：斜着的字读不清，所以
- 桌面上**只留一眼能认出的实体**：格子图标、归属色条、房子、棋子、转盘、牌堆；
- **文字一律上屏幕层**——格名/售价/租金走已有的**格详情卡**（点格子才弹，正好复用）；
  身家/体力/倒计时走底部信息带；对手名字走桌边小名牌（短，可斜）。

## 四、小卖部 / 赌场：改为触发式全屏界面

- **触发时机不变**：落到小卖部格（`_run_shop`）/ 赌场格（`casino.run`）照旧，玩法逻辑一行不动。
- **呈现 = 全屏独占**（用户选定方案 a）：整屏换成该界面，淡入淡出切进切出，只留关闭/离开按钮。
  理由：桌面已不给它们留位置；赌场现在本就是"相机推近铺满屏"，改成独立场景更顺、还能拆掉一堆相机特技；
  全屏界面里的文字与按钮不受倾斜影响，可读性最好。
- **小卖部界面**：3 格货架 + 品质图例 + 刷新价 + 买按钮 + 倒计时（现成控件，改成全屏布景版式）。
- **赌场界面**：CSGO 式抽游戏 + 投骰子 + 奖池（现成演出，改成独立场景）。

## 五、桌面上的"人"与"物"

- **棋子照旧**：4 个棋子（含自己的）仍在桌面上沿格走，是第一人称下"谁在哪一格"的唯一来源。
- **自己的形象不在桌上**：第一人称看不到自己，全部信息在屏幕底栏。
- **对手 = 3D 立牌（方案 A1）**：每位对手一张立在桌沿外的牌子，正对相机、有投影。

**A1 分两步走**（用户同意）：

| 步 | 立牌内容 |
|---|---|
| **简版（本版）** | 头像（复用 `assets/pieces/` 的 4 张棋子图）+ `Label3D` 名牌与现金 |
| 后续 | 再把座位卡整块搬上立牌（体力槽 / 道具位 / 倒计时） |

**不选 A2/A3 的理由**：A2"平贴桌沿"在固定视角下会退化成"四张扁卡片躺在桌子远端"，
不叫围桌；A1 的立牌**正对相机**，牌面文字不被压扁，且现有座位卡控件能大半复用。

**1~3 人局**：空座位不放人，桌面照常（棋子与格子是主体）。

## 六、技术实现

### 6.1 SubViewport 搬家
`board_view` 的世界层整体塞进 `SubViewport`（尺寸建议 2048×2048 起，见风险 2）。
2D 相机保留，但 `_view_edge` / `rotate_*` 一系删除后它恒为"自己视角"的固定取景。

### 6.2 输入映射（唯一的真活）
```
屏幕点 → Camera3D.project_ray_origin/normal
       → Plane(Vector3.UP, 0).intersects_ray()      # 与水平桌面求交，不需要物理体
       → 桌面板 global_transform.affine_inverse()   # 世界点 → 桌面局部
       → UV = (local.x/size + 0.5, local.z/size + 0.5)
       → SubViewport 像素坐标 → SubViewport.push_input(合成事件)
```
SubViewport 内部的 2D 相机自己会处理坐标，**格子/座位/货架的点击逻辑不用重写**。
悬停（棋子 tooltip、格子高亮）同理，推 `InputEventMouseMotion`。

**这段映射必须抽成纯函数**（像 `net_addr.gd` 那样），才能单测——见 §八 测试策略。

### 6.3 相机与演出
- 滚轮 → 3D 相机沿视线推拉。
- **保留** 2D 相机"推近转盘 / 推近牌堆"的演出（桌面内的戏，仍需要）。
- **删除** `focus_casino` 一系（赌场改全屏后无用）。

### 6.4 渲染器约束（`gl_compatibility`）
能用：实时阴影、ViewportTexture、屏幕层 shader 暗角。
**没有**：SSAO / 屏幕空间反射 / 真景深。氛围靠"暗角贴片 + 一盏暖光 + 桌面投影"凑，**约七成**，
到不了邪恶铭刻那种。若要拉满需评估切 Forward+（低配机器风险，本版不做）。

## 七、批次 0 探针结论（2026-10-03 实测）

一次性脚本 `_spike_25d.gd`（throwaway，不入库；用完已删）。环境：Godot 4.6.2 stable，
OpenGL 3.3 / NVIDIA MX550 / **Compatibility** 渲染器。

| 验证项 | 结果 |
|---|---|
| SubViewport 贴 3D 材质（Compatibility） | ✅ 通过，方位正确无镜像 |
| 屏幕点 → 射线 → 桌面 → UV → SubViewport 坐标 | ✅ 往返误差 **< 0.01 px** |
| `push_input` 端到端点中 2D 控件 | ✅ 4/4 象限全中 |
| 3D 画面截图（`get_texture().get_image().save_png`） | ✅ 通过 |
| 射线打不到桌面 | ✅ 返回 null，可安全忽略 |

**取景实测数据**：相机 `(0, 6, 5)`（≈50.2° 俯角）+ 默认 75° FOV 时，8×8 桌面仅占屏 **320×210 px**
（视口 1280×800）。→ 正式实现需**拉近相机 + 收紧 FOV**，批次 2 调参。

**踩坑记录**：`SceneTree._initialize()` 阶段节点尚未真正入树，`look_at()` 会报
`Node not inside tree`；须改用 **`look_at_from_position()`**。

## 十、风险与待定

**风险**

1. **清晰度**：SubViewport 固定分辨率被透视缩小后，远端格子丢细节。对策：开大（2048+）或随缩放动态调整，会吃性能 → 批次 2 实测。
2. **氛围上限**：Compatibility 无 SSAO/SSR/景深，约七成（§6.4）。
3. **测试大面积失效**：见 §8.4，靠"纯函数化 + 逐条改断言"控制。

**待定（批次 2 已收敛）**

1. **SubViewport 尺寸**：定为**固定 2048×2048**，不随窗口变化 —— 清晰度够用，低配机开销是已知代价（风险 1）；「随窗口动态调整」留待以后。
2. **立牌上座位卡细节**（体力 / 道具 / 倒计时）：**仍未搬** —— 立牌本身在批次 3，届时一并评估。
3. **暗角 / 顶光参数**：批次 2 对着 `--shot` 调定，实际选值如下——
   - 相机：俯角 `CAM_TILT_DEG = 50°`、`CAM_FOV = 55°`（收窄默认 75°：探针实测默认 FOV 下桌面只占屏约 1/4）、`CAM_DIST = 5.8`（窗口恢复整张画布后桌面回到 8×8，需拉远才不让下家座位栏顶出屏幕）；
   - 顶光：`OmniLight3D` y=2.4 / `omni_range` 8.5 / energy 2.4、暖色 (1.0, 0.90, 0.78)；阴影先关（场上还没有投影物，开了等于每帧白跑一张阴影图）；
   - 暗角：屏幕层 `ColorRect` + shader，`smoothstep(0.35, 1.0, r)`、alpha 0.35。
