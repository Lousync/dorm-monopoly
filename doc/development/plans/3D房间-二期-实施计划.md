**Goal:** 让四把椅子上坐上人（3 个可见角色 + "我"不渲染），带骨骼动画：待机 + 四个玩法事件反应

**Tech Stack:** Godot 4.6.2 / GDScript；**素材未定**（Quaternius 带动画人形 vs Kenney 方块人）——

## 为什么 Task 1 起还是草案

`doc/development/3D房间-二期设计.md` §四 记着两条**未知事实**，它们决定后面所有步骤长什么样：

1. **导入通路未定**：Quaternius 的包**只有 FBX / OBJ / Blend、没有 glTF**，而 **Godot 4 不认 FBX**，
   且本项目**从未配过 Blender**（`project.godot` 无 `[filesystem]`/`blender_path`）。
   `.blend` 直读 / FBX→glTF / 换 Kenney GLB —— **三选一走哪条，决定素材、决定 `LICENSE` 登记、
   决定"4 个不同的人"是否退化成"1 个模型换 4 色"**。
2. **动画清单未知**：包页只说「many animations」，**没列名字**，而且**未必有坐姿**。
   而"付钱动哪一下、破产动哪一下"**必须用包里真实存在的动画名**去写 ——
   写了不存在的名字，计划本身就是废的（这也是它现在只能是草案的原因）。

⇒ 所以：**Task 0 先把这两件事问清楚并写下结论**，**然后按结论重写 Task 1 起**。
重写这件事**由控制者做**（改本文件 + 重新生成任务简报），不是实施者自己发挥。

## Task 1 起的草案（**待 Task 0 定案后重写为逐条步骤**）

下面是**意图清单**，不是可执行步骤 —— 列在这里是为了让用户看到全貌与顺序。
**Task 0 一有结论，控制者就把它展开成和一期一样的"每步 2–5 分钟 + 变红验证 + 提交"的形状。**

| 单元 | 交付物 | 关键判据（一期已有同型断言，照抄形状） |
|---|---|---|
| **T1 骨架接入** | `scripts/chars.gd` 骨架 + `CHARS_ENABLED`；**先只放 1 个角色**到 slot 1 | `CHARS_ENABLED=false` ⇒ 画面与一期**逐字节一致**；角色挂在 `seat_anchor(1)` 上、不穿模 |
| **T2 四个座位** | 3 个角色（slot 1/2/3）；**slot 0 不渲染** | "我"无角色节点；角色 ↔ peer 与 `game._seat_peers()` 一致（**二期最怕的还是坐错位**） |
| **T3 待机 + 随取景淡出** | 待机循环；按取景淡入淡出并**停播** | 推近端 `AnimationPlayer.is_playing() == false`；拉远端在播 |
| **T4 四个事件反应** | 出牌 / 付钱 / 被抢地 / 破产 —— **动画名由 Task 0 的清单填** | 每个事件各出一次图；幅度由用户点头 |
| **T5 验收** | 性能两组（角色在播 / 已停播）、出图、`LICENSE` 与 `AGENTS.md` 同步 | `--fps=` 与一期基线对比；**"读棋盘"档不许变慢** |

**顺序理由**：T1 先把"一个人坐对"钉死（一期的 Task 2 也是先骨架后填肉）；
T2 才是复数化（**"坐错位"这类错在只有一个人时看不出来**）；
T3 的淡出是**性能保险**，必须在 T4 加动画之前就位 —— 否则 T4 一加动画，主玩法档立刻变慢，
而那时你会以为是"骨骼动画本身太贵"，其实是"该停的时候没停"。
