# 实施计划：开局科技（掷骰定档 + 三选一）

> 来源：2026-10-04~05 设计拍板（见 `doc/development/开发台账.md` §一「开局科技」行）。
> 机制与图鉴唯一来源：`doc/game-design/开局科技.md`。**本计划随版本合入 `main` 后连同文件一起删除。**

## 一、已敲定的口径

| 口径 | 结论 |
|---|---|
| 等级 | 白银 / 黄金 / 钻石三档，每局**掷骰定档**（1~2 / 3~4 / 5~6，等分），全场同档、骰子公开 |
| 池子规模 | 每档目标 20 条、分期补；白银 20 条已定稿，黄金 / 钻石各 4 条**草案占池** |
| 重复 | 允许多人选同一条科技，各自独立生效 |
| 流程 | `_host_setup` 建 hp 后、回合循环前：掷骰 → 逐人私密同档三选一（bot / 超时随机兜底）→ 公告 + 即时效果 |
| 开关 | `tech_on` 默认关；入口 = 大厅「游戏设置」弹窗（对局内不可改） |
| 标签 | 科技无 buff/debuff 标签，香皂无效；厄运保单自带 4 次计数、独立于香皂判定链 |
| 实现备注 | 学生折扣只作用于小卖部现金价（黑市按地皮计价）；兼职达人「经过」含路过与停留、焦土期间不算；摸鱼时刻仅原始掷出 0 触发（隔离压到 0 不算）；灵活就业与错峰用电可叠加为首件 −2 |

## 三、影响面（核对清单）

- **踩过的坑**（已修，供回溯）：① GDScript 字典点号赋值对不存在的键报错——科技相关字段（`tech` / `wuyun_left` / `yanguang_left` / `kingtu`）已在 `_build_hp` 预声明；② `_use_item` 的成功收尾块曾被缩进进 `return` 死区（`item_used_n` 不递增），item_test 抓出后已修复；③ 测试必须等 `_host_setup` 恢复执行完（1.5s）再改状态，否则开局流程与测试并发互踩；④ `_shop_buy` 要求商店处于打开态（`_shop_peer` / `_shop_tile`）。
- **已知边界**：测试环境 `Net.players` 为空导致 `_host_setup` 的广播在空 hp 上报越界（既有现象，套件容忍）；黄金 / 钻石占池条目待批改后可整批替换（数据层改 `tech_data.gd` 即可）。
- **后续批次**：黄金 / 钻石池子逐条批改（凑每档 20）；发车定档演出与座位卡科技角标（随界面美术重构）；「科技每人可选数 >1」的扩展。
