# 架构总览

> 面向新加入的开发者：先读本文，再读 `联机协议.md` 与 `上手指南.md`。
> 更新：2026-10-03。

## 一、项目定位

- **《宿舍大富翁》**：Godot **4.6** + **GDScript** 的 2D 桌游；56 格外圈棋盘，**1~4 人联机**（房主即权威服务器）。
- 单机 = 房主 + 机器人，同一套代码。
- 纯程序化美术：UI/卡面/轮盘/棋子/木纹为运行时绘制或开源素材（Kenney / Twemoji / ambientCG，见根目录 `LICENSE`）；音效由 `fx.gd` 程序合成。
- 无存档、**不支持中途加入与观战**；房主退出即对局结束。

## 二、场景流

```
main_menu.tscn  ──(创建/加入房间)──►  lobby.tscn  ──(全员准备+开始)──►  game.tscn
  昵称/搜房             Net.host_game / join_game          Net.start_game()
                        准备、加/减机器人、聊天              对局主循环
```

- `item_lab.tscn`（**道具试验场**，`--lab` 或主菜单开发者入口进入）复用 `game.tscn` 的房主逻辑、进入「lab 空闲模式」但不跑回合循环，用于逐个验证道具效果；见 `道具试验场.md`。
- 场景切换统一走 `Fx.go_to(path)`（带淡入淡出）。
- 自动加载单例（`project.godot`）：
  - `Net`（`scripts/net.gd`）：连接、大厅数据、聊天、UDP 搜房。
  - `Fx`（`scripts/fx.gd`）：音效 + 震屏/飘字/彩带/入场动画。

## 三、核心：房主权威（Host-Authoritative）

- **所有玩法状态在房主计算**：`hp`（玩家）、`htiles`（地块）、`shops`（小卖部）、黑市、道具、冷却、事件…全在 `game.gd` 的房主侧。
- 客户端**只发意图请求**，不做判定；收到状态后**只渲染**。
- 全量状态快照通过可靠 RPC 广播（`s_state`），客户端 `s_state()` 只负责刷新 UI 与棋盘。

```
客户端点击 ──c_* RPC──► 房主校验/结算 ──s_* RPC(含 s_state)──► 全员渲染
```

## 五、表现层约定

- **持续动画统一手写**（`_process` 相位驱动，如转轮、牌堆抽卡）；Tween 只用于一次性过渡（弹入、按钮缩放）。
- **对局画面是三层结构**（v0.5.0 批次 2 起，自下而上）：
  ① **3D 场景**（`TableView3D`）：暗色 `WorldEnvironment` + **一盏暖色台灯的光（全场唯一主光源，
  批次 6 起；可见几何批次 12 A1 已删、只留光）** + 一张**水平**桌面板
  （`PlaneMesh`，材质贴的就是②的画面）+ **一层程序化房间**（v0.8.0 一期：地板 / 天花板 /
  四面墙 / 三件家具 / 四把椅子与椅背名牌 / 地毯 / 一盏不投影的补光，`scripts/room.gd`，
  总开关 `ROOM_ENABLED`；见下面「房间层」那条）+ 固定在自己座位、**俯角 ~50°** 的 `Camera3D`。
  ② **`SubViewport`（2048²）内的 2D 世界**：`BoardView` 原样住在里面，自研 2D 相机
  （注视点 / 缩放）**仍然保留**，继续驱动「推近转盘 / 推近牌堆」的对焦演出，
  **视角恒在自己座位、不旋转**（转视角已随批次 1 删除）。
  画布里**只剩桌垫**（棋盘 + 一圈留白，`BoardView.MAT_RECT`）：贴到桌面的**纹理窗口 =
  桌垫区域**（`TableView3D.TEX_WINDOW_PX`，桌面材质取样与输入映射同源），桌垫之外再铺一圈
  木纹（第二个平面，`assets/textures/wood_floor.jpg`）⇒ 观感是「印在木桌上的一块桌垫」。
  **批次 10 收窄过一圈**（桌垫留白 `MAT_MX/MT/MB` 100/100/260 → 40/40/90、木纹框 `WOOD_FRAME`
  1.2 → 0.7、`TEX_WINDOW_PX` 与 `HAND_BASE_PX` 按新桌垫同步重算）⇒ 棋盘在桌垫与桌面上都大了
  一圈、木纹只剩薄薄一条边；取景判据只认桌垫四角，木纹框因此不必再为取景留预算。
  **批次 2 推迟的「棋盘铺满桌面」比例目标在批次 5 结清**：四条座位栏离开画布之后，画布不再需要
  用整张 2048² 当窗口来容纳它们（当时那条约束与踩过的坑见 `table_3d.gd` 的 `TEX_WINDOW_PX` 注释）。
  ③ **屏幕层 HUD**（自己的身家条 / 战报 / 暂停 / 规则说明 / 格详情卡 /
  小卖部与赌场全屏界面 / 黑市操作条 / 顶部居中的畸变横幅）：仍是 `game` 上的普通 Control，
  叠在 3D 之上，**不受桌面倾斜影响**（斜着的字读不清，文字一律留在屏幕层）。
  **屏幕底部不再有操作坞**（批次 3 Task 6 拆除），**右侧名册栏也没有了**
  （批次 5 由四角身家条取代，**批次 12 D 起四角条只剩"我"那一条、他人改由一条常驻名册条（**v0.10.0 起那条名册条已整体删除、他人那一份搬到桌面立牌**，见 `3D房间-二期设计.md` §5.9）
  承担** —— **批次 13 ② 起这条名册条在左上角「暂停」旁**，见下）。
- **输入映射（2.5D 唯一的真活）**：由 `TableView3D` 接管——屏幕点 → `Camera3D` 射线 →
  与水平桌面求交 → 桌面 UV → `SubViewport` 像素坐标 → `push_input`（合成 `InputEventMouseButton`
  / `InputEventMouseMotion`）送进 ②的 2D 世界，**格子 / 座位 / 货架的点击逻辑不用重写**；
  悬停同理（并**额外**经 `TableView3D.on_table_hover` 通知 `game` 更新**屏幕层**的悬停信息条 ——
  它**不消费输入**，见 §五「悬停棋子信息条在屏幕层」那条）。反方向（画布坐标 → 屏幕坐标）走
  `viewport_to_screen`，供消费棋盘坐标的屏幕层
  HUD 用（格详情卡、飘字）。几何全在纯函数 `TableGeometry`，可无头单测。
  **滚轮 = 3D / 2D 视角连续推移**（v0.5.0 批次 4 起；**推拉 `dolly` 在批次 4 曾整个删除、
  v0.8.0 3D 房间一期又以 `Ctrl` + 滚轮请回来** —— 它是**第二条轴**，只作用在 3D 端，
  见下面「双视角」那条的末段）；
  拖拽平移已随批次 1 删除（第一人称没有「平移桌子」这回事）。
- **双视角（v0.5.0 批次 4）**：相机沿**一条轨道**在「3D 第一人称」与「2D 桌面」之间连续推移
  （`TableView3D`，平滑，不是硬切开关）。
  - **`view_t ∈ [0,1]` 是这条轨道上的位置**：`0` = 3D 第一人称（俯角 **50°**、相机到注视点的
    3D 距离 **13.85**（= `CAM_DIST 8.90 / cos 50°`；v0.8.0 一期把 `CAM_DIST` 5.77 → **8.90**
    以把房间拉进画）、手里有牌、能出牌），`1` = 2D 桌面
    （俯角 **88°**、距离 **9.20**（= `VIEW_DIST_2D`）、只看桌上地图）。
    **两端参数与取值推导**（两条断言：四角不出画面 + 两端桌面占屏面积比 0.86）见
    `table_3d.gd` 的 `VIEW_DIST_2D` 常量注释。
  - **取景判据 = 桌垫四角**（v0.5.0 批次 10 定案）：**整条视角轨道（21 档）上，桌垫
    （`TABLE_SIZE`）的四个角必须都在画面内**；外圈**木纹是"桌子本身"、可以出画**（第一人称下
    桌子伸出画面是自然的）—— `layout_test` 的取景断言从头到尾量的都是桌垫。批次 10 顺带把
    `table_3d.CAM_DIST` 段那句过期的「取景断言按**木桌四角**量（±5.2 / ±4.28）、最紧 93.4px」
    **改准**（它与"桌垫最紧"那一组数对不上：木桌在桌垫之外、余量不可能更大），并更新为
    本档实测值（21 档最紧 **81.6px** @ wt=0.00、两端 **81.6 / 112.1px**）。
  - **滚轮改的是目标值不是当前值**：`set_view(view_target ± VIEW_STEP)`（`VIEW_STEP = 0.25`，
    四格从 3D 走到 2D；向前滚 = 推向 2D，向后滚 = 拉回 3D），`_process` 里按
    `e^(-VIEW_SNAP·delta)` **指数逼近**（帧率无关、单调不过冲）。`snap_view(t)` 是"设目标并立即
    到位"的旁路，只给摆拍与测试用（玩法别用，那会丢掉推移感）。
  - **第二条轴：`Ctrl` + 滚轮 = 推拉（v0.8.0 3D 房间一期）**。滚轮已经被视角推移占满、
    而且它是切 3D/2D 的唯一入口（没有按钮）⇒ 推拉另给 `Ctrl` 作修饰键（`set_dolly` /
    `dolly_target`，`dolly ∈ [DOLLY_MIN, DOLLY_MAX] = [0.70, 1.40]`，同样指数逼近）。
    （⚠ 这里曾写成 `[1.00, 1.40]` —— 那是**推拉刚回来时**的值；一期 Task 7 把 `DOLLY_MIN`
    定到 **0.7**（推近端、格宽 44.5px），二期 Task 5 顺手改准。**二期的角色淡出就挂在 0.7 这一档上**。）
    **只作用在 3D 端**：那一维乘在 3D 端那段距离上、再与 `VIEW_DIST_2D` 插值 ⇒ 它的权重正好是
    **`(1 − view_t)`**，`view_t = 1` 时**归零** ⇒ **2D 端的取景与格宽在推拉前后逐字节相同**
    （`layout_test` 有一条断言钉着它）。默认档 = `dolly 1.00`（用户选「默认看屋子」），
    推近端才是"读棋盘"的那一档（格子屏幕宽：默认 32.3px / 推近 44.5px / 拉远 23.7px /
    2D 端 53.2px）。**推拉不动俯角**（沿 50° 射线退远）—— "抬头看吊灯"因此仍然做不到。
  - **手牌随视角淡出、「看不见就点不到」**：`TableView3D` 把 `view_t` 推给 `TableProps`
    （`set_view_t`，挂在 `_apply_camera()` 末尾，`snap_view` 那条路也覆盖），手牌在
    `HAND_FADE_LO = 0.35 → HAND_FADE_HI = 0.65` 之间淡出；淡到 `HAND_HIT_MIN_ALPHA = 0.15`
    以下 `hand_hit` 直接返回 `-1` ⇒ **2D 端出牌要回 3D 这条意图不需要任何玩法代码**
    （`game.gd` 一行未改）。`(0.576, 0.625]` 那条"看得见但点不到"的窄带及其可接受性见
    `table_props.gd` 的 `HAND_HIT_MIN_ALPHA` 常量注释。
  - **视角是纯本地表现，不进协议**：不写进 `s_state`、不同步 —— 每个人自己滚自己的；
    `_broadcast_state` 与所有 `@rpc` 装饰器都不受影响。
- **2D 相机（`BoardView`）的倍率一律写「相对全景的倍数」**：`focus_grid` 的 `zoom` 参数，以及
  `MIN_ZOOM_FACTOR 0.55` / `MAX_ZOOM_FACTOR 3.1` 都是这个意思（1.0 = 全景），统一由
  `BoardView._zoom_from_factor()` 换算成绝对倍率。
  **别写绝对字面量**——画布尺度一变换算就废（真踩过：早先的抽卡推近写成绝对 `0.78`，
  在 2048² 画布下比全景的 0.97 还小，等于完全不推近；那条推近连同 `DECK_PUSH_FACTOR` 已随
  批次 8 删除，见 §六 抽卡演出那条）。
- **桌面实物的摆放约定（v0.5.0 批次 3 定案，批次 4 继承，批次 6 收口，批次 7 物件表更新，批次 9 再缩，
  批次 11 加入棋子 / 光环 / 房子）**：
  3D 物件里
  **跟 2D 相机的只有"压在同一个物体的印刷图案上"的那几件**（转盘轮缘、两摞牌堆、**行动光环、装修房子**
  ——位置与尺寸都跟；**棋子只跟位置、尺寸写死**，它要"站在印着的那一格上"），
  **手牌一律不跟**（筹码堆 / 体力件已在批次 7 整体退场，**立牌已在批次 9 整体退场**）。
  - **跟**：轮缘的位置来自 `BoardView.wheel_screen_pos()`、半径 = `200 × _zoom`（`table_props.build_wheel`
    量真变换得来）；两摞牌堆的位置来自 `BoardView.deck_screen_pos(deck)`（批次 6 Task 3 新增的
    公开入口 —— 内部就是 `global_position + _view_from_world(deck_center)`）；**棋子的落点来自
    `BoardView.token_screen_pos(idx, slot)`、房子薄牌来自 `BoardView.tile_screen_pos(idx)`**
    （批次 11，同一套 `global_position + _view_from_world(局部点)`）。它们都压在**印在桌垫上**
    的图案上（轮盘 / 卡背 / 棋子与房子那格），而桌垫图案随 2D 取景缩放，不跟就会脱开。
  - **不跟**：其余物件的位置走**画布常量**（`table_props.HAND_BASE_PX`；同族的 `STANDEE_BASE_PX`
    已随批次 9 的立牌退场一并删除）——
    它们是**自由立在桌上的实物**，不该因为"印出来的图案"变了而移动。
    相机推近是「你凑近看」，不是「桌子被重新排版」。
    棋子的**尺寸**同理写死在**世界单位**里（只跟位置）——「小人」不该随镜头推近长个儿。
  - **刷新时机（批次 6 Task 3 补齐，批次 8 收缩为一个调用点，批次 11 再加两条）**：跟的那几件由
    `game._refresh_board_followers()`（轮缘 / 牌堆）、`game._refresh_tokens()`（棋子 / 光环）、
    `game._refresh_houses()`（房子）重摆，**广播那条路上**（`game._refresh_table_props`）各走一遍。
    **滚轮推移视角不在其列**：那只改 3D 相机的俯角与到桌心的距离、不碰 2D 的 `_zoom`。
    曾有的 ②「抽卡演出期间逐帧」（条件是 `board.is_showing_deck_card()`）**已随批次 8 删除** ——
    它的唯一触发者就是那次抽卡推近（`focus_point_zoom`，**不伴随任何状态广播**；只靠 ① 的话桌垫
    图案在演出中滑动、实体纹丝不动，实测会分开 556 画布像素）。**抽卡演出搬去屏幕层后相机全程
    不动**，这条逐帧重推失去前提。其余"不伴随 `s_state` 的镜头变化"（`focus_grid` / 人数变化）

  **菜单 / 暂停遮罩带（80）现已高于结算（50）与弹问（60）**（v0.5.0 批次 8 给 `menu_layer`
  显式设 z 80，此前它是隐式 0、反被这两层压着）—— 这是"菜单是最顶模态"的合理结果，**不是 bug**：
  客户端本地开着暂停菜单时若房主结束对局，菜单会**盖在结算面板之上**（此前相反）。

- **公共 / 私人分层红线**：桌面面板只放公共信息，真实信息（三选一选项、赌场透视）走**私密 RPC**（`rpc_id`）。

## 六、命名与约定

- RPC：`s_*` = 房主→全员（authority）；`c_*` = 客户端→房主（any_peer）。详见 `联机协议.md`。
- 「无主」哨兵 `NO_OWNER = -100`（**不能用 -1**：机器人 peer id 从 -1 起编号）。
- 唯一性池 `_item_pool` 必须同时计入：玩家背包 + 小卖部货架 + 黑市货架 + 已焚毁。
- 数值占位多处标注「待数值专场」，改动请同步 `game-design/*`。
