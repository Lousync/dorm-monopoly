# 架构总览

> 面向新加入的开发者：先读本文，再读 `联机协议.md` 与 `上手指南.md`。
> 更新：2026-10-03。

## 一、项目定位

- **《宿舍大富翁》**：Godot **4.6** + **GDScript** 的 2D 桌游；56 格外圈棋盘，**1~4 人联机**（房主即权威服务器）。
- 单机 = 房主 + 机器人，同一套代码。
- 纯程序化美术：UI/卡面/轮盘/棋子/木纹为运行时绘制或开源素材（Kenney / Twemoji / ambientCG，见根目录 `LICENSE`）；音效由 `fx.gd` 程序合成。
- 无存档、**不支持中途加入与观战**；房主退出即对局结束。

## 二、场景流

```
main_menu.tscn  ──(创建/加入房间)──►  lobby.tscn  ──(全员准备+开始)──►  game.tscn
  昵称/搜房             Net.host_game / join_game          Net.start_game()
                        准备、加/减机器人、聊天              对局主循环
```

- `item_lab.tscn`（**道具试验场**，`--lab` 或主菜单开发者入口进入）复用 `game.tscn` 的房主逻辑、进入「lab 空闲模式」但不跑回合循环，用于逐个验证道具效果；见 `道具试验场.md`。
- 场景切换统一走 `Fx.go_to(path)`（带淡入淡出）。
- 自动加载单例（`project.godot`）：
  - `Net`（`scripts/net.gd`）：连接、大厅数据、聊天、UDP 搜房。
  - `Fx`（`scripts/fx.gd`）：音效 + 震屏/飘字/彩带/入场动画。

## 三、核心：房主权威（Host-Authoritative）

- **所有玩法状态在房主计算**：`hp`（玩家）、`htiles`（地块）、`shops`（小卖部）、黑市、道具、冷却、事件…全在 `game.gd` 的房主侧。
- 客户端**只发意图请求**，不做判定；收到状态后**只渲染**。
- 全量状态快照通过可靠 RPC 广播（`s_state`），客户端 `s_state()` 只负责刷新 UI 与棋盘。

```
客户端点击 ──c_* RPC──► 房主校验/结算 ──s_* RPC(含 s_state)──► 全员渲染
```

## 五、表现层约定

- **持续动画统一手写**（`_process` 相位驱动，如转轮、牌堆抽卡）；Tween 只用于一次性过渡（弹入、按钮缩放）。
- 桌面世界用自研 2D 相机（注视点/缩放/旋转）；屏幕层 HUD（顶栏/行动条/私弹/菜单）叠在世界之上。
- **底栏是一条固定的屏幕底部操作坞**（牌垫阶段条 + 操作条并排，见 `game._place_dock`），
  不锚在座位卡上——跟随座位卡会让按钮跟着镜头满屏跳。两条外面包一层共用底板
  （`UIKit.dock_plate`，只做外观不吃鼠标），结构上仍是两条独立控件。
  底栏的横向可用带由 `game._dock_band()` 从两侧栏（规则说明面板 / 战报栏）的实际几何推导，
  避免互相压住。
- **右栏名册复用座位卡那套身家/排名**（`game._refresh_players` 算完直接喂给
  `_refresh_rail`，带签名缓存）——身家公式只留一处，避免两套算法悄悄跑偏。
- **弹层与其外层容器必须一起显隐**：`menu_layer` 里三块面板各套一个全屏
  `CenterContainer`（默认 `mouse_filter=STOP`），只切内层面板会把整屏点击吃光
  （点开暂停后「界面卡死」的真凶，见 `fix/v0.1.0` 与 `tests/pause_menu_test.gd`）。
  菜单族统一走 `game._menu_show(which)` 切换。
- **公共 / 私人分层红线**：桌面面板只放公共信息，真实信息（三选一选项、赌场透视）走**私密 RPC**（`rpc_id`）。

## 六、命名与约定

- RPC：`s_*` = 房主→全员（authority）；`c_*` = 客户端→房主（any_peer）。详见 `联机协议.md`。
- 「无主」哨兵 `NO_OWNER = -100`（**不能用 -1**：机器人 peer id 从 -1 起编号）。
- 唯一性池 `_item_pool` 必须同时计入：玩家背包 + 小卖部货架 + 黑市货架 + 已焚毁。
- 数值占位多处标注「待数值专场」，改动请同步 `game-design/*`。
