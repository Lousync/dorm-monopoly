# 架构总览

> 面向新加入的开发者：先读本文，再读 `联机协议.md` 与 `上手指南.md`。
> 更新：2026-10-03。

## 一、项目定位

- **《宿舍大富翁》**：Godot **4.6** + **GDScript** 的 2D 桌游；56 格外圈棋盘，**1~4 人联机**（房主即权威服务器）。
- 单机 = 房主 + 机器人，同一套代码。
- 纯程序化美术：UI/卡面/轮盘/棋子/木纹为运行时绘制或开源素材（Kenney / Twemoji / ambientCG，见根目录 `LICENSE`）；音效由 `fx.gd` 程序合成。
- 无存档、**不支持中途加入与观战**；房主退出即对局结束。

## 二、场景流

```
main_menu.tscn  ──(创建/加入房间)──►  lobby.tscn  ──(全员准备+开始)──►  game.tscn
  昵称/搜房             Net.host_game / join_game          Net.start_game()
                        准备、加/减机器人、聊天              对局主循环
```

- `item_lab.tscn`（**道具试验场**，`--lab` 或主菜单开发者入口进入）复用 `game.tscn` 的房主逻辑、进入「lab 空闲模式」但不跑回合循环，用于逐个验证道具效果；见 `道具试验场.md`。
- 场景切换统一走 `Fx.go_to(path)`（带淡入淡出）。
- 自动加载单例（`project.godot`）：
  - `Net`（`scripts/net.gd`）：连接、大厅数据、聊天、UDP 搜房。
  - `Fx`（`scripts/fx.gd`）：音效 + 震屏/飘字/彩带/入场动画。

## 三、核心：房主权威（Host-Authoritative）

- **所有玩法状态在房主计算**：`hp`（玩家）、`htiles`（地块）、`shops`（小卖部）、黑市、道具、冷却、事件…全在 `game.gd` 的房主侧。
- 客户端**只发意图请求**，不做判定；收到状态后**只渲染**。
- 全量状态快照通过可靠 RPC 广播（`s_state`），客户端 `s_state()` 只负责刷新 UI 与棋盘。

```
客户端点击 ──c_* RPC──► 房主校验/结算 ──s_* RPC(含 s_state)──► 全员渲染
```

## 五、表现层约定

- **持续动画统一手写**（`_process` 相位驱动，如转轮、牌堆抽卡）；Tween 只用于一次性过渡（弹入、按钮缩放）。
- **对局画面是三层结构**（v0.5.0 批次 2 起，自下而上）：
  ① **3D 场景**（`TableView3D`）：暗色 `WorldEnvironment` + 一盏暖顶灯 + 一张**水平**桌面板
  （`PlaneMesh`，材质贴的就是②的画面）+ 固定在自己座位、**俯角 ~50°** 的 `Camera3D`。
  ② **`SubViewport`（2048²）内的 2D 世界**：`BoardView` 原样住在里面，自研 2D 相机
  （注视点 / 缩放）**仍然保留**，继续驱动「推近转盘 / 推近牌堆」的对焦演出，
  **视角恒在自己座位、不旋转**（转视角已随批次 1 删除）。
  贴到桌面的**纹理窗口 = 整张 2048² 画布**（`TableView3D.TEX_WINDOW_PX`，桌面材质取样与
  输入映射同源）——正因铺满整张画布，四条座位栏才落在桌面上（可见且可点到）；
  **「棋盘铺满桌面」的比例目标推迟到批次 3**（届时座位栏将换成桌上立牌）。
  ③ **屏幕层 HUD**（右栏名册 / 战报 / 暂停 / 规则说明 / 格详情卡 / 小卖部与赌场全屏
  界面 / 黑市操作条）：仍是 `game` 上的普通 Control，叠在 3D 之上，**不受桌面倾斜影响**
  （斜着的字读不清，文字一律留在屏幕层）。**屏幕底部不再有操作坞**（批次 3 Task 6 拆除）。
- **输入映射（2.5D 唯一的真活）**：由 `TableView3D` 接管——屏幕点 → `Camera3D` 射线 →
  与水平桌面求交 → 桌面 UV → `SubViewport` 像素坐标 → `push_input`（合成 `InputEventMouseButton`
  / `InputEventMouseMotion`）送进 ②的 2D 世界，**格子 / 座位 / 货架的点击逻辑不用重写**；
  悬停同理。反方向（画布坐标 → 屏幕坐标）走 `viewport_to_screen`，供消费棋盘坐标的屏幕层
  HUD 用（格详情卡、飘字）。几何全在纯函数 `TableGeometry`，可无头单测。
  **滚轮 = 推拉 3D 相机**（`dolly`：只改相机到桌心的距离、方向不变，于是俯角恒定）；
  拖拽平移已随批次 1 删除（第一人称没有「平移桌子」这回事）。
- **2D 相机（`BoardView`）的倍率一律写「相对全景的倍数」**：`focus_grid` / `focus_point_zoom`
  的 `zoom` 参数，以及 `MIN_ZOOM_FACTOR 0.55` / `MAX_ZOOM_FACTOR 3.1` / `DECK_PUSH_FACTOR 2.0`
  都是这个意思（1.0 = 全景），统一由 `BoardView._zoom_from_factor()` 换算成绝对倍率。
  **别写绝对字面量**——画布尺度一变换算就废（本批次真踩过：抽卡推近原写成绝对 `0.78`，
  在 2048² 画布下比全景的 0.97 还小，等于完全不推近）。
- **桌面实物的摆放约定（v0.5.0 批次 3 定案，批次 4 必须继承）**：3D 物件里**只有转盘轮缘跟 2D 相机**
  （`_zoom`），筹码堆 / 体力件 / 手牌**一律不跟**。
  - **跟**：轮缘的位置来自 `BoardView.wheel_screen_pos()`、半径 = `200 × _zoom`（`table_props.build_wheel`
    量真变换得来）——它必须贴**印在桌垫上的**那个轮盘，而桌垫图案随 2D 取景缩放，不跟就会脱开。
  - **不跟**：其余物件的位置走**画布常量**（`table_props.HAND_BASE_PX` / `CHIP_BASE_PX` / `PIP_BASE_PX`）
    ——它们是**自由立在桌上的实物**，不该因为"印出来的图案"变了而移动。相机推近是「你凑近看」，
    不是「桌子被重新排版」。
  - **代价（如实留痕）**：抽卡动画把 2D 取景推到 ≥2×（`DECK_PUSH_FACTOR`）时，桌垫图案滑动、**实物不动**
    ⇒「手牌不压座位栏 / 不压自己那排格子」这些断言**只在全景取景下成立**。批次 4 要**连续移相机**，
    必须继承这条决定，并顺带决定是否为轮缘补「每帧跟 `_zoom`」（当前只在每次状态广播刷新，
    `game._refresh_table_props`）。放大取景可复现：`--shot=*freecam*`（见 `开发台账.md` §三）。
- **屏幕底部已没有操作坞**（v0.5.0 批次 3 Task 6 拆除）。原先那条固定底栏（牌垫阶段条 +
  操作条 + 共用底板，见旧 `game._place_dock` / `UIKit.dock_plate`，两者已删）连同座位卡上的
  **道具牌位**那一排一并去掉，玩家侧入口改到桌面上：
  - **掷轮 = 点桌面中央的转盘实体**（`game._on_table_click` → `_on_roll_pressed`）；
  - **出牌 = 点自己面前的「手中牌」实体**选中（再点同一张取消），**再点牌垫上的「使用道具」
    确认**（两段式选目标的道具照旧进选目标态）；
  - **现金 / 体力 = 桌上的筹码堆与体力件**（`table_props.gd`）。
  牌垫上的两个阶段按钮（`BoardView.set_phase_buttons` / `_phase_spin` / `_phase_use`）**保留** ——
  它们才是掷轮与出牌的世界坐标入口；坞里那两个同名按钮早就只是 `visible=false` 的空壳。
  仍留在屏幕底部的只有**黑市操作条**（触发式，走 `game._place_overlay_bar`），所以
  `_place_overlay_bar` / `_dock_band` / `_clamp_dock_x` 三个函数为它保留。
  **信息损失（批次 3 已裁定接受，此处如实留痕）**：`status_label` 一走，屏幕上再没有
  「轮到你转盘了！／等待 X 转盘…／轮到你使用道具！」这类**状态文案**了（客户端那句
  「等待房主同步状态…」也没有了）。「该你了」现在由**牌垫阶段按钮的点亮/置灰**
  （`set_phase_buttons` 的 style 参数）+ 座位卡上的**操作倒计时**承担；发生过的事由**战报**承担。
  代价是玩家看不出「别人正在小卖部/黑市/做决定」这类**他人状态**，只能从战报与桌面上推。
- **`BoardView` 在 v0.5.0 批次 3 只有三处改动，都不是玩法逻辑**：① 删掉座位卡上的**道具牌位**
  那一排（连 `set_seat_slot` 与 `item_slot_clicked` 的发射点一起，Task 6）；② 新增**手牌锚点**
  只读查询（Task 4，供 `table_props` 把手中牌摆在自己面前）；③ 新增 `wheel_screen_radius()`
  （Task 2）。**为什么 ③ 属"只读查询"而非玩法逻辑**：它只是把画布上**已经画出来的**那个转盘半径
  （`200 × _zoom`）如实报出来，让 3D 轮缘跟住镜头倍率——点数、扇区、转动动画、命中判定全在
  BoardView 与 `game.gd` 的既有路径里，一行没动；②同理，只是报一个位置。
  **玩法逻辑仍只在房主（`game.gd`）**，这条红线没有被破。
- **右栏名册复用座位卡那套身家/排名**（`game._refresh_players` 算完直接喂给
  `_refresh_rail`，带签名缓存）——身家公式只留一处，避免两套算法悄悄跑偏。
- **弹层与其外层容器必须一起显隐**：`menu_layer` 里三块面板各套一个全屏
  `CenterContainer`（默认 `mouse_filter=STOP`），只切内层面板会把整屏点击吃光
  （点开暂停后「界面卡死」的真凶，见 `fix/v0.1.0` 与 `tests/pause_menu_test.gd`）。
  菜单族统一走 `game._menu_show(which)` 切换。
- **小卖部 / 赌场是触发式全屏界面**（v0.5.0 批次 1 起）：挂在 `game` 屏幕层，
  照 `menu_layer` 那套「全屏压暗底 + 居中面板」一起显隐；不再画在桌面世界层。
- **屏幕层各弹层的层级只能靠 `z_index`，靠树序置顶不够**：置顶只解决「后建的屏幕层控件
  （暂停按钮 / 格详情卡 / 战报）按树序画在压暗底之上」那一半，两条都不做就会两头穿帮。
  现有档位：结算层 50 / 弹问 60 / 小卖部·赌场 70 / 飘字 90·彩带 95；其中小卖部 / 赌场
  两层还在显示时 `move_child` 置顶，改层级时别把任一条去掉。
  **这条规则在 3D 下照旧适用**——棋盘住进 `SubViewport` 后只是 3D 场景里的一块贴图，
  board 内部的 `z_index`（棋子 20 / 光环 15 / 牌堆卡 30 / 悬停提示 60）不再跨层穿帮，
  但屏幕层之间仍得靠 `z_index` 排序。
- **公共 / 私人分层红线**：桌面面板只放公共信息，真实信息（三选一选项、赌场透视）走**私密 RPC**（`rpc_id`）。

## 六、命名与约定

- RPC：`s_*` = 房主→全员（authority）；`c_*` = 客户端→房主（any_peer）。详见 `联机协议.md`。
- 「无主」哨兵 `NO_OWNER = -100`（**不能用 -1**：机器人 peer id 从 -1 起编号）。
- 唯一性池 `_item_pool` 必须同时计入：玩家背包 + 小卖部货架 + 黑市货架 + 已焚毁。
- 数值占位多处标注「待数值专场」，改动请同步 `game-design/*`。
