# 架构总览

> 面向新加入的开发者：先读本文，再读 `联机协议.md` 与 `上手指南.md`。
> 更新：2026-10-03。

## 一、项目定位

- **《宿舍大富翁》**：Godot **4.6** + **GDScript** 的 2D 桌游；56 格外圈棋盘，**1~4 人联机**（房主即权威服务器）。
- 单机 = 房主 + 机器人，同一套代码。
- 纯程序化美术：UI/卡面/轮盘/棋子/木纹为运行时绘制或开源素材（Kenney / Twemoji / ambientCG，见根目录 `LICENSE`）；音效由 `fx.gd` 程序合成。
- 无存档、**不支持中途加入与观战**；房主退出即对局结束。

## 二、场景流

```
main_menu.tscn  ──(创建/加入房间)──►  lobby.tscn  ──(全员准备+开始)──►  game.tscn
  昵称/搜房             Net.host_game / join_game          Net.start_game()
                        准备、加/减机器人、聊天              对局主循环
```

- `item_lab.tscn`（**道具试验场**，`--lab` 或主菜单开发者入口进入）复用 `game.tscn` 的房主逻辑、进入「lab 空闲模式」但不跑回合循环，用于逐个验证道具效果；见 `道具试验场.md`。
- 场景切换统一走 `Fx.go_to(path)`（带淡入淡出）。
- 自动加载单例（`project.godot`）：
  - `Net`（`scripts/net.gd`）：连接、大厅数据、聊天、UDP 搜房。
  - `Fx`（`scripts/fx.gd`）：音效 + 震屏/飘字/彩带/入场动画。

## 三、核心：房主权威（Host-Authoritative）

- **所有玩法状态在房主计算**：`hp`（玩家）、`htiles`（地块）、`shops`（小卖部）、黑市、道具、冷却、事件…全在 `game.gd` 的房主侧。
- 客户端**只发意图请求**，不做判定；收到状态后**只渲染**。
- 全量状态快照通过可靠 RPC 广播（`s_state`），客户端 `s_state()` 只负责刷新 UI 与棋盘。

```
客户端点击 ──c_* RPC──► 房主校验/结算 ──s_* RPC(含 s_state)──► 全员渲染
```

## 五、表现层约定

- **持续动画统一手写**（`_process` 相位驱动，如转轮、牌堆抽卡）；Tween 只用于一次性过渡（弹入、按钮缩放）。
- **对局画面是三层结构**（v0.5.0 批次 2 起，自下而上）：
  ① **3D 场景**（`TableView3D`）：暗色 `WorldEnvironment` + **一盏暖色台灯（全场唯一主光源，
  批次 6 起）** + 房间剪影 + 一张**水平**桌面板
  （`PlaneMesh`，材质贴的就是②的画面）+ 固定在自己座位、**俯角 ~50°** 的 `Camera3D`。
  ② **`SubViewport`（2048²）内的 2D 世界**：`BoardView` 原样住在里面，自研 2D 相机
  （注视点 / 缩放）**仍然保留**，继续驱动「推近转盘 / 推近牌堆」的对焦演出，
  **视角恒在自己座位、不旋转**（转视角已随批次 1 删除）。
  画布里**只剩桌垫**（棋盘 + 一圈留白，`BoardView.MAT_RECT`）：贴到桌面的**纹理窗口 =
  桌垫区域**（`TableView3D.TEX_WINDOW_PX`，桌面材质取样与输入映射同源），桌垫之外再铺一圈
  木纹（第二个平面，`assets/textures/wood_floor.jpg`）⇒ 观感是「印在木桌上的一块桌垫」。
  **批次 2 推迟的「棋盘铺满桌面」比例目标在批次 5 结清**：四条座位栏离开画布之后，画布不再需要
  用整张 2048² 当窗口来容纳它们（当时那条约束与踩过的坑见 `table_3d.gd` 的 `TEX_WINDOW_PX` 注释）。
  ③ **屏幕层 HUD**（四角身家条 / 战报 / 暂停 / 规则说明 / 格详情卡 / 小卖部与赌场全屏
  界面 / 黑市操作条）：仍是 `game` 上的普通 Control，叠在 3D 之上，**不受桌面倾斜影响**
  （斜着的字读不清，文字一律留在屏幕层）。**屏幕底部不再有操作坞**（批次 3 Task 6 拆除），
  **右侧名册栏也没有了**（批次 5 由四角身家条取代，见下）。
- **输入映射（2.5D 唯一的真活）**：由 `TableView3D` 接管——屏幕点 → `Camera3D` 射线 →
  与水平桌面求交 → 桌面 UV → `SubViewport` 像素坐标 → `push_input`（合成 `InputEventMouseButton`
  / `InputEventMouseMotion`）送进 ②的 2D 世界，**格子 / 座位 / 货架的点击逻辑不用重写**；
  悬停同理。反方向（画布坐标 → 屏幕坐标）走 `viewport_to_screen`，供消费棋盘坐标的屏幕层
  HUD 用（格详情卡、飘字）。几何全在纯函数 `TableGeometry`，可无头单测。
  **滚轮 = 3D / 2D 视角连续推移**（v0.5.0 批次 4 起，**推拉已取消**：`dolly` 整个删除）；
  拖拽平移已随批次 1 删除（第一人称没有「平移桌子」这回事）。
- **双视角（v0.5.0 批次 4）**：相机沿**一条轨道**在「3D 第一人称」与「2D 桌面」之间连续推移
  （`TableView3D`，平滑，不是硬切开关）。
  - **`view_t ∈ [0,1]` 是这条轨道上的位置**：`0` = 3D 第一人称（俯角 **50°**、相机到注视点的
    3D 距离 **9.02**、手里有牌、能出牌），`1` = 2D 桌面（俯角 **88°**、距离 **8.6**、只看桌上地图）。
    **两端参数与取值推导**（两条断言：四角不出画面 + 两端桌面占屏面积比 0.96）见
    `table_3d.gd` 的 `VIEW_DIST_2D` 常量注释。
  - **滚轮改的是目标值不是当前值**：`set_view(view_target ± VIEW_STEP)`（`VIEW_STEP = 0.25`，
    四格从 3D 走到 2D；向前滚 = 推向 2D，向后滚 = 拉回 3D），`_process` 里按
    `e^(-VIEW_SNAP·delta)` **指数逼近**（帧率无关、单调不过冲）。`snap_view(t)` 是"设目标并立即
    到位"的旁路，只给摆拍与测试用（玩法别用，那会丢掉推移感）。
  - **手牌随视角淡出、「看不见就点不到」**：`TableView3D` 把 `view_t` 推给 `TableProps`
    （`set_view_t`，挂在 `_apply_camera()` 末尾，`snap_view` 那条路也覆盖），手牌在
    `HAND_FADE_LO = 0.35 → HAND_FADE_HI = 0.65` 之间淡出；淡到 `HAND_HIT_MIN_ALPHA = 0.15`
    以下 `hand_hit` 直接返回 `-1` ⇒ **2D 端出牌要回 3D 这条意图不需要任何玩法代码**
    （`game.gd` 一行未改）。`(0.576, 0.625]` 那条"看得见但点不到"的窄带及其可接受性见
    `table_props.gd` 的 `HAND_HIT_MIN_ALPHA` 常量注释。
  - **视角是纯本地表现，不进协议**：不写进 `s_state`、不同步 —— 每个人自己滚自己的；
    `_broadcast_state` 与所有 `@rpc` 装饰器都不受影响。
- **2D 相机（`BoardView`）的倍率一律写「相对全景的倍数」**：`focus_grid` / `focus_point_zoom`
  的 `zoom` 参数，以及 `MIN_ZOOM_FACTOR 0.55` / `MAX_ZOOM_FACTOR 3.1` / `DECK_PUSH_FACTOR 2.0`
  都是这个意思（1.0 = 全景），统一由 `BoardView._zoom_from_factor()` 换算成绝对倍率。
  **别写绝对字面量**——画布尺度一变换算就废（本批次真踩过：抽卡推近原写成绝对 `0.78`，
  在 2048² 画布下比全景的 0.97 还小，等于完全不推近）。
- **桌面实物的摆放约定（v0.5.0 批次 3 定案，批次 4 继承，批次 6 收口，批次 7 物件表更新）**：3D 物件里
  **只有压在"画着同一个物体的印刷图案"上的那两件跟 2D 相机**（转盘轮缘、两摞牌堆），
  手牌 / 立牌**一律不跟**（筹码堆 / 体力件已在批次 7 整体退场）。
  - **跟**：轮缘的位置来自 `BoardView.wheel_screen_pos()`、半径 = `200 × _zoom`（`table_props.build_wheel`
    量真变换得来）；两摞牌堆的位置来自 `BoardView.deck_screen_pos(deck)`（批次 6 Task 3 新增的
    公开入口 —— 内部就是 `global_position + _view_from_world(deck_center)`）。两者都压在**印在桌垫上**
    的图案上（轮盘 / 卡背），而桌垫图案随 2D 取景缩放，不跟就会脱开。
  - **不跟**：其余物件的位置走**画布常量**（`table_props.HAND_BASE_PX` / `STANDEE_BASE_PX`）——
    它们是**自由立在桌上的实物**，不该因为"印出来的图案"变了而移动。
    相机推近是「你凑近看」，不是「桌子被重新排版」。
  - **刷新时机（批次 6 Task 3 补齐）**：跟的那两件由 `game._refresh_board_followers()` 重摆，
    两个调用点 —— ① 每次状态广播（`game._refresh_table_props`）；② **抽卡演出期间逐帧**
    （`game._process` 里那条，条件是 `board.is_showing_deck_card()`）。② 是必需的：抽卡会做一次
    ≥2× 的推近且**不伴随任何状态广播**（`focus_point_zoom`），只靠①的话桌垫图案在演出中滑动、
    实体纹丝不动，两者会分开**几百画布像素**（实测：全景 → 2× 推近，同一摞的落点从画布
    (513.5, 951.1) 挪到 (999.1, 1224.5)，差 556 画布像素）。这条逐帧升级顺带结掉了轮缘
    同款的旧待办（`table_props.gd` 文件头原来挂着的"不伴随 s_state 的镜头变化会短暂脱开"）。
  - **代价（如实留痕）**：抽卡动画把 2D 取景推到 ≥2×（`DECK_PUSH_FACTOR`）时，桌垫图案滑动、
    **不跟的那些实物不动** ⇒「手牌不压自己那排格子」这类断言**只在全景取景下成立**
    （原来还有"不压牌垫阶段按钮"那条，随批次 7 那两枚按钮退场一并作废）。
    放大取景可复现：`--shot=*freecam*`（见 `开发台账.md` §三）。
- **房间 / 台灯 / 光照与阴影策略（v0.5.0 批次 6）**：观感的主角是**光**——近黑的屋子里只亮着
  **一盏台灯**，四周落进剪影（设计稿 §五）。
  - **房间 = 纯程序化剪影**：三面墙 + 书架 + 床架，全是 `BoxMesh` + **共用一份**近黑高粗糙材质
    （`table_3d.ROOM_*`），**一律不投影**（又大又远，投影只是白跑一张阴影图）。近端那一面墙不造：
    在相机之后，看不见。
    **"剪影可辨"靠的是一层极弱的自发光底光**（`ROOM_EMISSION`，终审修复波 D 补）：台灯照不到最远
    的床架（离灯 ~11.0，出图实测 1/255、比身后的近黑背景 4~6/255 还暗），**"在射程内"必要而不充分**；
    底光不过光照、与距离无关，把每件剪影抬到背景之上（实测床架 18/255）。原先"自身不发光、
    不吃那盏灯的光就走不进画面"那句是**当时没兑现的设想**，已按事实改准。
    **房间里看到的"黑"是背景色给的**（`Environment.background_color` 压到近黑），不是射程卡出来的
    —— 所以别拿 `LAMP_RANGE` 去调房间明暗（调不动，只会连桌子一起改）。
  - **只有一盏主光源、且它是唯一投影的光源**：`table_3d.lamp_light`（`OmniLight3D`，挂在灯罩里、
    跟着灯罩的倾角走）。**为什么只留一盏**：氛围是一整个（两盏灯 = 氛围被拆成两半），而且
    `gl_compatibility` 下每个带阴影的 `OmniLight3D` 每帧要多渲染一张阴影图 —— 台灯是**唯一**
    需要投影的（手牌 / 立牌 / 牌堆的影子都来自它）。批次 3 为"实物能投影"重开的 `shadow_enabled`
    在批次 6 随光源换到了台灯身上；`layout_test` 有一条断言钉住"全场只有一处 `Light3D`"。
  - **灯座站在木纹带上（桌垫之外）**：压在桌垫上就是"站在棋盘上"（遮格子与字）。代价是
    **光池的池心恒在桌垫左沿**（几何定的，搬不到桌心），且抬杆（`LAMP_POLE_H`）受取景限制
    —— 灯越高屏幕投影越往左外扩。取值与量测见 `table_3d.gd` 的 `LAMP_*` 常量注释。
  - **环境光压到很低**（`ambient_light_energy` 0.20），但它**管不到"房间空处"**：那里看到的是
    背景色（`BG_COLOR` 直出、不过环境光）。屏幕层还有一层**暗角贴片**（`build_vignette`）补
    Compatibility 没有的 SSAO / 景深。
- **牌堆实体化 + 抽卡起点（v0.5.0 批次 6 Task 2/3）**：桌垫上最后两处"贴片"（画布上印着的
  机会 / 命运两摞卡背）做成**有厚度的实体**（`table_props.build_decks`：每摞 5 层薄 `BoxMesh`
  错缝叠厚 + 顶面平贴一块牌名 `Label3D`；底**直接落在桌面上**，不加 `PROPS_Y`）。
  抽卡动画「抽出」的**起点**从"画布上那点扁图案"改成**实体摞的顶面**（`TableProps.deck_top_px`
  经 `BoardView.deck_top_provider` 注入）—— 四段动画的语义与节奏一字未动，`BoardView` 本批次的
  改动**只有这一处**（外加同一处必需的"起点逐帧重取"，见 `deck_top_provider` 的注释）。
- **四条座位栏整体退场、座位卡变成桌上的 3D 立牌**（v0.5.0 批次 5，设计稿 §三）：
  - **立牌**（`TableProps` 的 `standees` 子层）：四块**有厚度、向后倾 ≈25°、带投影**的薄板
    （`BoxMesh` + `Label3D`），名字 / 身家 / **公开背包**（一件一张品质色小卡，封顶 7 件，
    不截到 5）/ **操作倒计时**都长在牌面上；**点它 = 选目标**（转发给既有的
    `game._on_seat_clicked`，玩法链路一行未改）。位置是**画布常量** `STANDEE_BASE_PX`，
    走**同一套** `canvas_px_to_world` 口径（与手牌一致，**改 `TEX_WINDOW_PX` 必须一起重取**）。
    **自己的那面在 3D 端隐藏**（第一人称看不见自己，`STANDEE_SELF_HIDE_T`；它被提到**手牌最后
    可见的档之上**，免得两者在 `view_t = 0.5` 那个滚轮停驻位上同框）。
  - **四角身家条**（`TableHud.CORNER_SLOTS`）**取代右侧名册栏**：名次徽章 + 名字 + 身家（大字）+
    **现金**（第二行小字，见下）+ **当前行动者的操作倒计时行**（修复波 A），
    四家各挂屏幕一角；**角位 = 桌位**（`game._seat_peers` 是「谁坐哪个桌位」的唯一判据，
    立牌顺序与四角角位同源，两处永远一致）。名册栏连同它那行「地产 ×n · 道具 n / 现金」一并

## 六、命名与约定

- RPC：`s_*` = 房主→全员（authority）；`c_*` = 客户端→房主（any_peer）。详见 `联机协议.md`。
- 「无主」哨兵 `NO_OWNER = -100`（**不能用 -1**：机器人 peer id 从 -1 起编号）。
- 唯一性池 `_item_pool` 必须同时计入：玩家背包 + 小卖部货架 + 黑市货架 + 已焚毁。
- 数值占位多处标注「待数值专场」，改动请同步 `game-design/*`。
