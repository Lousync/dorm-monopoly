### 三条**必须知道**的实测细节

1. **`loop_mode` 全是 0（`LOOP_NONE`）** —— glTF 格式里**没有循环标记**，
   导入器**不会**替你标。⇒ **二期要给 `idle` 自己设**（`Animation.loop_mode = LOOP_LINEAR`，
   或走 `AnimationTree`）。**"导入成功 ⇒ 会自动循环"是个会静默出错的假设。**
2. **"首尾闭合"是我另量的一把尺子**（glTF 没有循环标记，引擎那个 `loop_mode` 是**默认值、
   不是素材的事实**）：逐条轨道比第一帧与最后一帧的值。
   结果：**27 条里只有 `die` 与 `pick-up` 不闭合** —— 那两条**结束在一个非静止的姿态**
   （`die` 躺下、`pick-up` 弯腰）⇒ 想停在末帧要**手动 `pause()`**，想循环就要另接回位。
   其余 25 条首尾同值 ⇒ 可无缝循环 / 可停末帧。
3. **导入器会把常值轨道压成 1 帧**（实测 `idle`：4 条会动的轨道各 **39 帧**，
   另 4 条常值轨道只剩 **1 帧**）。第一版探针把"1 帧"判成"不闭合"，于是 27 条全报"否" ——
   **这是个假阴性**，改成"1 帧轨道跳过"之后才对。记在这里是因为二期若也去读轨道数，
   会撞上同一件事。

## 四、模型的量测：AABB 与朝向

### 4.1 实测 AABB（世界；原点 = 脚底 / 站立基线）

**静止姿**（= `static`，也 = 节点默认 TRS）：

```
合并 AABB   min=(-0.800, 0.000, -0.400)   max=(0.800, 2.700, 0.400)   size=(1.600, 2.700, 0.800)
  leg-left   min=( 0.000, 0.000, -0.200)   max=( 0.400, 1.000,  0.200)
  leg-right  min=(-0.400, 0.000, -0.200)   max=( 0.000, 1.000,  0.200)
  torso      min=(-0.400, 1.000, -0.300)   max=( 0.400, 1.900,  0.300)
  arm-left   min=( 0.400, 0.800, -0.300)   max=( 0.800, 1.900,  0.100)
  arm-right  min=(-0.800, 0.800, -0.300)   max=(-0.400, 1.900,  0.100)
  head       min=(-0.400, 1.900, -0.400)   max=( 0.400, 2.700,  0.400)
```

**⇒ 站立高 = 2.700 模型单位**、宽 1.600（含张开的手臂）、深 0.800。

**坐姿**（包自带的 `sit` 末端）：

```
合并 AABB   min=(-0.800, 0.600, -0.400)   max=(0.800, 2.500, 1.000)   size=(1.600, 1.900, 1.400)
  leg-left   min=( 0.000, 0.600,  0.000)   max=( 0.400, 1.000,  1.000)
  leg-right  min=(-0.400, 0.600,  0.000)   max=( 0.000, 1.000,  1.000)
  torso      min=(-0.400, 0.800, -0.300)   max=( 0.400, 1.700,  0.300)
  head       min=(-0.400, 1.700, -0.400)   max=( 0.400, 2.500,  0.400)
```

### 4.2 ⚠ 一个被抓住的量错（正好是这条规则存在的理由）

我**第一遍用 Python 手算**得到"站立高 = 2.000、头在 y ∈ [1.2, 2.0]" —— **错的**。
原因：算 `head` 的世界位置时**只加了 `head` 自己那一层 translation(1.2)**，
**漏了 `torso` 那一层的 translation(0.7)** ⇒ 少了 0.7。真值 **2.700**。
Godot 探针照抄 `room.gd::_collect_aabb` 的**累乘局部变换**，量出来是对的。
⇒ 这条再次确认：**AABB 是量出来的，而且"量"必须把嵌套那几层一起乘进去**。

### 4.3 朝向：正面 = **`+Z`**（量出来的）

两处独立佐证，都是几何量出来的：

1. 包自带的 **`sit`**：两条腿绕 X 转 −90° ⇒ 腿从 `z ∈ [−0.2, 0.2]` 变成 `z ∈ [0, 1.0]`。
   **坐着的腿朝前** ⇒ **前 = `+Z`**。
2. **`holding-*` / `pick-up`**：两条手臂同样绕 X 转 −90° ⇒ 手臂从下垂变成伸向 `+Z`。
   **"拿/抱"是往前伸** ⇒ **前 = `+Z`**。

旁证（不是判据，只是解释来源）：GLB 的 `asset.generator = "UnityGLTF"` ——
UnityGLTF 保留 Unity 的坐标习惯（**+Z forward**），与 glTF 的惯例（−Z forward）不同。

### 4.4 ⇒ **与 `seat_anchor(slot)` 的朝向正好对齐，不需要补旋转**

`room.gd` 里四把椅子是**绕 Y 转到"座位框自己的 `+z` 指向桌心"**摆的
（`seat_anchor` 返回的就是这个 `Transform3D`）。而角色**正面也是 `+Z`**
⇒ **角色挂到 `seat_anchor(slot)` 下面、朝向用单位旋转即可**（"面对桌子"，
椅背在 `−z`、名牌在 `−z`，位置关系自然一致）。
**这一条省掉了二期最容易写错的那半步**（补 180° 是这里最直觉、也最容易多绕一次的错）。

## 五、Step 6：坐姿从哪来 —— **结论：手摆，不用包里的 `sit`**

### 5.1 包里确实有坐姿，但它**不是"坐椅子"**

`sit` / `wheelchair-sit` / `drive` / `wheelchair-move-*` 实测**都是同一个几何**：
`root` 下移 0.2 + 两条腿绕 X 转 −90° ⇒ **腿变成一根横杠往前伸**。
根因是**结构性的**：**腿是**一整块 `leg-left` / `leg-right` 刚体、**没有膝关节**
（整个包只有 6 块），所以**永远弯不了膝**。
⇒ 摆到椅子上就是"**坐在椅子上、两腿笔直伸出去**"（还捅进桌子里，见 §6）。
**"接受站着"那条不必讨论**（包里坐姿是有的）；但**"包里的 `sit` 直接拿来用"也不行**。

### 5.2 手摆坐姿 —— **已实测跑通，而且比 `sit` 好**

因为这是**刚体分件**（不是蒙皮），**每个分件都有自由的 `rotation` 与 `scale`** ——
这正是它比骨骼更好办的地方：**腿可以"压短"**。做法（两行）：

```gdscript
root.position = Vector3(0, -0.2, 0)          # 髋枢轴 1.0 → 0.8，正落到座面
leg_left.scale  = Vector3(1, 0.8, 1)         # 腿保持竖直、压到 0.8 长 ⇒ 脚正好落回地面
leg_right.scale = Vector3(1, 0.8, 1)
```

**探针实测**（`character-a.glb`）：手摆后
`min=(−0.800, 0.000, −0.400) max=(0.800, 2.500, 0.400)`
⇒ **脚底 `y = 0.000`（正好站回地面）**、**髋枢轴 `y = 0.800`（= 座面）**、头顶 `2.500`。
**数字全是整的 ⇒ 这不是凑出来的，是包作者自己的意图**：
`root` 下移 −0.2 正是包自带 `sit` 的那一键，作者设的座面就是 `y = 0.8`。

### 5.3 ⚠ 叠 `idle` 时的实测陷阱（二期一定会撞上）

想"手摆坐姿 + 叠待机摆动"，但**实测**：

```
叠 `idle` 之后            min=(−0.800, 0.200, −0.400) max=(0.800, 2.700, 0.400)
  root.position.y 现在 = 0.000（手摆时是 −0.200）      ← **被顶掉**
  leg-left.scale.y 现在 = 0.800（手摆时是 0.800）      ← 没被碰
```

**原因**：`idle` 虽然只"动"躯干/双臂/头 4 条轨道，但**导入器给 `root` 与 `leg-*` 也留了
1 帧的常值轨道**（见 §3 细节 3）⇒ **播 `idle` 会把 `root.position.y` 写回 0**，
腿的 `scale` 反而没事（**这个包里根本没有任何 scale 轨道**）。

**⇒ 二期要照这两条做**：
1. **坐姿的 `root` 下移放到角色场景之上的"外套节点"上**（`AnimationPlayer` 够不着它，
   不会被顶掉）；
2. 腿的压短可以留在 `leg-*.scale`（安全），或者干脆**自己写一条坐姿动画**
   （复制 `idle`、补上 `root` / `leg-*` 的坐姿键）—— 二期本来就要做动画集合，这条更干净。

### 5.4 结论

| 选项 | 判定 |
|---|---|
| 用包里的 `sit` | ❌ 腿平举、捅进桌子（§6）；只适合"坐地板/坐沙发"那种语境 |
| **手摆坐姿（`root` −0.2 + 腿竖直压短 0.8）+ `idle` 叠层** | ✅ **推荐**。实测脚落地、髋落座面、数字全整 |
| 接受站着 | ❌ 不可接受（brief 已排除） |
| 换素材 | ❌ 不必 —— 手摆这条路已经走通，换素材只会把"导入通路"这个已解决的问题重新打开 |

## 六、比例：**这个包与一期家具不是同一个比例族**

### 6.1 先算清楚：家具那一族是"半比例"

一期 `FURNITURE_SCALE := 10.0` 的由来：Kenney 家具是**半比例**的
（书桌 `0.384` 模型单位 = 真实 `0.75 m`）⇒ **1 模型单位 ≈ 1.95 m**。

### 6.2 角色包：**1 模型单位 ≈ 0.65 m**（**不是同一族**）

角色站立高 **2.700 模型单位** = 一个人（按 1.75 m 算）⇒ **1 模型单位 ≈ 0.65 m**。
**差了约 3 倍。**

> ⇒ **`FURNITURE_SCALE = 10.0` 绝不能复用**：×10 的人 = **27 世界单位 = 5.4 m 高**，
> 比整间屋子还高。**二期必须另取一个 `CHARS_SCALE`。**

### 6.3 该取多少：把"坐上去"当标尺反推

**椅子（一期实测）**：`chair.glb` AABB = `0.2 × 0.47 × 0.2` 模型单位
⇒ ×10 = `2.0 × 4.7 × 2.0` 世界 ⇒ **椅背顶离地 `FLOOR_Y + 4.7` = 桌面之上 `+1.00`**；
**座面 `FLOOR_Y + 2.25`**（= 真实 0.45 m 座高）。

| 口径 | 算式 | 结果 | 后果（实测） |
|---|---|---|---|
| **A 腿的下沿落座面**（包自带 `sit` 的最低点 `0.600`） | `2.25 / 0.600` | **3.75** | 站立 `2.7×3.75 = 10.125` 世界 = **2.03 m**；坐姿头顶 `2.500×3.75 = 9.375` 世界 = **桌面之上 1.135 m** ⇒ **出图看就是个巨人，否决** |
| **B 髋枢轴落座面**（`0.800`，**= 包作者自己 `sit` 的座面**） | `2.25 / 0.800` | **2.8125** | 站立 `7.59` 世界 = **1.52 m**；坐姿头顶 `7.03` 世界 = 离地 1.41 m = **桌面之上 0.665 m**；头顶比椅背顶（`+1.00`）高 `2.33` 世界 = **0.47 m** ⇒ **合理** |

### 6.4 ⇒ **给二期的数：`CHARS_SCALE := 2.8125`**

**推导**：座面高 `2.25`（世界）÷ 髋枢轴 `0.800`（模型单位）= **2.8125**。
**旁证**：手摆坐姿在这个比例下**每一项都落到整数**
（髋 `0.800×2.8125 = 2.25` = 座面；腿 `0.8×2.8125 = 2.25` = 座面高 ⇒ 脚落地）
⇒ 这不是凑的，是这个包的作者比例。
**注意**：这与一期的 `FURNITURE_SCALE` **不是同一个数，也不该是同一条注释**
—— 一期那条注释("缩放只改变外形，不改站哪儿")的纪律照旧适用。

## 七、二期必须知道的两个硬问题（都是量出来的）

### 7.1 ⚠ 包自带的 `sit` 会把腿捅进桌子（手摆则不会）

**算清楚**（全部用一期已有的数）：
- 桌子木框外沿（`_table_half`）= `Vector2(4.7, 3.4795)`
- 座位框落点 `off_z = _table_half.y + SEAT_INSET(0.15) + 椅子半深(1.0)` = `4.6295`
- ⇒ **座位框到木桌外沿 = `4.6295 − 3.4795` = `1.15` 世界单位**

角色**正面 = `+Z` = 朝桌心** ⇒ 在**角色局部坐标**里，**桌子外沿在 `z = +1.15`**。
- 包自带 `sit` 的腿伸到 **`1.0` 模型单位** ⇒ ×2.8125 = **`2.81` 世界** ⇒
  **越过桌沿 `1.66` 世界 = 33 cm**，而 `table_3d.TableBase` 是**一直落到地板**的
  （一期注释："椅子塞不进桌下"）⇒ **腿会与桌子底座互穿**。
- **手摆坐姿的腿是竖直的**（`z ∈ [−0.2, 0.2]`）⇒ **根本够不到桌沿**。**又一个选手摆的理由。**

> 出图核对（本地 `shots/probe_panel_A.png` / `_B.png`，`shots/` 已忽略、不入库）：
> A（`sit` ×2.8125）里那根平举的腿**明显跨过红色的"桌面外沿"参考墙**；B（手摆）没有。
>
> **摆位细节（留给二期）**：手摆坐姿的髋应该落在**椅子座面的前缘**，
> 而不是椅子正中 —— 否则竖直的腿会**穿过椅子自己的座板**。
> 按椅子半深 `1.0` 世界估，角色要往 `+z` 挪约 `0.6` 世界左右，让腿顶正好贴着座面前沿下来。

### 7.2 ⚠ 材质是 `KHR_materials_unlit` ⇒ Godot 导成 **UNSHADED**

实测（探针 `_dump_material`）：

```
leg-left: StandardMaterial3D shading=0 unshaded=true albedo_tex=true
```

`shading=0` = `BaseMaterial3D.SHADING_MODE_UNSHADED`。⇒ **角色不响应房间的灯**
（一期立过"照明契约"：吊灯 + `FILL_LIGHT_POS` 那盏补光）。
二期要选一条：**保留 unlit**（便宜；方块风格下未必难看，但**不会随房间变暗**，
与一期的"暗木 + 灰墙"层次会脱节），或**只改 `shading_mode` 并保留 `albedo_texture`**。
⚠ **不能照抄一期的 `room.gd::_paint()`** —— 它是**整个材质换掉**（家具是纯色，无所谓），
**套到角色身上会把贴图（脸/衣服）一起抹掉**。二期需要一个**新的、只调光照参数**的辅助函数。

1. **导入通路 = Kenney Blocky Characters（GLB，CC0），Godot 4.6 原生导入、零障碍、`project.godot` 不动。**

   （`root.y = −0.2`、`leg-*.scale.y = 0.8`、腿保持竖直）**+ `idle` 叠层**；
   叠层时 `root` 的偏移要放到**外套节点**上（`idle` 会把 `root.position.y` 顶回 0，实测）。
3. **比例 `CHARS_SCALE = 2.8125`**（= 座面 2.25 ÷ 髋枢轴 0.800；**不是** `FURNITURE_SCALE` 的 10.0，
   也不是"腿下沿落座面"那个 3.75 —— 那个出图看就是巨人）。
