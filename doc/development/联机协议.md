# 联机协议

> 房主即权威服务器。本文是 RPC 与状态快照的清单，改协议时同步更新。
> 实现：`scripts/game.gd`（对局 RPC）、`scripts/net.gd`（大厅/连接/聊天）。
> 更新：2026-10-08（§一 补直连地址展示 + 连接探针/超时/取消）。

## 一、传输与端口

- ENet，TCP 语义可靠通道。默认端口 **7777**；大厅搜房 UDP **7778**。
- 房主 `create_server(port, MAX_PLAYERS-1)`；客户端 `create_client(addr, port)` 支持 IPv4 / IPv6 / `[v6]:port` / 域名。
- 单例 `Net` 负责连接与大厅；返回主菜单用 `OfflineMultiplayerPeer` 复位。
- **机器人**：本地补位，peer id 从 **-1** 开始递减（所以无主地产用 `-100` 而非 -1）。
- **直连地址展示**（`NetAddr.classify_addresses`）：过滤 IPv4/IPv6 回环、链路本地、通配地址；
  IPv6 回环在 Godot/Windows 上是**展开式** `0:0:0:0:0:0:0:1`（不是 `::1`），两种写法都要滤；
  同一 `/64` 前缀的多个地址（EUI-64 + RFC4941 隐私地址）**只展示一条**。
- **直连连接体验**（fix/0.14.1）：`join_game` 起 ENet 连接的同时，并行向目标发 `DISCO_REQ`
  探针 —— 收到合法 `INFO` 视为对方在线；`PROBE_TIMEOUT_MS`（3s）无响应即 `_fail_join`
  自动断开并说明原因，`CONNECT_TIMEOUT_MS`（12s）为整体硬超时；UI 侧提供「取消」
  （`Net.cancel_join()`）。超时用**真实墙钟** `Time.get_ticks_msec()`，不受 `Engine.time_scale` 影响。

## 二、RPC 约定

| 前缀 | 装饰器 | 方向 | 用途 |
|---|---|---|---|
| `s_*` | `@rpc("authority","call_local","reliable")` | 房主 → 全员 | 广播状态/动画（`call_local` 让房主本地也执行同一函数） |
| `c_*` | `@rpc("any_peer","call_remote","reliable")` | 客户端 → 房主 | 上报意图（房主校验） |
| 私密 | `@rpc(...) rpc_id(peer, …)` | 房主 → 指定客户端 | 私人信息（三选一、赌场透视） |

> `call_local` 是「镜像」关键：房主调 `s_xxx.rpc()` 时自己也走一遍 `s_xxx()`，UI 才不会两端不一致。

### 对局 RPC 清单

**广播（s_）**
| RPC | 作用 |
|---|---|
| `s_state(state)` | 全量状态快照（见 §三） |
| `s_roll(v)` | 转轮落点（含动画） |
| `s_move(peer, path, step_time)` | 棋子逐步移动动画 |
| `s_tp(peer, idx)` | 传送（送监等） |
| `s_card(text, kind, deck, card_item)` | 事件卡/提示卡展示。`deck` 非空 = 屏幕层大字演出（机会/命运）；`card_item` 非空 = 演**该道具的卡面**（⑪ 失物招领，批次 12 C3），两者共用同一段演出 |
| `s_card_close()` | 抽卡演出收卡（批次 12 C2）：抽卡者确认 / 超时 / 机器人托管三条路都汇到它，全员一起收 |
| `s_log(line)` | 战报一行（带颜色） |
| `s_op_timer(kind, left, total, owner_peer)` | 操作窗口倒计时（掷轮/决定/道具/小卖部/黑市）：窗口开启、剩余整秒变化、关闭时各发一条，呈现在 `owner_peer` 那一条上（**载体史：座位卡 → 桌上立牌 → 四角身家条 → 身家条 + 名册条 → 身家条 + 左上角名册格（批次 13 ②）**，全表见 `game-design/回合与行动.md`）。**走专用 RPC 而不进 `s_state`**——它按秒高频变化，进全量快照会让所有端每秒白渲染一整帧棋盘。`kind=""` 收簇；`total<=0` = 不限时。剩余时间本机 `_process` 逐帧扣 delta 插值（暂停冻结、随 time_scale 缩放，与房主窗口计时同节奏） |
| `s_prompt(token, title, text, ok_text)` | 向目标玩家弹询问框 |
| `s_pause(on)` | 房主暂停全场 |
| `s_casino_start/turn/event/end` | 赌场小游戏同步 |
| `s_casino_peek(card)` | 赌场透视（`rpc_id` 私发） |
| `s_aberr(id, action, left)` | 畸变公告：`action`=`start`/`end`，`left`=持续剩余回合。文本公告已由 `_log`→`s_log` 走顶部气泡，本 RPC 只补全场动效（debuff 触发震屏）；持续期「生效中」标签由快照 `aberrations` 驱动 |
| `s_tech_offer(token, tier, names)` | 开局科技三选一弹层（`rpc_id` 私发给选卡玩家，`call_local` 覆盖房主本人）：等级 + 3 个候选名。答完即毁弹层；超时由房主随机兜底 |
| `s_assign_token(token)` | **重连凭证**（`rpc_id` 私发，开局时逐个真人客户端发一枚随机 int）：客户端存 `Net.rejoin_token`（仅内存），掉线重连时随 `c_hello` 带回 |
| `s_reclaim()` | **认领成功**（`rpc_id` 私发）：客户端置 `Net.rejoined`、直进对局场景等全量快照 |
| `s_pong(t)` | 延迟探测回包（`unreliable`，`rpc_id` 私发）：把客户端时间戳原样带回，客户端同一时钟算 RTT |
| `c_tech_pick(token, tech)` | 客户端回传所选科技（校验 sender==选卡玩家、token 有效、名字在候选内） |

**请求（c_）**
| RPC | 作用 |
|---|---|
| `c_roll()` | 掷轮 |
| `c_decision(token, yes)` | 回答询问 |
| `c_use_item(slot, arg, arg2=-1)` / `c_item_skip()` | 使用道具 / 跳过道具阶段（`arg`=目标玩家 peer 或格 idx；两段式 `arg2`=地皮格 idx） |
| `c_shop_buy(slot)` / `c_shop_refresh()` / `c_shop_leave()` | 小卖部操作 |
| `c_black_buy(slot)` / `c_black_refresh()` / `c_black_leave()` / `c_black_pay(prop_idx)` | 黑市操作 |
| `c_card_ok()` | 抽卡演出的「确定」（批次 12 C2）：只认抽卡者本人（`_awaiting_card` 归属校验，同 `c_decision`） |
| `c_casino_action(epoch, action)` | 赌场出牌 |
| `c_ping(t)` | 延迟探测（`unreliable`）：非房主每 1s 发一枚带本机时间戳的包，房主回 `s_pong` |

**大厅（net.gd）**：`c_hello(name, token=0)` / `c_ready` / `c_chat` → `s_lobby` / `s_start` / `s_chat` / `s_kick` / `s_assign_token` / `s_reclaim`。`token` 非零 = 重连认领（见 §六）。

## 三、状态快照 `s_state` 字段

| 字段 | 含义 |
|---|---|
| `phase` | `playing` / `ended` |
| `round` / `max_rounds` | 当前轮 / 上限（30） |
| `turn` | 当前行动者 peer |
| `await` / `await_peer` | 等待状态机（见 §四） |
| `players[]` | `{peer,name,color,bot,money,pos,alive,skip,sleep,stamina,items[],item_used}` |
| `tiles[]` | `{owner,level, soil?, soil_prog?}` |
| `shops` | `{tile_idx:{slots:[id×3]}}` |
| `refresh_price` | 小卖部当前刷新价 |
| `shop_open` / `shop_peer` | 小卖部打开的格子 / 正在逛的玩家 |
| `black_peer` / `black_slots` | 黑市行动者 / 三栏货 |
| `black_pay_mode` / `black_pay_need` / `black_pay_got` | 黑市交地支付态 |
| `winner` / `roll_epoch` | 胜者 / 掷轮请求序号 |
| `timeout_tier` | 操作限时挡位（`current`/`15`/`30`/`60`/`none`），房主改后随快照同步 |
| `aberrations` | 生效中的持续型畸变：`[{id, left}]`（left = 剩余玩家回合数），驱动「生效中」标签 |
| `ab_freq` / `ab_dur` / `ab_cond` | 畸变设置：触发频率（`关`=总开关关闭）/ 持续回合基准 / 条件触发开关，房主改后随快照同步（见 `game-design/畸变.md` §六） |
| `tech_tier` | 本局科技等级（`白银`/`黄金`/`钻石`，设计为掷骰定档；黄金/钻石池定稿前恒为 `白银`；空 = 本局未开科技） |
| `players[].tech` | 该玩家所选的科技名（空 = 未选 / 未开科技） |

> **铁律**：任何「全员可见」的状态都必须进快照。曾因漏发 `shop_peer` 导致小卖部操作条永不显示。

## 四、等待状态机（await）

`await` 标明当前卡在谁身上，UI 与超时托管都据此工作：

| await | 场景 | 超时（挡位为「现状」时的值） | 兜底 |
|---|---|---|---|
| `roll` | 等掷轮 | `ROLL_TIMEOUT 35s` | 系统代掷 |
| `prompt` | 等买地/升级决定（**批次 12 C1 起问在格详情卡里，不再是居中弹窗**） | `PROMPT_TIMEOUT 25s` | 视为拒绝 |
| `card` | 抽卡演出停在 HOLD 等该玩家点「确定」（批次 12 C2 / ⑧⑪） | `PROMPT_TIMEOUT 25s` | 自动确认（收卡） |
| `item` | 道具阶段 | `ITEM_TIMEOUT 12s` | 跳过 |
| `shop` | 逛小卖部 | `SHOP_TIMEOUT 20s` | 请出 |
| `black` | 逛黑市 | `BLACK_TIMEOUT 20s` | 付完当前动作 → 自动出口（凑不齐则挨打） |

> 「操作限时」挡位由房主设置，六个环节**各自**取该秒数；`不限时` 档不托管（见 `game-design/开局设置.md` §三之一）。

- 机器人 / 休眠玩家走**托管路径**（`_is_managed`）：自动代掷、拒绝买地升级、商店自动离开、赌场自动抽牌、
  **抽卡演出短暂延时后自动确认**（`card`，批次 12 C2）。
- `card` 的倒计时条挂在**抽卡者**那一条上（`_op_window_owner` 认 `_awaiting_card`；**批次 13 ② 起
  别人那一条是左上角名册里的一格**），与其他环节同一套 `s_op_timer`。
- **断线**：`peer_disconnected` → 该玩家转机器人接管（对局继续），座位**整局保留**、随时可重连认领（见 §六）；房主退出 → 全场结束回主菜单。

## 六、掉线与重连（2026-10-06 实装）

> 期望：网络波动掉线的玩家可以**回到本局继续玩**。掉线即断开连接，座位由机器人托管（既有行为），
> 重连不是「恢复连接」，而是**新连接凭凭证认领旧座位**。

### 1. 身份凭证（token）

- 开局时（`start_game`）房主给每位真人客户端私发一枚随机 int（`s_assign_token`），
  客户端存 `Net.rejoin_token`（**仅内存**——进程被杀即失效，座位由机器人打到局终）。
- token **整局有效、可重复使用**（掉几次都能认领）；认领成功后房主把座位表里
  「token → 旧 peer」改写成「token → 新 peer」，token 本身不变。
- 房主没有重连：房主掉线 = 服务器没了，全场回主菜单（与现状一致）。

### 2. 座位保留与托管

- 对局中掉线：`players` 大厅表**保留该行**（不从房里删）；`game.gd _on_peer_disconnected`
  把 hp 座位转机器人托管（正在等他掷轮 → 机器人 0.8s 后代掷；正在等他决策 → 机器人立刻按策略决定）。
- **重连窗口 = 整局**：不设倒计时，任何时候（含破产观战位）都能认领；对局结束、房主重启后 token 失效。

### 3. 重连握手与认领（房主权威）

1. 客户端重新 `join_game(同一地址)` → 连上后 `c_hello(名字, token)`。
2. 房主校验：token 命中座位表 → **认领**；未命中（没带 token / token 错）→ 维持原口径踢出
   「对局已开始，无法中途加入」。
3. 认领（`game.gd reclaim_seat(旧peer, 新peer)`，幂等）：
   - hp 座位 `peer` 换 key 到新 peer、`bot=false`；名下地皮 `owner` 全部换 key；
   - 所有按 peer 记账的**瞬时等待态**换 key：掷轮 / 询问 / 道具 / 抽卡确定 / 科技挑卡 /
     发现挑卡 / 变卖会话 / 黑市会话 / 选目标 / 畸变补掷；`players` 行 peer 同步更新；
   - **补发一次性弹层**：当前正等他的询问（`s_prompt`）、科技三选一（`s_tech_offer`）、
     发现三选一（`s_discover`）各补一份（这些是 `rpc_id` 一次性 RPC，重连端没收到过）；
   - 广播全量快照 + 战报公告「XX 重连回到座位」。
4. 客户端收 `s_reclaim` → 置 `Net.rejoined` → 直进对局场景，靠快照渲染（状态本就是全量的，
   小卖部 / 变卖等界面都由快照驱动，无需补建）。
5. 主菜单：掉线回主菜单后状态条提示「连接中断——用同一地址点『加入』即可回到对局」，
   地址栏自动回填上次加入的地址（`Net.last_join_addr`）。

### 4. 连接中陌生人的防逗留

`peer_connected` **不再立即踢**（会误杀重连握手的瞬间），改为延迟 1.5 秒：
期间该连接没有完成 hello / 认领才踢出。hello 校验逻辑不变（`hello_verdict`）。

### 5. 已知边界（v1 接受）

- **抽卡演出不补发**：`s_card` 是一次性广播，掉线错过的演出看不到，等待中的「确定」到点自动确认。
- **赌局中途掉线**：当前赌局按机器人继续、结算照常；下一局恢复真人操作。
- 机器人代掷守卫：认领瞬间若挂着一个「0.8s 后代掷」的定时器，座位已转真人则不再代掷。
