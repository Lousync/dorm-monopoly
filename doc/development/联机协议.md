# 联机协议

> 房主即权威服务器。本文是 RPC 与状态快照的清单，改协议时同步更新。
> 实现：`scripts/game.gd`（对局 RPC）、`scripts/net.gd`（大厅/连接/聊天）。
> 更新：2026-10-08（新增 §六 掉线与重连；**§二 RPC 全表与 §三 / §四 按代码重建**）。

## 一、传输与端口

- ENet，TCP 语义可靠通道。默认端口 **7777**；大厅搜房 UDP **7778**。
- 房主 `create_server(port, MAX_PLAYERS-1)`；客户端 `create_client(addr, port)` 支持 IPv4 / IPv6 / `[v6]:port` / 域名。
- 单例 `Net` 负责连接与大厅；返回主菜单用 `OfflineMultiplayerPeer` 复位。
- **机器人**：本地补位，peer id 从 **-1** 开始递减（所以无主地产用 `-100` 而非 -1）。

## 二、RPC 约定

| 前缀 | 装饰器 | 方向 | 用途 |
|---|---|---|---|
| `s_*` | `@rpc("authority","call_local","reliable")` | 房主 → 全员 | 广播状态/动画（`call_local` 让房主本地也执行同一函数） |
| `c_*` | `@rpc("any_peer","call_remote","reliable")` | 客户端 → 房主 | 上报意图（房主校验） |
| 私密 | `@rpc(...) rpc_id(peer, …)` | 房主 → 指定客户端 | 私人信息（三选一、赌场透视） |

> `call_local` 是「镜像」关键：房主调 `s_xxx.rpc()` 时自己也走一遍 `s_xxx()`，UI 才不会两端不一致。

### 对局 RPC 清单

**广播（`s_*`，`authority` + `call_local`）**
| RPC | 作用 |
|---|---|
| `s_state(state)` | 全量状态快照（见 §三） |
| `s_roll(v)` | 转轮落点（含动画） |
| `s_move(peer, path, step_time)` | 棋子逐步移动动画 |
| `s_tp(peer, idx)` | 传送（送监、任意门落点等） |
| `s_card(text, kind, deck, card_item)` | 事件卡/提示卡展示。`deck` 非空 = 屏幕层大字演出（`deck` = **卡类名 / 演出标题**，2026-10-09 起不再是牌堆名）；`card_item` 非空 = 演**该道具的卡面**（⑪ 失物招领，批次 12 C3），两者共用同一段演出 |
| `s_card_close()` | 抽卡演出收卡（批次 12 C2）：抽卡者确认 / 超时 / 机器人托管三条路都汇到它，全员一起收 |
| `s_card_target(owner_peer, field, cands, done)` | 卡的**选目标态**（机会卡 15 个新字段里的目标类 / 地皮类用）：`cands` = 此刻可选 peer；`done=true` 收尾（熄灭高亮、收起提示条）。**只给抽卡者那一端进态**（`owner_peer` = 抽卡者；旁观者不进态、不挂提示条 —— 原先传 `NO_PEER` 时全员都进）。高亮与"点谁真的有反应"同源（`_push_peer_highlight`） |
| `s_card_choices(labels, owner_peer)` | **抉择卡**的选项按钮（1~3 条；`labels` 空 = 退出抉择态）。同样**只有抽卡者那一端出按钮**：判据必须走状态快照 `_state_player`（`hp` 只在房主侧填充，客户端为空），否则真人客户端永远看不到按钮 |
| `s_ask_bury(owner_peer, done)` | **小抄置底询问**（2026-10-10 M1）：「要不要把机会牌堆的顶张塞到底」（`done=true` 收尾、收按钮）。`owner_peer` = 小抄使用者，只有他那一端出「塞到底 / 算了」两枚（同 `s_card_choices` 的口径）。**挡位复用既有的 `item`**（`_await_turn_window("item", …)`），故 `s_op_timer` 不用改；但归属位是**单列**的 `_awaiting_bury` |
| `s_log(line)` | 战报一行（带颜色） |
| `s_op_timer(kind, left, total, owner_peer)` | 操作窗口倒计时（掷轮/决定/道具/小卖部/黑市）：窗口开启、剩余整秒变化、关闭时各发一条，呈现在 `owner_peer` 那一条上（**载体史：座位卡 → 桌上立牌 → 四角身家条 → 身家条 + 名册条 → 左上角名册格（批次 13 ②）→ 桌面立牌（v0.10.0，名册条整体删除）**，全表见 `game-design/回合与行动.md`）。**走专用 RPC 而不进 `s_state`**——它按秒高频变化，进全量快照会让所有端每秒白渲染一整帧棋盘。`kind=""` 收簇；`total<=0` = 不限时。剩余时间本机 `_process` 逐帧扣 delta 插值（暂停冻结、随 time_scale 缩放，与房主窗口计时同节奏） |
| `s_prompt(token, title, text, ok_text)` | 向目标玩家弹询问框 |
| `s_pause(on)` | 房主暂停全场 |
| `s_aberr(id, action, left)` | 畸变公告：`action`=`start`/`end`，`left`=持续剩余回合。文本公告已由 `_log`→`s_log` 走顶部气泡，本 RPC 只补全场动效（debuff 触发震屏）；持续期「生效中」标签由快照 `aberrations` 驱动 |
| `s_tech_tier(tier)` | 科技**定档**演出：本局等级（全员同档，2026-10-07 实装）。原为 `s_tech_dice(pips, tier)`，2026-10-09 去掉骰子后 `pips` 参数一并删除 |
| `s_slot(digits, prize)` | 老虎机演出（紫货「老虎机」）：三个 0~9 数字 + 奖金（屏幕层） |
| `s_peek_card(peer, text)` | 「小抄」透视：把机会牌堆顶卡文本发给 `peer`。**是广播 + 收端自过滤**（`if peer == my_peer`），不是 `rpc_id` 私发 |
| `s_casino_start(game_name, stake, pot, order, names)` | 赌场开局：切进赌场场景 + 抽游戏演出 |
| `s_casino_roll(vals)` | 赌场骰子定格（各 peer 点数） |
| `s_casino_end(winners, pot)` | 赌场结算、关闭全屏回桌 |

## 四、等待状态机（await）

`await` 标明当前卡在谁身上，UI 与超时托管都据此工作：

| await | 场景 | 超时（挡位为「现状」时的值） | 兜底 |
|---|---|---|---|
| `roll` | 等掷轮 | `ROLL_TIMEOUT 35s` | 系统代掷 |
| `prompt` | 等买地/升级决定（**批次 12 C1 起问在格详情卡里，不再是居中弹窗**） | `PROMPT_TIMEOUT 25s` | 视为拒绝 |
| `card` | 抽卡演出停在 HOLD 等该玩家点「确定」（批次 12 C2 / ⑧⑪）；**卡的选目标（`s_card_target`）与抉择按钮（`s_card_choices`）复用同一挡位** | `PROMPT_TIMEOUT 25s` | 自动确认（收卡）/ 取第一项 / bot 兜底选目标 |
| `item` | 道具阶段；**小抄置底询问复用同挡位**（2026-10-10 M1：`await` 值同为 `item`，归属人走单列的 `_awaiting_bury`） | `ITEM_TIMEOUT 12s` | 跳过 / 不置底（两者都保留「白拿一张信息」的原效果） |
| `shop` | 逛小卖部 | `SHOP_TIMEOUT 20s` | 请出 |
| `black` | 逛黑市 | `BLACK_TIMEOUT 20s` | 付完当前动作 → 自动出口（凑不齐则挨打） |
| `tech` | 科技三选一（**全员同时**，2026-10-07 起）；`await_peer` 恒 `0`，客户端看快照的 `tech_open` 显隐 | 复用 `prompt` 档 | 房主随机兜底 |
| `discover` | 「发现」三选一挑卡 | 复用 `prompt` 档 | 自动挑一张 |
| `renmen` | 「任意门」选目标格（钻石科技） | 复用 `prompt` 档 | 自动选 |
| `liq` | 破产变卖保底：等玩家自选卖哪块地（见 `game-design/经济与胜负.md` §三） | 复用 `prompt` 档 | 自动按累计投入从低到高变卖 |

> 上表 `roll`/`prompt`/`card`/`item`/`shop`/`black` 是 `game_settings.gd` 的 `turn_seconds()` 里
> **单独列档**的六种；`tech`/`discover`/`renmen`/`liq` 没有自己的档位，代码里都复用
> `_await_turn_window("prompt", …)`，故随 `prompt` 秒数走。

> 「操作限时」挡位由房主设置，六个环节**各自**取该秒数；`不限时` 档不托管（见 `game-design/开局设置.md` §三之一）。

- 机器人 / 休眠玩家走**托管路径**（`_is_managed`）：自动代掷、拒绝买地升级、商店自动离开、赌场自动抽牌、
  **抽卡演出短暂延时后自动确认**（`card`，批次 12 C2）、**小抄置底询问直接「不置底」**
  （`item`，2026-10-10 M1 —— 另有一支 `at_mode` 旁路管「自动回归里房主自己那张」，同
  `_await_card_confirm` / `_await_card_target`）。
- `card` 的倒计时条挂在**抽卡者**那一条上：`_op_window_owner` 认两条归属位 —— **等确定 / 抉择**走
  `_awaiting_card`，**卡选目标**走 `_awaiting_card_target`（都写在 `_broadcast_state` 的等待链里，
  两处顺序一致）。**别拿"抽卡者就是当前行动者"当回退**：`pull_target` / `push_back` 会
  `await _resolve_tile(tgt)` 让**被拉 / 被推的那个人**照常结算落点（`_card_apply_tile_move`），
  落到机会格时抽卡者就是**他**、不是当前行动者 —— 少了 `_awaiting_card_target` 这支，
  25 秒倒计时会挂在不需要作答的人身上。**其他人那一条现在是桌上立牌**
  （左上角名册条已在 v0.10.0 连同 3D 房间第四次改版整体删除），与其他环节同一套 `s_op_timer`。
- **断线**：`peer_disconnected` → 该玩家转机器人接管（对局继续），座位**整局保留**、随时可重连认领（见 §六）；房主退出 → 全场结束回主菜单。

## 六、掉线与重连（2026-10-06 实装）

> 期望：网络波动掉线的玩家可以**回到本局继续玩**。掉线即断开连接，座位由机器人托管（既有行为），
> 重连不是「恢复连接」，而是**新连接凭凭证认领旧座位**。

### 1. 身份凭证（token）

- 开局时（`start_game`）房主给每位真人客户端私发一枚随机 int（`s_assign_token`），
  客户端存 `Net.rejoin_token` 并**持久化到 `user://rejoin.cfg`**（0.13.1 起；退出程序、
  回主菜单再开也还能凭它重连——**此前是仅内存**，进程被杀即失效）。
- token **整局有效、可重复使用**（掉几次都能认领）；认领成功后房主把座位表里
  「token → 旧 peer」改写成「token → 新 peer」，token 本身不变。
- 房主没有重连：房主掉线 = 服务器没了，全场回主菜单（与现状一致）。

### 2. 座位保留与托管

- 对局中掉线：`players` 大厅表**保留该行**（不从房里删）；`game.gd _on_peer_disconnected`
  把 hp 座位转机器人托管（正在等他掷轮 → 机器人 0.8s 后代掷；正在等他决策 → 机器人立刻按策略决定）。
- **重连窗口 = 整局**：不设倒计时，任何时候（含破产观战位）都能认领；对局结束、房主重启后 token 失效。

### 3. 重连握手与认领（房主权威）

1. 客户端重新 `join_game(同一地址)` → 连上后 `c_hello(名字, token)`。
2. 房主校验：token 命中座位表 → **认领**；未命中（没带 token / token 错）→ 维持原口径踢出
   「对局已开始，无法中途加入」。
3. 认领（`game.gd reclaim_seat(旧peer, 新peer)`，幂等）：
   - hp 座位 `peer` 换 key 到新 peer、`bot=false`；名下地皮 `owner` 全部换 key；
   - 所有按 peer 记账的**瞬时等待态**换 key：掷轮 / 询问 / 道具 / 抽卡确定 / 科技挑卡 /
     发现挑卡 / 变卖会话 / 黑市会话 / 选目标 / 畸变补掷；`players` 行 peer 同步更新；
   - **补发一次性弹层**：当前正等他的询问（`s_prompt`）、科技三选一（`s_tech_offer`）、
     发现三选一（`s_discover`）各补一份（这些是 `rpc_id` 一次性 RPC，重连端没收到过）；
   - 广播全量快照 + 战报公告「XX 重连回到座位」。
4. 客户端收 `s_reclaim` → 置 `Net.rejoined` → 直进对局场景，靠快照渲染（状态本就是全量的，
   小卖部 / 变卖等界面都由快照驱动，无需补建）。
5. 主菜单：**就在掉线那一刻**回主菜单，状态条才提示「连接中断——用同一地址点『加入』即可回到对局」，
   地址栏自动回填上次加入的地址（`Net.last_join_addr`）。
   ⚠ 那条提示由 `Net.take_rejoin_hint()` 这个**一次性**提示位驱动（`_on_server_disconnected` /
   `simulate_drop` 置位，主菜单取走即清），**不是**看 `rejoin_token` 是否非零 —— 那枚凭证是
   **持久化**的（`user://rejoin.cfg`），拿它当判据会让首局之后**每次**进首页都挂着红字，
   网络明明正常（2026-10-08 修，`tests/regression_test.gd` 钉着）。
   地址回填则**冷启动也做**，方便凭持久化凭证一键回对局。

### 4. 连接中陌生人的防逗留

`peer_connected` **不再立即踢**（会误杀重连握手的瞬间），改为延迟 1.5 秒：
期间该连接没有完成 hello / 认领才踢出。hello 校验逻辑不变（`hello_verdict`）。

### 5. 已知边界（v1 接受）

- **抽卡演出不补发**：`s_card` 是一次性广播，掉线错过的演出看不到，等待中的「确定」到点自动确认。
- **赌局中途掉线**：当前赌局按机器人继续、结算照常；下一局恢复真人操作。
- 机器人代掷守卫：认领瞬间若挂着一个「0.8s 后代掷」的定时器，座位已转真人则不再代掷。
