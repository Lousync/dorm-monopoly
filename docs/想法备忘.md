## 一、顶部区域升级为「活动面板区」

**状态**：方案已讨论认可，待实现。商店部分随道具系统解冻一起做；赌场迁移可单独排期。

### 目标
棋盘上方的空区（现放「战况」+「最近战报」两块面板）升级为**桌面活动区**：
进商店、开赌场时，对应界面不再是全屏弹层，而是出现在桌面的活动面板位——
全桌人都能围观，保持桌游临场感，棋盘不再被遮挡。

### 布局方案
- **右半 = 活动面板位**（约 1000×460 世界像素）：
  - 默认显示「最近战报」；
  - 商店开张 → 货架界面（3 栏货架 + 刷新按钮 + 购买操作）落位此处；
  - 赌场开局 → 赌场面板（奖池 / 行动者 / 牌堆余量 / 事件流 / 抽牌按钮）落位此处；
  - 活动结束自动复原为最近战报。
- **左半 = 战况排行常驻**；活动期间最近战报压缩到战况下方（战报同时在右上角
  屏幕折叠面板有完整流，不丢信息）。
- 商店界面按此规格新建（道具系统解冻时零迁移）；赌场需把现有屏幕弹层
  `_casino_layer` 迁移为世界面板（中等工作量）。

### 公共 / 私人分层（红线）
- 桌面面板只放**公共信息**：货架存货、奖池、轮到谁、牌堆余量、已公开的事件流、
  操作按钮（买 / 刷新 / 抽顶 / 抽底——所有人可见，host 只认当前行动者的点击，超时托管）。
- **私人信息永远走屏幕私弹**（沿用赌场透视的私密 RPC 模式）：透视结果、
  以后道具系统的私人交互同理。真实桌游类比：桌面摆公共牌，手牌在各自手里。

### 镜头规则
- 活动开张 / 轮到行动时，只对**处于自己视角**的玩家平滑聚焦到活动区
  （复用掷轮对焦转盘的逻辑）；
- 身在别人视角的玩家镜头不被抢（沿用现有 at_home_view 闸），想围观按空格。

## 二、3D 视角（俯视 2D → 可倾斜的 2.5D / 完整 3D）

**状态**：想法讨论完毕，挂起——等美术第一批「模型」素材定格式（2D 立绘 vs 3D 模型）后拍板路线。

### 现状
整个对局画面是纯 2D（Control 节点 + 自研 2D 相机：注视点/缩放/旋转），
镜头恒为俯视，所以观感是 2D。

### 三条路线
1. **假 2.5D（斜切变形）**：Godot 2D 只有仿射变换，做不出真透视，文字跟着变形，
   可读性受损。**不推荐**。
2. **SubViewport 2.5D（推荐的中间路线）**：现有 2D 棋盘整体渲染进 SubViewport，
   作为贴图铺在 3D 场景的斜置桌面上，Camera3D 透视观看；俯角成为表现参数
   （90°=现在的俯视，45~60°=3D 感，可做动画）。
   - **核心好处：玩法代码零改动**——2D 相机、座位旋转、世界面板全部原样活在
     SubViewport 内部；
   - 输入：3D 射线打桌面 → UV → 2D 坐标映射回现有命中逻辑；
   - 屏幕层 HUD（行动条 / 顶栏 / 私弹）照常叠加；
   - GL Compatibility 渲染器支持该管线；
   - 成本：相机层 + 输入映射重做，一次性中大型改造。
3. **完整 3D**：格子 / 棋子 / 模型全 3D 资产 + Camera3D。效果上限最高，
   但渲染层推倒重来，现阶段不建议。

### 决策依赖
- 美术素材格式：2D 立绘 → 保持纯 2D 即可；3D 模型（glTF）→ 走路线 2。
- 路线 2 下，现有「点座位转视角」可升级为 Camera3D 环绕桌面（后续增强项）。

### 关联
- 格子已放大到 112×112 世界像素，为模型预留版面（见道具系统设计文档·格子规格）。
