# 道具试验场（Item Lab）

> **状态：设计定稿（原型已确认 2026-10-02，未实现）**。目标：让开发者**一步直达**地验证任意一件道具的效果——选中 → 一键生效 → 看状态前后差异。
> 与正常对局、F1 开发者面板、`--card-gallery`、`tests/*.gd` 都不同，见 §一。
> 关联：`docs/gameplay/道具系统.md`、`docs/gameplay/道具图鉴.md`、`docs/dev/上手指南.md`。
> **可交互原型（UI 定稿参考）**：`docs/道具试验场-原型.html`（浏览器直接打开）。
> 更新：2026-10-02。

---

## 一、为什么需要 / 与现有工具的区别

| 工具 | 面向 | 局限 |
|---|---|---|
| 正常对局 | 玩 | 验证一件道具要掷轮、走格、等回合，慢 |
| F1 开发者面板 | 对局内注入 | 仍受回合/闸门约束；选目标、选地块、恶状态构造不全 |
| `--card-gallery` | 看卡面模板 | 只看样式，不看效果 |
| `tests/*.gd` | headless 断言 | 写用例成本高，不适合「先试一下」 |

**试验场**：独立沙盒，开局即停；**选中道具 → 一键生效 → 前后 diff**。面向**手动验证 + 复现**，不替代单测。

## 二、形态与入口

- **独立场景** `scenes/item_lab.tscn` + `scripts/item_lab.gd`；**单机本地权威**（不做联机，本机即 host）。
- **入口**（与 F1 明确分离，对局内不混入）：
  - 启动参数 `--lab`：直达试验场（在 `main_menu.gd` 解析，参考 `--autotest` 的既有写法）。
  - 主菜单：当 dev 开关（`user://settings.cfg` 的 `dev.enabled`，或启动带 `--dev`）开启时，显示「道具试验场」按钮。
- **复用真实逻辑**：试验场实例化 `game.tscn`，令其进入 **lab 空闲模式**（`game.gd` 新增 `enter_lab_mode()`）：
  - `_host_setup()` 照常建 `hp / htiles / shops`；隐藏对局 HUD（牌垫 / 阶段条 / 转盘按钮 / 选项等），只保留棋盘；
  - **不调用 `_run_game()`**，不联网，不触发超时/托管/赌场倒计时；
  - 效果复用 `_grant_item` / `_apply_item_effect` / `_resolve_tile` / `_apply_*` 等**原路径**，**不复制效果代码**。

## 三、关键前置重构（顺带清理重复）

- 现状：`_use_item`（game.gd:1940）的 `match` 效果主体，与 `_dev_force_use`（game.gd:2882）里**各有一份**，已重复。
- **抽出 `_apply_item_effect(p, it, arg) -> bool`**：`_use_item` 与试验场（以及重构后的 `_dev_force_use`）共用。
- 好处：试验场**不绕过闸门**即可打效果、dev 面板重复代码一并消除。
- 副作用：`_use_item` 里「使用后置冷却 / 扣体力 / `item_used` / 焚毁」等**闸门与生命周期**仍留在 `_use_item`；`_apply_item_effect` 只负责「效果本体」。

## 四、界面（原型定稿）

**三栏 + 顶栏 + 底栏**（1280×800 基准，等比缩放）：

- **顶栏**：标题 + 种子/模式标签；右侧工具：`重置`、`快照`、`回滚`、`时间倍率(1/2/4/8x)`、`复制状态 JSON`。
- **左 · 玩家**：1~4 张玩家卡（`＋/－ 机器人`）。显示 钱 / 体力条（含上限>5 的紫格）/ 位置 / 背包色块（品质色）/ 状态标（反省 `skip`、休眠 `sleep`、护盾、破产）。点选 = 当前**操作对象**（金框）。
- **中 · 棋盘**：复用 `board_view` 的 56 格环；显示归属色、装修等级、玩家落点。**点格 = 选地块目标**（红框）。棋盘中央悬浮**选中道具的大卡**（`ItemCard` 大号）+ 目标提示。
- **右 · 道具工坊**：
  - 品质筛选（全部 / 白 / 绿 / 蓝 / 紫 / 橙）。
  - 道具网格：列出 `ItemData.ITEMS`；`implemented=false` 灰显标「未实装」。
  - 卡片预览 + 元信息（品质/类型/⚡或被动/冷却/唯一/desc）。
  - **参数/目标**：需目标时提示「点左侧玩家卡选目标」或「点棋盘选目标格」；`作弊器` 显点数输入。
  - 操作按钮：`授予进背包` / `立即使用` / `仅触发效果`。
  - 开关：`计入唯一性`、`一次性用后焚毁`、`绕过闸门(体力/冷却)`。
- **底 · 状态与日志**：左「日志」（沿用战报前缀风格）；右「效果前后 diff」（钱 ±、体力、位置、背包增减、地产 owner/level、护盾…）。
  - diff 子弹：`玩家 ¥20000 → ¥20800 (+800)`、`地块 #24 归属 机器人C → 无主` 等。

## 五、交互细则（原型语义）

- **操作对象 vs 目标**：点玩家卡默认设为**操作对象**；当所选道具 `need == "player"` 时，点玩家卡改为设**目标玩家**；`need == "tile"` 时点棋盘设**目标格**。目标选择在切换道具时清空。
- **三种动作语义**：
  - `授予`：只进背包，不触发效果（唯一性、满包校验）。
  - `立即使用`：走闸门（体力 / 冷却 / 每回合次数），跑 `_apply_item_effect`，消耗/焚毁按开关。
  - `仅触发`：临时实例 → 只跑效果 → 丢弃；不校验闸门、不留包（用于看被动 / 一次性效果）。
- **被动道具**：任选动作都会入包并提示「持有即生效」。
- **开关**：`计入唯一性`、`一次性用后焚毁`、`绕过闸门` 仅影响 lab，不写回正式规则。

## 六、实现映射（建议）

- `game.gd` 新增（host 侧，仅 lab 调用）：
  - `enter_lab_mode()`：置 `lab_mode=true`，隐藏 HUD，`running=false`。
  - `_apply_item_effect(p, it, arg) -> bool`：从 `_use_item` 抽出。
  - `lab_grant(peer, id) -> bool` / `lab_use(peer, id_or_slot, arg, consume: bool, gate: bool)`。
  - 注入：`lab_set_money / lab_set_stamina / lab_set_pos / lab_set_tile(idx, owner, level) / lab_set_soil(idx, prog) / lab_stock(quality_or_id) / lab_set_refresh(n)`。
  - `lab_reset()` / `lab_snapshot() -> Dictionary` / `lab_diff(before, after) -> Array`。
- `main_menu.gd`：解析 `--lab`（→ host + 切试验场）与 dev 开关下的入口按钮。
- `item_lab.tscn` / `item_lab.gd`：三栏 UI，持有 `game` 实例引用，调 `lab_*`。
- 未实装道具：`ItemData.def(id).implemented == false` → 列表灰显、动作提示「未实装」。

## 七、状态注入（构造任意前提）

| 对象 | 可注入 |
|---|---|
| 玩家 | 钱、体力、位置（点格/输入序号）、冷却清零、skip/sleep、alive/破产 |
| 地产 | 点格设 owner（含 `NO_OWNER`）、等级、`soil` + 进度 |
| 商店 | 铺货指定品质 / 指定 item；刷新次数 |
| 全局 | 回合数、时间倍率、当前操作对象 |

- `重置`：重新 `_host_setup()`、清日志、随机新局（种子递增）。

## 八、与正常游戏的关系（红线）

- lab 模式：**不跑回合循环、不联网、不改正式对局数据**；仅在主菜单读 dev 开关。
- `running=false` 或旁路，避免 `_arm_*_timeout` / 托管 / 赌场倒计时误触发。
- `--autotest` 与 `--lab` 互斥（自动测试优先，`lab` 不启用）。

## 九、实现批次

| 批次 | 内容 |
|---|---|
| A | `--lab` 入口 + 场景 + `enter_lab_mode()` 空闲 + 玩家栏 + 棋盘栏 + 工坊（授予/立即使用，无目标类） |
| B | 抽 `_apply_item_effect`；选玩家 / 选地块 / 参数输入（作弊器、点名、快递直达、二两寒暑…）；`仅触发` 与开关 |

| D | 可复现用例保存 / `--lab-case=file.json` 回放（可选，见 §十） |

## 十、已定 / 待定

**已定（2026-10-02 原型确认）**
1. 形态：独立场景 + 复用 `game` 真实逻辑；入口 `--lab` **且** dev 开关下主菜单放入口。
2. 玩家规模：固定最多 4 人同屏可控（含机器人）。
3. 布局与交互：即原型（三栏 + 顶/底栏；操作对象/目标/参数三分）。
4. 「对比模式」**暂不做**；「复制状态 JSON」已覆盖复现需求。

**待定（实现时再定）**
1. 用例保存 / 回放（§九 D）是否纳入首个实现批次。
2. 注入面板的呈现：是常驻右栏还是单独弹层（原型未画，建议独立「注入」标签页）。
3. 是否复刻 `board_view` 的镜头/旋转，或固定俯视（建议固定，专注效果）。
