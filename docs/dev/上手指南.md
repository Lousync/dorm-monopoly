# 上手指南

> 从零把项目跑起来、跑测试、提代码。更新：2026-10-02。

## 一、环境

- **Godot 4.6.x**（项目 `config/features = "4.6"`；团队用 `4.6.2-stable`）。
- 打包需导出模板（见 `README.md`「打包」）。渲染器 `gl_compatibility`。

## 二、跑起来

```powershell
# 双击 start.bat，或：
start.bat "D:\develp\Godot\Godot_v4.6.2-stable_win64.exe"
# 或编辑器打开 project.godot 按 F5
# 命令行：
& "D:\develp\Godot\Godot_v4.6.2-stable_win64_console.exe" --path .
```

> ⚠ **首次拉仓库后，请先用 Godot 编辑器打开一次项目**：`.import` / `.uid` 已加入 `.gitignore` 不再入库，需要编辑器重建（否则可能报资源/UID 缺失）。

## 三、测试

```powershell
$G = "D:\develp\Godot\Godot_v4.6.2-stable_win64_console.exe"

# 1) 脚本静态加载检查（改完脚本先跑这个）
& $G --headless --path . --script tests/load_all.gd
# 2) 规则单测（棋盘形状/租金/路径/地址/坐标闭合）
& $G --headless --path . --script tests/rules_test.gd
# 3) 道具单测（蛋蛋节/coco 焦土）
& $G --headless --path . --script tests/item_test.gd
# 4) 黑市单测（计价/挨打/休眠/机会卡过滤）
& $G --headless --path . --script tests/blackshop_test.gd
# 5) 双实例联机回归（房主 + 客户端自动打 N 轮，含机器人）
#    必须放在同一条命令里：host 起后台 → 等它就绪 → 再起 client。
#    分成两次调用的话，代理沙箱会把两个进程隔到各自的网络命名空间，
#    host 永远等不到 client（现象：client 报 connection_failed、
#    host 打印 AUTOTEST LOBBY humans=1 后直接补机器人开打）。
& $G --headless --path . -- --autotest=host --rounds=5 &
sleep 2.5
& $G --headless --path . -- --autotest=client --rounds=5
```

- 新增系统请补一个 `tests/<系统>_test.gd`（`extends SceneTree`，参考 `blackshop_test.gd` 的脚手架：起 ENet server → 实例化 `game.tscn` → 手动摆状态 → 断言）。
- 自动化开关：`--autotest=host/client`、`--rounds=N`、`--max-rounds=N`；截图 `--shot=`；卡片图鉴 `--card-gallery`；菜单探针 `--menu-probe`；开发者模式 `--dev`。
- 道具试验场（规划，见 `道具试验场.md`）：`--lab` 直达独立沙盒，逐个验证道具效果。

## 四、代码风格与约定

- GDScript，**Tab 缩进**（跟随现有文件）。数据/工具类用 `class_name`。
- 注释用中文；业务逻辑尽量静态类型（`var x := ...` / `: int`）。
- **持续动画手写** `_process`，不用 Tween 做循环/持续动画。
- RPC 命名与 `call_local` 镜像见 `联机协议.md`。
- **公共状态必须进 `_broadcast_state`**。
- 数值占位改动请同步 `docs/gameplay/*`；机制改动同步对应文档。

## 五、分支与提交

- 分支：`main` 为集成分支；功能开发开个人分支（如 `xuzhiyan`）。
- 提交信息用中文、说明「做了什么 + 为什么」，一条提交尽量聚焦一件事；参考 `git log --oneline` 的历史风格。
- **只在明确要求时** commit / push；不提交 `shots/`、`_patch_*.py`、`*.import`、`*.uid`（已忽略）。

## 六、常见坑

1. 改了客户端却不同步？玩法逻辑在房主；客户端只渲染 + `c_*` 请求。
2. UI 不出现？先查状态快照是否带上了对应字段（历史上漏 `shop_peer` 踩过）。
3. `NO_OWNER` 是 `-100`，别用 -1（机器人 peer id 会撞）。
4. GDScript 整数除法返回 int（如 `total / n`），注意取整预期。
5. `.import`/`.uid` 忽略后，换机/新克隆需编辑器重建。
6. 布局仍在返工中，动布局前先对齐 `docs/想法备忘.md`。

## 七、新增内容 checklist

**新增一件道具**
1. `scripts/item_data.gd` 加条目（`implemented`、品质、能量、类型、唯一、冷却、desc）。
2. 效果：`game.gd:_use_item` 的 `match` 分支（主动）或被动钩子（回合开始/购买等）。
3. bot 策略：`_item_phase` / 对应 `_bot_*`。
4. 集权/唯一性：确认 `_item_pool`、焚毁、免疫标签符合预期。
5. 文档：`docs/gameplay/道具图鉴.md` + `道具系统.md` 进度表。
6. 测试：`tests/item_test.gd`（或新开）。

**新增一种格型**
1. `game_data.gd` 生成/数值/`TILE_DESC`。
2. `board_view.gd` 图标/配色/渲染。
3. `game.gd:_resolve_tile` 结算分支。
4. `docs/gameplay/棋盘与地产.md` + 单测 `rules_test.gd`。
